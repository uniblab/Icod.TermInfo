# Icod.TermInfo 1.1.0 — S02 Lexical and Source-Location Model

**Tranche:** S02

**Development version:** `1.1.0-Alpha-2`

**Runtime assembly identity:** `Icod.TermInfo, Version=1.0.0.0`

**Source assembly identity:** `Icod.TermInfo.Source, Version=1.0.0.0`
**Status:** implementation candidate; build/test/package validation required

---

## 1. Purpose

S02 introduces the first public `Icod.TermInfo.Source` API and establishes the
lexical boundary for System V/ncurses-compatible terminfo source.

The tranche is intentionally lexical. It identifies source structure and
preserves raw field text, but it does **not** interpret numeric or string values.
Escape decoding, numeric bases, control-character notation, and source-value
semantics remain S03 work.

The runtime package remains unchanged except for coordinated package versioning:

```text
Icod.TermInfo.Source
        |
        v
  Icod.TermInfo
```

`Icod.TermInfo` does not acquire a dependency on the source package.

---

## 2. Adopted source syntax

The lexical rules follow the mainstream System V/ncurses source form documented
by `terminfo(5)`:

- every entry begins with its first field in column one;
- fields are terminated by commas;
- inter-field whitespace is formatting trivia;
- an embedded comma may be escaped with a backslash;
- entry headers contain the canonical name, aliases, and final descriptive name
  separated by `|`; when the final component has no embedded whitespace, ncurses
  permits it to serve as both an alias and the verbose name, and S02 preserves
  both lexical roles;
- Boolean fields contain only a capability name;
- numeric fields use `#`;
- string fields use `=`;
- cancellation uses `@`;
- inheritance references use `use=`;
- full-line comments begin with `#` in column one;
- entries and string fields may span physical lines;
- the ncurses leading-period form for disabling an individual capability is
  retained as a lexical unit.

S02 deliberately recognizes escape parity only where it is necessary to find
field separators and operators. For example, an escaped comma does not terminate
a field. The meaning of `\E`, `\054`, `^X`, and other value escapes is deferred to
S03.

---

## 3. Public lexical model

S02 introduces:

```text
TermInfoSourceLexer
TermInfoSourceLexerOptions
TermInfoSourceLexResult
TermInfoSourceToken
TermInfoSourceTokenKind
TermInfoSourceSpan
TermInfoSourceDiagnostic
TermInfoSourceDiagnosticSeverity
TermInfoSourceDiagnosticCodes
```

### 3.1 Tokens

The public token stream contains semantic lexical units rather than punctuation
trivia. Token kinds cover:

- canonical terminal name;
- alias;
- descriptive name;
- Boolean capability;
- numeric capability;
- string capability;
- cancelled capability;
- `use=` reference;
- disabled capability;
- comment;
- invalid field retained for diagnostics.

Field-separator commas, formatting whitespace, and physical line endings are
recognized by the scanner but are not emitted as public tokens.

Each token retains its exact source text. In particular, string and numeric
values remain encoded exactly as supplied. S02 does not normalize continuation
lines or decode escapes.

### 3.2 Source spans

`TermInfoSourceSpan` records:

- optional caller-supplied source identity;
- zero-based source offset;
- one-based line;
- one-based column;
- span length;
- exclusive end offset.

Offsets and lengths are measured in UTF-16 code units so that they index the
original .NET `string` directly.

The source layer does not invent paths. If a caller tokenizes anonymous text,
`SourceName` remains `null`.

---

## 4. Input APIs and bounds

S02 supports tokenization from:

```csharp
TermInfoSourceLexer.Tokenize(string, ...)
TermInfoSourceLexer.Tokenize(TextReader, ...)
```

I/O failures raised by a caller-supplied `TextReader` remain I/O failures and are
not converted into source diagnostics.

`TermInfoSourceLexerOptions` bounds complete source documents. The initial
policy is:

```text
DefaultMaximumSourceLength     4 Mi UTF-16 code units
MaximumSupportedSourceLength  64 Mi UTF-16 code units
```

A source document which exceeds the configured bound produces `TIS0001` rather
than allowing unbounded growth.

---

## 5. Diagnostic assignments

S02 consumes the first diagnostic codes frozen by S01:

| Code | Meaning |
|---|---|
| `TIS0001` | configured maximum source length exceeded |
| `TIS0002` | indented capability field before any entry header |
| `TIS0003` | field reaches end of input without a terminating comma |
| `TIS0004` | capability operator without a capability name |
| `TIS0005` | empty canonical terminal name |
| `TIS0006` | empty alias or descriptive-name header component |
| `TIS0007` | empty `use=` reference |
| `TIS0008` | empty field between separators |
| `TIS0009` | non-whitespace text follows a cancellation marker |

All S02 diagnostics are errors. The warning severity exists because S01 froze an
explicit severity model and later source-compatibility work may require
non-fatal diagnostics.

Diagnostics are data. The lexer never writes to stdout or stderr.

## 6. Multiline and escape boundary

A field continues until an **unescaped** comma.

This distinction is important for source such as:

```text
example|Example terminal,
        text=left\,right,
        sgr=\E[0;%?%p1%t
                7%;m,
```

The escaped comma remains part of the string capability. The multiline `sgr`
field remains one token. S02 preserves the original line break and indentation
inside `TermInfoSourceToken.Text`; S03 decides how terminfo continuation and
escape rules affect the resulting capability value.

Backslash parity is respected while locating separators. An odd run of
backslashes escapes a comma; an even run leaves the comma as a field separator.

---

## 7. Comments and disabled capabilities

A `#` beginning in column one while the scanner is between fields produces a
comment token. Comment text is retained exactly through the end of the physical
line, excluding the line terminator.

The ncurses form:

```text
        .ind=\E[%p1%dS,
```

is emitted as `DisabledCapability`. S02 does not attempt to interpret the field
behind the leading period; later source-model work can decide whether and how
such disabled fields are represented.

## 8. Public API baseline

S02 is the first tranche with an intentional exported `Icod.TermInfo.Source`
surface. The reviewed baseline is:

```text
docs/1.1.0-SOURCE-PUBLIC-API-BASELINE.txt
```

The existing public API snapshot tool is extended so `--write` and `--check`
may operate on an explicitly supplied assembly while preserving the existing
1.0 runtime baseline behavior.

Package validation therefore enforces both:

1. exact source-package API parity between `net8.0` and `net10.0`; and
2. exact agreement with the reviewed S02 source public API baseline.

The frozen runtime baseline remains:

```text
docs/1.0.0-PUBLIC-API-BASELINE.txt
```

and is not regenerated or weakened by S02.

## 9. Compatibility corpus covered by S02

Tests cover at least:

- representative entry headers with aliases and descriptions, including the
  ncurses final-name alias/description ambiguity;
- the existing checked-in `.ti` source corpus used to generate compiled parser
  fixtures;
- Boolean, numeric, string, cancellation, and `use=` fields;
- escaped commas;
- odd/even backslash parity before commas;
- multiline string fields;
- comments between fields and entries;
- disabled capability fields;
- LF and CRLF source positioning;
- deterministic repeated tokenization;
- bounded `string` and `TextReader` input;
- orphaned continuation fields;
- missing field terminators;
- missing capability names;
- empty header components;
- empty `use=` references;
- empty fields;
- malformed cancellation tails.

---

## 10. Explicit non-goals

S02 does not implement:

- escape decoding;
- control-character notation;
- octal or hexadecimal numeric conversion;
- numeric range semantics;
- string-value normalization;
- capability catalog lookup;
- extended-capability classification;
- cancellation resolution;
- `use=` inheritance resolution;
- unresolved source entries;
- `TerminalDescription` materialization.

Those remain assigned to S03 through S08.

---

## 11. S02 gate

S02 is complete when:

1. both packages use development version `1.1.0-Alpha-2`;
2. both assemblies retain stable 1.x identity `1.0.0.0`;
3. representative `.ti` source tokenizes deterministically;
4. entry names, aliases, descriptions, comments, Boolean/numeric/string fields,
   cancellation, disabled fields, and `use=` references are distinguished;
5. escaped commas and multiline fields do not split incorrectly;
6. source spans remain precise across LF and CRLF input;
7. malformed lexical input produces stable `TISdddd` diagnostics;
8. source-size limits are enforced for both `string` and `TextReader` input;
9. the source public API matches the reviewed S02 baseline on both target
   frameworks;
10. the runtime 1.0 public API baseline remains exact;
11. fresh package consumers continue to pass for both target frameworks; and
12. no source-value decoding or unresolved-entry semantics leak forward from
    S03/S04.

After this gate, S03 may implement string and numeric source semantics over the
raw lexical fields established here.
