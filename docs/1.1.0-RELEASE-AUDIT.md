# Icod.TermInfo 1.1.0 Release Audit

**Release version:** `1.1.0`
**Runtime assembly version:** `1.0.0.0`
**Source assembly version:** `1.0.0.0`
**Status:** Release sign-off pending

## Purpose

This document is the final release gate for the coordinated `Icod.TermInfo`
1.1.0 package family. It records what must remain true when the final package
version replaces `1.1.0-Alpha-9`.

The planned S01-S09 implementation program is complete. Release closure is not
an additional source-language feature tranche; it is the final API, package,
documentation, CI, and publication audit for the completed work.

## Release scope

The runtime package remains the stable low-level terminfo implementation
established in 1.0. Its public contract is not enlarged by the 1.1 source work.

`Icod.TermInfo.Source` adds the optional source-language path:

```text
.ti source
    |
    v
lexer / parser
    |
    v
unresolved source entries
    |
    v
cancellation + use= resolution
    |
    v
resolved source entry
    |
    v
TerminalDescription
```

The 1.1 implementation includes:

- deterministic source lexing and source-location diagnostics;
- terminfo string and numeric source semantics;
- unresolved entry and field models;
- standard and extended capability classification;
- cancellation semantics;
- bounded, cycle-safe `use=` inheritance resolution;
- materialization into the existing immutable `TerminalDescription` model;
- duplicate canonical-name and alias warnings;
- an authoritative checked-in source corpus;
- deterministic mutation fuzzing;
- source-size and inheritance-depth hostile-input coverage;
- offline source-versus-compiled compatibility fixtures.

Compiler output, `tic`/`infocmp`/`toe` command projects, termcap conversion,
hashed-database providers, live terminal sessions, PTYs, curses, and terminal
emulation remain outside 1.1.

## API and assembly contract

The final release SHALL preserve all of these conditions:

- `docs/1.0.0-PUBLIC-API-BASELINE.txt` remains the exact runtime public API
  contract;
- `docs/1.1.0-SOURCE-PUBLIC-API-BASELINE.txt` remains the exact Source public
  API contract;
- runtime `net8.0` and `net10.0` public API manifests remain identical;
- Source `net8.0` and `net10.0` public API manifests remain identical;
- both assemblies remain unsigned;
- `Icod.TermInfo` retains assembly version `1.0.0.0`;
- `Icod.TermInfo.Source` retains assembly version `1.0.0.0`.

The package version advances to `1.1.0`; the assembly version does not. This is
intentional. The 1.x policy uses stable assembly identity so compatible package
minor and patch releases do not create unnecessary binary identities.

The runtime baseline MUST NOT be regenerated merely to accommodate the 1.1
Source package. The Source baseline MUST NOT be rewritten merely to silence a
release check.

## Semantic and robustness gate

Final validation SHALL retain the cumulative S01-S09 evidence, including:

- exact source diagnostics and stable diagnostic codes;
- case-sensitive capability and source-identity semantics;
- rightmost local capability behavior and cancellation tombstones;
- deterministic `use=` precedence, missing-parent diagnostics, cycle detection,
  and maximum-depth enforcement;
- semantic equivalence between checked-in source and compiled T29 fixtures;
- duplicate source identities diagnosed without nondeterministic lookup;
- deterministic mutation results;
- bounded source-length behavior for both `string` and `TextReader` entry paths.

Normal CI SHALL remain independent of host `tic`, `infocmp`, and terminfo
database contents.

## Package contract

Both package projects SHALL publish version `1.1.0`.

`Icod.TermInfo` SHALL:

- remain dependency-free at the NuGet runtime level;
- contain managed and XML documentation assets for `net8.0` and `net10.0`;
- produce portable symbols for both targets;
- retain README, icon, LGPL license, repository metadata, and Source Link.

`Icod.TermInfo.Source` SHALL:

- depend one-way on the matching `Icod.TermInfo` package version;
- contain managed and XML documentation assets for `net8.0` and `net10.0`;
- produce portable symbols for both targets;
- retain README, icon, LGPL license, repository metadata, and Source Link.

The final workflow artifacts are immutable. The exact validated `.nupkg` files
published to NuGet.org SHALL also be the package artifacts published to GitHub
Packages.

## Required final validation

Before release sign-off, run:

```text
dotnet restore Icod.TermInfo.sln
dotnet build Icod.TermInfo.sln -c Release
dotnet test Icod.TermInfo.sln -c Release
dotnet pack Icod.TermInfo.csproj -c Release --output artifacts
dotnet pack Icod.TermInfo.Source/Icod.TermInfo.Source.csproj -c Release --output artifacts
```

Then run the coordinated release verifier with the same Release outputs:

```text
.github\scripts\verify-release-package.cmd artifacts Release
bash .github/scripts/verify-release-package.sh artifacts Release
```

The verifier SHALL continue to exercise `public-api-snapshot --check`, runtime
and Source cross-target API comparison, both package versions, both
package-reference-only smoke consumers, and the repository's non-interactive
sample path.

The final `main` workflow SHALL then pass on Windows, Linux, and macOS before
release sign-off.

## Publication sign-off

Before the final publication commit is considered released:

- NuGet trusted publishing must authorize `uniblab/Icod.TermInfo`,
  `push-main.yaml`, environment `Release`, and both package IDs;
- GitHub Packages publication must retain `packages: write`;
- both `Icod.TermInfo` and `Icod.TermInfo.Source` version `1.1.0` must be visible
  in NuGet.org and GitHub Packages;
- fresh consumers of both packages must restore the final version;
- tag `v1.1.0` must identify the exact `main` commit whose Release validation
  and publication succeeded.

No source, documentation, package metadata, API baseline, or package payload may
change after that validation without rerunning this release gate.
