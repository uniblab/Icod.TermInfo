# Icod.TermInfo 1.1.0 S08 — `TerminalDescription` Materialization

**Development version:** `1.1.0-Alpha-8`
**Assembly version:** `1.0.0.0`
**Status:** implementation complete — validation pending
**Next tranche:** S09 — corpus, fuzzing, and compatibility

## Purpose

S08 closes the source-to-runtime semantic path introduced by S01-S07. A
successfully resolved `TermInfoSourceResolvedEntry` can now be projected into the
stable `Icod.TermInfo.TerminalDescription` model without changing the frozen
runtime package API.

The dependency direction remains:

```text
Icod.TermInfo.Source
        |
        v
  Icod.TermInfo
```

`Icod.TermInfo` does not acquire a dependency on the Source package.

## Public materialization contract

S08 adds one public method to the already reviewed resolved-entry type:

```csharp
TerminalDescription TermInfoSourceResolvedEntry.ToTerminalDescription()
```

No new public Source type is required. Materialization is deliberately attached
to the resolved semantic result rather than to the parser or unresolved entry so
callers cannot accidentally bypass S07 inheritance and cancellation semantics.

Each call creates a new immutable `TerminalDescription`.

## Identity projection

The materialized runtime description uses identity from the resolved root source
entry:

- `CanonicalName` becomes `TerminalDescription.Name`;
- source aliases become `TerminalDescription.Aliases` in source order;
- the optional source description becomes `TerminalDescription.Description`.

Identity from inherited parents does not replace the child's identity.

## Capability projection

Only effectively present resolved capabilities are copied:

- standard Boolean capabilities;
- standard numeric capabilities;
- standard string capabilities;
- case-sensitive extended Boolean capabilities;
- case-sensitive extended numeric capabilities;
- case-sensitive extended string capabilities.

The existing public `TerminalDescriptionBuilder` performs construction. S08 does
not add a parallel runtime representation and does not duplicate standard
capability metadata.

The runtime builder continues to provide canonical standard-capability ordering
by compiled binary index.

## Source-only state does not leak

The following remain Source-layer concepts and are not represented in the
materialized runtime description:

- `use=` declarations;
- cancellation tombstones;
- comments;
- source tokens;
- source spans;
- inheritance graph structure;
- diagnostic provenance.

A capability canceled during source resolution therefore materializes exactly
like an absent capability. This matches the effective semantic state visible
after reading an equivalent compiled terminfo entry.

## Source/compiled equivalence gate

S08 reuses the authoritative T29 fixture pairs already checked into the runtime
test corpus. Each source file is parsed, resolved, and materialized, while its
paired binary file is parsed by `CompiledTermInfoParser`. The resulting runtime
descriptions must be semantically equivalent.

The gate covers:

```text
t29-legacy-minimal
t29-legacy-alignment
t29-legacy-edge
t29-extended
t29-extended32
```

Together these fixtures exercise ordinary standard capabilities, alignment,
cancellation, padding text, high-byte strings, extended Boolean/numeric/string
capabilities, and the wide-numeric compiled format.

Equivalence includes:

- canonical name;
- description;
- aliases;
- effectively present standard Boolean capabilities;
- standard numeric values;
- standard string values;
- extended capability names, kinds, and values.

The `t29-legacy-edge` fixture specifically verifies that source cancellation
tombstones disappear at the runtime boundary while the remaining semantic state
matches the compiled form.

## Package and API contract

Both packages advance together to `1.1.0-Alpha-8` while retaining assembly
version `1.0.0.0`.

The Source public API baseline adds only:

```text
TermInfoSourceResolvedEntry.ToTerminalDescription()
```

The frozen `docs/1.0.0-PUBLIC-API-BASELINE.txt` runtime contract remains
unchanged. Cross-target Source API equivalence continues to be checked for
`net8.0` and `net10.0`.

The package-reference-only Source smoke test now exercises materialization as
well as parsing and resolution.

## S08 gate

S08 is ready for completion when:

- resolved source identity materializes correctly;
- inherited standard and extended capabilities survive materialization;
- local cancellations materialize as absence;
- source-only state does not appear in `TerminalDescription`;
- all five authoritative T29 source/compiled fixture pairs produce semantically
  equivalent runtime descriptions;
- the Source public API baseline includes the reviewed conversion method;
- net8.0 and net10.0 Source public APIs remain equivalent;
- package smoke validation succeeds for both target frameworks;
- the frozen 1.0 runtime API baseline remains exact.

After this gate, S09 can concentrate on corpus breadth, duplicate identity
diagnostics, fuzzing, adversarial inputs, and compatibility closure for the 1.1
release.
