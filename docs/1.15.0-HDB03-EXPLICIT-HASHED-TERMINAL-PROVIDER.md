## Accepted public API

The package exports exactly these three public types:

```csharp
public sealed class BerkeleyDbTerminalDescriptionProvider
	: ITerminalDescriptionProvider
public sealed class BerkeleyDbTerminalDescriptionProviderOptions
public sealed class BerkeleyDbDatabaseFormatException : FormatException
```

The provider owns one canonical absolute database path. Options snapshot
`CompiledTermInfoParserOptions`, maximum database bytes, and maximum index
hops at construction. No raw Berkeley DB page, cursor, environment,
transaction, or write API is public.

## Accepted behavior

The provider:

- validates construction and lookup arguments before file access;
- encodes the exact requested key as UTF-8 and compares identities ordinally;
- reads one bounded Hash-v9 image through the accepted HDB02 reader;
- follows bounded marker-2 index links and extracts marker-0 compiled bytes;
- calls `CompiledTermInfoParser` as the only terminfo semantic parser;
- accepts the parsed canonical name or an exact declared alias;
- caches only successful immutable descriptions using publication-once semantics;
- removes only the exact failed or missed cache entry so later calls retry; and
- requires a new provider instance to observe changed content after a success.

Container and ncurses-envelope `InvalidDataException` failures are wrapped in
`BerkeleyDbDatabaseFormatException` with the original exception retained.
Parser failures, identity mismatches, and ordinary I/O failures retain their
existing exception types.

## Bounds and compatibility

The default database limit is 64 MiB. The default index-hop limit is 16 and the
largest configurable hop limit is 1024. The internal stored-item cap is the
Runtime parser's maximum supported compiled-entry size plus the one-byte ncurses
marker. The configured parser limit remains authoritative for the extracted
entry. The database-size limit bounds aggregate acquisition storage; it is not
a per-record promise.

The qualified storage subset remains unencrypted, non-checksummed Berkeley DB
Hash format version 9 with sorted Hash pages, inline/off-page records, overflow
chains, and both byte orders. Validation follows encountered structures and does
not promise an atomic snapshot against concurrent writers or exhaustive
validation of unrelated pages.

Native fixtures use ASCII terminal identities. Database keys are encoded as
UTF-8, while compiled identity bytes retain Runtime's reversible Latin-1
interpretation. Broader non-ASCII producer interoperability is not accepted by
this tranche. Native producer qualification covers Linux and macOS; Windows
reads the Linux-generated store without Berkeley DB installed. Big-endian
coverage remains synthetic.

## HDB03 acceptance

All HDB03 roadmap requirements are accepted within the documented subset and
limits: canonical path ownership, immutable options, terminal-name validation,
exact lookup, bounded ncurses envelope resolution, parser reuse, identity
verification, successful caching, retry semantics, concurrency coverage,
native differential qualification, and package-only consumption.

The package remains optional, pure managed, read-only, and dependency-free
beyond the matching `Icod.TermInfo` runtime package. HDB04 system discovery is
the next tranche.
