# Icod.TermInfo 1.7.0 RS01 — Synthesis Contract and Internal Model

**Development version:** `1.7.0-Alpha-1`
**Tranche:** RS01
**Status:** implementation contract
**Next tranche:** RS02 — Standard Capability Delta and Cancellation Engine

## Objective

RS01 establishes the reusable contract for relative terminfo source synthesis
without prematurely implementing the capability-delta algorithm. The new surface
belongs to `Icod.TermInfo.Inspection`, which already owns effective source
rendering and semantic comparison and already depends only on Runtime and Source.

The production dependency graph remains:

```text
Icod.TermInfo.Inspection
    -> Icod.TermInfo.Source
    -> Icod.TermInfo
```

Inspection does not acquire a production Compiler or Termcap dependency. Runtime,
Source, Compiler, and Termcap public APIs remain frozen.

## Public synthesis surface

RS01 adds three public Inspection types:

```text
TerminalDescriptionSourceSynthesisParent
TerminalDescriptionSourceSynthesisOptions
TerminalDescriptionSourceSynthesizer
```

The parent descriptor associates the exact name to be written after `use=` with
the already-resolved `TerminalDescription` whose effective capabilities that
reference contributes:

```csharp
TerminalDescriptionSourceSynthesisParent parent = new(
    "xterm-base",
    parentDescription
);
```

The distinction is deliberate. `UseName` is source identity chosen by the
caller; `Description.Name` is effective Runtime identity. A caller may therefore
emit a canonical name or a valid alias without mutating the effective parent
model.

The synthesizer exposes string and caller-owned writer entry points:

```csharp
string source = TerminalDescriptionSourceSynthesizer.Synthesize(
    target,
    parents,
    options
);

TerminalDescriptionSourceSynthesizer.Write(
    writer,
    target,
    parents,
    options
);
```

Invalid API arguments use normal .NET argument exceptions. RS01 does not add a
parallel public diagnostic/result model merely to report caller-contract errors.
Semantic synthesis diagnostics may be introduced later only if an actual
non-exceptional synthesis condition requires them.

## Ordered parent contract

The supplied parent sequence is semantic input and SHALL be preserved exactly.
The synthesizer does not reorder, optimize, or silently remove parents.

The existing Source resolver remains authoritative for future execution:

```text
parents = empty

for each use= from rightmost to leftmost:
    parents.OverlayHigherPriority(resolvedParent)

local = CreateLocal(child)
local.Inherit(parents)
```

Consequently, the leftmost supplied parent has higher priority in
parent-to-parent collisions while explicit child state outranks every parent.
RS02 will implement the standard capability delta against that already-frozen
precedence model rather than creating a second inheritance algorithm.

## Parent reference names

`TerminalDescriptionSourceSynthesisParent.UseName` is validated when the parent
descriptor is constructed.

A reference name must be non-null and non-empty and must not contain:

- whitespace;
- control characters;
- `|`;
- `,`.

A reference name also may not end in an odd run of backslashes because the final
backslash would escape the source field terminator. These restrictions keep the
emitted reference losslessly representable by the existing Source grammar.

Within one synthesis request, `UseName` values must be unique under ordinal,
case-sensitive comparison. Two different effective parents cannot be represented
faithfully by the same emitted source reference. The same effective
`TerminalDescription` may still appear more than once when the caller supplies
distinct valid reference names.

## Synthesis options

`TerminalDescriptionSourceSynthesisOptions` freezes the RS01 reusable policy:

```text
LineWidth              80
Layout                 Canonical
CapabilityOrder        Database
MaximumParentCount     64
```

The presentation properties intentionally reuse the existing Inspection renderer
concepts rather than introducing duplicate layout enums.

The hard supported parent-count limit is:

```text
MaximumSupportedParentCount = 256
```

A caller may select a limit from 0 through 256. The default of 64 and hard bound
of 256 deliberately match the scale already used by the frozen Source
inheritance-depth contract.

RS01 does not expose `IncludeExtendedCapabilities` on the synthesis options.
Relative synthesis must not silently omit inherited extended state while claiming
to reproduce the target. RS03 owns the exact extended-capability filtering
contract.

No separate synthesis-output length limit is added in RS01. The zero-parent path
uses the existing bounded/validated effective source renderer, while the only new
multiplicative input introduced by relative synthesis is the ordered parent list,
which RS01 bounds explicitly. RS02-RS05 may introduce a synthesis-specific output
limit if the implemented delta/rendering pipeline demonstrates a need for one.

## Internal synthesis plan

RS01 introduces an internal `TerminalDescriptionSourceSynthesisPlan` containing:

- the exact target `TerminalDescription`;
- an immutable copy of the ordered validated parents;
- the effective immutable synthesis options.

The plan deliberately contains no public second semantic representation of a
terminal. Later tranches may extend the internal implementation with local
Boolean, numeric, string, cancellation, extended, and `use=` directive plans
without changing Runtime or Source APIs.

Materializing the caller-provided parent enumeration during plan creation also
ensures that later synthesis does not re-enumerate a stateful input or depend on
provider/dictionary insertion order.

## RS01 execution boundary

RS01 makes the degenerate zero-parent case operational because it requires no new
relative semantics:

```text
Synthesize(target, empty parents)
    == effective TerminalDescriptionSourceRenderer output
```

The existing renderer is invoked with the selected line width, layout, and
capability order and with extended capabilities included so semantic content is
not silently filtered.

A request containing one or more parents is validated and represented by the
internal plan, but execution currently throws `NotSupportedException`. This is an
intentional development-tranche boundary. RS01 must not emit a full target entry
plus `use=` references because that would be semantically wrong whenever inherited
state needs cancellation or override.

RS02 replaces this temporary execution guard with standard Boolean, numeric, and
string delta/cancellation generation.

## Target identity

The target `TerminalDescription` is retained by reference in the synthesis plan.
Its canonical name, aliases, and verbose description remain the only source of
child identity. Parent identity metadata is never inherited into the child
header.

The existing effective renderer remains authoritative for whether target identity
can be represented losslessly by the Source 1.1 grammar. RS01 does not weaken or
duplicate those validation rules.

## Determinism

RS01 freezes the inputs required for later deterministic synthesis:

- parent order is caller-controlled and preserved;
- reference-name equality is ordinal and case-sensitive;
- options use already-frozen Inspection layout/order enums;
- parent enumeration is materialized once;
- no environment variables or database discovery are consulted;
- no culture-sensitive comparison is used.

The same target, ordered parent descriptors, and options therefore create the
same synthesis plan on every target framework and operating system.

## Versioning and API boundary

RS01 advances the coordinated suite version to:

```text
1.7.0-Alpha-1
```

All five reusable assemblies retain:

```text
AssemblyVersion 1.0.0.0
```

The historical frozen baselines remain unchanged:

- Runtime 1.0;
- Source 1.1;
- Compiler 1.2;
- Inspection 1.4;
- Termcap 1.6.

The new Inspection surface is an additive 1.7 development contract. Cross-target
Inspection API equality remains a release-verifier gate during development. The
final exact `docs/1.7.0-INSPECTION-PUBLIC-API-BASELINE.txt` is intentionally
created only by RS08 after the 1.7 API has passed the intervening semantic and CLI
tranches.

The package smoke test is updated in RS01 to prove that the three new public types
are present in the packed Inspection artifact while Runtime and Source remain its
only production package dependencies.

## RS01 gate

RS01 is complete when:

- the coordinated version is `1.7.0-Alpha-1`;
- the public parent, options, and synthesizer types are present on net8.0,
  net9.0, and net10.0;
- Runtime, Source, Compiler, and Termcap public surfaces remain frozen;
- Inspection still depends exactly on Runtime and Source in production;
- the default parent limit is 64 and the hard maximum is 256;
- invalid reference names are rejected deterministically;
- duplicate reference names are rejected ordinally;
- parent order is preserved without optimization;
- zero-parent synthesis is identical to effective source rendering;
- parent-relative execution remains explicitly reserved for RS02;
- package smoke validates the additive Inspection surface;
- release verification accepts additive 1.7 Inspection development while still
  retaining the historical 1.4 baseline as immutable evidence;
- all existing solution tests continue to distinguish the published stable
  `1.6.1` documentation/audits from the current `1.7.0-Alpha-1` coordinated
  development version.

RS02 may then implement the standard capability parent aggregate, local delta,
and cancellation engine against this frozen contract.
