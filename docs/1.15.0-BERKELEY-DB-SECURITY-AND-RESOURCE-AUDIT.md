# Icod.TermInfo 1.15.0 Berkeley DB Security and Resource Audit

## Scope and result

This audit covers untrusted or damaged Berkeley DB Hash-v9 files supplied to the
optional read-only package. The implementation uses checked arithmetic, bounded
allocation, explicit structure validation, deterministic failure categories,
and no native database code. No write, repair, recovery, or executable-payload
surface is exposed.

The result is acceptable for the reviewed 1.15 acquisition scope subject to the
documented bounds and the important non-atomicity limitation below.

## Resource limits

`BerkeleyDbTerminalDescriptionProviderOptions` snapshots:

- `MaximumDatabaseSize` (default 64 MiB); and
- `MaximumIndexHops` (default 16, maximum supported 1024).

`BerkeleyDbTerminalCatalogReaderOptions` additionally snapshots:

- `MaximumRecordCount` (default 65536).

Runtime's immutable `CompiledTermInfoParserOptions` continues to bound compiled
entry sections, strings, extended capabilities, and total parsed entry size.
Zero/negative sizes, negative hops, or hops above the supported maximum are
rejected at option construction.

The reader rejects files larger than the configured database bound before
allocation. Page count, page offsets, item offsets, declared payload sizes,
record count, and overflow accumulation use checked/range-validated arithmetic.
An item cannot exceed the compiled-entry parser's effective byte bound.

## Structural and logical validation

The reader validates metadata magic, format version, page geometry, byte order,
page identity/type, key/value pairing, strict unsigned byte-key order, duplicate
keys, inline-item boundaries, overflow page identity/type/linkage, cycles,
length mismatch, trailing pages, and unsupported features.

The ncurses layer validates nonempty envelopes, marker 0 data, marker 2 index
targets, index cycles/hops, dangling targets, exact identity, and catalog name
collisions. Found corruption is never converted into a clean miss.

## Filesystem, permissions, and mutation

Paths are canonicalized, but the caller owns trust in the selected location and
filesystem. Missing files and ordinary I/O failures keep their platform
exceptions. Real operating-system permission denial propagates as
`UnauthorizedAccessException`; qualification proves denial and restoration on
Windows, Linux, and macOS.

Production opens one read handle and performs two complete observations. A
content or length difference is rejected as detected mutation. This reduces the
risk of accepting an obviously changing file, but it is **not an atomic snapshot**,
does not lock out arbitrary writers, and cannot prove no same-byte rewrite
occurred. Callers requiring stronger coordination must provide it outside this
package.

Successful provider results are cached per provider instance. Clean misses and
failures are not cached. Catalog reads are always fresh, independent snapshots.

## Cancellation and lifecycle

Catalog enumeration accepts caller-owned cancellation and checks cancellation
before and during bounded record/index processing. Streams are disposed before
compiled parsing and before results escape. Independent calls share no mutable
reader state. Cancellation remains `OperationCanceledException` rather than a
format error.

## Native and supply-chain boundary

The production package has no third-party package dependency beyond matching
Icod Runtime, no native library, no RID asset, no dynamic library probing, no
hidden download, and no copied Berkeley DB implementation source. Native
Berkeley DB and ncurses are confined to isolated CI oracle construction.

The remaining managed attack surface is audited and tested as a file-format
parser. Any future native binding, write support, broader access method, or new
format revision requires a new security and distribution review.
