## Purpose

I01 establishes the fourth coordinated package before public inspection behavior
is introduced. It freezes the dependency and release-quality boundary so later
rendering/comparison tranches cannot accidentally enlarge Runtime, Source, or
Compiler merely for implementation convenience.

The production dependency graph is:

```text
Inspection -> Source -> Runtime
Inspection ----------> Runtime

Compiler   -> Source -> Runtime
Compiler   ------------> Runtime
```

There is no production dependency between Inspection and Compiler. Inspection
tests may acquire Compiler later for round-trip/differential evidence without
changing the production graph.

## Package contract

`Icod.TermInfo.Inspection`:

- targets `net8.0`, `net9.0`, and `net10.0`;
- uses C# 13;
- remains unsigned;
- retains assembly version `1.0.0.0`;
- produces XML documentation and portable symbol packages;
- carries README, icon, license-expression, repository, deterministic-build,
  and Source Link metadata;
- depends directly on matching Runtime and Source packages;
- does not depend on Compiler.

Beginning with I01, Runtime, Source, Compiler, and Inspection all carry
`1.3.0-Alpha-1`. Their `<Version>` and `<PackageVersion>` values remain
identical and coordinated.

## Public API baseline

I01 deliberately exports no Inspection public types. The initial
`docs/1.3.0-INSPECTION-PUBLIC-API-BASELINE.txt` therefore contains only the
snapshot header and stable assembly identity.

This is intentional rather than an omission. I02 is the first behavior tranche
and will introduce the reviewed canonical effective renderer surface. An empty
I01 baseline makes accidental public types detectable immediately.

The frozen existing baselines remain unchanged:

```text
docs/1.0.0-PUBLIC-API-BASELINE.txt
docs/1.1.0-SOURCE-PUBLIC-API-BASELINE.txt
docs/1.2.0-COMPILER-PUBLIC-API-BASELINE.txt
```

## Verification contract

I01 extends release validation to require:

- Inspection API equivalence across net8/net9/net10;
- the independent Inspection API baseline;
- structural Inspection package validation;
- exact Runtime+Source Inspection dependency groups;
- explicit absence of a Compiler package dependency;
- stable unsigned assembly identity;
- XML, portable PDB, repository metadata, and Source Link validation;
- an isolated package-reference-only Inspection consumer on all three TFMs;
- four-package coordinated version checks.

The package smoke consumer is intentionally copied outside the repository before
restore/run, matching the existing Runtime/Source/Compiler pattern. It proves the
packed Inspection package and its transitive Runtime/Source dependencies can be
restored without project references or stale repository outputs.

## Release pipeline contract

PR and main workflows now pack four packages. The tag workflow validates and
publishes the same four package IDs:

```text
Icod.TermInfo
Icod.TermInfo.Source
Icod.TermInfo.Compiler
Icod.TermInfo.Inspection
```

A release therefore contains eight `.nupkg` / `.snupkg` files plus
`SHA256SUMS.txt`, for nine GitHub Release assets total.

Pull-request and ordinary-main workflows remain non-publishing. Registry
credentials and package-write/OIDC publication permissions remain confined to
the tag-driven release workflow.

## I01 gate

I01 is complete only after the exact `1.3.0-Alpha-1` candidate:

1. builds and tests on Windows, Linux, and macOS;
2. packs all four packages;
3. passes all four API-equivalence/baseline gates;
4. passes Runtime, Compiler, and Inspection structural verifiers;
5. executes all four isolated package consumers on all three TFMs;
6. proves the Inspection production project references only Runtime and Source;
7. passes the non-publishing PR/main validation path and the tag-release
   validation plumbing.

This document records the implementation contract. It does not claim external
CI results before they occur.
