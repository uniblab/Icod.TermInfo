# Icod.TermInfo 1.6.0 TC01 — Termcap Package and Parser Foundation

**Development version:** `1.6.0-Alpha-1`
**Tranche:** TC01
**Status:** Implementation patch

## Objective

TC01 creates the opt-in `Icod.TermInfo.Termcap` reusable package and establishes
a bounded conventional termcap parser without changing the frozen Runtime,
Source, Compiler, or Inspection public APIs.

## Package boundary

The new dependency edge is intentionally one-way:

```text
Icod.TermInfo.Termcap
    -> Icod.TermInfo
```

TC01 does not add a dependency on `Icod.TermInfo.Source`. Although both packages
parse terminal-description text, termcap and terminfo have different source
syntax, vocabulary, inheritance, and compatibility policy. Keeping the source
models separate avoids enlarging or reinterpreting the frozen 1.1 Source API.

## Parser contract

The TC01 parser recognizes:

- physical comments beginning with `#`;
- blank lines;
- backslash-newline continuation, removing only the backslash/newline pair and preserving following source characters;
- `|`-separated terminal header components;
- colon-delimited capability fields;
- two-character Boolean capabilities;
- `xx#number` numeric capabilities;
- `xx=value` string capabilities;
- `xx@` cancellation;
- final `tc=name` inheritance references;
- `^X`, `^?`, C-style backslash escapes, `\E`/`\e`, and one-to-three-digit
  octal string escapes.

The parser treats literal `:` as a field delimiter. A colon byte in a termcap
string is therefore represented safely as `\072`; `\:` is not treated as a
mechanism for hiding the delimiter.

Numeric values are accepted as non-negative decimal values plus conventional
C-style octal and hexadecimal forms used by BSD capability databases. Values
which do not fit the signed 32-bit runtime numeric model are diagnosed.

## Unresolved-model boundary

The parser produces ordered source objects and diagnostics. It does not yet:

- select a canonical terminfo name from the termcap header;
- classify two-character fields against Runtime capability metadata;
- resolve `tc=`;
- apply inherited cancellation;
- materialize `TerminalDescription`;
- read termcap databases or environment variables.

Those responsibilities are assigned to later 1.6 tranches.

## Defensive behavior

`TermcapSourceParserOptions` defaults to a 4 MiB maximum source length and caps
caller-selected limits at 64 MiB. Oversized `string` and `TextReader` inputs fail
without partial parsing.

Malformed input is represented by deterministic `TCAPxxxx` diagnostics with
source spans. The parser reports unsafe NUL values and out-of-range octal or
numeric values instead of silently truncating them.

## Integration

TC01:

- advances the coordinated development version to `1.6.0-Alpha-1`;
- adds `Icod.TermInfo.Termcap` and `Icod.TermInfo.Termcap.Tests` to the solution;
- builds/tests the new projects in the existing three-host solution matrix;
- packs the new Termcap package in PR and main-validation package construction;
- verifies its package version is coordinated and that both `.nupkg` and
  `.snupkg` are present;
- leaves stable 1.5 install documentation unchanged;
- leaves release-tag publication topology unchanged until 1.6 release
  finalization.

## TC01 gate

TC01 is complete when the full solution succeeds on Windows, Linux, and macOS;
the parser tests cover conventional syntax, continuation, numeric bases, disabled fields, escapes, cancellation,
reference placement, malformed fields, and resource limits; and existing
reusable public API baseline gates remain unchanged.
