## Raster-backend profile JSON

The profile document records:

- concrete backend identity;
- classified backend support status;
- evidence count; and
- the complete canonical evidence snapshot, including backend, polarity, provenance kind, source label, and source ordinal.

Ordering is inherited from the immutable classified profile and is deterministic.

## Selection-plan JSON

The selection-plan document records the complete audit boundary required to understand a planner decision:

- lifecycle request;
- optional placement request;
- explicit caller preference order;
- overall selection status;
- selected backend or `null`;
- explicit remaining blocker or `null`;
- canonical candidate evaluations;
- each candidate's backend status and derived candidate status;
- frozen lifecycle-plan status, steps, and issues; and
- optional frozen placement-plan status, requirements, and issues.

Stable blocker names are:

- `runtimeVerification`
- `preference`
- `impossibility`

A selected plan has no remaining blocker and renders `null`.
