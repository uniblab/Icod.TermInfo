# Icod.TermInfo 1.0.0 T42 — Contract and API Regret Audit

T42 begins the 1.0 stabilization sequence at `1.0.0-alpha.1`.

The tranche intentionally changes release/build contract machinery but does not
add production terminal behavior.

## Baseline

The T42 baseline is the completed 0.9.0 contract as merged to `main`.

0.9 already supplies:

- the frozen standard capability model;
- immutable terminal descriptions and explicit provider composition;
- parameter expansion and padding-aware output;
- ANSI/DEC/xterm and Windows profiles;
- color and descriptive modern-protocol metadata;
- pure compiled terminfo parsing for the frozen conventional format family;
- explicit directory acquisition;
- deterministic encoded/environment/user/system discovery;
- provider-local success caching and new-provider refresh;
- package-reference-only acquisition smoke coverage.

T42 asks whether that completed low-level library is ready to promise a stable
1.x identity.

## Frozen support matrix

Consumer package targets:

```text
net8.0
net10.0
```

CI host families:

```text
Windows
Linux
macOS
```

The solution tests both target frameworks. CI explicitly installs both runtime/
SDK lines rather than relying on whatever happens to be preinstalled on a hosted
runner.

The isolated package consumer also targets both frameworks and release scripts
execute it once per target.

Repository-only maintenance executables are normalized to `net10.0`. They do not
need to multiply their own output merely because the shipped library supports
two consumer targets.

## Assembly identity policy

T42 freezes:

```text
AssemblyName       Icod.TermInfo
AssemblyVersion    1.0.0.0
Strong-name signed no
```

Package and informational versions continue to advance normally.

The assembly version is intentionally decoupled from 1.x package patch/minor
versions. The 1.x package line is expected to retain assembly identity
`1.0.0.0`.

The package remains unsigned. Strong naming would change assembly identity and
is not added without a concrete compatibility requirement.

`T42ContractTests` and the package verifier both enforce this decision.

## Dual-target package contract

The primary package must contain:

```text
lib/net8.0/Icod.TermInfo.dll
lib/net8.0/Icod.TermInfo.xml

lib/net10.0/Icod.TermInfo.dll
lib/net10.0/Icod.TermInfo.xml
```

No additional managed runtime DLL is permitted.

The symbol package must contain:

```text
lib/net8.0/Icod.TermInfo.pdb
lib/net10.0/Icod.TermInfo.pdb
```

Both PDBs must remain portable and contain the expected Source Link repository
mapping and exact package repository commit.

The package verifier extracts each managed assembly only long enough to inspect
its `AssemblyName`, assembly version, and public-key token. Both must identify
`Icod.TermInfo`, report `1.0.0.0`, and remain unsigned.

## Workflow boundary remains unchanged

T42 does not change the publication boundary.

```text
pull request
    -> pr-build-and-test.yaml
    -> build/test only
    -> never publish

push to main
    -> push-main.yaml
    -> Release build/test
    -> package validation
    -> publish validated artifact
```

The build/test and package-validation jobs install both .NET 8 and .NET 10.

The deploy job may remain on the .NET 10 SDK because it performs package
publication rather than consumer-target execution.

## Public API regret audit

The existing `PublicApiSurfaceTests` remain valuable because they express
architectural intent in human-readable assertions.

T42 adds a second mechanism:

```text
tools/public-api-snapshot
```

It emits a deterministic reflection manifest of every exported type and every
declared public/protected:

- enum name/value;
- field/constant;
- constructor;
- property/indexer;
- event;
- method/operator;
- generic constraint;
- parameter name and order;
- `ref`/`out`/`in`/`params` shape;
- optional/default value;
- nullability state;
- relevant code-analysis/obsolete/flags attribute.

This tool is intentionally not wired to auto-create a baseline. The first
baseline is a human decision.

Generate the candidate:

```text
dotnet run --project tools/public-api-snapshot/Icod.TermInfo.PublicApiSnapshot.csproj -c Release -- --write
```

Default output:

```text
docs/1.0.0-PUBLIC-API-BASELINE.txt
```

Then review the entire file.

The audit question is:

> If compatibility did not matter, is there any exported name, type, overload,
> parameter, default, nullability contract, enum value, or mutability choice we
> would change?

If yes, T42 is the tranche in which to change it.

If no, commit the reviewed baseline. The same tool then provides:

```text
dotnet run --project tools/public-api-snapshot/Icod.TermInfo.PublicApiSnapshot.csproj -c Release -- --check
```

T43 will turn the reviewed baseline into a stronger compatibility gate rather
than silently generating a new baseline.

## Historical version ownership

`T41CompletionGateTests` previously asserted that the current assembly was final
`0.9.0`. That assertion was correct only while 0.9 was current.

T42 removes the historical current-version assertion from T41 and gives current
version/assembly identity ownership to `T42ContractTests`. T41 continues to own
its semantic completion and workflow-boundary evidence.

## Production API and behavior

T42 adds no production source type and changes no public runtime signature.

The only main-project changes are version/package metadata and explicit stable
assembly identity.

All remaining changes live in:

- tests;
- maintenance tools;
- release/package validation;
- CI SDK installation;
- roadmaps/documentation.

## T42 acceptance checklist

- [ ] solution builds on the supported host matrix;
- [ ] tests pass for `net8.0`;
- [ ] tests pass for `net10.0`;
- [ ] package contains exactly the two intended managed framework assets;
- [ ] both symbol PDBs verify;
- [ ] package smoke runs on `net8.0`;
- [ ] package smoke runs on `net10.0`;
- [ ] assembly identity is `1.0.0.0`;
- [ ] assembly is unsigned;
- [ ] PR workflow remains non-publishing;
- [ ] main workflow remains main-only publishing;
- [ ] candidate public API baseline is generated;
- [ ] complete baseline is manually reviewed;
- [ ] final approved baseline is committed;
- [ ] `public-api-snapshot --check` passes.

T42 is complete only after the API-regret review has been performed, not merely
because the code compiles.
