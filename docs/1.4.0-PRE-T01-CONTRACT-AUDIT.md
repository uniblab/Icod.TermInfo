# Icod.TermInfo 1.4.0 — Pre-T01 Contract Audit

**Tranche:** T01 — Tool-suite foundation and frozen command contract
**Development version:** `1.4.0-Alpha-1`
**Baseline commit:** `7359eba4b5dffe8e69eda2fece4bd4cd8cdf5003`
**Baseline release:** `v1.3.0`
**Status:** foundation contract

---

## 1. Purpose

T01 establishes the structural command layer for the 1.4 tool-suite program.
It deliberately does not implement operational `tic`, `infocmp`, or `toe`
semantics.

The tranche freezes the boundaries which later command work must respect before
filesystem discovery, compilation, rendering, comparison, or database
enumeration is added.

## 2. Frozen lower-layer contracts

T01 SHALL preserve these historical public API baselines unchanged:

```text
docs/1.0.0-PUBLIC-API-BASELINE.txt
docs/1.1.0-SOURCE-PUBLIC-API-BASELINE.txt
docs/1.2.0-COMPILER-PUBLIC-API-BASELINE.txt
docs/1.3.0-INSPECTION-PUBLIC-API-BASELINE.txt
```

Runtime, Source, Compiler, and Inspection retain `AssemblyVersion` `1.0.0.0`.

The new `docs/1.4.0-INSPECTION-PUBLIC-API-BASELINE.txt` begins as an exact copy
of the released 1.3 Inspection baseline. T01 adds no Inspection public API.
Future 1.4 Inspection additions require explicit API review before this new
baseline changes.

## 3. Target-framework boundary

The library package family remains:

```text
net8.0
net9.0
net10.0
```

The command layer targets:

```text
net10.0
```

This separation is intentional. `Icod.CommandFramework 2.0.0` targets
`net10.0`, and command infrastructure SHALL NOT cause the reusable TermInfo
libraries to drop supported target frameworks.

## 4. Dependency boundary

T01 establishes:

```text
tic
    -> Icod.CommandFramework
    -> Icod.TermInfo.Compiler
    -> Icod.TermInfo.Inspection

infocmp
    -> Icod.CommandFramework
    -> Icod.TermInfo.Inspection

toe
    -> Icod.CommandFramework
    -> Icod.TermInfo.Inspection
```

Existing production library dependencies remain unchanged.

No Runtime, Source, Compiler, or Inspection project may reference
`Icod.CommandFramework` or a command project.

No command project may reference another command project.

## 5. Command-host contract

Each command uses a thin process entry point and a separately testable command
engine.

`Program` owns process streams, Ctrl+C wiring, and process lifetime.

`Command` owns argument validation, command policy, diagnostics, output, and exit
status.

The T01 engine surface is equivalent to:

```csharp
Command.RunAsync(
    args,
    stdin,
    stdout,
    stderr,
    cancellationToken
)
```

Caller-owned streams remain open.

T01 recognizes only the foundation switches:

```text
--help
--version
```

All operational command behavior is intentionally deferred to later tranches.

## 6. Exit and stream contract

T01 adopts `Icod.CommandFramework.Diagnostics.CommandExitCodes`:

```text
0    success
1    operational/data failure
2    usage error
130  cancellation
```

Requested successful output is written to stdout. Diagnostics are written to
stderr. Source stdin is only consumed by later command semantics.

Text emitted by the T01 command layer is UTF-8 without a BOM.

## 7. CI contract

The repository pull-request workflow already builds and tests the complete
solution on Windows, Ubuntu, and macOS. T01 therefore adds the command and test
projects to `Icod.TermInfo.sln` rather than duplicating the CI matrix.

The package publication workflows remain library-only in T01. Command release
bundles belong to T11 and SHALL NOT be published by this tranche.

## 8. T01 gate

T01 is complete when:

- all four library projects report `1.4.0-Alpha-1`;
- all four library assemblies remain `1.0.0.0`;
- `tic`, `infocmp`, and `toe` target `net10.0`;
- all three commands report `1.4.0-Alpha-1`;
- all three commands support deterministic `--help` and `--version` behavior;
- unknown/operational arguments remain usage errors because semantics are not
  implemented yet;
- cancellation returns 130;
- caller-owned streams remain open;
- no lower library acquires a command-layer dependency;
- the 1.4 Inspection baseline equals the 1.3 baseline exactly;
- the complete solution passes the existing Windows/Linux/macOS Staging gate.

No real terminfo command semantics are required or permitted for T01.
