## Scope

HDB07 hardens the accepted HDB06 read-only acquisition and command surfaces. It
adds deterministic adversarial fixtures and permanent characterization for:

- metadata, page, item, offset-table, ordering, and arithmetic boundaries;
- inline, off-page, overflow, empty, shared-tail, cyclic, truncated, and
  overlong storage;
- exact-key lookup, duplicate keys, record limits, cancellation, and file
  release;
- ncurses marker-0 and marker-2 resolution, bounded chains, cycles, invalid
  UTF-8, unsafe names, identity mismatches, parser limits, and orphan records;
- culture-independent ordinal publication ordering;
- cache, retry, refresh, replacement, concurrent-read, and permission-failure
  behavior;
- direct provider, explicit `TerminalDatabase`, opt-in system provider,
  `infocmp`, `toe`, and routed-command failure boundaries; and
- native multi-record differential coverage at first, middle, and last
  primary/alias positions.

The one production correction is deliberately narrow: an off-page Hash item
must be exactly its 12-byte header, and an overflow chain must not continue
after its declared item length has been reconstructed.

## Non-goals and residual limitations

HDB07 does not claim:

- native-produced big-endian interoperability;
- broader non-ASCII ncurses/Berkeley DB producer compatibility;
- an atomic or stable snapshot during arbitrary concurrent external file
  replacement or writes;
- support for access methods, revisions, duplicate/subdatabase features,
  checksums, encryption, or legacy Hash page types outside the reviewed subset;
  or
- hashed writes, recovery, transactions, or general-purpose Berkeley DB APIs.
