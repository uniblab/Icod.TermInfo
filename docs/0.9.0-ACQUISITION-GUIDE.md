# Icod.TermInfo 0.9.0 Compiled Terminfo Acquisition Guide

This guide is the consumer-facing entry point for the compiled-database
acquisition APIs added in 0.9. It consolidates the frozen T32-T41 contracts by
task rather than by implementation tranche.

`Icod.TermInfo` remains a low-level description library. Acquisition returns
immutable `TerminalDescription` objects; it does not create a live terminal
session, probe the terminal, decode input, own a PTY, or implement curses.

## 1. Choose the narrowest acquisition API

Use the smallest API which owns the discovery policy you actually need.

```text
Already have the compiled bytes?
    -> CompiledTermInfoParser.Parse

Own one conventional terminfo directory?
    -> DirectoryTerminalDescriptionProvider

Want host TERMINFO / user / TERMINFO_DIRS / platform discovery?
    -> SystemTerminalDescriptionProvider

Want host discovery followed by deterministic package built-ins?
    -> TerminalDatabase(systemProvider, TerminalDatabase.BuiltIn)
```

The providers are explicit caller-owned objects. Constructing them does not
replace or mutate `TerminalDatabase.BuiltIn`.

## 2. Parse caller-supplied compiled bytes

```csharp
byte[] entry =
    File.ReadAllBytes("xterm.compiled");

TerminalDescription terminal =
    CompiledTermInfoParser.Parse(
        entry);
```

The parser is pure with respect to filesystem and environment state and does not
retain the caller's byte storage.

Supported conventional compiled layouts are:

```text
legacy magic 0432
ncurses extended Boolean/numeric/string section
magic 01036 with signed 32-bit standard numerics
```

The parser preserves the library's frozen semantic model:

- canonical name;
- aliases;
- verbose description;
- standard Boolean/numeric/string capabilities by fixed compiled index;
- exact case-sensitive extended capability names;
- absent and canceled semantics;
- reversible Latin-1 representation of capability-string bytes.

### Parser bounds

```csharp
CompiledTermInfoParserOptions options =
    new(
        maximumEntrySize: 2_000_000);

TerminalDescription terminal =
    CompiledTermInfoParser.Parse(
        entry,
        options);
```

The default maximum is 1 MiB. The largest configurable maximum is 16 MiB.
Changing the bound does not enable another compiled format.

Malformed, truncated, oversized, or unsupported compiled bytes throw
`CompiledTermInfoFormatException`.

`Offset` and `Section` provide stable diagnostics when the parser can identify
them. `Offset == -1` or `Section == null` means that diagnostic dimension was
not available.

## 3. Load one explicit directory tree

When the application already knows the database root, avoid system discovery:

```csharp
DirectoryTerminalDescriptionProvider provider =
    new(
        "/opt/myapp/share/terminfo");

if (provider.TryLoad(
        "my-terminal",
        out TerminalDescription? terminal))
{
    Console.WriteLine(
        terminal.Name);
}
```

The root is canonicalized to an absolute path at construction and does not need
to exist yet.

For requested name `xterm`, the provider checks candidates in this exact order:

```text
<root>/x/xterm
<root>/78/xterm
```

The first candidate is the literal first-character layout. The second is the
lowercase two-digit hexadecimal value of the first byte when that representation
is available.

There is no recursive scan and no uppercase-hex fallback.

The parsed canonical name or one parsed alias must match the exact requested
name using ordinal, case-sensitive comparison. A present file containing a
different terminal is an inconsistent database entry, not a clean miss.

### Safe names

Terminal names are validated before path construction. Directory traversal,
rooted paths, separators, control characters, surrogates, and platform-invalid
file-name forms are rejected.

## 4. Use normal system discovery

```csharp
SystemTerminalDescriptionProvider system =
    new();

if (system.TryLoad(
        "xterm-256color",
        out TerminalDescription? terminal))
{
    Console.WriteLine(
        terminal.Description);
}
```

The provider snapshots its permitted environment, user-home, current-directory,
and platform inputs at construction.

The frozen precedence is:

```text
1. encoded TERMINFO
2. ordinary TERMINFO directory
3. non-Windows <home>/.terminfo
4. TERMINFO_DIRS roots in declared order
5. enabled platform defaults
```

The first successful source wins.

A valid encoded `TERMINFO` entry for some other terminal is an encoded-source
miss and discovery continues. Malformed encoded syntax or malformed decoded
compiled bytes is an error and does not fall through.

## 5. Encoded TERMINFO

Two exact case-sensitive prefixes are supported:

```text
TERMINFO=hex:...
TERMINFO=b64:...
```

`hex:` accepts hexadecimal byte pairs.

`b64:` accepts ordinary Base64 and the URL/filename-safe alphabet. Valid omitted
padding is accepted; embedded whitespace is not.

Transport syntax and compiled-entry syntax remain distinct:

```text
bad hex/base64 wrapper
    -> FormatException

valid wrapper containing malformed compiled bytes
    -> CompiledTermInfoFormatException
```

Decoded length is bounded before the decoded output allocation and remains
subject to the configured parser maximum.

## 6. TERMINFO_DIRS

The list separator is platform-safe:

```text
Windows       ;
other hosts   :
```

The Windows rule preserves drive-letter colons.

Relative components are resolved against the current directory captured when
the system provider is constructed.

Empty components are meaningful. When system databases are enabled, each empty
component expands to the platform-default root sequence at that point in the
list. An unset variable is different from a set-but-empty variable.

Duplicate canonical roots are removed while retaining the first occurrence.

Path comparison is:

```text
Windows       OrdinalIgnoreCase
other hosts   Ordinal
```

## 7. Platform defaults

The 0.9 contract deliberately freezes a conservative set.

Linux:

```text
/etc/terminfo
/lib/terminfo
/usr/share/terminfo
```

macOS:

```text
/usr/share/terminfo
```

Windows:

```text
none
```

Other hosts:

```text
none
```

The library does not guess Homebrew Cellar paths and does not invent a
`%USERPROFILE%\.terminfo` convention on Windows. Use `TERMINFO`,
`TERMINFO_DIRS`, or an explicit directory provider for application-specific
roots.

## 8. Restrict system discovery

The options are independent:

```csharp
SystemTerminalDescriptionProviderOptions options =
    new(
        useEnvironment: false,
        useUserDatabase: false,
        useSystemDatabases: false);

SystemTerminalDescriptionProvider restricted =
    new(
        options);
```

Their ownership is:

| Option | Controls |
| --- | --- |
| `UseEnvironment` | encoded/directory `TERMINFO` and non-empty `TERMINFO_DIRS` roots |
| `UseUserDatabase` | non-Windows `<home>/.terminfo` |
| `UseSystemDatabases` | final platform defaults and expansion of empty `TERMINFO_DIRS` components |

A non-empty `TERMINFO_DIRS` root is environment-controlled and can still be
used when `UseSystemDatabases` is false, provided `UseEnvironment` is true.

## 9. Compose system discovery with built-in fallback

The recommended normal application shape is explicit:

```csharp
TerminalDatabase database =
    new(
        new ITerminalDescriptionProvider[]
        {
            new SystemTerminalDescriptionProvider(),
            TerminalDatabase.BuiltIn,
        });

TerminalDescription terminal =
    TerminalEnvironment.Resolve(
        database,
        TerminalProfiles.Dumb);
```

`TerminalDatabase` is itself an `ITerminalDescriptionProvider`.

Providers are consulted in constructor order. A clean miss continues to the
next provider. A provider exception is propagated rather than hidden as a miss.

`TerminalDatabase.BuiltIn` is immutable, environment-independent, and I/O-free.
External acquisition never mutates it.

## 10. Clean misses versus errors

A clean provider miss means the requested terminal was not found in an
otherwise valid source.

Examples:

```text
candidate file absent
configured directory absent
valid encoded entry belongs to another terminal
all enabled sources exhausted
```

Those cases produce:

```text
TryLoad == false
terminal == null
```

Errors remain errors:

```text
unsafe terminal name
malformed hex/base64 wrapper
malformed/unsupported compiled entry
parsed identity mismatch for a present candidate
permission/access failure
ordinary propagated I/O failure
configured/reached database location is a file or unsupported hashed store
```

Do not treat `false` as a generic "anything went wrong" result.

## 11. Caching, concurrency, and refresh

`DirectoryTerminalDescriptionProvider` and
`SystemTerminalDescriptionProvider` cache successful immutable descriptions per
provider instance.

The first concurrent successful load for one exact requested name is
single-flight. Later successful lookups return the same immutable description
instance without rereading/reparsing the entry.

Clean misses are not permanently negative-cached.

Failures are not converted into cached misses.

Therefore the same provider may observe:

```text
lookup missing entry -> false
entry is installed
lookup again -> success
```

and:

```text
lookup malformed entry -> exception
entry is corrected
lookup again -> success
```

After a successful load, however, that provider intentionally keeps the
successful snapshot:

```text
provider A loads version 1
file changes to version 2
provider A still returns version 1

construct provider B
provider B can load version 2
```

Constructing a new provider is the ordinary refresh mechanism. There is no
filesystem watcher, TTL, background refresh worker, public `ClearCache`, or
process-global external-entry cache.

## 12. Files and hashed databases

The 0.9 system provider supports conventional directory-tree databases.

When a configured/reached database source exists as a file rather than a
directory, the provider throws `NotSupportedException` rather than silently
treating the source as absent. Berkeley DB/hashed terminfo stores are outside the
0.9 contract.

## 13. Ownership summary

```text
caller owns byte storage
    -> parser does not retain it

caller owns provider instance
    -> provider owns its discovery snapshot and successful cache

caller owns explicit directory root policy
    -> directory provider never consults environment

TerminalDatabase owns ordered provider composition
    -> first provider wins

TerminalDatabase.BuiltIn
    -> immutable
    -> environment-independent
    -> I/O-free
```

There is no process-global current terminal and no global external-description
cache.
