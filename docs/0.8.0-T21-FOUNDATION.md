# Icod.TermInfo 0.8.0 — T21 Foundation Record

**Tranche:** T21 — 0.8 Foundation and Contract Reset  
**Development version:** `0.8.0-alpha.1`  
**Previous release contract:** `0.7.0` — complete and frozen  
**Next required release boundary:** `0.9.0` arbitrary compiled/system terminfo support

---

## Purpose

T21 establishes the implementation boundary for the 0.8 semantic-completion
release. It does not add terminal capabilities or new terminal identities.

The governing split is:

```text
0.8
    complete the in-memory meaning and execution of terminfo

0.9
    acquire arbitrary descriptions from compiled/system terminfo databases
```

The 0.6.0 and 0.7.0 roadmap/audit documents remain historical records and are
not rewritten for 0.8.

## Frozen 0.7 compatibility baseline

The 0.7 exported public type set and all existing public capability-enum numeric
values are release compatibility data.

T21 adds tests which require:

- every exported 0.7 public type to remain available;
- every 0.7 `BooleanCapability` member to keep its numeric value;
- every 0.7 `NumericCapability` member to keep its numeric value;
- every 0.7 `StringCapability` member to keep its numeric value;
- future 0.8 enum members to use values after the frozen 0.7 range.

The existing 0.7 behavior/golden suites remain authoritative for profile,
color, parameter, output, environment, and provider behavior.

## Selected upstream ncurses baseline

The selected starting provenance baseline for 0.8 is the ncurses development
`terminfo.src`:

```text
Revision: 1.1267
Date:     2026/08/14 08:03:59
```

Primary upstream reference:

```text
https://invisible-island.net/ncurses/terminfo.src.html
```

This is the same baseline already used by the completed 0.7 DEC/xterm work and
is the initial reference for the 0.8 Windows profiles.

T22 capability metadata SHALL use the conventional ncurses/System V capability
tables corresponding to the selected 0.8 baseline and SHALL record the exact
upstream source used for generated or mechanically validated data.

An upstream change does not silently alter the package contract. Updating the
baseline requires a deliberate tranche change with regenerated golden data and
tests.

## Metadata tooling convention

Build-time/reference tooling for T22 standard-capability metadata lives under:

```text
tools/terminfo-metadata/
```

The directory is not part of the runtime package.

Conventions:

- authoritative checked-in metadata inputs belong beneath this tooling area;
- generated runtime C# remains under `src/Capabilities/`;
- generation/validation must be deterministic;
- normal builds/tests must not require network access;
- generated output must be reviewable and checked in where used by the runtime;
- provenance for every imported/generated table must identify its upstream
  source and selected baseline.

T21 creates only the convention and documentation. T22 owns the actual complete
metadata table and generation/validation implementation.

## Future 0.9 fixture convention

Compiled-entry fixtures reserved for T29/0.9 readiness live under:

```text
tests/Icod.TermInfo.Tests/fixtures/compiled-terminfo/
```

The test project copies this fixture tree to its output directory so future
tests can consume binary data without depending on repository-relative paths.

The future fixture tree should use the following roles:

```text
source/       small documented .ti inputs
compiled/     checked-in compiled entry bytes
manifests/    expected semantic results
malformed/    deterministic adversarial seeds
```

Fixture provenance/regeneration instructions belong with the fixture corpus.
Normal tests must not require `tic` to be installed.

The presence of fixture infrastructure does not authorize a production parser
in 0.8.

## 0.8 database-acquisition guard

T21 freezes the following boundary for the entire 0.8 release:

**Not present in production 0.8 code:**

- compiled terminfo entry parser/reader;
- explicit terminfo directory provider;
- system terminfo provider;
- `TERMINFO` discovery;
- `TERMINFO_DIRS` discovery;
- `$HOME/.terminfo` discovery;
- system terminfo path discovery;
- filesystem-loaded description cache/refresh policy.

These are required 0.9 features, not optional future ideas.

T21 adds an initial assembly-level guard against conventional production parser
or directory/system-provider type names. T29 SHALL strengthen this into the
final 0.9-readiness architecture guard when the fixture corpus is added.
