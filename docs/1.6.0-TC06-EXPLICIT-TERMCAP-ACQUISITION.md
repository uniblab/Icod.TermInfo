# Icod.TermInfo 1.6.0 TC06 — Explicit Termcap Acquisition

**Development version:** `1.6.0-Alpha-6`
**Package:** `Icod.TermInfo.Termcap`
**Status:** Implemented acquisition tranche
**Next tranche:** TC07 — conversion commands and coordinated distribution

---

## 1. Objective

TC06 adds an explicit, opt-in acquisition path for historical termcap sources.
It composes the existing TC01 parser, TC03 inheritance resolver, and TC04 semantic
converter; it does not create another terminal-description representation and it
does not modify Runtime discovery.

The public surface is centered on:

```text
TermcapAcquirer
TermcapAcquisitionOptions
TermcapAcquisitionResult
TermcapAcquisitionSource
TermcapAcquisitionSourceKind
TermcapDefaultPathPolicy
ITermcapEnvironmentProvider
ITermcapFileProvider
SystemTermcapEnvironmentProvider
SystemTermcapFileProvider
```

The resulting semantic value remains the ordinary Runtime
`TerminalDescription`.

---

## 2. Explicit source precedence

`TermcapAcquirer.Acquire` searches only sources represented by the supplied
`TermcapAcquisitionOptions`, in this order:

1. caller-supplied inline termcap source;
2. caller-supplied explicit `TERMCAP` database path;
3. caller-supplied ordered `TERMPATH` database paths;
4. conventional paths only when an explicit `TermcapDefaultPathPolicy` selects
   them.

The same ordered provider is used for the requested root and every `tc=` parent.
Inheritance can therefore cross database-file boundaries without introducing a
second resolver or different precedence rules.

Within each parsed document, TC03's existing case-sensitive header-component
lookup remains authoritative. The first matching source in acquisition order
wins.

A missing file is a clean acquisition miss and search continues. Filesystem
failures such as access denial propagate from the caller-selected file provider.
A configured source which can be opened but contains parser errors is not
silently ignored; those errors remain visible and prevent publication of a
`TerminalDescription` even if a later source contains a matching entry.

---

## 3. Environment snapshotting

Process-environment access is not automatic. A caller which wants historical
environment behavior explicitly calls:

```csharp
TermcapAcquisitionOptions options =
    TermcapAcquisitionOptions.FromEnvironment(
        new SystemTermcapEnvironmentProvider(),
        new SystemTermcapFileProvider(),
        TermcapDefaultPathPolicy.Ncurses
    );
```

`FromEnvironment` snapshots only:

```text
TERMCAP
TERMPATH
HOME
```

It deliberately does not read `TERM`; the terminal name remains the explicit
`TermcapAcquirer.Acquire` argument. It does not inspect `TERMINFO`,
`TERMINFO_DIRS`, user `.terminfo`, Runtime built-in profiles, or any Runtime
provider configuration.

The historical `TERMCAP` interpretation adopted for TC06 is:

- a non-empty rooted Unix path is a database path;
- a rooted Windows path is also accepted as a database path for cross-platform
  managed callers;
- another non-empty value is inline termcap source.

`TERMPATH` is snapshotted into an ordered path list. The environment helper
accepts historical colon/whitespace separation and semicolon separation when a
semicolon-delimited value is supplied. Direct `TermcapAcquisitionOptions`
construction remains available when callers need path spellings which should not
be interpreted through historical environment syntax.

---

## 4. Filesystem isolation and bounded input

`ITermcapFileProvider` exposes reader acquisition rather than `ReadAllText`.
`TermcapAcquirer` passes the returned `TextReader` directly to
`TermcapSourceParser.Parse` with the caller's snapshotted
`TermcapSourceParserOptions`.

This preserves TC01's maximum-source-length enforcement before an arbitrary
termcap database is materialized as one unbounded string by TC06.

`SystemTermcapFileProvider` is the explicit host-filesystem implementation. A
caller can replace it with an in-memory, virtual, sandboxed, or otherwise
controlled provider for deterministic tests and applications.

`ITermcapEnvironmentProvider` provides the corresponding environment seam.
`SystemTermcapEnvironmentProvider` is the explicit current-process
implementation. Ordinary acquisition performs no process-global environment
reads unless that provider is intentionally used to create the options snapshot.

---

## 5. Conventional default paths

The default `TermcapDefaultPathPolicy` is `None`; there is no implicit host search.

Selecting `TermcapDefaultPathPolicy.Ncurses` appends this fallback order after
explicit sources:

```text
/etc/termcap
/usr/share/misc/termcap
$HOME/.termcap      when HomeDirectory was supplied
```

`HOME` is available automatically only when the caller chose
`FromEnvironment`; direct options construction may supply `homeDirectory`
explicitly.

Duplicate file path spellings are removed in first-occurrence order so one
configured path is not reparsed merely because it appears through multiple
acquisition inputs.

---

## 6. Result and diagnostics

`TermcapAcquisitionResult` keeps the acquisition stages observable:

- `Description` is the completed Runtime `TerminalDescription`, if any;
- `Source` identifies the configured source which supplied the root entry;
- `SourceDiagnostics` contains parser and TC03 resolver diagnostics;
- `ConversionDiagnostics` contains TC04 semantic conversion diagnostics;
- `Found`, `HasErrors`, `HasLoss`, `IsSuccess`, and `IsLossless` summarize the
  outcome without hiding conversion loss.

TC06 does not invent acquisition-specific approximations. Parser, inheritance,
and conversion policy remain owned by their existing engines.

---

## 7. Compatibility boundary

TC06 changes only `Icod.TermInfo.Termcap` and its tests/documentation.

It does **not**:

- modify `TerminalDatabase`;
- modify `SystemTerminalDescriptionProvider`;
- add termcap to Runtime `TERMINFO` / `TERMINFO_DIRS` discovery;
- alter user `.terminfo` lookup;
- alter built-in Runtime fallback behavior;
- add a dependency from Runtime, Source, Compiler, or Inspection to Termcap;
- add `captoinfo`, `infotocap`, or router commands.

The Termcap package continues to reference only `Icod.TermInfo`, and all five
reusable assemblies retain `AssemblyVersion` `1.0.0.0`.

---

## 8. TC06 gate

TC06 is complete when deterministic tests prove that a caller can explicitly
acquire termcap through inline source, an explicit database, ordered `TERMPATH`,
and selected conventional defaults; that missing paths, malformed input,
inherited cross-file lookup, parser bounds, and provider failures remain
observable; and that Runtime discovery and the existing package dependency graph
remain unchanged.

TC07 may now compose the parser/resolver/converter/renderer/acquirer engines into
conversion command surfaces. It must not duplicate these semantics in command
projects.
