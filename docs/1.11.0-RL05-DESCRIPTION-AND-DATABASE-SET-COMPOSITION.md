## Public contract

RL05 adds:

```text
PersistentRasterLifecycleInspector
PersistentRasterLifecycleDatabaseSetInspection
```

`PersistentRasterLifecycleInspector` recognizes only explicit Icod-owned extended Boolean lifecycle declarations. It does not infer lifecycle support from terminal names, brands, ordinary graphics capability names, or ephemeral raster support.

The frozen semantic extended Boolean names are:

```text
IcodRasterDisplay
IcodPersistentRasterUpload
IcodPersistentRasterAcknowledgedUpload
IcodPersistentRasterPlacement
IcodPersistentRasterMultiplePlacements
IcodPersistentRasterPlacementUpdate
IcodPersistentRasterPlacementDeletion
IcodPersistentRasterResourceDeletion
```

Each declaration maps one-to-one to the corresponding RL02 evidence subject and produces `CapabilityDerived` evidence with deterministic source ordinals `0` through `7`. Absence remains `Unknown`. A reserved lifecycle semantic name with a non-Boolean extended-capability value is rejected rather than guessed.

## TerminalDescription inspection

`PersistentRasterLifecycleInspector.Inspect(TerminalDescription, ...)` derives only explicit lifecycle evidence from the immutable description and passes that evidence through the frozen RL03 classifier.

An unrelated extended capability such as `Sixel` does not establish persistent lifecycle support. Ordinary raster display and persistent terminal-resident resource lifecycle remain separate semantic facts.

## Database-set composition

`PersistentRasterLifecycleInspector.Inspect(TermInfoDatabaseSet, canonicalName, ...)` delegates effective-definition precedence entirely to the frozen 1.10 `TermInfoDatabaseSet.LookupCanonicalName` contract.

`PersistentRasterLifecycleDatabaseSetInspection` retains:

- the exact ordered `TermInfoDatabaseSet`;
- the unchanged `TermInfoDatabaseSetLookupResult` including occurrence, shadow, incomplete-root, and blocking-root evidence;
- one immutable lifecycle profile per observed occurrence in exact lookup occurrence order;
- an `EffectiveProfile` only when the lookup status is `WinnerKnown`.

An incomplete database earlier than the first observed occurrence therefore leaves the lookup `Indeterminate`: the later occurrence profile remains inspectable but does not become effective truth. An incomplete database after an already-known winner does not invalidate that winner.

## Determinism and compatibility

Inspection is culture- and repetition-independent. Occurrence profiles are immutable snapshots. Existing 1.10 database-set precedence semantics are not reimplemented or altered.

The frozen 1.10 Inspection API remains exact. The reviewed 1.11 public-additions allow-list was advanced only for the two RL05 public types. Cross-TFM public API equality remains exact.
