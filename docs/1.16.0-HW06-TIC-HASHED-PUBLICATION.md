## Command contract

`--database-format directory|hashed` selects compiled publication format. The
omitted option means `directory`; existing directory destination discovery,
publication, and summary behavior are unchanged. The option accepts one exact,
case-sensitive value and rejects duplicate or missing values. Check-only `-c`
rejects explicit format selection along with other publication options.

Hashed publication requires explicit `-o` before source input is read. That path
names the exact file; no suffix or format inference is applied. The immediate
parent must already exist. Ambient database discovery never chooses a hashed
write destination.

The existing source parser, selected-name/alias resolution, inheritance, unknown
extension policy, and compiled writer produce the entries. Only the executable
adds a BerkeleyDb dependency; reusable Compiler remains independent. `--force`
opts into whole-database replacement, not catalog merging. The roadmap's earlier
`-f` reference was corrected to the existing `--force` spelling.

The accepted HW05 writer owns locking, staging, verification, and commit.
Expected publication failures use controlled `TIC0007` diagnostics without
payload bytes, stack traces, or generated temporary paths. Destination resolution
retains `TIC0006`. Cancellation before commit returns the suite's canceled exit
status; the summary after successful commit does not observe later cancellation.

Ordinary successful publication is quiet. Hashed `-s` reports `format: hashed`,
the normalized exact destination, compiled canonical-entry count, alias-key
count, and warning count on standard error.

cases because format selection was unsupported; the existing pre-cancellation

`tic` suite passed 98/98, router suite 48/48, and coding conventions 6/6.

The 18 added command cases cover exact paths, semantic directory parity,
canonical/alias lookup, selected publication, summaries, deterministic bytes,
default overwrite refusal, whole-file replacement, controlled usage failures,
check-only conflicts, missing parents, invalid source, pre-cancellation,
contended-lock cancellation, and cancellation during the committed summary.

alias through the production reader.

Installed-package and all six matching-host archive smoke paths now publish a
hashed database with `tic` and compare its managed `infocmp` output with the same
source's conventional database. Native HDB00 checks publish inherited source via
both direct and routed commands, validate each file with Berkeley DB, compare
canonical and alias payloads against managed conventional compiled bytes, and
read both names with pinned native ncurses `infocmp` and managed `infocmp`.

release assertion still named Alpha-5, and the initial native harness used
`infocmp -A` for a hashed file. In the pinned ncurses source, `-A` directly selects
the directory reader; the corrected harness uses process-scoped `TERMINFO` and
checks that native output identifies the intended file. The generated database
already passed Berkeley DB verification and byte-exact payload lookup.

## Boundaries

This milestone introduces no migration, incremental update, catalog automation,
new public writer types, native production dependency, or release publication.
Persistent sibling locks, filesystem-dependent atomic visibility, fresh
replacement metadata, and safe refusal when Windows readers block replacement
retain the HW05 contract. Native writers are not coordinated.

Implementation and review were performed inline without subagents, as requested.
