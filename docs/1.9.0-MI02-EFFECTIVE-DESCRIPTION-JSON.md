# Icod.TermInfo 1.9.0 MI02 - Effective Description JSON

**Development version:** `1.9.0-Alpha-2`
**Published baseline:** `1.8.0`
**Schema:** `urn:icod:terminfo:inspection:json:1`
**Schema version:** `1`
**Document kind:** `terminalDescription`
**Status:** complete
**Next tranche:** MI03 - Comparison and Planning Evidence JSON

## 1. Outcome

MI02 makes the two existing `TermInfoJsonRenderer` overloads for
`TerminalDescription` operational. It adds no public type, method, option,
package dependency, command switch, or schema file. The renderer reports an
already effective immutable description; it does not resolve source ancestry,
reconstruct cancellations, or invent defaults.

Comparison and planning payloads remain deferred to MI03. Database-catalog
payloads remain deferred to MI04, where the complete version-1 JSON Schema will
be published.

## 2. Frozen payload

The exact property sequence is:

```text
schema
schemaVersion
documentKind
data
    identity
        name
        aliases
        description
    capabilities
        booleans
        numbers
        strings
        extended
            booleans
            numbers
            strings
```

Each capability array contains objects with `name` followed by `value`.
Boolean values are JSON Booleans, numeric values are signed JSON integers, and
string values are JSON strings. Empty arrays remain present so consumers receive
one stable shape. A missing terminal description is represented by explicit JSON
null.

## 3. Identity and capability correspondence

Identity is copied exactly from the managed value. The canonical name is not
normalized, aliases retain their immutable order, and a description is neither
synthesized nor discarded.

Present standard capabilities are grouped by value kind and ordered by compiled
database position. Their names are canonical terminfo short names such as `am`,
`cols`, and `clear`; managed enum identifiers are never emitted. Absent standard
capabilities are omitted rather than assigned invented values.

Extended capabilities are grouped first by Boolean, number, and string value
kind. Each group is then sorted by exact ordinal name with case-sensitive
comparison. Their values retain their managed JSON type. Effective descriptions
contain no source ancestry and no cancellation tombstones, so the payload does
not invent either form of evidence.

## 4. Deterministic text and escaping

The implementation uses explicit writer code instead of reflection-driven
serialization. Property and array order are written deliberately. Invariant
integer formatting and the `System.Text.Json` default safe encoder provide a
stable representation for quotation marks, non-ASCII text, and control bytes.
Control values remain the same managed strings after JSON parsing; terminfo
source-language escapes are not introduced.

Compact output is the default and contains no insignificant whitespace. The
reviewed indented form uses LF line endings, two-space indentation, and no
trailing line terminator. The reusable returned string has no trailing
whitespace. Checked-in compact and indented fixtures are repository text files
with one final LF; fixture tests remove exactly that repository line terminator
before comparing the reusable result.

## 5. Bounds, cancellation, and invalid text

The renderer applies `MaximumOutputByteCount` to the exact UTF-8 byte count of
the final representation. A document that fits exactly succeeds; a limit one
byte smaller fails with `InvalidOperationException`. No truncated JSON is
returned as success.

Cancellation is checked before traversal and at stable identity, capability,
and extended-capability item boundaries. Cancellation remains
`OperationCanceledException`. Invalid UTF-16 is rejected deterministically with
`InvalidOperationException` rather than being replaced or emitted lossily.

## 6. Evidence

MI02 checks:

- exact compact and indented fixtures;
- JSON parsing and exact envelope/property order;
- identity, null, and typed value correspondence;
- compiled-table standard ordering and ordinal extended ordering;
- control, quotation-mark, backslash, and non-ASCII escaping;
- repeated-run, insertion-order, and culture independence;
- exact UTF-8 boundary success and one-byte-smaller failure;
- deterministic pre-cancellation and invalid UTF-16 failure;
- preservation of the 31-type reviewed Inspection surface;
- continued MI03 and MI04 `NotSupportedException` boundaries; and
- package-reference-only execution of real description JSON.

No local command behavior changes in MI02. Command JSON composition remains
owned by MI05.
