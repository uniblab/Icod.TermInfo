## Purpose

MI07 closes the 1.9 development program without adding another feature tranche.
It freezes the additive machine-readable Inspection API, the version-1 JSON
Schema, command behavior, package graph, samples, fixtures, router and archive
topology, and release evidence established by MI01 through MI06.

No API, schema, command, package, or semantic change is permitted between a
green Alpha-7 release gate and stable publication. The stable transition is
version-only:

```text
1.9.0-Alpha-7 -> 1.9.0
```

## Frozen command semantics

`infocmp --json` continues to project an effective description or structured
comparison. Planning JSON continues to require `--plan-use`, and explicit
all-candidates planning continues to require one caller-selected conventional
database root through `-B`:

```text
infocmp --json target
infocmp --json -d left right
infocmp --json --plan-use target candidate [candidate ...]
infocmp --json --plan-use --all-candidates -B directory target
toe --json directory
```

Successful stdout contains exactly one JSON document followed by one LF.
Diagnostics remain on stderr. Existing human-readable, comparison, synthesis,
planning, acquisition, and exit-status behavior is unchanged. Direct commands,
the `icod-terminfo` router, the installed tool package, and matching standalone
archives use the same command implementations.

## Frozen samples and consumer evidence

The package-reference-only Inspection consumer renders and parses all four
document kinds on every supported reusable target framework. It also proves
culture invariance, large and pathological strings, exact UTF-8 bound
acceptance, and one-byte-below rejection.

The Toolchain sample retains its controlled end-to-end path:

```text
parse and resolve target/candidates
-> plan relative source
-> reparse and resolve selected source
-> compile and publish
-> reacquire through Runtime
-> compare with the original target
-> render exact sourcePlan JSON
```

The checked-in source-plan fixture is exact. Release verification executes the
sample twice in separate processes and requires byte-identical output.
ToolSuite retains direct and routed examples for every version-1 document kind.
