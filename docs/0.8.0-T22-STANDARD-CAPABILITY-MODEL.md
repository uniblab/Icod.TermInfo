# 0.8.0 T22 — Complete Standard Terminfo Model

T22 completes the in-memory standard capability model required by the 0.8
semantic-completion contract. It does **not** add a compiled terminfo parser or
system database provider.

## Capability baseline

The standard compiled-table baseline is the ncurses/System V-compatible ABI
represented by the ncurses capability tables generated from `include/Caps`.
The selected source baseline is:

- ncurses `Caps` revision 1.62, dated 2025-11-12;
- 44 Boolean table positions;
- 39 numeric table positions;
- 414 string table positions.

The table includes compatibility positions retained by ncurses at the tail of
its compiled arrays. Those positions are deliberately represented because T22
models the future compiled ABI, not merely the subset commonly emitted by
modern terminal descriptions.

The checked-in canonical source is:

```text
tools/terminfo-metadata/standard-capabilities.tsv
```

The runtime definition table is deterministic generated output:

```text
src/Capabilities/StandardCapabilityDefinitions.Generated.cs
```

No network access or ncurses runtime dependency is required to build or use the
package.

## Enum and binary-index rule

The 0.7 public values of `BooleanCapability`, `NumericCapability`, and
`StringCapability` remain frozen. T22 appends the missing standard members.

A managed enum numeric value is **not** a compiled table index.

For example, the pre-existing `BooleanCapability.AutoRightMargin` remains enum
value 0 while its standard Boolean compiled-table index is 1. Binary positions
are obtained only from `StandardCapabilityMetadata<TCapability>`.

This rule is required so 0.9 can parse positional compiled data without
renumbering any public 0.7 enum member.

## Public metadata

`StandardCapabilityCatalog` exposes deterministic read-only metadata in
compiled-table order for Boolean, numeric, and string capabilities.

Each metadata record carries:

- managed capability identifier;
- value kind;
- compiled binary index;
- terminfo short name;
- terminfo long/variable name;
- termcap compatibility code.

Traditional per-description short-name lookup remains conservative and uses
terminfo short names. Adding metadata does not silently make long names or
termcap codes alternate lookup spellings.

## Per-description enumeration

`TerminalDescription` exposes read-only effective standard capability
enumerations for:

- present Boolean capabilities;
- present numeric capabilities and values;
- present string capabilities and values.

Enumeration order is the canonical compiled-table order, independent of builder
insertion order or managed enum numeric value. Extended capabilities remain a
separate namespace and collection.

## Terminal identity

`TerminalDescription.Description` now stores the verbose terminal description
separately from `Name` and `Aliases`. `TerminalDescriptionBuilder` provides
`SetDescription` to set or clear that field.

The 0.7 built-ins are populated with their stable authoritative verbose
terminfo descriptions. The description is data only; it is never treated as a
resolvable alias.

## Numeric width

Standard and extended numeric capability values are contractually signed
32-bit managed integers. T22 tests values above the legacy signed-16-bit range,
including direct-color-scale values, so the future 0.9 extended-number parser
requires no model change.

## 0.9 boundary

T22 intentionally contains no production code for:

- compiled entry parsing;
- filesystem terminfo lookup;
- `TERMINFO` or `TERMINFO_DIRS`;
- system database discovery;
- loaded-description caching.

The completed model is the target into which those 0.9 acquisition layers will
load data.
