## Purpose

T40 freezes the release-facing 0.9 contract.

The tranche does not add another acquisition mechanism or redesign any parser,
provider, cache, or terminal semantic. It reviews and locks the public surface
created by T32 through T39, updates the release-facing documentation and sample
coverage, expands the package-reference-only smoke consumer to exercise the
actual acquisition APIs, and moves the active release workflow to the 0.9
branch.

If T41 finds that the public object model or package shape still requires
redesign, T40 must be reopened rather than silently changing the release
contract.

## Pure parser freeze

`CompiledTermInfoParserOptions` remains immutable:

```csharp
public sealed class CompiledTermInfoParserOptions
{
    public const int DefaultMaximumEntrySize = 1_048_576;
    public const int MaximumSupportedEntrySize = 16_777_216;

    public CompiledTermInfoParserOptions(
        int maximumEntrySize = DefaultMaximumEntrySize);

    public int MaximumEntrySize { get; }
}
```

The parser remains a pure static byte parser:

```csharp
public static class CompiledTermInfoParser
{
    public static TerminalDescription Parse(
        ReadOnlySpan<byte> entry,
        CompiledTermInfoParserOptions? options = null);
}
```

No stream, path, environment, cache-control, or native ncurses API is added to
the parser surface.

Filesystem and environment acquisition remain provider responsibilities.

## Compiled-format exception freeze

Malformed/unsupported compiled-entry diagnostics remain distinct from parameter
program syntax.

The public exception surface is:

```csharp
public sealed class CompiledTermInfoFormatException : FormatException
{
    public CompiledTermInfoFormatException();
    public CompiledTermInfoFormatException(string? message);
    public CompiledTermInfoFormatException(
        string? message,
        Exception? innerException);

    public int Offset { get; }
    public string? Section { get; }
}
```

`Offset == -1` means that no stable byte offset was supplied.

`Section == null` means that no stable section label was supplied.

Provider code continues to propagate this exception rather than convert it to a
clean miss.

## Explicit directory provider freeze

The explicit-root provider remains caller-owned:

```csharp
public sealed class DirectoryTerminalDescriptionProvider
    : ITerminalDescriptionProvider
{
    public DirectoryTerminalDescriptionProvider(
        string root,
        CompiledTermInfoParserOptions? parserOptions = null);

    public string Root { get; }

    public bool TryLoad(
        string name,
        out TerminalDescription? terminal);
}
```

The actual result parameter retains `[NotNullWhen(true)]`.

`Root` is canonicalized at construction.

The provider performs exact conventional directory-tree lookup only and does not
consult environment, user, or platform defaults.

Successful immutable descriptions are provider-cached. Misses and failures are
retryable. Refresh is a new provider instance.

No public cache-control member is added.

## System provider options freeze

The immutable discovery options remain:

```csharp
public sealed class SystemTerminalDescriptionProviderOptions
{
    public SystemTerminalDescriptionProviderOptions(
        bool useEnvironment = true,
        bool useUserDatabase = true,
        bool useSystemDatabases = true,
        CompiledTermInfoParserOptions? parserOptions = null);

    public bool UseEnvironment { get; }
    public bool UseUserDatabase { get; }
    public bool UseSystemDatabases { get; }
    public CompiledTermInfoParserOptions ParserOptions { get; }
}
```

The Boolean controls remain independent trust/search controls.

No mutable path list, environment abstraction, cache dictionary, or provider
registry is exposed.

Explicit application roots remain the responsibility of
`DirectoryTerminalDescriptionProvider`.

## System provider freeze

The public system provider remains:

```csharp
public sealed class SystemTerminalDescriptionProvider
    : ITerminalDescriptionProvider
{
    public SystemTerminalDescriptionProvider(
        SystemTerminalDescriptionProviderOptions? options = null);

    public bool TryLoad(
        string name,
        out TerminalDescription? terminal);
}
```

The actual result parameter retains `[NotNullWhen(true)]`.

The provider snapshots permitted environment/home/platform inputs during
construction and preserves the T38 precedence:

```text
encoded TERMINFO
ordinary TERMINFO directory
user .terminfo
TERMINFO_DIRS
platform defaults
```

The T38 platform-default freeze remains:

```text
Linux:
    /etc/terminfo
    /lib/terminfo
    /usr/share/terminfo

macOS:
    /usr/share/terminfo

Windows:
    none

Other:
    none
```

No public refresh/cache-clear/watch API is added.

## Nullability and ownership review

T40 confirms these acquisition annotations are intentional:

- `CompiledTermInfoParser.Parse(..., options)` accepts nullable options;
- `DirectoryTerminalDescriptionProvider(..., parserOptions)` accepts nullable
  parser options;
- `SystemTerminalDescriptionProvider(options)` accepts nullable options;
- `CompiledTermInfoFormatException.Section` is nullable;
- provider `TryLoad` result parameters retain `[NotNullWhen(true)]`.

Ownership remains:

- caller owns caller-supplied byte storage;
- parser returns an immutable `TerminalDescription`;
- caller owns provider instances and therefore their cache/snapshot lifetime;
- caller owns explicit directory roots and determines when a new provider should
  be constructed for refresh;
- system provider owns one immutable discovery snapshot for its lifetime;
- `TerminalDatabase` owns only its immutable ordered provider list;
- `TerminalDatabase.BuiltIn` remains immutable, environment-independent, and
  I/O-free.

## Exception and miss boundary

The 0.9 clean-miss rule remains:

```text
entry absent
valid encoded entry belongs to another terminal
enabled sources exhausted
    -> TryLoad == false
```

The following remain errors:

```text
invalid encoded TERMINFO
malformed compiled entry
unsupported compiled layout
permission/access failure
I/O failure
unsafe requested terminal name
configured hashed/file database reached where a conventional directory tree is required
```

Providers do not silently hide those errors as misses.

## Release-facing samples

T40 adds `SampleAcquisition` to the repository sample.

It demonstrates five distinct public acquisition patterns:

1. parse caller-supplied compiled bytes;
2. load an explicit conventional directory root;
3. create a fully restricted system provider;
4. create the normal system provider;
5. compose system lookup with `TerminalDatabase.BuiltIn`.

The ordinary sample resolver uses the fifth pattern for environment resolution.

The existing `--profile` option remains an explicit built-in selection.

The README contains the same five release-facing patterns so package consumers
do not need to infer provider composition from implementation details.
