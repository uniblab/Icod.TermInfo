# Icod.TermInfo 1.7.0 RS03 — Extended Capability Synthesis

**Development version:** `1.7.0-Alpha-3`
**Tranche:** RS03
**Status:** implementation contract
**Previous tranche:** RS02 — Standard Capability Delta and Cancellation Engine
**Next tranche:** RS04 — Ordered Multi-Parent Semantics and Reference Fidelity

## Objective

RS03 extends the relative-source synthesis engine from the standard capability
catalog to the complete effective `TerminalDescription` capability universe.

The implementation remains owned by `Icod.TermInfo.Inspection`. Runtime and
Source public APIs are unchanged. Inspection continues to depend only on Runtime
and Source in production.

## Extended semantic identity

Extended capability names are compared with `StringComparer.Ordinal` and are
therefore case-sensitive. `Vendor` and `vendor` are distinct capabilities.

For one name, the value kind is part of the effective value rather than part of
the name. The same name may therefore change between Boolean, numeric, and
string values across parents or between the inherited aggregate and the target.
A value-kind change is emitted as one ordinary target-local declaration using
the target value kind; a separate cancellation is not required.

Runtime validation remains authoritative for preventing an extended name from
shadowing a standard capability name.

## Ordered parent aggregate

RS03 extends the RS02 parent aggregate with:

```text
Dictionary<string, TermInfoCapabilityValue>
    comparer = StringComparer.Ordinal
```

Parents are still processed from rightmost to leftmost. Each leftward parent
overlays the current aggregate, so the leftmost supplied `use=` reference wins
parent-to-parent collisions even when the colliding extended values have
different kinds.

No provider, dictionary, or hash-table insertion order affects the aggregate.

## Local delta rules

For every name in the ordinal union of target and inherited extended names:

| Target | Inherited | Local source |
|---|---|---|
| absent | absent | nothing |
| value `T` | absent | declare `T` |
| absent | value `P` | `name@` |
| value `T` | equal value `T` | nothing |
| value `T` | different value `P` | declare `T` |
| kind `K1` | kind `K2` | declare target value using `K1` |

`TermInfoCapabilityValue.Equals` supplies kind-aware value equality. String
comparison remains ordinal through the Runtime value contract.

Boolean target values render as bare capability names, numeric values use `#`,
and string values use `=` with the existing Inspection source escaping rules.
Inherited removals render with `@` regardless of the inherited value kind.

## Deterministic ordering

RS03 reuses the established effective-renderer ordering for extended values:

1. Boolean;
2. numeric;
3. string;
4. ordinal, case-sensitive name within each value-kind group.

For a target declaration or override, the target value kind determines its
ordering group. For a cancellation, the inherited value kind determines its
ordering group. This keeps cancellations adjacent to the semantic class of the
capability they remove instead of creating a separate cancellation bucket.

The same target, ordered parents, and synthesis options therefore produce
byte-identical text across dictionary insertion orders, current cultures,
operating systems, and target frameworks.

## `IncludeExtendedCapabilities`

RS01 deliberately deferred the extended filtering contract. RS03 adds the
following additive property to `TerminalDescriptionSourceSynthesisOptions`:

```csharp
public bool IncludeExtendedCapabilities { get; }
```

The existing constructor remains available unchanged. A new five-argument
overload accepts the explicit Boolean policy. Defaults are:

```text
IncludeExtendedCapabilities = true
```

The flag controls whether synthesis may emit local extended declarations or
cancellations. It does **not** redefine the target or parent semantics.

When the flag is `false`:

- synthesis succeeds if the target extended state already equals the ordered-
  parent extended aggregate, because no local extended directive is required;
- synthesis fails with `InvalidOperationException` if any extended declaration,
  override, kind change, or cancellation is required;
- zero-parent synthesis fails when the target contains any extended capability.

This rule prevents a presentation option from silently producing source that
resolves to semantics different from the stated target. RS06 may map `infocmp`
`-x` onto this reusable policy only within that safety contract.

## Renderer reuse

RS03 does not introduce a second source encoder. The relative renderer reuses the
existing configurable renderer helpers for:

- identity validation;
- Boolean fields;
- numeric fields and Source 1.1 numeric representability checks;
- string escaping and wrapping;
- extended-name validation;
- physical layout;
- `use=` rendering.

The RS02 standard delta engine remains unchanged semantically and shares the
same parent aggregate traversal.

## Semantic verification

RS03 fixtures verify the real Source pipeline:

```text
relative child source
+ full effective parent source entries
    -> TermInfoSourceParser
    -> TermInfoSourceResolver
    -> TerminalDescription
    -> TerminalDescriptionComparer
    -> AreEqual
```

Coverage includes:

- target-only Boolean, numeric, and string extensions;
- inherited extensions requiring cancellation;
- equal inherited values and no-op elimination;
- same-kind overrides;
- inherited/target value-kind changes;
- parent-to-parent kind collisions;
- ordinal case-sensitive names;
- opposite dictionary insertion orders;
- explicit extended-output disabling;
- Runtime standard-name shadow rejection.

## Public API and dependency boundary

RS03 adds only the synthesis-options property and overload in Inspection. It does
not change:

- `Icod.TermInfo` public API;
- `Icod.TermInfo.Source` public API;
- `Icod.TermInfo.Compiler` public API;
- `Icod.TermInfo.Termcap` public API;
- command semantics;
- assembly version `1.0.0.0`;
- reusable target frameworks.

The exact stable 1.7 Inspection public API remains an RS08 freeze item.

## Versioning

RS03 advances the coordinated development version to:

```text
1.7.0-Alpha-3
```

The published stable release remains `1.6.1`. Historical RS01 and RS02 records
retain their original Alpha-1 and Alpha-2 development versions.

## RS03 gate

RS03 is complete when:

- the coordinated version is `1.7.0-Alpha-3`;
- the full standard and extended capability universe round-trips through Source;
- parent precedence remains leftmost-wins for extended values and kind changes;
- inherited extended removals produce deterministic cancellations;
- extended ordering is insertion-order independent;
- disabling extended output cannot silently change target semantics;
- Runtime, Source, Compiler, and Termcap frozen public contracts remain intact;
- Inspection retains Runtime-and-Source-only production dependencies;
- package smoke exercises parent-relative extended synthesis.

RS04 may then stress and freeze ordered multi-parent/reference fidelity across the
complete capability universe without changing the RS03 extended semantics.
