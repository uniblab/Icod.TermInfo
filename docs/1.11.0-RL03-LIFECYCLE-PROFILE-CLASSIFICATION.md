# Icod.TermInfo 1.11.0 RL03 — Lifecycle Profile Classification

**Development version:** `1.11.0-Alpha-3`  
**Tranche:** RL03  
**Published baseline:** `1.10.0`  
**Primary package:** `Icod.TermInfo.Inspection`  
**Status:** validated and frozen

## Objective

RL03 deterministically classifies the immutable RL02 evidence snapshot into a protocol-neutral persistent-raster lifecycle profile.

Classification answers what lifecycle semantics are known for each independent dimension. It does not plan an operation sequence, execute a terminal protocol, allocate terminal-owned identity, or prove that a live terminal will accept any operation.

## Public additions

RL03 adds exactly two public types to `Icod.TermInfo.Inspection`:

```text
PersistentRasterLifecycleProfile
PersistentRasterLifecycleClassifier
```

Together with RL01 and RL02, the explicitly approved 1.11 Inspection additions are recorded in `docs/1.11.0-INSPECTION-PUBLIC-API-ADDITIONS.txt`.

## Profile dimensions

`PersistentRasterLifecycleProfile` exposes the eight independent RL02 evidence subjects as immutable support states:

```text
RasterDisplay
PersistentUpload
AcknowledgedUpload
PlacementCreation
MultiplePlacements
PlacementUpdate
PlacementDeletion
ResourceDeletion
```

Each dimension is one `PersistentRasterLifecycleSupportStatus`:

```text
Unknown
Supported
Unsupported
Contradicted
```

`GetStatus(PersistentRasterLifecycleEvidenceSubject)` provides the equivalent indexed semantic query and rejects undefined subjects.

## Explicit evidence precedence

Precedence is evaluated independently for each subject and is encoded explicitly by the classifier:

```text
Verified
    >
Declared
    >
CapabilityDerived
    >
absence / Unknown
```

The classifier does not infer precedence from enum numeric values.

For one subject, only evidence from the highest provenance tier present determines the final support state. Lower-precedence facts remain retained in the profile evidence snapshot but do not override a stronger tier.

Examples:

```text
CapabilityDerived positive
Declared negative
=> Unsupported
```

```text
CapabilityDerived negative
Declared negative
Verified positive
=> Supported
```

## Contradiction semantics

Contradiction is evaluated within the highest provenance tier present for the subject.

```text
Verified positive
Verified negative
=> Contradicted
```

Lower-tier agreement does not erase a higher-tier contradiction, and lower-tier disagreement does not make a stronger conclusive tier contradictory.

Contradictory evidence remains visible in the complete evidence snapshot.

## Absence and unknown

When no evidence exists for a subject, its state is `Unknown`.

Absence of static terminfo evidence is therefore never converted into `Unsupported` merely because no positive capability was found.

## Canonical evidence retention

The classifier delegates evidence validation, bounds, canonical ordering, duplicate retention, and immutable snapshotting to the frozen RL02 `PersistentRasterLifecycleEvidence.Snapshot` contract.

Every profile retains that complete canonical snapshot through its read-only `Evidence` property. This includes:

- the evidence that determined each support state;
- overridden lower-precedence evidence;
- contradictory evidence;
- evidence for unrelated profile dimensions.

Classification does not mutate, normalize, or discard the underlying evidence.

## Determinism

Classification is independent of:

- caller input ordering;
- current culture;
- current UI culture;
- hash ordering;
- platform-specific ambient state.

Equivalent evidence produces equivalent profile states and canonical evidence ordering across supported hosts.

## Bounds

RL03 introduces no second evidence bound. The caller may supply `PersistentRasterLifecycleEvidenceOptions` to `PersistentRasterLifecycleClassifier.Classify`, and the classifier uses the frozen RL02 evidence-count limits and validation rules.

Ordinary bound violations remain parameter/input validation errors. Unknown, unsupported, and contradictory semantic states are data, not exception-driven planner control flow.

## API shape

The classifier entry point is:

```text
PersistentRasterLifecycleClassifier.Classify(
    IEnumerable<PersistentRasterLifecycleEvidence> evidence,
    PersistentRasterLifecycleEvidenceOptions? options = null
)
```

It returns one immutable `PersistentRasterLifecycleProfile`.

## Deferred to RL04+

RL03 does not yet add:

- lifecycle requests;
- ordered lifecycle plans;
- plan feasibility or structured uncertainty results;
- runtime-verification requirements;
- database-set lifecycle composition;
- machine-readable lifecycle profile/plan documents.

RL04 consumes this frozen profile and introduces bounded deterministic semantic planning.
