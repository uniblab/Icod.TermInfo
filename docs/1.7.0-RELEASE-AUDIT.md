## 1. Purpose and status

RS08 closes the 1.7 development program without adding another feature tranche.
The stable release promotes the validated `1.7.0-Alpha-8` surface to `1.7.0`,
freezes the additive Inspection synthesis API, and makes the existing package,
API, router, archive, sample, and command validation paths responsible for the
1.7 contract.

This document is a pre-publication release audit. It does not claim that
`1.7.0` has already been tagged or published. After the exact stable commit is
validated and tagged, the two pending publication fields above must be replaced
with the final commit SHA and `v1.7.0` tag in the stable release record.

No feature work is permitted between the successful Alpha-8 release gate and
the stable transition.

## 2. Public API change

The 1.7 reusable API change is confined to `Icod.TermInfo.Inspection` and is
additive. The complete frozen Inspection surface is recorded in:

```text
docs/1.7.0-INSPECTION-PUBLIC-API-BASELINE.txt
```

The three additive public types are:

```text
TerminalDescriptionSourceSynthesisParent
TerminalDescriptionSourceSynthesisOptions
TerminalDescriptionSourceSynthesizer
```

The frozen synthesis API provides:

- explicit ordered parent descriptors whose `UseName` is independent of the
  acquired parent's canonical `TerminalDescription.Name`;
- deterministic source layout, line-width, capability-order, parent-count, and
  extended-capability policy;
- a default parent limit of 64 and an absolute supported limit of 256;
- `Synthesize` and `Write` entry points over an immutable effective target and
  an explicit ordered parent sequence.

The previously frozen 1.4 Inspection baseline remains immutable historical
evidence. RS08 does not rewrite that document.

## 5. Relative synthesis semantic contract

The stable synthesis contract is:

```text
target TerminalDescription
+ ordered parent TerminalDescriptions
    -> deterministic relative source
    -> local additions / overrides
    -> cap@ cancellations where inherited state must be removed
    -> exact ordered use= references
```

Parent-to-parent aggregation follows the already-frozen Source resolver
precedence: parents are aggregated right-to-left so the leftmost supplied parent
wins parent collisions. The synthesizer never reorders parents to reduce local
output.

An absent capability in an effective higher-priority parent is absence/no
contribution. Synthesis does not invent source cancellation provenance that an
effective `TerminalDescription` cannot retain.

Extended capability identity is ordinal and case-sensitive. Boolean, numeric,
and string extended values participate in additions, overrides, kind changes,
and inherited cancellations. Suppressing extended directives is accepted only
when doing so still reproduces the target semantics.

## 6. Semantic round-trip evidence

RS02-RS07 establish the permanent semantic gate:

```text
Synthesize(target, parents)
+ rendered parent source
    -> TermInfoSourceParser
    -> TermInfoSourceResolver
    -> TerminalDescriptionComparer
    -> AreEqual == true
```

RS05 also makes the compiled path permanent:

```text
same combined source
    -> TermInfoSourceCompiler
    -> CompiledTermInfoParser
    -> TerminalDescriptionComparer
    -> AreEqual == true
```

The coverage includes standard and extended capabilities, additions,
overrides, cancellations, value-kind changes, exact parent reference spelling,
multiple ordered parents, all three layouts, wrapping and ordering controls,
long escaped strings, culture changes, and deterministic LF rendering.

RS07 extends this with deterministic seeded generated-state testing and hostile
boundary cases. Each generated failure reports a reproducible case seed.

## 7. Differential corpus provenance

RS07 records an offline ncurses semantic differential corpus under:

```text
tests/Icod.TermInfo.Inspection.Tests/fixtures/
    rs07-ncurses-6.5.20250216/
```

Pinned reference provenance:

```text
ncurses      6.5.20250216
host         Debian GNU/Linux 13 (trixie), x86_64
terminfo     /usr/share/terminfo
reference    infocmp -u
```

The corpus exercises representative xterm, screen, tmux, Linux console, and
VT-family cases, including 256-color extensions, cancellation-producing pairs,
and multiple plausible parents. The differential gate is semantic rather than
byte-for-byte presentation identity.

Normal tests consume checked-in fixtures and do not require ncurses to be
installed. The checked-in regeneration script refuses a different ncurses
version so a deliberate corpus refresh cannot silently change the reference.

## 8. `infocmp -u` command contract

RS06 exposes the reusable synthesis engine through:

```text
infocmp -u target parent [parent ...]
```

Command responsibilities remain limited to argument parsing, acquisition,
construction of synthesis inputs/options, diagnostics, output, cancellation,
and exit-status mapping. The command does not duplicate the synthesis merge
algorithm.

Database policy:

```text
-A directory    target database
-B directory    parent database for every parent operand
```

The exact supplied parent operand becomes the `use=` reference, preserving
aliases and caller order.

Presentation controls retained in synthesis mode:

```text
-0
-1
-w width
-s d|i|l|c
-x
```

Compatibility interaction is frozen as:

```text
-u          relative synthesis
-c -u       accepted synthesis synonym
-d -u       usage error
-n -u       usage error
-q -u       usage error
```

Exit statuses remain:

```text
0    successful synthesis
1    acquisition or operational synthesis failure
2    usage error
130  cancellation
```

## 13. Deterministic Toolchain sample

`Icod.TermInfo.Toolchain.Sample` remains a host-independent composition sample.
For 1.7 it explicitly constructs the frozen synthesis-options contract,
synthesizes a child relative to a base, requires deterministic expected source,
reparses/resolves that source, compiles it, publishes a temporary conventional
database, reacquires the child, and requires semantic equality.

The sample does not inspect the host terminfo database or invoke native ncurses.
