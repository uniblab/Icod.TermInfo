# Icod.TermInfo 1.12.0 Advanced Persistent-Raster Placement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deterministic protocol-neutral persistent-raster placement evidence, classification, lifecycle-aware planning, database-set composition, version-4 automation, and package/downstream qualification to `Icod.TermInfo.Inspection`.

**Architecture:** Preserve the complete 1.11 persistent-raster lifecycle surface and JSON v3 contract unchanged. Add a parallel placement-semantic family for exactly two capabilities—pixel-space source rectangles and signed z-order—then compose placement requirements with existing 1.11 lifecycle profiles/plans without importing execution values, protocol identifiers, live terminal state, or an `Icod.Terminal` production dependency.

**Tech Stack:** C# 13, .NET 8/9/10, xUnit, existing `Icod.TermInfo.Inspection` evidence/planning infrastructure, deterministic JSON rendering, package validation, and GitHub Actions three-host/six-archive qualification.

**Spec:** `docs/superpowers/specs/2026-09-12-1.12.0-advanced-persistent-raster-placement-design.md`

## Global Constraints

- Development sequence: `1.12.0-Alpha-1` through `1.12.0-Alpha-8`.
- Primary implementation package: `Icod.TermInfo.Inspection`.
- Baseline is stable `1.11.0`.
- Existing Runtime, Source, Compiler, Termcap, and Inspection contracts through 1.11 remain source/binary compatible except unavoidable defect corrections.
- `PersistentRasterLifecycleEvidenceSubject`, `PersistentRasterLifecycleProfile`, `PersistentRasterLifecycleRequest`, lifecycle planner semantics, and JSON v3 remain frozen.
- JSON v1, v2, and v3 remain immutable; 1.12 introduces additive JSON v4.
- Initial placement subjects are exactly `SourceRectangle` and `SignedZOrder`.
- TermInfo planning never carries actual rectangle coordinates or signed z-order values.
- `Icod.TermInfo` and `Icod.TermInfo.Inspection` SHALL NOT acquire a production dependency on `Icod.Terminal`.
- Absence of evidence means `Unknown`, not `Unsupported`.
- Evidence ordering, plan ordering, serialization, and database-set composition remain deterministic and culture-independent.
- Parameter validation, explicit bounds, XML documentation, package-only qualification, and all repository coding-convention gates are mandatory.

## File Structure

New source files are split by one responsibility each:

- `Icod.TermInfo.Inspection/src/PersistentRasterPlacementSubject.cs` — frozen 1.12 placement vocabulary.
- `Icod.TermInfo.Inspection/src/PersistentRasterPlacementEvidence.cs` — immutable one-subject positive/negative evidence.
- `Icod.TermInfo.Inspection/src/PersistentRasterPlacementEvidenceKind.cs` — placement evidence provenance category.

- `Icod.TermInfo.Inspection/src/PersistentRasterPlacementClassifier.cs` — deterministic evidence-to-profile transformation.
- `Icod.TermInfo.Inspection/src/PersistentRasterPlacementRequest.cs` — semantic requirements only (`RequireSourceRectangle`, `RequireSignedZOrder`).
- `Icod.TermInfo.Inspection/src/PersistentRasterPlacementPlanStatus.cs` — success/impossible/indeterminate result status.
- `Icod.TermInfo.Inspection/src/PersistentRasterPlacementPlanRequirement.cs` — one resolved placement requirement and verification flag.
- `Icod.TermInfo.Inspection/src/PersistentRasterPlacementPlanIssue.cs` — structured planning issue.
- `Icod.TermInfo.Inspection/src/PersistentRasterPlacementPlan.cs` — immutable lifecycle-aware placement plan.
- `Icod.TermInfo.Inspection/src/PersistentRasterPlacementPlanner.cs` — compose 1.11 lifecycle readiness with 1.12 placement requirements.
- `Icod.TermInfo.Inspection/src/PersistentRasterPlacementInspector.cs` — derive recognized evidence from descriptions/database sets.
- `Icod.TermInfo.Inspection/src/TermInfoJsonRenderer.PersistentRasterPlacement.cs` — additive version-4 automation.
- `tests/Icod.TermInfo.Inspection.Tests/src/PG*.cs` — tranche-scoped TDD contract/behavior tests.
- `docs/1.12.0-PG*.md` — tranche freeze/qualification records.

Existing schema/package/public-API files change only in the tranche that owns the change.
