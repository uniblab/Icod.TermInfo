# Icod.TermInfo 1.11.0 Persistent Raster Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deterministic protocol-neutral persistent-raster lifecycle evidence, classification, planning, database-set composition, automation, and package/downstream qualification to `Icod.TermInfo.Inspection`.

**Architecture:** Keep all new semantic work in `Icod.TermInfo.Inspection`; preserve the frozen Runtime/Source/Compiler/database-set contracts. Model static and explicit evidence separately from classification, then plan semantic operations from immutable profiles. Runtime verification and terminal-side ownership stay outside this repository.

**Tech Stack:** C# 13, .NET 8/9/10, xUnit, existing `Icod.TermInfo.Inspection` deterministic JSON infrastructure and package validation.

**Spec:** `docs/superpowers/specs/2026-09-11-1.11.0-persistent-raster-lifecycle-design.md`

## Global Constraints

- Development sequence: `1.11.0-Alpha-1` through `1.11.0-Alpha-8`.
- Primary implementation package: `Icod.TermInfo.Inspection`.
- `Icod.TermInfo` SHALL NOT depend on `Icod.Terminal`.
- Existing 1.9 version-1 and 1.10 version-2 JSON contracts remain unchanged for equivalent existing inputs.
- Existing 1.10 ordered database-set precedence/incompleteness semantics remain authoritative.
- Public lifecycle vocabulary is protocol-neutral; no Kitty image/placement identifiers or raw protocol dictionaries.
- Absence of static evidence is `Unknown`, not automatically `Unsupported`.
- Deterministic ordering, explicit bounds, parameter validation, XML documentation, and culture independence are release requirements.
