# Icod.TermInfo 1.14.0 RB02 Backend Classification and Static Inspection Plan

**Goal:** Implement deterministic per-backend availability classification and conservative `TerminalDescription` inspection on top of the accepted RB01 / `1.14.0-Alpha-1` contract.

**Baseline:** accepted RB01 head `7f43c4ad27f1858f8648237cbcb26e6808142458`, workflow #865 / run `34862203053`.

**Primary package:** `Icod.TermInfo.Inspection`

## Constraints

- Preserve all RB01 enum numerics, immutable shapes, bounds, and public constructors.
- Add only `RasterBackendClassifier` and `RasterBackendInspector` as new RB02 public types.
- Classification is per backend. Evidence for another backend is caller ambiguity and is rejected rather than ignored.
- Precedence is exactly `Verified > Declared > CapabilityDerived`.
- Within the highest present precedence: positive only => `Supported`; negative only => `Unsupported`; both => `Contradicted`; none => `Unknown`.
- The complete canonical evidence snapshot is retained in the resulting profile, including lower-precedence evidence.
- `RasterBackendInspector` recognizes only exact extended Boolean capability `Sixel` for `RasterBackendKind.Sixel`.
- Static Sixel presence produces one positive `CapabilityDerived` evidence item with source label `Sixel` and source ordinal `0`.
- Sixel absence remains `Unknown`; absence never manufactures negative evidence.
- A non-Boolean extended capability named `Sixel` is invalid authoritative metadata and causes `InvalidOperationException` when inspecting Sixel.
- Kitty Graphics has no static terminfo capability in RB02. Inspection returns `Unknown` with no evidence regardless of terminal name, built-in profile identity, Windows Terminal identity, xterm identity, environment, or unrelated capabilities.
- No database-set overload, lifecycle/placement composition, candidate evaluation, backend ranking, live probing, or `Icod.Terminal` dependency enters RB02.
- TDD is mandatory: tests-only RED before production types.
