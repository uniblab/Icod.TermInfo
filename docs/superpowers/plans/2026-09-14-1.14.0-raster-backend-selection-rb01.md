# Icod.TermInfo 1.14.0 RB01 Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze the additive 1.14 raster-backend availability and selection vocabulary, immutable public shapes, deterministic bounds, and compatibility reconstruction before backend classification or selection behavior is implemented.

**Architecture:** `Icod.TermInfo.Inspection` gains a backend-scoped layer above the frozen 1.11 lifecycle, 1.12 placement, and 1.13 runtime-integration contracts. Backend availability is independent of lifecycle/placement truth. RB01 exposes only immutable vocabulary/data shapes and validation; classifier, inspector, candidate evaluation, and planner behavior remain RB02-RB04 work.

**Tech Stack:** C# 13, .NET 8/9/10, xUnit 2.9, `Icod.TermInfo.Inspection`, PowerShell 5.1-compatible compatibility verification, GitHub Actions Windows/Linux/macOS plus existing package/archive gates.

**Spec:** `docs/superpowers/specs/2026-09-14-1.14.0-raster-backend-evidence-selection-design.md`

## Global Constraints

- Baseline is stable `1.13.0` with complete Inspection API normalized-LF SHA-256 `fd827a25abafb8e9ff3915567f45f9f2ec51b332bfd8a82dd4e4bca20290e764` and 90 exported public types.
- Development version advances to `1.14.0-Alpha-1` only after a clean RB01 test-only RED witness has been observed.
- Runtime, Source, Compiler, Termcap, and Inspection contracts through 1.13 remain source/binary compatible except unavoidable defect corrections.
- JSON v1-v5 remain unchanged in RB01.
- Production `Icod.TermInfo` and `Icod.TermInfo.Inspection` SHALL NOT reference `Icod.Terminal`.
- `RasterBackendKind` is closed in 1.14 to exactly `Sixel = 0` and `KittyGraphics = 1`.
- `RasterBackendEvidenceKind` is exactly `CapabilityDerived = 0`, `Declared = 1`, `Verified = 2`.
- `RasterBackendSupportStatus` is exactly `Unknown = 0`, `Supported = 1`, `Unsupported = 2`, `Contradicted = 3`.
- `RasterBackendCandidateStatus` is exactly `Satisfied = 0`, `RequiresRuntimeVerification = 1`, `Impossible = 2`.
- `RasterBackendSelectionStatus` is exactly `Selected = 0`, `RequiresRuntimeVerification = 1`, `RequiresPreference = 2`, `Impossible = 3`.
- Backend evidence count defaults to 256 and may be configured up to 4096.
- Backend evidence source labels are bounded to 256 UTF-16 code units.
- Selection candidate count is bounded by the closed backend vocabulary to 2; duplicate backend candidates are invalid.
- Preference order is snapshotted, must contain defined unique backend values, and may contain at most 2 values. Empty means no caller ranking. Completeness against the actual candidate set is enforced later by the planner; RB01 freezes that semantic rule without inventing hidden fallback.
- `RasterBackendSelectionRequest.PlacementRequest` is nullable. `null` means no advanced 1.12 placement semantics are requested. This is required because the frozen `PersistentRasterPlacementRequest` rejects an empty request.
- No alpha/pixel-format/quality/performance/latency semantics enter RB01.
- C# follows repository 1TBS conventions, tabs, existing XML-doc style, and no multiline ternary drift.
- TDD is mandatory: test-only RED before any production file.
