# Icod.TermInfo 1.11.0 Persistent Raster Lifecycle Design

## Status

Approved architectural design for the `1.11.0` development line.

## Purpose

`Icod.TermInfo 1.11.0` adds a protocol-neutral semantic layer for persistent raster lifecycle inspection and planning. It does not create live terminal resources, transmit graphics protocol frames, or own terminal-side identity.

The release exists to let downstream consumers answer, deterministically and without live side effects, what persistent-raster lifecycle semantics are known, what evidence supports those conclusions, and what ordered semantic operations appear admissible for a requested task.

## Library boundary

`Icod.TermInfo` owns static/explicit evidence, classification, provenance, uncertainty, contradiction, and planning.

`Icod.Terminal` owns live verification, protocol execution, terminal-resident resource and placement identity, lifecycle-generation invalidation, transport failure, and cleanup.

`Icod.DCurses` owns layout, virtual-screen policy, and higher-level scene/application state.

`Icod.TermInfo` SHALL NOT depend on `Icod.Terminal`.

## Foundational state model

The public support state is:

```text
Unknown      no conclusive positive or negative evidence
Supported    available evidence conclusively supports the semantic capability
Unsupported  available evidence conclusively rejects the semantic capability
Contradicted conclusive positive and negative evidence coexist
```

Absence of a capability is not, by itself, `Unsupported`.

## Foundational operation model

The public semantic operation vocabulary is:

```text
DisplayEphemeral
UploadResource
CreatePlacement
UpdatePlacement
DeletePlacement
DeleteResource
```

The vocabulary intentionally describes semantic intent, not wire protocol commands.

## Evidence direction

RL02 will add immutable evidence records and provenance. Evidence kinds will distinguish capability-derived facts from explicit caller-declared and caller-verified facts. Verified evidence outranks declared evidence; declared evidence outranks recognized static derivation; absence remains unknown. Contradictions are retained rather than discarded.

## Profile direction

RL03 will classify independent lifecycle dimensions including ordinary raster display, persistent upload, acknowledged upload, placement creation, multiple placements, placement update, placement deletion, and resource deletion.

A profile is a deterministic classification of evidence. It is not a live terminal session and does not guarantee execution success.

## Planner direction

RL04 will accept a lifecycle profile plus a bounded semantic request and produce either an ordered plan or a structured inability/uncertainty result.

Plans may require live verification explicitly. A plan is advisory execution policy, not proof that the live terminal will accept the operation.

## Database-set composition

RL05 will compose lifecycle inspection with the frozen 1.10 ordered database-set model. Existing effective-definition precedence and incompleteness semantics remain authoritative. A later root cannot establish certainty when an incomplete earlier root makes the effective definition indeterminate.

## Automation

RL06 may add lifecycle-profile and lifecycle-plan machine-readable documents through an additive schema/document contract. Existing 1.9 version-1 and 1.10 version-2 documents remain unchanged for equivalent existing inputs.

## Downstream qualification

RL07 will prove package-only interoperability with a downstream consumer shaped like `Icod.Terminal`: static TermInfo evidence and planning occur first; consumer-owned live verification may then strengthen knowledge before runtime execution. No TermInfo API will expose or require Terminal's private image/placement identifiers.

## Explicit non-goals

The release does not add Kitty identifiers, raw APC dictionaries, Sixel encoding, raster codecs, pixel buffers, image caches, terminal resource registries, placement registries, hidden replay, terminal lifecycle-generation ownership, cursor positioning, scene graphs, animation, Unicode placeholders, z-order, live probing owned by TermInfo, or terminal-brand heuristics.

## RL01 public regret gate

RL01 freezes only the smallest vocabulary that future tranches require:

```csharp
public enum PersistentRasterLifecycleSupportStatus {
    Unknown = 0,
    Supported = 1,
    Unsupported = 2,
    Contradicted = 3,
}

public enum PersistentRasterLifecycleOperation {
    DisplayEphemeral = 0,
    UploadResource = 1,
    CreatePlacement = 2,
    UpdatePlacement = 3,
    DeletePlacement = 4,
    DeleteResource = 5,
}
```

The enums live in `Icod.TermInfo.Inspection`. No lower-layer public contract changes in RL01.

The numeric values are explicit and SHALL remain stable once RL01 is frozen.

## Error and compatibility policy

Ordinary unknown/unsupported lifecycle combinations will eventually be structured results, not exception-driven flow. Public/protected/internal methods added in later tranches validate parameters at entry. Existing 1.x API numerics, serialized contracts, parser semantics, database-set precedence, and lower-layer package contracts remain frozen.

## Testing strategy

RL01 verifies exact enum membership/numerics and package placement. Later tranches add determinism, culture independence, contradiction, bound, database-set incompleteness, machine-readable schema, package-only consumer, and downstream integration coverage.
