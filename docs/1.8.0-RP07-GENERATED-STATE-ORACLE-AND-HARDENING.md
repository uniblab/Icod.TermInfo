# Icod.TermInfo 1.8.0 RP07 - Generated-State Oracle and Hardening

**Roadmap tranche:** RP07
**Development version:** `1.8.0-Alpha-7`
**Implementation base:** PR 33 commit `ae15944c07086ccfe49f92ee2492ddc856db06df`
**Production API change:** none
**Production semantic change:** none

## Purpose

RP07 establishes permanent generated-state and boundary evidence for the
relative-source planner delivered by RP01 through RP06. It does not add another
planning policy, score component, candidate source, command option, or public
type. The production planner and frozen 1.7 synthesizer remain unchanged.

The tranche answers three release questions:

1. Does exhaustive production planning choose the same representation as an
   independently enumerated oracle?
2. Does every selected source reconstruct the exact effective target?
3. Do bounded, pathological, and nondeterminism-sensitive inputs retain the
   frozen limits and evidence contract?

## Seeded generated universes

`RP07GeneratedPlanningTests` owns 48 fixed generated universes beginning at
seed `0x18070001` with stride `0x9E3779B9`. Each failure reports the exact
reproducible seed together with the active layout and capability order.

Every universe contains one target and three caller-ordered candidates. The
generator varies:

- standard Boolean, numeric, and string capabilities;
- extended Boolean, numeric, and string capabilities;
- inherited capabilities which must be cancelled;
- extended capabilities whose kind changes among target and candidates;
- numeric and escaped string boundary values; and
- candidates which help, conflict, or add irrelevant inherited state.

The matrix crosses all three synthesis layouts with all four standard-
capability ordering modes:

```text
Canonical             x Database, TermInfoName, LongName, TermcapCode
SingleLine            x Database, TermInfoName, LongName, TermcapCode
OneCapabilityPerLine  x Database, TermInfoName, LongName, TermcapCode
```

Each combination is exercised by multiple seeds.

## Independent brute-force oracle

The RP07 independent brute-force oracle does not call the production planner
and does not use its recursive enumeration implementation. For each three-
candidate universe it explicitly constructs this finite domain:

```text
[]
[0] [1] [2]
[0,1] [0,2] [1,0] [1,2] [2,0] [2,1]
```

For every legal position sequence the oracle:

1. invokes only the frozen public 1.7 synthesizer;
2. rejects duplicate `use=` spellings and invalid representations;
3. parses the generated source independently;
4. derives local-directive and cancellation counts from parsed fields;
5. measures the UTF-8 representation length;
6. constructs the public frozen planning score; and
7. chooses the strict lexicographic minimum.

The production result must match the oracle's exact source, score, selected
object references, candidate count, evaluated-plan count, and exhaustive
evidence. Every exhaustive generated result is then combined with source for
its selected effective parents, parsed, resolved, and compared semantically
with the original target.

## Bounded-prefix evidence

Every fourth generated universe also runs with a five-evaluation budget and
explicit non-exhaustive opt-in. The oracle evaluates exactly the corresponding
increasing-depth lexicographic prefix. Production must return the same source,
score, and selected parent references, report exactly five evaluations, and
report `IsExhaustive == false`.

This validates budget-limited behavior without converting it into a heuristic
or claiming that a prefix winner is globally optimal.

## Score ties and candidate permutations

Focused tests freeze progression through every score component:

1. local directive count;
2. cancellation count after a local-directive tie;
3. parent count after both directive counts tie;
4. rendered UTF-8 byte count after the semantic counts tie; and
5. selected candidate indices after all scalar components tie.

All six permutations of a controlled three-candidate set are also compared
with the oracle. Two candidate positions intentionally reference the same
effective description through distinct aliases. They remain distinct positions
and the final candidate-index tie-break remains relative to caller order.

## Determinism

RP07 verifies that planning output and score remain byte-for-byte equal across:

- Turkish and French current cultures;
- opposite capability insertion orders;
- repeated calls in one process; and
- two separate Toolchain sample process executions in package validation.

The Windows package gate compares the two process outputs with `fc /b`; the
Bash gate uses `cmp -s`. A mismatch prints evidence and fails validation.

## Frozen boundaries

Boundary tests accept the exact supported maxima for candidate snapshot,
selected-parent policy, evaluated-plan policy, and generated-source policy.
They reject one-past values and a 257th candidate position. The maximum-candidate
snapshot test uses a zero-parent domain, so it proves the boundary without
attempting to materialize or enumerate a factorial plan space.

The existing RP04 allocation, overflow, cancellation, runtime, exhaustive-
preflight, and deterministic-prefix tests remain authoritative and continue to
run beside RP07.

## Pinned 1.7 corpus reuse

The checked-in differential corpus remains pinned to
`ncurses 6.5.20250216`. RP07 resolves each corpus target and its recorded parent
states from `effective.ti`, passes those effective descriptions to the planner,
and requires the selected source to resolve back to the exact target.

This does not make normal validation depend on host ncurses, host terminfo
locations, environment discovery, or network access. The corpus provenance and
all source states remain checked in.

## Toolchain composition

`Icod.TermInfo.Toolchain.Sample` now contains a useful base, a decoy candidate,
and a target. It performs the complete reusable-library path:

```text
parse and resolve controlled source
    -> plan over explicit candidates
    -> consume the planner's synthesized source
    -> parse and resolve the planned source
    -> compile
    -> publish a temporary conventional database
    -> reacquire through Runtime
    -> compare with the original effective target
```

The sample requires an exhaustive three-plan search, requires the useful base
object to be selected instead of the decoy, writes only the final planned source
to stdout, and deletes its unique temporary database.

## Compatibility and ownership

RP07 preserves:

- the RP01 public planning types and lexicographic score;
- RP02 zero- and single-parent semantics;
- RP03 ordered multi-parent enumeration;
- RP04 bounds, cancellation, and result evidence;
- RP05 explicit catalog and directory orchestration;
- RP06 direct, routed, package, and archive command behavior;
- the frozen 1.7 synthesizer contract;
- the frozen Runtime, Source, Compiler, and Termcap public APIs;
- Inspection's Runtime-and-Source-only production dependencies;
- `net8.0`, `net9.0`, and `net10.0` reusable-library support; and
- reusable assembly version `1.0.0.0`.

Compiler remains a sample and test dependency, not an Inspection production
dependency.

## Gate

RP07 is complete when repository validation proves that:

- every exhaustive seeded case agrees exactly with the independent oracle;
- every exhaustive and bounded selected source round-trips to its target;
- every generated failure identifies a reproducible seed;
- every layout and ordering mode is covered;
- score ties, permutations, equivalent descriptions, kind changes, and
  cancellations are covered;
- exact maxima are accepted and one-past boundaries are rejected;
- culture, insertion order, repeated calls, and repeated processes are stable;
- the pinned 1.7 differential corpus remains usable as planning evidence;
- the Toolchain sample completes plan through reacquire and compare; and
- all coordinated versions report `1.8.0-Alpha-7`.
