# Icod.TermInfo 1.16.0 BerkeleyDb public API freeze

The authority is `docs/1.16.0-BERKELEYDB-PUBLIC-API-BASELINE.txt`, originally
approved in HW01 and unchanged through HW08. It contains **12 exported public types**,
assembly version `1.0.0.0`, and normalized-LF SHA-256:

```text
01a84c409fb222324009272de0213d1b1a8dc3df1ccac46ce66341f17d4baa81
```

The only additions to 1.15 are `BerkeleyDbTerminalDatabaseEntry`,
`BerkeleyDbTerminalDatabaseWriterOptions`, and
`BerkeleyDbTerminalDatabaseWriter`. Their complete members, defaults, and
nullability are recorded in the manifest; no raw key/value or page API is public.

The managed package verifier removes exactly these three type blocks and
requires the remainder to equal the complete immutable nine-type 1.15 manifest,
whose normalized-LF SHA-256 is:

```text
f519600aa4085d07c2d20bd8dc7a32c4dc06a43f4e361554b205ce2f97a8bf36
```

This proves that reader members, defaults, annotations, inheritance, interfaces,
and assembly identity are retained. Mutation tests reject reader member/default
drift, assembly-version drift, missing writer types, and unapproved extra types.
The verifier also enforces the historical reader fingerprint, so changing both
manifests together cannot redefine the accepted 1.15 API.
The existing release script independently generates current assembly manifests,
compares all three frameworks, and requires exact equality with the 1.16
baseline. Subtraction of a baseline is not a substitute for that live check.

Package verification retains Runtime-only dependencies, exact package assets,
XML documentation, portable symbols, Source Link, and IL-only assemblies with
no native assets. Other frozen reusable APIs and JSON versions 1–6 are unchanged.
HW08 adds qualification and documentation only; stable identity promotion must
not change the accepted feature/API source.

The Alpha-8 freeze was qualified at
`b458b0d18c0a8b1e2c6c37a0698cc9ea4fd6341e` in normal workflow
`36279869607` (12/12 jobs) and native workflow `36279869638` (3/3 jobs).
Stable `1.16.0` retains both manifest fingerprints and the accepted feature/API
source; its independent qualification is recorded in the release audit.
