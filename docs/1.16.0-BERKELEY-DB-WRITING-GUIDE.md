# Writing ncurses Hash-v9 databases

Icod.TermInfo 1.16 adds whole-file publication to the optional
`Icod.TermInfo.BerkeleyDb` package. It creates ncurses-compatible Berkeley DB
Hash-v9 stores using managed code; no native library or process is needed.
The package depends only on the matching Runtime package and targets .NET 8,
9, and 10. Migration and catalog automation remain assigned to 1.17.

## Publish compiled entries

Supply existing compiled terminfo bytes, with their exact canonical name and
ordered aliases. The writer validates them with Runtime's parser. Applications
that start from source can use `Icod.TermInfo.Compiler` separately; BerkeleyDb
does not depend on Compiler.

```csharp
using Icod.TermInfo;
using Icod.TermInfo.BerkeleyDb;

byte[] bytes = File.ReadAllBytes("compiled-entry");
TerminalDescription terminal = CompiledTermInfoParser.Parse(bytes);
var entry = new BerkeleyDbTerminalDatabaseEntry(
    terminal.Name, terminal.Aliases, bytes);

// The parent directory must already exist. The default refuses replacement.
BerkeleyDbTerminalDatabaseWriter.Write("./terminfo.db", new[] { entry });

var provider = new BerkeleyDbTerminalDescriptionProvider("./terminfo.db");
if (provider.TryLoad(terminal.Name, out var published))
    Console.WriteLine(published.Name);
```

`BerkeleyDbTerminalDatabaseEntry` copies its input aliases and payload. Reading
`Data` returns another copy. `Write` enumerates the source once and checks the
record budget before retaining each entry. Input must be nonempty. Canonical
names and aliases must be safe portable identities and globally unique; parsed
names and alias order must agree with the declarations.

The [executable sample](../samples/Icod.TermInfo.BerkeleyDb.Sample/README.md)
publishes two entries and proves that reversing their order gives identical
database bytes. It cleans up its own private directory after all work finishes.

## Limits and replacement

```csharp
var options = new BerkeleyDbTerminalDatabaseWriterOptions(
    maximumDatabaseSize: 64 * 1024 * 1024,
    maximumRecordCount: 65536,
    overwriteExisting: true);
BerkeleyDbTerminalDatabaseWriter.Write("./terminfo.db", new[] { entry }, options);
```

These are the default size/count limits; replacement is false by default.
Each entry costs two physical records plus one for each alias: a payload record,
a canonical redirect, and alias redirects. The size limit bounds the complete
output image, not total managed memory. Parser limits apply separately to each
compiled entry. Caller allocations and blocked caller enumeration are outside
the writer's control. All limits must be positive.

Replacement publishes exactly the supplied entries. It does not retain old
entries, merge databases, update pages in place, or discover a destination.
Output is little-endian Hash-v9 with 4096-byte pages, power-of-two primary bucket
counts, collision chains, and overflow pages. Logical lookup keys are exact
UTF-8: no case folding, normalization, transliteration, or Latin-1 aliases are
manufactured. Input payload bytes retain their compiled-format encoding.

## Filesystem and cancellation contract

The immediate parent must be an existing ordinary directory. Destination and
lock paths must not be directories, symbolic links, or reparse points. The
writer validates and builds the image before publication, acquires a cooperative
exclusive lock, creates a unique sibling temporary file, writes and flushes it,
closes it, then reopens it through the production reader. Complete bytes,
physical records, and logical publications must match before a same-directory
move commits the file.

For `terminfo.db`, the lock is `.terminfo.db.icod-terminfo.lock`. It persists
after the operation and does not indicate that a writer is active. Do not delete
it while cooperative writers may use that destination. Lock contention waits
until acquisition or cancellation; there is no timeout.

Cancellation before commit preserves the old destination or its absence. A
successful move remains successful if cancellation arrives during the commit.
Cleanup of this attempt's temporary file is best effort. Replacement uses fresh
metadata and inherited access controls rather than preserving old ACLs or mode.

Atomic visibility relies on supported filesystem rename semantics. There is no
universal power-loss durability guarantee, hostile ancestor-substitution
protection, or coordination with native Berkeley DB writers. Windows readers
can cause safe replacement refusal. The writer never substitutes copy/delete.

## Errors

| Failure | API result |
| --- | --- |
| Null, empty, or unsafe arguments | `ArgumentNullException` / `ArgumentException` |
| Duplicate ownership, declared/parsed identity mismatch, record or image budget exceeded | `InvalidOperationException` |
| Invalid compiled bytes | Runtime parser format exception |
| Existing destination without overwrite, I/O failure | `IOException` |
| Permission denial | `UnauthorizedAccessException` |
| Required exclusive locking unsupported | `NotSupportedException` |
| Staged verification mismatch | `InvalidDataException` |
| Cancellation before commit | `OperationCanceledException` |

Exceptions raised by caller enumeration propagate; the enumerator is disposed.
No pre-commit failure intentionally changes the destination.

## Command line

```sh
icod-terminfo tic --database-format hashed -o ./terminfo.db source.ti
icod-terminfo tic --database-format hashed --force -s -o ./terminfo.db source.ti
```

`directory` remains the default. Values are exact and case-sensitive;
`--database-format` cannot be repeated or combined with `-c`. Hashed output
requires an explicit `-o` file and an existing parent. Extensions do not select
format. `--force` replaces the entire store; `-s` reports format, destination,
canonical/alias counts, and warnings. Failures use controlled `TIC0007`
diagnostics without exposing temporary names or payload bytes. See
[tic usage](../tic/README.md#116-hashed-publication) for selection and exit rules.

## Compatibility evidence

The twelve-type API is the frozen nine-type 1.15 reader plus the three writer
types. Runtime, Source, Compiler, Termcap, Inspection, and JSON APIs are unchanged.
See the [API freeze](1.16.0-BERKELEYDB-PUBLIC-API-FREEZE.md),
[HW07 security/resource audit](1.16.0-HW07-WRITER-HARDENING.md), and
[release audit](1.16.0-RELEASE-AUDIT.md). Native Berkeley DB 5.3 and pinned ncurses
are CI oracles only; none of their code or runtime assets is shipped.
