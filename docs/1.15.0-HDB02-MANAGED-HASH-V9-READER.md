## Accepted big-endian checkpoint

Exact head: `6e9f53f6c501d36063b0f4026bd1c4ea53ced048`.

- [PR workflow #1035 / 35009135968](https://github.com/uniblab/Icod.TermInfo/actions/runs/35009135968): completed/success, all 12 jobs.
- [HDB00 workflow #64 / 35009136012](https://github.com/uniblab/Icod.TermInfo/actions/runs/35009136012): completed/success, all 3 jobs.

The production reader supports tested inline exact-key lookup, little-endian
off-page value reconstruction, and big-endian inline lookup. Byte order is
detected from the Hash magic and carried in immutable metadata through numeric
reads. No public acquisition API is exported.

HDB00 still exercises its exploratory managed probe. Its success must not be
reported as a differential test of the production `BerkeleyDbHashReader`.

## Page identity and corruption checkpoint

Test-only RED head: `219555c023b53018fa79a80b3b41c4a63a36c1f0`.

[PR workflow #1036 / 35010444473](https://github.com/uniblab/Icod.TermInfo/actions/runs/35010444473)
proved the RED on Linux across net8.0/net9.0/net10.0: 5 failed, 34 passed,
39 total per target framework. All five failures were the expected
`Assert.Throws` failure because no exception was thrown.

The five regression cases cover:

- incorrect base metadata page identity, in both byte orders;
- incorrect scanned Hash-page identity, in both byte orders;
- incorrect followed overflow-page identity.

The fixture builders now set the correct page identities. The independent
layout reference is Berkeley DB's
[DBMETA/PAGE definition](https://github.com/berkeleydb/libdb/blob/5b7b02ae052442626af54c176335b67ecc613a30/src/dbinc/db_page.h).
The production fix reads the stored page number in the detected byte order and
rejects a mismatch before consuming that page's records or overflow payload.

Validation is deliberately attached to metadata, scanned Hash pages, and
followed overflow pages. It is not attached to generic page slicing:
unused/sparse pages are not required to carry an initialized page identity.

The same test-only commit adds passing characterization coverage for:

- invalid magic, revision, page sizes, encryption/checksum flags, metadata type,
  and last-page bounds;
- odd/oversized item counts, free-offset bounds, and item-offset bounds;
- empty/truncated metadata and partial data pages;
- overflow cycles, out-of-range references, wrong page type, declared-length
  underflow/overflow, and oversized declared values;
- case-, prefix-, and suffix-different requested keys returning a clean miss.

The tests use real temporary files and the production reader. They do not use
mocked storage or assert private diagnostic wording.

GREEN qualification for this checkpoint is pending at this commit. Exact-head
results are recorded in PR #45 after the workflows finish. Do not infer a pass
from this progress document.

## Remaining HDB02 work

Before HDB02 can be accepted:

1. Establish explicit file/value resource limits and bounded file ownership;
   `File.ReadAllBytes` is not yet an explicit resource-limit policy.
2. Broaden valid fixtures to off-page keys, multi-page overflow, big-endian
   overflow, multiple records/pages, and supported page-size boundaries.
3. Finish unsupported-layout and corruption coverage, including deterministic
   behavior for unsupported page/item shapes.
4. Qualify the production reader directly against native-generated HDB00
   fixtures on all supported hosts. Research-probe success is insufficient.
5. Verify independent concurrent reads and finish exact package/full CI
   qualification.

The implementation remains internal-only, managed, and read-only. Ncurses
marker-0/marker-2 resolution, compiled-entry parsing, terminal identity,
provider caching, and public APIs remain HDB03 responsibilities.
