# Icod.TermInfo 0.7.0 Contract Audit

This document records the T19 API/scope hardening evidence for the 0.7.0 line and identifies the remaining T20 release gate. It is intentionally a **pre-completion** audit: T19 freezes the consumer-facing contract, while T20 will confirm the final release version, CI results, package artifacts, and publication readiness.

## T19 contract freeze

The T19 review freezes the intended 0.7 public surface as represented by `PublicApiSurfaceTests`.

The 0.7 additions are deliberately low-level and descriptive:

- generic extended Boolean, numeric, and string capability values;
- semantic color inspection through `TerminalColors` and immutable color value types;
- indexed and direct-RGB color expansion driven by profile capability programs;
- built-in DEC VT102/VT220 and modern xterm-family descriptions;
- modern xterm mouse/focus/paste/key/reporting/clipboard metadata carried as standard or extended capabilities.

No T19 public type is added merely to manage terminal state. Full-screen lifecycle, input decoding, terminal probing, clipboard operations, and other live-session behavior remain outside this package.

## Nullability, exception, allocation, and thread-safety review

The T19 review did not identify a need for additional public stateful objects or nullable ownership conventions.

- Public APIs which accept caller-owned reference arguments validate them before use; missing capabilities are represented by the established nullable/Try-pattern contracts rather than sentinel objects.
- Invalid enum values, invalid indexes, malformed extended metadata, and missing required capabilities continue to fail through the existing `ArgumentException`/`ArgumentOutOfRangeException`/`InvalidOperationException` contracts rather than through terminal-specific fallback behavior.
- `TerminalColors` remains stateless. Semantic inspection returns an immutable value and color expansion delegates to the existing parameter engine; T19 adds no cache, terminal-name dispatch table, or live-session allocation.
- Built-in profiles are constructed once as immutable `TerminalDescription` instances. Their capability collections are read-only snapshots, and concurrent consumers do not mutate shared terminal state.
- Extended capability values and RGB/layout/color-support values remain immutable value types or immutable data exposed through read-only collections.
- T19 adds no process-global current terminal, mutable static session state, background worker, input loop, or stream ownership.

These findings keep the allocation/thread-safety model established by earlier tranches intact while freezing the final 0.7 API shape.

## Built-in profile contract

The selected 0.7 built-ins are:

- `dumb`;
- `ansi`;
- `vt100` with alias `vt100-am`;
- `vt102`;
- `vt220` with alias `vt200`;
- `xterm`;
- `xterm-16color`;
- `xterm-88color`;
- `xterm-256color`;
- `xterm-direct`;
- `xterm-direct16`;
- `xterm-direct256`.

The database remains conservative: nearby or unrelated terminal names are not inferred or aliased unless explicitly represented by a built-in profile.

## Color contract

The semantic color layer remains derived from raw capability data rather than terminal names.

T13-T17 tests provide evidence for:

- monochrome classification;
- synthetic/provider-created 4-color support;
- retained 8-color ANSI behavior;
- 16-color behavior;
- arbitrary indexed palettes, including 88 colors;
- 256-color behavior;
- direct RGB behavior;
- independent `pairs` handling;
- `RGB` layout interpretation;
- `CO` retained indexed-prefix interpretation;
- selector expansion through the shared T2 parameter engine;
- palette/reset capability fidelity.

The selected direct xterm profiles use 8/8/8 packed RGB semantics and retain 8, 16, or 256 indexed entries according to `CO`.

## Modern xterm metadata contract

T18 freezes the selected current xterm metadata as data, including:

- standard `kmous`;
- extended `XM`/`xm` mouse metadata;
- focus enable/disable and focus-in/focus-out strings;
- bracketed-paste enable/disable and begin/end strings;
- modified key strings;
- cursor style/color metadata;
- terminal-reporting metadata;
- OSC 52 clipboard/selection metadata where present in the selected profile.

Parameterized metadata is expanded by the same generic terminfo parameter engine used by standard capabilities. No continuous input parser or live terminal state is introduced.

## CI and package evidence

T19 hardens the repository workflows before the final release gate:

- pull requests run Debug and Release on Windows, Linux, and macOS;
- pushes to `main` run the same six build/test combinations;
- a dedicated Ubuntu package job builds/tests Release, packs the project, runs `.github/scripts/verify-release-package.sh`, and uploads `.nupkg`/`.snupkg` artifacts;
- the package verifier rejects unexpected runtime/native payloads and runtime NuGet dependencies;
- the verifier checks repository metadata, portable PDBs, and Source Link information;
- the verifier restores/runs a fresh `net10.0` consumer using only the local package source;
- the verifier exercises xterm indexed/direct color, full-screen capability presence, and modern extended metadata;
- the verifier runs the sample in `--describe-only` mode.

Publication is intentionally not automatic at T19. T20 owns the final version/tag/publication gate.

## Project-family boundary

The 0.7 boundary remains:

- **Icod.TermInfo:** immutable terminal descriptions, standard/extended capabilities, color semantics, parameter expansion, padding/output transformation, provider-supplied metadata, and built-in profiles.
- **Future live terminal layer:** terminal mode/session ownership, full-screen lifecycle, cursor lifecycle, keyboard/mouse/focus/paste decoding, probing, protocol operations, progress helpers.
- **Future curses-style layer:** virtual screen, refresh optimization, windows, pads, panels, menus, forms, widgets.
- **PTY/process layer:** pseudo-terminal creation and process plumbing.

Descriptive metadata does not imply operational ownership.

## 0.8.0 reservation

The following remain explicitly deferred to 0.8.0:

1. classic Windows Console support/profile modeling;
2. Windows Terminal support/profile modeling;
3. arbitrary/system compiled terminfo database loading, including `TERMINFO`, `TERMINFO_DIRS`, user/system discovery, parsing, precedence, malformed-file handling, and caching policy.

The 0.7 built-in xterm family does not depend on the host terminfo database.

## Remaining T20 gate

T19 does **not** declare 0.7.0 released. T20 must still:

1. run the final full checklist in `Icod.TermInfo-Development-Roadmap-0.7.0.md`;
2. require all Debug/Release Windows/Linux/macOS jobs to be green;
3. require package validation and fresh-consumer smoke tests to be green;
4. confirm compatibility/profile/scope assertions remain green;
5. set both version elements to `0.7.0`;
6. tag `v0.7.0` at the validated release commit;
7. publish the same validated package to NuGet.org and GitHub Packages;
8. mark the roadmap complete.

Until those steps pass, this document is the T19 pre-completion evidence map rather than the final release sign-off.
