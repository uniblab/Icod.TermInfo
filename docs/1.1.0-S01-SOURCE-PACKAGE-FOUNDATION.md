# Icod.TermInfo 1.1.0 — S01 Source Package Foundation

**Tranche:** S01
**Development version:** `1.1.0-Alpha-1`
**Runtime assembly identity:** `Icod.TermInfo, Version=1.0.0.0`
**Source assembly identity:** `Icod.TermInfo.Source, Version=1.0.0.0`
**Status:** implementation candidate; build/test/package validation required

---

## 1. Purpose

S01 establishes the package and repository boundary for the post-1.0 terminfo
source-language work without adding source parsing yet.

The dependency direction is:

```text
Icod.TermInfo.Source
        |
        v
  Icod.TermInfo
```

`Icod.TermInfo` remains the stable runtime package and SHALL NOT reference
`Icod.TermInfo.Source`.

Both packages use the coordinated development version
`1.1.0-Alpha-1`. The stable 1.x runtime assembly identity remains
`1.0.0.0`; package version progression does not change that compatibility
contract.

---

## 2. Package and repository contract

S01 adds:

- `Icod.TermInfo.Source/Icod.TermInfo.Source.csproj`;
- `tests/Icod.TermInfo.Source.Tests`;
- a package-reference-only source-package smoke consumer;
- solution participation for source package and tests;
- Windows and Bash build/package validation;
- net8.0/net10.0 public API equivalence validation for the source assembly.

The source package targets:

```text
net8.0;net10.0
```

and uses C# 13.

The package is intentionally almost empty in S01. An internal assembly marker
prevents an empty-compilation warning while avoiding a meaningless public API.
S02 introduces the first source-language types.

## 3. Diagnostic convention

S01 freezes the convention that later source parsing and resolution diagnostics
will follow. The concrete public diagnostic types are deferred to S02.

### 3.1 Diagnostic codes

Source-language diagnostics use stable machine-readable codes of the form:

```text
TISdddd
```

where `dddd` is a four-digit decimal identifier.

Diagnostic codes identify a condition, not a particular English message.
Existing codes SHALL NOT be silently reused for unrelated conditions.

### 3.2 Severity

Every source diagnostic has an explicit severity. The initial model will
distinguish at least:

- error;
- warning.

Informational diagnostics may be added later only if a consumer requirement
justifies them.

### 3.3 Source location

Where the offending construct came from source text, a diagnostic SHOULD carry
a source location sufficient to identify:

- caller-supplied source identity or file name when available;
- line;
- column;
- span/length where meaningful.

No diagnostic SHALL invent a file path when the caller supplied text without a
file identity.

### 3.4 Deterministic reporting

For identical input and resolver inputs, diagnostics SHALL be produced in a
deterministic order.

Parser and resolver libraries SHALL return or expose diagnostics as data. They
SHALL NOT write diagnostics directly to process stdout or stderr.

Ordinary malformed terminfo source is a diagnostic condition. Programmer
contract violations such as null arguments remain .NET exceptions, and actual
I/O failures remain I/O failures at the layer which performs I/O.

## 4. API snapshot policy

The existing `Icod.TermInfo.PublicApiSnapshot` tool remains authoritative for
the stable runtime package.

During S01, the source assembly has no intended exported API. Package validation
uses the tool's `--compare` mode to require exact public API equivalence between
the `net8.0` and `net10.0` source assemblies.

The first reviewed `Icod.TermInfo.Source` public API baseline SHALL be created
when S02 introduces the source-location and lexical public surface. S01 does not
commit an empty baseline merely to create churn one tranche later.

---

## 5. Fresh-package-consumer gate

Repository package validation packs both:

- `Icod.TermInfo`;
- `Icod.TermInfo.Source`.

A temporary consumer references only `Icod.TermInfo.Source` from the local
artifact directory. The consumer must compile and run for both supported target
frameworks while also using `Icod.TermInfo.TerminalDescription`.

That proves the source package carries the intended NuGet dependency on the
runtime package rather than relying on a repository-local project reference.

---

## 6. S01 gate

S01 is complete when:

1. clean/restore/build/test succeeds for the complete solution;
2. both packages pack for the supported development/release configuration;
3. `Icod.TermInfo` retains assembly version `1.0.0.0`;
4. `Icod.TermInfo` and `Icod.TermInfo.Source` use package version
   `1.1.0-Alpha-1`;
5. source and source-test projects target `net8.0;net10.0`;
6. net8.0/net10.0 source public API equivalence passes;
7. fresh runtime and source package consumers pass;
8. no runtime dependency from `Icod.TermInfo` to `Icod.TermInfo.Source` exists.

After this gate, S02 may introduce the lexical and source-location model.
