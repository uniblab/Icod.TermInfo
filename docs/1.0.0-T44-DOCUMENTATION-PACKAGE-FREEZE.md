# Icod.TermInfo 1.0.0 T44 — Documentation and Package Freeze

T44 advances the package to `1.0.0-rc.1`.

This tranche is the release-candidate documentation/package freeze. It adds no
runtime terminal feature and changes no public runtime signature.

## Release documentation becomes enforceable

The shipped project already generates XML documentation. T44 removes the Release
`CS1591` exemption while retaining `TreatWarningsAsErrors=true`.

The result is intentional:

```text
missing XML documentation on a public member
    -> CS1591
    -> Release build failure
```

The compiler, not a checklist, is therefore the final completeness gate.

The package verifier additionally opens both packaged XML files and requires
them to be non-empty, parseable, identify `Icod.TermInfo`, and contain documented
members.

## Stable 1.x policy documents

T44 adds:

```text
docs/VERSIONING.md
docs/COMPATIBILITY.md
```

The policies record the decisions frozen in T42/T43:

```text
consumer TFMs        net8.0; net10.0
host CI families     Windows; Linux; macOS
AssemblyVersion      1.0.0.0
strong-name signed   no
package dependencies none
native ncurses       none
```

The versioning policy makes the API baseline an intentional compatibility
artifact rather than something to regenerate mechanically after a mismatch.

The compatibility policy also records semantic/discovery/package guarantees and
the features which remain outside `Icod.TermInfo`.

## README and sample audit

The repository README is moved from 0.9-release wording to the 1.0 release-
candidate contract.

The documentation audit found an important multi-target usability issue: the
sample projects target both `net8.0` and `net10.0`, so `dotnet run` without
`--framework` is ambiguous.

T44 updates root and sample documentation to use:

```text
-f net10.0
```

in examples and explicitly tells users to substitute `-f net8.0` when testing
the .NET 8 target.

The 0.9 acquisition guide remains authoritative for the acquisition feature
family because 1.0 does not redesign those semantics.

## Release procedure

`docs/RELEASING.md` now documents the current verifier order:

```text
capability metadata
    -> approved API baseline
    -> net8/net10 API equivalence
    -> package/XML/metadata/symbol verification
    -> fresh package consumer on net8
    -> fresh package consumer on net10
    -> non-interactive sample
```

The workflow boundary remains unchanged:

```text
pull request
    -> validation only
    -> never publish

push to main
    -> Release validation
    -> package validation
    -> publish exact validated artifact
```

T44 does not broaden `push-main.yaml`.

## Package freeze


The package verifier additionally freezes the NuGet title and validates both XML
documentation assets.

No runtime dependency, native payload, repository fixture, sample, test, or
maintenance tool belongs in the runtime package.

## Outstanding earlier acceptance evidence

At the time T44 is prepared, the reviewed
`docs/1.0.0-PUBLIC-API-BASELINE.txt` is still not present on the working branch.

T44 does not fabricate that human-owned artifact and does not mark T42/T43
acceptance complete on its behalf.

Before release-package validation can pass, generate the candidate with:

```text
dotnet run --project tools/public-api-snapshot/Icod.TermInfo.PublicApiSnapshot.csproj -c Release -- --write
```

Review the entire manifest, commit it only after approval, and then require:

```text
public-api-snapshot --check
public-api-snapshot --compare bin/Release/net8.0/Icod.TermInfo.dll bin/Release/net10.0/Icod.TermInfo.dll
```

The pinned ncurses T43 differential also remains an explicit maintainer
acceptance item until recorded as passing.

## T44 acceptance

T44 is ready to close when:

1. Release builds succeed with no CS1591 exemption;
2. tests pass on both target frameworks;
3. all root/sample commands are valid for multi-target projects;
4. versioning and compatibility policies are reviewed;
5. API baseline is reviewed/committed and `--check` passes;
6. net8/net10 API equivalence passes;
7. package verification passes, including XML documentation;
8. fresh-package smoke passes on both targets;
9. the package shape is accepted as the final 1.0 shape;
10. no production runtime API or behavior was expanded.

T45 owns only the final version transition and completion evidence once these
gates are satisfied.
