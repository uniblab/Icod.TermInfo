# Icod.TermInfo 1.3.0 I05 — Source-aware comparison

**Development version:** `1.3.0-Alpha-5`

I05 adds deterministic, machine-readable comparison for the unresolved Source
1.1 model without flattening it into `TerminalDescription` first.

## Public API

I05 adds:

```csharp
TermInfoComparisonResult TermInfoSourceComparer.Compare(
    TermInfoSourceEntry left,
    TermInfoSourceEntry right
);

TermInfoComparisonResult TermInfoSourceComparer.Compare(
    TermInfoSourceDocument left,
    TermInfoSourceDocument right
);
```

The I04 `TermInfoComparisonResult`, `TermInfoDifference`, and
`TermInfoDifferenceKind` types remain the common result envelope. I05 extends
that model with source-specific difference kinds and immutable Source context
rather than introducing a second parallel result hierarchy.

## Comparison domain

Source-aware comparison observes:

- canonical name, ordered aliases, and description;
- document entry order;
- local field order;
- duplicate local fields;
- Boolean, numeric, and string declaration kinds;
- cancellation;
- disabled fields;
- `use=` references;
- decoded local numeric/string values;
- retained source entry/field spans for actual differences.

It does not compare:

- comments;
- incidental whitespace;
- source spans by themselves;
- equivalent lexical spellings of successfully decoded values;
- information which Source 1.1 did not retain structurally.

For standard capability aliases, the comparer uses the canonical capability
identity when Source classification supplied one. Successfully decoded numeric
and string values are compared semantically. If both sides contain malformed
numeric/string fields whose decoded value is unavailable, their retained field
text is used so two different malformed fields are not silently declared equal.

## Ordered field contract

Fields are compared positionally. This is deliberate: source declaration order
can affect inheritance, cancellation, and duplicate-field semantics. Reordering
fields is therefore observable rather than normalized away.

Source-specific difference categories are:

```text
SourceEntryOnlyInLeft
SourceEntryOnlyInRight
SourceFieldOnlyInLeft
SourceFieldOnlyInRight
SourceFieldKind
SourceFieldCapability
SourceFieldValue
SourceUseReference
```

`SourceFieldKind` covers state changes such as present versus cancelled or
present versus disabled. The attached left/right `TermInfoSourceField` values
make the exact states machine-readable.

## Source context on differences

`TermInfoDifference` now exposes source-aware context when applicable:

```text
IsSourceDifference
LeftSourceEntry / RightSourceEntry
LeftSourceEntryIndex / RightSourceEntryIndex
LeftSourceField / RightSourceField
LeftSourceFieldIndex / RightSourceFieldIndex
LeftSourceSpan / RightSourceSpan
```

The entry indexes are populated for document comparison. Field indexes are
populated for field differences. The span properties return field spans for
field differences and entry spans for entry/identity differences; the missing
side of a one-sided difference has no synthetic span.

Effective I04 differences leave all source-context properties null and retain
their existing capability/identity representation.

## Effective versus source-aware semantics

I05 explicitly tests the 1.3 invariant that these are different questions:

```text
source comparison:    DIFFERENT
effective comparison: EQUAL
```

For example, a child entry may set a local capability before `use=base` in one
source program and after `use=base` in another while both resolve to the same
effective value. `TermInfoSourceComparer` reports the ordered source-program
difference; `TerminalDescriptionComparer` reports the resolved descriptions as
equal.

## Determinism and reversal

Comparison order is deterministic:

1. entry identity metadata;
2. fields in source order;
3. document entries in document order.

Reversing the operands swaps the source sides and reverses only the one-sided
entry/field categories. Symmetric metadata, field-kind, field-value, capability,
and `use=` differences retain their category.

## Package and compatibility boundary

All four packages advance together to `1.3.0-Alpha-5` while retaining
`AssemblyVersion` `1.0.0.0`.

I05 does not change the frozen Runtime 1.0, Source 1.1, or Compiler 1.2 public
API contracts. `Icod.TermInfo.Inspection` continues to depend only on Runtime
and Source in production.

## Gate

I05 is complete when callers can choose either effective or source-aware
comparison and receive a deterministic structured result appropriate to that
domain, with paired tests demonstrating source-different/effective-equal cases.
