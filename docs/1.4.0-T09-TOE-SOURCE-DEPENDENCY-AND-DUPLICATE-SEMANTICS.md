# Icod.TermInfo 1.4.0 — T09 `toe` Source Dependency and Duplicate Semantics

**Development version:** `1.4.0-Alpha-9`
**Tranche:** T09
**Command:** `toe`
**Status:** implementation candidate
**Reusable public API change:** none

---

## 1. Objective

T09 completes the planned 1.4 `toe` behavior by adding terminfo source
`use=` dependency reports and optional semantic duplicate analysis to the T08
conventional database listing command.

The tranche composes existing reusable engines rather than moving policy into
the library layers:

```text
-u / -U source file
        |
        v
Icod.TermInfo.Source parser
        |
        +--> unresolved use= fields in source order
        |
        v
Icod.TermInfo.Source resolver
        |
        +--> alias lookup, missing-parent and cycle diagnostics

-a -s database listing
        |
        v
T03 parsed TerminalDescription catalog entries
        |
        v
TerminalDescriptionComparer
        |
        v
Icod-defined semantic duplicate marker
```

## 2. Source dependency modes

The new standalone forms are:

```text
toe -u file
toe -U file
```

They are deliberately separate from database-listing options and directory
operands. Combining `-u` or `-U` with listing arguments is a usage error.

T09 accepts terminfo source only. It does not add termcap `tc=` analysis,
source rewriting, relative `use=` synthesis, or another database backend.

## 3. Forward dependency report

`-u` emits one edge per distinct parent reference of each source entry:

```text
child<TAB>parent
```

Entries are visited in source document order. Within each entry, `use=` fields
retain their source order. Repeated references to the same effective parent are
reported once at their first position.

Source aliases participate in lookup through the same first-match semantics as
the Source resolver. A reference through an alias is presented using the
resolved parent's canonical source identity.

If a referenced parent is missing, its literal reference name remains visible
in forward output so the report does not conceal the broken edge.

## 4. Reverse dependency report

`-U` constructs the complete identity map and dependency edge set only after the
complete source document has been parsed. Forward references and aliases which
are declared later in the file therefore resolve normally.

Reverse output is:

```text
parent<TAB>child
```

Parents are visited in source document order. Their children retain the
original edge order derived from source traversal. This is deterministic and
source-aware without introducing an unrelated culture-sensitive sort.

A missing parent has no source identity to own a reverse group, so the resolver
diagnostic is emitted but no synthetic reverse node is invented.

## 5. Source validation and diagnostics

After parsing succeeds, T09 resolves every canonical source entry through
`TermInfoSourceResolver`. This reuses the frozen Source behavior for:

- canonical and alias identity lookup;
- missing parents;
- direct and indirect inheritance cycles;
- inheritance-depth limits;
- malformed `use=` references.

Resolver diagnostics which recur while validating multiple roots are
deduplicated by stable diagnostic identity. Parser warnings remain warnings and
do not force failure. Any Source error causes exit status 1.

Safely parsed dependency edges are emitted even when later graph validation
finds a missing parent or cycle. This gives callers the graph evidence needed to
repair the source while still reporting failure accurately.

Input is read as strict UTF-8 with BOM stripping matching the managed `tic`
source path. Input/open/decoding failures use command-private code `TOE0006`.

## 6. Duplicate semantic analysis

T08 deliberately preserved duplicate canonical names across roots. T09 adds an
optional semantic marker when both `-a` and `-s` are active.

For each canonical name, the first database occurrence is the reference. The
first occurrence in each later root is compared with:

```csharp
TerminalDescriptionComparer.Compare(
    first.Terminal,
    current.Terminal
).AreEqual
```

The result is emitted as one of:

```text
# Icod duplicate <name>: semantically equal to <first-root>
# Icod duplicate <name>: semantically different from <first-root>
```

The `Icod` prefix is intentional: this is an Icod-defined presentation marker,
not a claim of exact ncurses `toe` formatting. Compiled bytes are never used as
the equality criterion.

Ordinary T08 listing output is unchanged unless both `-a` and `-s` request this
analysis.

## 7. Dependencies and API boundary

Production dependencies become explicit as:

```text
toe
    -> Icod.CommandFramework
    -> Icod.TermInfo.Source
        -> Icod.TermInfo
    -> Icod.TermInfo.Inspection
        -> Icod.TermInfo.Source
        -> Icod.TermInfo
```

No production Compiler dependency is added. Compiler remains test-only for
private compiled-database fixtures.

T09 adds no public member to Runtime, Source, Compiler, or Inspection. The
reviewed 1.4 Inspection public API baseline therefore remains unchanged.

All reusable library assemblies retain `AssemblyVersion 1.0.0.0`.

## 8. Validation coverage

T09 tests cover:

- no-dependency source;
- forward dependencies;
- multiple parents and source order;
- alias references resolving to canonical identities;
- reverse dependencies built from the complete document;
- deterministic source-aware reverse ordering;
- duplicate source identities with first-match alias behavior;
- missing-parent diagnostics with safe forward output;
- malformed source diagnostics;
- inheritance-cycle diagnostics with safe edge output;
- source/listing option separation;
- same-name compiled terminals in two roots;
- semantic equality through `TerminalDescriptionComparer`;
- semantic difference through `TerminalDescriptionComparer`;
- cancellation before source analysis;
- help/version coordination.

The existing T08 suite continues to cover conventional database enumeration,
filesystem safety, malformed/oversized entries, and stable listing order.
