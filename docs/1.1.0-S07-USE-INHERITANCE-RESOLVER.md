# Icod.TermInfo 1.1.0 S07 — `use=` Inheritance Resolver

**Development version:** `1.1.0-Alpha-7`
**Assembly version:** `1.0.0.0`
**Status:** implementation complete — validation pending
**Next tranche:** S08 — `TerminalDescription` materialization

## Purpose

S07 turns the unresolved, classified source entries from S04-S06 into a
recursively resolved source semantic result. It implements the `use=` graph
without changing the frozen `Icod.TermInfo` 1.0 runtime API and without yet
materializing a `TerminalDescription`.

The resolver builds directly on the S06 capability state, including its
cancellation tombstones. No second inheritance or cancellation model is
introduced.

## Public resolver surface

S07 introduces a deliberately small reviewed Source API:

- `ITermInfoSourceEntryProvider` — caller-supplied unresolved-entry acquisition;
- `TermInfoSourceResolverOptions` — bounded inheritance-depth policy;
- `TermInfoSourceResolver` — document and provider based resolution entry points;
- `TermInfoSourceResolveResult` — deterministic diagnostics plus an all-or-nothing
  resolved result;
- `TermInfoSourceResolvedEntry` — resolved capability queries while retaining the
  root `TermInfoSourceEntry`.

`TermInfoSourceResolvedEntry` intentionally does not expose source cancellation
tombstones and does not create a `TerminalDescription`. S08 owns conversion to
the stable runtime model.

## Source-entry provider contract

`ITermInfoSourceEntryProvider` follows the clean-miss versus failure convention
already used by `ITerminalDescriptionProvider`:

- returning `false` is a clean miss and requires a null entry;
- returning `true` requires a non-null entry;
- acquisition failures are reported by throwing and are not rewritten as
  missing-parent diagnostics.

The provider lookup key may be either a canonical source name or an alias. The
built-in document adapter scans `TermInfoSourceDocument.Entries` in source order,
uses ordinal case-sensitive comparison, and returns the first canonical or alias
match. Duplicate-name and duplicate-alias diagnostics remain S09 work; choosing
the first source-order match keeps S07 deterministic in their presence.

## Authoritative precedence

The adopted terminfo rule is:

1. explicit capabilities in the child outrank inherited capabilities;
2. multiple `use=` references are processed from right to left;
3. as resolution moves leftward, the newly reached parent overlays the parent
   aggregate built from parents to its right;
4. the finished parent aggregate is inherited beneath the child's local state.

This uses the S06 operations directly:

```text
parents = empty

for each use= from rightmost to leftmost:
    parents.OverlayHigherPriority(resolvedParent)

local = CreateLocal(child)
local.Inherit(parents)
```

Consequently, the leftward parent wins parent-to-parent collisions, while an
explicit child value or cancellation wins over every parent.

This matches the documented ncurses/System V compatible `use=` merge rule and
the differential `tic`/`infocmp` checks used while designing S06/S07.

## Cancellation through inheritance

S07 preserves the S06 tombstones during all source-to-source parent merges.
This is necessary because a resolved source parent can distinguish:

```text
capability absent
```

from:

```text
capability explicitly cancelled
```

whereas a compiled `TerminalDescription` cannot reconstruct that provenance.

Standard short and long names already converge on the same runtime capability
enum identity through S05, so a cancellation written with a long name suppresses
the equivalent short-name value after inheritance. Extended capability names
remain ordinal and case-sensitive.

## Recursive resolution

Resolution proceeds by canonical source identity after provider lookup:

1. load the requested canonical name or alias;
2. normalize graph identity to the returned entry's `CanonicalName`;
3. reject a canonical identity already active on the current recursion path;
4. build the entry's local S06 state;
5. recursively resolve `use=` parents from right to left;
6. compose the parent aggregate using S06 priority overlays;
7. inherit the aggregate beneath local state;
8. cache a clone of the successful state for the same canonical identity and
   graph depth.

Caching includes graph depth deliberately. A state successfully resolved at a
shallower depth is not blindly reused at a deeper depth where the same subtree
could exceed `MaximumInheritanceDepth`.

Cached and returned semantic states are cloned so one resolution branch cannot
mutate state shared with another branch.

## Cycle detection

Cycle detection uses the returned canonical entry name, not the spelling of the
incoming reference. This catches both ordinary cycles and alias-mediated cycles,
for example:

```text
self|self-alias,
    use=self-alias,
```

The cycle diagnostic includes the canonical path, such as:

```text
a -> b -> c -> a
```

Direct and indirect cycles are both deterministic failures and do not expose a
partial resolved entry.

## Inheritance-depth limit

`TermInfoSourceResolverOptions` defines:

```text
DefaultMaximumInheritanceDepth = 64
MaximumSupportedInheritanceDepth = 256
```

Depth counts `use=` edges from the requested root:

- the requested root is depth 0;
- its direct parent is depth 1;
- a grandparent is depth 2;
- and so on.

A limit of zero therefore permits an entry with no `use=` references but rejects
its first attempted parent edge. The hard upper bound prevents callers from
accidentally configuring effectively unbounded recursion.

## Diagnostics

S07 adds:

| Code | Meaning |
|---|---|
| `TIS0022` | requested root or `use=` source entry is missing |
| `TIS0023` | direct or indirect inheritance cycle |
| `TIS0024` | configured maximum inheritance depth exceeded |

Malformed empty `use=` fields continue to use the existing `TIS0007` diagnostic.

Resolver diagnostics are ordered deterministically by source identity, source
offset, span length, and discovery ordinal. A failed graph yields diagnostics but
no partial `TermInfoSourceResolvedEntry`.

Parser diagnostics are intentionally not copied into the resolver result because
the resolver accepts a `TermInfoSourceDocument` or provider rather than a
`TermInfoSourceParseResult`. Callers should reject or otherwise handle parser
errors before invoking S07 resolution.

## Determinism

S07 does not enumerate caller provider storage or rely on dictionary iteration
order. Semantic order derives from:

- source entry order for the document adapter;
- source field order for `use=` declarations;
- explicit right-to-left parent traversal;
- canonical-name recursion identity;
- deterministic diagnostic sorting.

Tests exercise the same graph through providers populated in opposite dictionary
insertion orders and require equivalent resolved semantics.

## Public API boundary

The runtime package remains unchanged except for coordinated package/product
version metadata. In particular:

```text
Icod.TermInfo.Source -> Icod.TermInfo
```

remains one-way. `Icod.TermInfo` does not reference Source.

The public S07 API is additive to `Icod.TermInfo.Source`; the frozen
`docs/1.0.0-PUBLIC-API-BASELINE.txt` runtime contract remains unchanged.

## S07 gate

S07 is ready for completion when:

- direct, recursive, alias, and multiple-parent inheritance resolve correctly;
- explicit child values and cancellations retain priority;
- standard and extended cancellation tombstones survive parent composition;
- missing roots and parents produce `TIS0022`;
- direct and indirect cycles produce `TIS0023`;
- configured depth boundaries produce `TIS0024`;
- caller-supplied providers work across separately parsed documents;
- provider failures propagate rather than becoming clean misses;
- repeated resolution is deterministic and independent of provider dictionary
  insertion order;
- net8.0 and net10.0 Source public APIs remain equivalent;
- the reviewed Source API snapshot, package validation, and fresh-package smoke
  tests pass.

S08 can then consume the internal resolved capability state to create the stable
`TerminalDescription` representation without carrying `use=` or cancellation
provenance into the runtime model.
