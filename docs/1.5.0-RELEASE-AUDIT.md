# Icod.TermInfo 1.5.0 Release Audit

**Release version:** `1.5.0`
**Runtime assembly version:** `1.0.0.0`
**Source assembly version:** `1.0.0.0`
**Compiler assembly version:** `1.0.0.0`
**Inspection assembly version:** `1.0.0.0`
**Status:** Final release candidate — main Release validation and tag publication remain

## Purpose

Version 1.5.0 changes coordinated versioning and command distribution without
changing the frozen reusable-library APIs or the released 1.4 command semantics.

The release introduces one repository-level version authority and an installable
.NET tool router while retaining the six standalone command archives.

## Central version contract

`Directory.Build.props` SHALL declare exactly one coordinated release value:

```text
IcodTermInfoSuiteVersion = 1.5.0
```

The four reusable libraries SHALL consume it for `Version` and
`PackageVersion`. `tic`, `infocmp`, and `toe` SHALL consume it for `Version`.
`Icod.TermInfo.Router` SHALL consume it for both `Version` and `PackageVersion`.

No coordinated project SHALL introduce an independent current-release version
literal.

The four reusable assemblies SHALL retain `AssemblyVersion` `1.0.0.0`.

## Frozen reusable-library contract

The release SHALL preserve unchanged:

- `docs/1.0.0-PUBLIC-API-BASELINE.txt`;
- `docs/1.1.0-SOURCE-PUBLIC-API-BASELINE.txt`;
- `docs/1.2.0-COMPILER-PUBLIC-API-BASELINE.txt`;
- `docs/1.3.0-INSPECTION-PUBLIC-API-BASELINE.txt`;
- `docs/1.4.0-INSPECTION-PUBLIC-API-BASELINE.txt`;
- exact net8/net9/net10 API equivalence for all four reusable libraries;
- Runtime dependency-free;
- Source depending only on Runtime;
- Compiler depending on Runtime and Source;
- Inspection depending on Runtime and Source and not on Compiler.

No 1.5 public-API baseline is created by this distribution release.

## Standalone command contract

`tic`, `infocmp`, and `toe` SHALL retain the frozen 1.4 semantic and CLI
contracts. They remain:

- `net10.0`;
- non-packable;
- directly executable under the traditional command names;
- mutually independent, with no command-to-command project references;
- distributed together in the six framework-dependent release archives.

The archives remain intentionally user-installed. The user controls extraction
and `PATH` placement of the traditional names.

## Router contract

`icod-terminfo/Icod.TermInfo.Router.csproj` SHALL:

- target `net10.0`;
- use package ID `Icod.TermInfo.Tools`;
- set `PackAsTool` to `true`;
- expose `ToolCommandName` `icod-terminfo`;
- carry the centralized suite `Version` and `PackageVersion`;
- reference `tic`, `infocmp`, and `toe`;
- contain no terminfo semantic engine or command-specific option parser.

The router SHALL support:

```text
icod-terminfo --help
icod-terminfo --version
icod-terminfo tic ...
icod-terminfo infocmp ...
icod-terminfo toe ...
```

Dispatch SHALL be in-process through the existing command `RunAsync` entry
points, preserve caller-owned streams and cancellation, and return the selected
command's exit status.

For router-package composition, the three command project references SHALL build
with `UseAppHost=false`. `Icod.TermInfo.Tools` SHALL contain the managed command
assemblies needed for in-process dispatch but SHALL NOT contain host-specific
`tic`, `infocmp`, or `toe` apphosts under `tools/net10.0/any/`.

The standalone archive builder SHALL continue to request `UseAppHost=true`
explicitly for each RID-specific traditional command distribution.

The Router -> command dependency is a distribution-only exception to the
command-independence rule. `tic`, `infocmp`, and `toe` remain forbidden from
referencing one another.

## Registry artifact contract

The coordinated registry set contains:

```text
Icod.TermInfo
Icod.TermInfo.Source
Icod.TermInfo.Compiler
Icod.TermInfo.Inspection
Icod.TermInfo.Tools
```

The four reusable libraries continue to produce both `.nupkg` and `.snupkg`
artifacts. The router produces its `.nupkg` tool package.

The release therefore contains nine package artifacts:

```text
5 .nupkg
4 .snupkg
```

The `Icod.TermInfo.Tools` `.nupkg` SHALL pass an independent structural verifier
which validates its DotnetTool metadata, single router command, managed payload,
repository metadata, and absence of host-specific command apphosts.

## Archive artifact contract

The six framework-dependent standalone archives remain:

```text
Icod.TermInfo.Tools.1.5.0.win-x64.zip
Icod.TermInfo.Tools.1.5.0.win-arm64.zip
Icod.TermInfo.Tools.1.5.0.linux-x64.tar.gz
Icod.TermInfo.Tools.1.5.0.linux-arm64.tar.gz
Icod.TermInfo.Tools.1.5.0.osx-x64.tar.gz
Icod.TermInfo.Tools.1.5.0.osx-arm64.tar.gz
```

They contain standalone `tic`, `infocmp`, and `toe`; they do not need to contain
the `icod-terminfo` router.

Together, nine package artifacts plus six archives yield fifteen checksummed
artifacts. `SHA256SUMS.txt` is the sixteenth GitHub Release asset.

## Dual execution gates

Both command distributions SHALL execute successfully before publication.

### Standalone archive smoke

On matching Windows, Linux, and macOS runners, CI SHALL unpack the appropriate
archive and:

1. verify `tic`, `infocmp`, and `toe` report `1.5.0`;
2. publish a controlled entry with `tic`;
3. acquire it with `infocmp`;
4. enumerate it with `toe`.

### Installable router smoke

On Windows, Linux, and macOS runners, CI SHALL install the freshly packed
`Icod.TermInfo.Tools.1.5.0.nupkg` into an isolated tool path and:

1. require `icod-terminfo --version` to report `1.5.0`;
2. require routed `tic -V`, `infocmp -V`, and `toe -V` to report `1.5.0`;
3. publish the same controlled entry through `icod-terminfo tic`;
4. acquire it through `icod-terminfo infocmp`;
5. enumerate it through `icod-terminfo toe`.

The install smoke SHALL resolve the router package from the freshly produced
local artifact, not a previously published registry copy.

## Required final validation

Before tag creation, the exact 1.5.0 release-finalization commit SHALL pass:

- Release restore/build/test on Windows, Linux, and macOS;
- all four frozen library API baselines;
- net8/net9/net10 API equivalence;
- all four reusable-library package verifiers/consumers;
- Router unit and contract tests;
- `Icod.TermInfo.Tools` structural package verification;
- construction and structural verification of all six standalone archives;
- matching-host standalone archive smoke;
- matching-host `Icod.TermInfo.Tools` installation/routing smoke.

## Publication gate

Tag `v1.5.0` SHALL:

1. identify the exact validated commit which is still the current `main` HEAD
   when the tag workflow starts;
2. match `IcodTermInfoSuiteVersion` exactly;
3. repeat the complete Release validation;
4. publish all five `.nupkg` files to NuGet.org;
5. publish the same five `.nupkg` files to GitHub Packages;
6. create the GitHub Release with five `.nupkg`, four `.snupkg`, six archives,
   and `SHA256SUMS.txt`.

NuGet trusted publishing must authorize all five package IDs, including
`Icod.TermInfo.Tools`, before the tag is pushed.

## Final sign-off

The release is complete only when:

- the `v1.5.0` workflow succeeds;
- all five version 1.5.0 package IDs are visible on NuGet.org;
- all five are visible in GitHub Packages;
- the GitHub Release contains exactly sixteen expected assets;
- fresh consumers restore all four reusable libraries;
- `Icod.TermInfo.Tools` installs and routes all three commands;
- all six standalone archives remain downloadable and checksummed;
- `v1.5.0` identifies the exact validated release commit.

Do not move or recreate a published release tag. Any later package, archive,
source, documentation, command-contract, or API-baseline change requires a new
version and a new validated immutable tag.
