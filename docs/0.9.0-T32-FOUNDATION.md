# Icod.TermInfo 0.9.0 — T32 Foundation and Acquisition API Freeze

**Tranche:** T32 — 0.9 Foundation and Acquisition API Freeze
**Development version:** `0.9.0-alpha.1`
**Previous release contract:** `0.8.0` — complete and frozen
**Next implementation tranche:** T33 — legacy `0432` compiled parser

---

## Purpose

T32 converts the 0.9 roadmap from a planned reservation into an implementation
contract. It freezes the public ownership model, diagnostics vocabulary,
resource bounds, environment-snapshot policy, and provider lifetime semantics
before production binary parsing or filesystem discovery begins.

T32 deliberately does **not** implement a compiled parser or an I/O-backed
provider. Those implementations remain assigned to T33 through T39.

The dependency chain is frozen as:

```text
caller-supplied compiled bytes
        |
        v
pure compiled-entry parser
        |
        v
TerminalDescription
        |
        +------------------------------+
        |                              |
        v                              v
explicit directory provider      system provider
                                       |
                                       v
                           environment/user/default roots
```

Every acquisition path ultimately feeds the same pure parser.

## 0.8 compatibility floor

The complete public and behavioral 0.8 contract remains the compatibility floor
for 0.9.

T32 does not add a production parser/provider public type, so the T30 exact
exported-type baseline and T29 no-production-parser guard remain valid during
this tranche.

Two historical tests had asserted that the *current* assembly itself was
exactly version 0.8. Those assertions are release-line evidence rather than
forward compatibility guarantees and are removed when the project version
advances to `0.9.0-alpha.1`. Their substantive 0.8 semantic tests remain.

No 0.8 capability enum value, built-in identity, provider clean-miss contract,
parameter behavior, output behavior, Windows profile, or immutable-description
semantic is changed by T32.

## Pure parser API freeze

T33 SHALL introduce the following public concepts with this ownership shape:

```csharp
namespace Icod.TermInfo;

public sealed class CompiledTermInfoParserOptions
{
    public const int DefaultMaximumEntrySize = 1_048_576;
    public const int MaximumSupportedEntrySize = 16_777_216;

    public CompiledTermInfoParserOptions(
        int maximumEntrySize = DefaultMaximumEntrySize);

    public int MaximumEntrySize { get; }
}

public static class CompiledTermInfoParser
{
    public static TerminalDescription Parse(
        ReadOnlySpan<byte> entry,
        CompiledTermInfoParserOptions? options = null);
}
```

The parser is byte-oriented and pure:

- callers with `byte[]` use normal span conversion;
- providers read/decode bytes and call the same parser;
- the parser does not accept filesystem paths;
- the parser does not read environment variables;
- the parser does not own a cache;
- the parser does not inspect or modify terminal state;
- no native ncurses/libtinfo call is permitted;
- no mutable parser instance is required.

A future overload may be considered only if demonstrated by real usage. T32
does not reserve stream/path overloads merely for API symmetry.

## Parser resource policy

The default maximum compiled-entry size is frozen at:

```text
1 MiB = 1,048,576 bytes
```

The largest configurable limit accepted by the 0.9 parser is frozen at:

```text
16 MiB = 16,777,216 bytes
```

The default is intentionally generous relative to ordinary compiled entries
while still bounding untrusted input. The absolute ceiling prevents a caller
option from accidentally disabling the resource guarantee entirely.

Rules:

1. entry length is checked before parsing or input-derived allocation;
2. all count/length/offset arithmetic is overflow-safe;
3. input-derived collections are not allocated until the corresponding byte
   relationship has been proven possible;
4. names and strings remain bounded by validated containing sections;
5. malformed input yields no partial `TerminalDescription`.

The limits are parser policy, not claims about a particular ncurses writer.

## Compiled-format exception freeze

`TermInfoFormatException` remains exclusively the malformed
parameter-program-syntax exception.

T33 SHALL introduce a distinct:

```text
CompiledTermInfoFormatException
```

derived from `FormatException`.

The public exception SHALL support the normal public constructors:

```csharp
CompiledTermInfoFormatException()
CompiledTermInfoFormatException(string? message)
CompiledTermInfoFormatException(
    string? message,
    Exception? innerException)
```

and read-only diagnostics:

```csharp
int Offset
string? Section
```

`Offset == -1` means that no byte offset was supplied. `Section == null` means
that no stable section label was supplied.

Parser-internal constructors may attach an offset and stable section name.
Provider code SHALL allow this exception to propagate rather than translate it
into a clean miss.

Unsupported compiled magic/layout is also a compiled-format error unless a
later tranche freezes a narrower dedicated subtype. 0.9 does not add a broad
provider catch-all exception.

## Explicit directory provider freeze

T36 SHALL introduce one caller-owned-root provider with conceptual public shape:

```csharp
public sealed class DirectoryTerminalDescriptionProvider
    : ITerminalDescriptionProvider
{
    public DirectoryTerminalDescriptionProvider(
        string root,
        CompiledTermInfoParserOptions? parserOptions = null);

    public string Root { get; }

    public bool TryLoad(
        string name,
        out TerminalDescription? terminal);
}
```

The actual `out` parameter retains the existing
`[NotNullWhen(true)]` provider contract.

Construction:

- validates and canonicalizes the supplied root;
- does not inspect `TERMINFO`, `TERMINFO_DIRS`, `HOME`, or system defaults;
- snapshots parser options;
- creates a provider-local successful-entry cache.

Lookup:

- validates terminal names before path construction;
- checks only the conventional literal/hex first-character candidates frozen by
  T36;
- sends candidate bytes through `CompiledTermInfoParser`;
- verifies parsed canonical-name/alias identity against the requested name;
- returns `false` only for a genuine absent entry;
- propagates permission, I/O, malformed-data, and unsupported-format failures.

No recursive database scan is part of exact-name lookup.

## System provider and option ownership freeze

T37/T38 SHALL introduce immutable system-discovery options with conceptual
public shape:

```csharp
public sealed class SystemTerminalDescriptionProviderOptions
{
    public SystemTerminalDescriptionProviderOptions(
        bool useEnvironment = true,
        bool useUserDatabase = true,
        bool useSystemDatabases = true,
        CompiledTermInfoParserOptions? parserOptions = null);

    public bool UseEnvironment { get; }
    public bool UseUserDatabase { get; }
    public bool UseSystemDatabases { get; }
    public CompiledTermInfoParserOptions ParserOptions { get; }
}

public sealed class SystemTerminalDescriptionProvider
    : ITerminalDescriptionProvider
{
    public SystemTerminalDescriptionProvider(
        SystemTerminalDescriptionProviderOptions? options = null);

    public bool TryLoad(
        string name,
        out TerminalDescription? terminal);
}
```

The options express trust/search policy. They do not expose mutable search
lists, cache dictionaries, environment abstractions, or global registries.

Explicit application roots remain the job of
`DirectoryTerminalDescriptionProvider`; they are not smuggled into system
options merely as another mutable path list.

## Environment snapshot freeze

The public system-provider constructor snapshots all environment inputs it is
permitted to use.

The snapshot includes, as applicable:

- `TERMINFO`;
- `TERMINFO_DIRS`;
- home-directory information needed for the user database;
- platform identity needed to choose deterministic default roots.

After construction, changing process environment variables does not silently
change that provider instance's search policy.

Deterministic tests SHALL use an internal environment-snapshot abstraction or
internal constructor. The environment abstraction is not public API.

This gives callers a stable rule:

```text
new provider instance
    -> new environment/search snapshot
existing provider instance
    -> stable snapshot
```

## Cache and refresh freeze

Caching belongs to I/O-backed provider instances, never to the pure parser and
never to process-global state.

The 0.9 default policy is:

- cache successful immutable descriptions per provider instance;
- make first-load/cache publication thread-safe;
- do not permanently negative-cache ordinary misses;
- do not cache parser/I/O failures as misses;
- do not share arbitrary host entries between separately configured providers.

The ordinary refresh operation is constructing a new provider instance.

T39 does not need to add:

- filesystem watchers;
- TTL timers;
- asynchronous refresh threads;
- process-global invalidation;
- a mandatory public `ClearCache()` API.

If a later explicit refresh member proves useful, it must preserve these
lifetime and concurrency semantics.

## Provider composition freeze

`TerminalDatabase` remains the only provider-composition mechanism.

The following remain explicit caller choices:

```text
built-ins only
system only
system -> built-ins
application provider -> system -> built-ins
```

`TerminalDatabase.BuiltIn` SHALL remain deterministic, dependency-free,
environment-independent, and I/O-free.

It SHALL NOT begin consulting the system provider in 0.9.

## Clean miss and failure boundary

The T29 rule remains unchanged:

```text
entry absent
    -> TryLoad == false

permission denied
I/O failure
invalid encoded TERMINFO
malformed compiled entry
unsupported compiled layout
internal parser failure
    -> exception/error, not false
```

This preserves useful first-provider-wins composition without inventing a
second provider result model.

## T32 non-goals

T32 authorizes none of the following:

- production parsing before T33;
- directory loading before T36;
- environment/system discovery before T37/T38;
- filesystem caching implementation before the owning provider tranche;
- `.ti` source parsing or `use=` resolution;
- `tic`/`infocmp`-class product tooling;
- termcap/`TERMCAP`/`TERMPATH`;
- Berkeley-DB hashed terminfo stores;
- native ncurses/libtinfo dependencies;
- live terminal input/session ownership;
- active probing;
- PTY/ConPTY;
- curses/virtual-screen behavior;
- terminal emulation;
- graphics protocols.

Those remain governed by the 0.9 roadmap and
`docs/FUTURE-WORK-INVENTORY.md`.

## T32 implementation-state rule

Because T32 is an API/ownership freeze rather than an implementation tranche,
it SHALL NOT add public placeholder parser/provider classes whose only behavior
is `NotSupportedException` or a false clean miss.

A public acquisition type should appear in the production assembly only when
its owning tranche implements its contracted behavior.

Therefore:

```text
T32
    contract only

T33
    CompiledTermInfoParserOptions
    CompiledTermInfoParser
    CompiledTermInfoFormatException
    legacy parser implementation

T36
    DirectoryTerminalDescriptionProvider

T37/T38
    SystemTerminalDescriptionProviderOptions
    SystemTerminalDescriptionProvider

T39
    final provider cache/composition hardening
```
