# Icod.TermInfo 0.6.0 Contract Audit

This document maps the T10 completion gate to concrete repository evidence for the final `0.6.0` release commit.

The release commit is intentionally versioned `0.6.0` before the tag is created. Publication remains tag-driven: nothing is published until the normal `main` workflow is green and `v0.6.0` is pushed.

## Automated T10 evidence

| T10 check | Repository evidence |
| --- | --- |
| Windows/Linux/macOS CI passes | `.github/workflows/build.yml` runs Debug and Release build/test on `windows-latest`, `ubuntu-latest`, and `macos-latest`. |
| Debug and Release tests pass | The same three-OS matrix runs both configurations. |
| Package validation passes | `EnablePackageValidation` is enabled and the package job executes `dotnet pack`. |
| Public API baseline is clean | `PublicApiSurfaceTests` freezes the exported type set and compatibility facade surface. |
| Package installs into a fresh sample project | `.github/scripts/verify-release-package.sh` creates a temporary `net10.0` application, clears all NuGet sources except the freshly packed artifact directory, restores, builds, and runs it. |
| No runtime package dependency | The verifier rejects nuspec `<dependency>` entries, and the local-only fresh-consumer restore would fail if an external runtime package were required. |
| No native ncurses dependency/payload | `CompletionGateTests` limits native imports to `kernel32.dll` and `libc`; the package verifier rejects runtime/native payload directories and unexpected DLL/native-library files. |
| ANSI behavior is golden-tested | `AnsiTerminalProfileTests` enumerates the advertised ANSI capability contract and T10 reasserts the eight-color boundary. |
| VT100 behavior is golden-tested | `Vt100TerminalProfileTests` enumerates the advertised VT100 capability contract and T10 reasserts that color is absent. |
| dumb behavior is golden-tested | `DumbTerminalProfileTests` covers the safe fallback profile. |
| Unknown terminal names remain unknown | Profile/environment tests plus `CompletionGateTests` reject modern terminal-family aliases not built into 0.6.0. |
| Live size remains distinct from profile size | `TerminalEnvironmentTests` covers live, configured, and profile size APIs separately. |
| Windows VT changes remain explicit | `WindowsVirtualTerminalTests` covers opt-in enablement, redirection, flag preservation, and restoration. |
| Parameter expansion has no terminal-specific implementation | T2 tests exercise ANSI-style programs through the generic parser/evaluator; the T10 verifier also rejects direct ANSI/VT100 profile references from `src/Parameterization`. |
| Padding is stripped or processed | T5 output tests cover ignore/delay modes; T10 runs every built-in capability string through ignore-mode padding removal. |
| Symbols and Source Link are present | The package verifier requires a portable PDB in the `.snupkg`, repository URL+commit metadata in the nuspec, and the matching GitHub Source Link URL/commit bytes in the PDB. |
| NuGet/GitHub Packages artifacts are ready | The package verifier runs before artifact upload and before either publishing workflow can push a package. |
| README scope/non-goals match the contract | `README.md` states the exact built-ins, eight-color ANSI limit, VT100 monochrome behavior, explicit fallback, and excluded terminal/database/UI features. |

## Final human gate

After this commit is merged to `main`:

1. require the normal `build` workflow to finish successfully on all three operating systems, including the package job;
2. confirm the NuGet.org trusted-publishing policy described in `docs/RELEASING.md` is configured;
3. create and push `v0.6.0`;
4. require the tag-driven `release` workflow to complete successfully;
5. confirm `Icod.TermInfo` 0.6.0 and its symbols are visible on NuGet.org;
6. confirm the same `.nupkg` is visible in GitHub Packages and the GitHub Release contains both package artifacts.

When those steps pass, the T10 gate and the roadmap's 0.6.0 contract are complete.
