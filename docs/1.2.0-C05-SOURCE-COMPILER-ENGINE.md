# Icod.TermInfo 1.2.0 C05 — Source Compiler Engine

**Tranche:** C05
**Development version:** `1.2.0-Alpha-5`
**Runtime assembly identity:** `Icod.TermInfo, Version=1.0.0.0`
**Source assembly identity:** `Icod.TermInfo.Source, Version=1.0.0.0`
**Compiler assembly identity:** `Icod.TermInfo.Compiler, Version=1.0.0.0`
**Status:** implementation candidate; build/test/package validation required

## Purpose

C05 composes the completed 1.1 source-language pipeline with the C01-C04
compiled writer:

```text
.ti source
    |
    v
TermInfoSourceParser
    |
    v
TermInfoSourceResolver
    |
    v
TermInfoSourceResolvedEntry.ToTerminalDescription()
    |
    v
CompiledTermInfoWriter
    |
    v
compiled entry bytes
```

The Compiler package now directly references Source as well as Runtime.
Dependency direction remains:

```text
Compiler -> Source -> Runtime
Compiler ------------> Runtime
```

Runtime remains dependency-free and Source does not depend on Compiler.

## Public source compiler

C05 introduces:

```text
TermInfoSourceCompiler
TermInfoSourceCompilationResult
CompiledTermInfoSourceEntry
```

`TermInfoSourceCompiler.Compile` accepts either a complete source string or a
`TextReader`. Callers may pass the existing Source lexer and resolver options
and the existing C04 writer options.

No parallel Source option types or capability models are introduced.

## Multiple entries and dependency ordering

The parser first constructs the complete source document. Each source entry is
then resolved by canonical name against that complete document, so a `use=`
reference is independent of declaration order. A child may precede its parent
in the source file.

Successfully compiled entries are returned in source-document order. Each
`CompiledTermInfoSourceEntry` contains the canonical name, source aliases, and
a complete byte payload which can be parsed or stored independently.

The byte payload is defensively copied when exposed to callers.

## Diagnostics

C05 does not translate Source diagnostics into a second diagnostic model.
Parser and resolver diagnostics are retained as the original
`TermInfoSourceDiagnostic` instances and ordered deterministically by source
name, source offset, span length, then production order.

Consequently the complete 1.1 source location survives compilation:

```text
source name
line
column
offset
length
```

If parsing produces an error, semantic compilation does not proceed.
Resolution errors suppress only the affected entry; other independently
resolvable entries may still be returned together with the diagnostics.

## Writer failures

C05 deliberately preserves the C04 representation-failure contract.

Once Source has produced a valid `TerminalDescription`, inability to encode it
under the requested compiled representation remains an
`InvalidOperationException` from `CompiledTermInfoWriter`. C05 does not disguise
that representation error as a Source-language diagnostic.

## Cancellation semantics

Cancellation remains entirely a Source resolution concern. The resolved Source
entry materializes only effective values into `TerminalDescription`.

Accordingly C05 never attempts to reconstruct a source cancellation tombstone
in compiled output. A canceled inherited capability is simply absent from the
effective compiled entry.

## Package validation

The Compiler package verifier now requires matching Source and Runtime
dependencies for every target framework. The package smoke consumer compiles a
multi-entry source document using `use=` inheritance and reloads the child
through the runtime compiled parser.

All three coordinated package versions advance to `1.2.0-Alpha-5` while all
three assembly versions remain `1.0.0.0`.

## C05 gate

C05 is complete when a multi-entry source document with forward or backward
`use=` dependencies compiles deterministically into independently loadable
entries; source diagnostics retain their original locations; cancellation is
represented only through effective semantics; the reviewed Compiler API
baseline matches on net8.0/net9.0/net10.0; package verification and package
smoke consumers pass; and the Windows/Linux/macOS CI matrix is green.
