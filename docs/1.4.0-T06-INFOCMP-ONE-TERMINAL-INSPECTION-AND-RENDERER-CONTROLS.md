# Icod.TermInfo 1.4.0 T06 — infocmp One-Terminal Inspection and Renderer Controls

**Development version:** `1.4.0-Alpha-6`
**Baseline:** T05 complete managed `tic` validation/publication path
**Scope:** one-terminal `infocmp` acquisition, effective-source presentation, and reusable Inspection renderer controls
**Runtime public API change:** none
**Source public API change:** none
**Compiler public API change:** none
**Inspection public API change:** additive renderer controls only

## 1. Objective

T06 turns the `infocmp` shell into a complete one-terminal inspection utility.
The command acquires a compiled terminal description through the existing Runtime
provider model and renders that effective state through Inspection. Comparison is
intentionally deferred to T07 so acquisition and presentation can be validated
independently.

The tranche does not introduce a second parser, database reader, or semantic
model. `TerminalDescription` remains the single effective representation.

## 2. Operand contract

T06 supports:

```text
infocmp [options] [terminal]
infocmp -D
infocmp -V
infocmp --version
infocmp --help
```

Operand behavior is:

```text
0 terminal operands -> use TERM
1 terminal operand  -> inspect that exact name
2+ terminal operands -> usage error until T07
```

A missing or empty `TERM` in the zero-operand form is an operational failure,
not a usage error.

## 3. Acquisition contract

Without `-A`, `infocmp` constructs a normal `SystemTerminalDescriptionProvider`
and therefore consumes the Runtime discovery policy without reproducing it.

With:

```text
-A <directory>
```

`infocmp` constructs an explicit `DirectoryTerminalDescriptionProvider` rooted at
that directory. It does not rewrite `TERMINFO`, `TERMINFO_DIRS`, or any other
process environment variable.

Acquisition is composed through:

```text
TermInfoInspectionTarget
    -> TermInfoInspectionEngine.TryInspect
    -> TerminalDescription
```

A clean provider miss is distinguished from malformed compiled data and other
operational provider failures.

## 4. Effective-source rendering

Default one-terminal output is deterministic effective terminfo source. It does
not claim to reconstruct source-only information which is absent from
`TerminalDescription`, including:

- original comments;
- original whitespace;
- `use=` inheritance history;
- cancellation tombstones;
- disabled source fields;
- source provenance.

The command defaults to standard capabilities. `-x` includes effective extended
capabilities.

## 5. Additive Inspection renderer API

T06 adds:

```csharp
TerminalDescriptionSourceRendererOptions
TerminalDescriptionSourceLayout
TerminalDescriptionSourceCapabilityOrder
```

and overloads:

```csharp
TerminalDescriptionSourceRenderer.Render(
    TerminalDescription,
    TerminalDescriptionSourceRendererOptions
)

TerminalDescriptionSourceRenderer.Write(
    TextWriter,
    TerminalDescription,
    TerminalDescriptionSourceRendererOptions
)
```

The parameterless `TerminalDescriptionSourceRendererOptions` reproduces the
frozen 1.3 renderer policy:

```text
width                    80
layout                   canonical
standard ordering        compiled/database order
extended capabilities    included
```

The configurable renderer detects exactly that policy and routes directly
through the existing frozen rendering implementation. The existing one-argument
`Render` and two-argument `Write` overloads are unchanged.

The reviewed surface is recorded in:

```text
docs/1.4.0-INSPECTION-PUBLIC-API-BASELINE.txt
```

## 6. Presentation controls

T06 supports:

```text
-0          one logical source line, no wrapping
-1          header plus exactly one capability per physical line
-w <width>  canonical string-capability wrapping width
-s d        compiled/database order
-s i        terminfo short-name order
-s l        long/variable-name order
-s c        termcap-code order
-x          include effective extended capabilities
```

Ordering applies independently within the standard Boolean, numeric, and string
groups. Comparisons use `StringComparer.Ordinal`; culture never participates.
Ties fall back to stable metadata identity so output remains deterministic.

Extended capabilities retain their established deterministic grouping by value
kind and ordinal name. They are filtered as a presentation choice only; the
acquired `TerminalDescription` is never mutated.

`-w` is meaningful only for canonical layout in T06 and is rejected when combined
with `-0` or `-1`, rather than being silently accepted and ignored.

## 7. Database reporting

`infocmp -D` uses:

```csharp
TermInfoDatabaseInspector.GetSystemLocations()
```

and reports the same ordered Runtime discovery snapshot already used by `tic -D`.
No database is enumerated or modified.

## 8. Diagnostics and exit behavior

T06 adds controlled command diagnostics:

```text
INFOCMP0001  zero-operand TERM acquisition cannot be attempted
INFOCMP0002  requested terminal is a clean provider miss
INFOCMP0003  provider/database acquisition failure
INFOCMP0004  effective source cannot be rendered losslessly
INFOCMP0005  database-location discovery failure
```

Usage errors return the command-framework usage status. Operational failures
return failure. Cancellation returns the command-framework canceled status.
Differences are not yet part of T06; comparison output begins in T07.

## 9. Dependency boundary

Production remains:

```text
infocmp -> Icod.TermInfo.Inspection -> Icod.TermInfo.Source -> Icod.TermInfo
                              \---------------------------> Icod.TermInfo
```

`infocmp` does not acquire a production dependency on `Icod.TermInfo.Compiler`.
The `infocmp` test project may reference Compiler to publish deterministic private
database fixtures.

No Runtime, Source, or Compiler production API changes are required.

## 10. Validation matrix

T06 tests cover:

- zero-operand `TERM` fallback;
- missing `TERM`;
- explicit terminal name;
- alias acquisition;
- explicit `-A` database acquisition;
- clean missing entry;
- malformed compiled entry;
- `-0` single-line output;
- `-1` one-capability-per-line output;
- configurable wrapping boundaries;
- all four standard capability ordering keys;
- standard-only default and explicit `-x` extended output;
- culture-independent ordering;
- insertion-order-independent extended output;
- `-D` database reporting;
- two-operand deferral to T07;
- invalid presentation combinations;
- redirected/caller-owned streams;
- cancellation before acquisition;
- parameterless renderer options matching the frozen 1.3 renderer exactly;
- invalid renderer option values.

## 11. Gate T06

T06 is complete when managed `infocmp` can acquire and render one effective
terminal deterministically from the normal Runtime search model or an explicit
conventional database, all required presentation controls are functional, the
frozen renderer overloads are unchanged, and the additive Inspection API is
captured by the active 1.4 public API baseline.

T07 may then add semantic comparison without reopening acquisition or renderer
presentation design.
