# Icod.TermInfo 0.8.0 T25 — Byte and Output Fidelity

## Scope

T25 freezes the reversible 8-bit capability-string bridge and completes the
terminal-aware output policy needed before arbitrary compiled descriptions can
arrive in 0.9.

This tranche does not implement compiled terminfo parsing, terminal discovery,
profile cancellation, Windows profiles, tty ownership, or curses refresh
policy.

## 8-bit capability-string representation

Terminfo capability strings are byte strings, not intrinsically UTF-8 text.
`Icod.TermInfo` continues to expose them as .NET `string`, using the following
contract for data originating in conventional compiled terminfo:

- byte `0x01` through `0xFF` maps to the Unicode code point with the same value;
- `Encoding.Latin1.GetBytes(value)` reverses that mapping exactly;
- byte `0x00` remains the compiled string terminator rather than embedded
  capability data;
- bytes `0x80` through `0xFF` are ordinary capability data and are not decoded
  as UTF-8;
- application text encoding remains separate and caller-owned.

No new terminfo-string wrapper is required. Existing standard and extended
string storage, parameter expansion, and padding parsing preserve these
one-byte code points.

For exact capability-byte output, use the existing stream overloads with
`Encoding.Latin1`.

## Terminal-aware output options

`TermInfoOutputOptions` is an immutable caller-owned policy object containing:

- the `TerminalDescription`;
- an optional baud rate in bits per second;
- the selected `PaddingMode`;
- an optional `ITermInfoDelayProvider`.

The library never discovers baud rate, owns a tty or file descriptor, mutates
terminal modes, or introduces `cur_term`/`ospeed`-style process-global state.

Existing simple output overloads remain compatible. They continue to support
`PaddingMode.Ignore` and `PaddingMode.Delay`. `PaddingMode.PadCharacters`
requires a terminal-aware overload because pad-character output needs terminal
capabilities and, when characters are actually required, a caller-supplied
baud rate.

## Advisory padding policy

For terminal-aware output, non-mandatory padding is suppressed when:

- the terminal advertises `xon`; or
- the terminal advertises `pb`, the caller supplied a baud rate, and that baud
  rate is below `pb`.

If `pb` is present but the caller did not supply a baud rate, T25 does not
invent one and therefore does not suppress padding on the basis of `pb`.

The `/` suffix is mandatory. Mandatory padding bypasses both `xon` and `pb`
advisory suppression. An explicit `PaddingMode.Ignore` remains an intentional
caller request to discard all padding, including mandatory padding, preserving
the existing simple API contract.

The `*` suffix continues to multiply delay by the caller-supplied affected-line
count.

## Timed delays

`PaddingMode.Delay` resolves active padding through
`ITermInfoDelayProvider`. The default remains the system delay provider.

Delay calculations are capped at 30 seconds, matching the selected ncurses
baseline. Affected-line multiplication is performed with a pre-multiplication
bound check so an extreme valid decimal input cannot overflow `decimal`.

`npc` does not change timed-delay mode because no pad character is emitted.

## Pad-character output

`PaddingMode.PadCharacters` models the historical character-padding path.

When active padding must be emitted:

1. if the terminal advertises `npc`, T25 falls back to the delay provider;
2. otherwise a caller-supplied positive baud rate is required;
3. if `pad` is present, its first character is used;
4. if `pad` is absent or empty, NUL is used as the generated pad character;
5. the pad character must fit the one-byte terminfo range;
6. the number of emitted pad characters uses the selected ncurses historical
   timing model of nine transmitted bits per pad character.

The count is:

```text
floor(milliseconds * baudRate / 9000)
```

Resolved pad-character output is bounded to 4,194,304 characters. Exceeding
that bound fails before any output is written.

When exact bytes matter, pair character-padding output with `Encoding.Latin1`.

## Padding parser hardening

T25 adds a 1,048,576-character maximum padding source length, matching the
maximum expanded-output size established by T23. Numeric delay
parsing uses span-based invariant parsing rather than allocating a temporary
numeric substring.

Delay syntax remains the established form:

```text
$<number>
$<number*>
$<number/>
$<number*/>
```

with at most one decimal digit.

Malformed padding continues to throw `TermInfoPaddingFormatException`.

## Compatibility

T25 preserves:

- all existing simple `PutP`/`TPuts` behaviors for `Ignore` and `Delay`;
- caller-supplied arbitrary encodings on stream output;
- synchronous and asynchronous delay injection;
- affected-line semantics;
- existing `TermInfoDelay` and padding exception vocabulary.

T25 adds no terminal-name-specific or Windows-specific output branch.

## Boundaries

T26 owns profile composition and cancellation fidelity.

T27 and T28 own Windows Console and Windows Terminal profiles.

T29 owns the 0.9 compiled-entry readiness gate.

T25 does not read arbitrary terminal databases.
