# Icod.TermInfo 1.15.0 Berkeley DB Hashed Acquisition Guide

## Purpose

`Icod.TermInfo.BerkeleyDb` is the optional pure-managed package for reading
ncurses-compatible Berkeley DB Hash-v9 terminfo stores. It recovers compiled
terminfo bytes and delegates their semantics to the frozen `Icod.TermInfo`
Runtime parser.

Install it beside the coordinated Runtime package:

```text
dotnet add package Icod.TermInfo.BerkeleyDb --version 1.15.0
```

The package is read only. It has no Berkeley DB native dependency and does not
provide writes, transactions, recovery, environments, or general database APIs.

## Explicit provider

Use `BerkeleyDbTerminalDescriptionProvider` when the caller already knows the
exact hashed database file and terminal name:

```csharp
using Icod.TermInfo;
using Icod.TermInfo.BerkeleyDb;

var provider = new BerkeleyDbTerminalDescriptionProvider( "/path/to/terminfo.db" );
if ( provider.TryLoad( "xterm-256color", out TerminalDescription? terminal ) ) {
	Console.WriteLine( terminal.Name );
}
```

The constructor canonicalizes the caller-supplied path and snapshots parser,
database-size, and index-hop limits. A provider caches successful descriptions;
clean misses and failures remain retryable. Construct a new provider to observe
changed content after a successful lookup.

Lookup tries the exact ordinal UTF-8 key. Only an absent initial key permits one
distinct Latin-1 lookup, and only when every requested character is exactly
representable. A malformed or identity-invalid UTF-8 record never falls through.

Only an absent initial name is a clean miss (`TryLoad` returns `false`). Reached
malformed/unsupported storage or ncurses envelopes throw
`BerkeleyDbDatabaseFormatException`. Compiled-entry failures retain
`CompiledTermInfoFormatException`; identity mismatch, I/O, permission, and
cancellation failures retain their established exception categories.

## Logical catalog

`BerkeleyDbTerminalCatalogReader` reads every logical marker-2 publication from
one explicit hashed file:

```csharp
var reader = new BerkeleyDbTerminalCatalogReader( "/path/to/terminfo.db" );
foreach ( BerkeleyDbTerminalCatalogEntry entry in reader.Read() ) {
	Console.WriteLine( $"{entry.Kind}: {entry.Name} -> {entry.Terminal.Name}" );
}
```

Every call obtains a fresh immutable snapshot. Publications are ordered by
ordinal name, kind, and canonical terminal name, never physical page order.
Canonical and alias publications resolving to one storage record share one
parsed `TerminalDescription` instance within that result. Storage records are
validated but never published as user-facing terminal names.

Use the cancellation overload for caller-owned cancellation. Configure database
bytes, record count, compiled-entry parsing, and index hops through
`BerkeleyDbTerminalCatalogReaderOptions`.

## Opt-in system discovery

`BerkeleyDbSystemTerminalDescriptionProvider` adds hashed-aware storage-shape
selection while reusing Runtime's discovery inputs, precedence, normalization,
and logical-location deduplication. It considers an existing exact directory or
hashed file first, then a regular `.db` companion when the exact location does
not exist.

This is opt in. Runtime's frozen `SystemTerminalDescriptionProvider` remains
conventional-only and unchanged. Options independently allow or suppress
environment, user, and platform-system sources.

## Command integration

The coordinated commands use the optional package only at reviewed explicit
boundaries:

- `infocmp -A FILE NAME` and `infocmp -B FILE NAME` classify an explicit
  regular-file operand as a hashed store and use the explicit provider;
- human `toe FILE` / `toe -s FILE` classifies an explicit regular-file operand
  and uses `BerkeleyDbTerminalCatalogReader`;
- conventional directory operands retain their frozen behavior;
- ambient `toe` discovery and command JSON remain conventional; and
- `tic` remains a conventional directory publisher and never writes hashed
  Berkeley DB files.

The `icod-terminfo` router and all six standalone tool archives preserve those
same command contracts.

## Deterministic sample

`samples/Icod.TermInfo.BerkeleyDb.Sample` creates a controlled Hash-v9 fixture
in a temporary directory and resolves a controlled alias through the public
provider. It runs on net8.0, net9.0, and net10.0 and requires no ambient terminfo
state or native Berkeley DB installation.
