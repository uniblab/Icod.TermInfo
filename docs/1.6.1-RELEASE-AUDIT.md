# Icod.TermInfo 1.6.1 Release Audit

**Release version:** `1.6.1`
**Runtime assembly version:** `1.0.0.0`
**Source assembly version:** `1.0.0.0`
**Termcap assembly version:** `1.0.0.0`
**Compiler assembly version:** `1.0.0.0`
**Inspection assembly version:** `1.0.0.0`
**Status:** Patch release candidate
**Scope:** Release-verifier NuGet-cache isolation hotfix
**Public API:** Unchanged from 1.6.0
**Command semantics:** Unchanged from 1.6.0

## Defect

The 1.6.0 coordinated release verifier runs five package-reference-only smoke
consumers under deliberately isolated NuGet package caches. Both verifier entry
points then continued directly into the repository sample and deterministic
Source/Compiler/Inspection toolchain sample without first restoring the caller's
original `NUGET_PACKAGES` state.

On Windows this state leak was observed while the verifier rebuilt
`Icod.TermInfo.Compiler` for the toolchain sample. The build ran under the final
Inspection smoke consumer's temporary package-cache environment and failed with
CS0246 errors for framework types such as `IReadOnlyList<T>`, `IEnumerable<T>`,
`Span<T>`, `TextReader`, `FileSystemInfo`, and `StringComparer`.

The isolated Compiler package consumer had already completed before this failure.
The defect is therefore in release-verifier environment isolation, not in the
frozen Compiler source/API semantics or the published 1.6.0 package contract.

## Hotfix

Version 1.6.1 SHALL:

- restore the saved `NUGET_PACKAGES` value in the CMD verifier immediately after
  the isolated package-smoke consumers and before repository-owned samples are
  built;
- restore the original Bash `NUGET_PACKAGES` value when one existed, or unset it
  when the caller did not define it, at the same boundary;
- retain the temporary package caches for the duration of their isolated smoke
  consumers and remove them through the existing cleanup paths;
- preserve the non-interactive Runtime sample and deterministic
  Source/Compiler/Inspection toolchain sample as release gates;
- execute those repository samples from the already-built solution outputs with
  `--no-build`, preventing release verification from introducing a second
  production build after package-smoke isolation;
- add a regression contract requiring NuGet-cache restoration to occur before
  the toolchain sample and requiring the toolchain execution to use
  `--no-build`.

No production library source file is changed by this hotfix.

## Coordinated version contract

`Directory.Build.props` SHALL declare:

```text
IcodTermInfoSuiteVersion = 1.6.1
```

Runtime, Source, Termcap, Compiler, Inspection, all five standalone commands, and
`Icod.TermInfo.Tools` SHALL continue to consume that single coordinated version
authority.

All five reusable assemblies SHALL retain `AssemblyVersion` `1.0.0.0` and remain
unsigned.

## Frozen compatibility contract

Version 1.6.1 SHALL preserve unchanged:

- `docs/1.0.0-PUBLIC-API-BASELINE.txt`;
- `docs/1.1.0-SOURCE-PUBLIC-API-BASELINE.txt`;
- `docs/1.2.0-COMPILER-PUBLIC-API-BASELINE.txt`;
- `docs/1.4.0-INSPECTION-PUBLIC-API-BASELINE.txt`;
- `docs/1.6.0-TERMCAP-PUBLIC-API-BASELINE.txt`;
- Runtime dependency-free;
- Source depending only on Runtime;
- Termcap depending only on Runtime;
- Compiler depending on Runtime and Source;
- Inspection depending on Runtime and Source and not on Compiler or Termcap;
- all five command-line semantic contracts;
- the `icod-terminfo` five-command routing contract;
- the six-RID standalone archive topology;
- `net8.0`, `net9.0`, and `net10.0` reusable-library targets;
- `net10.0` command/router targets.

No 1.6.1 public API baseline is created because no public API changes.

## Required validation

Before `v1.6.1` publication, the exact release commit SHALL pass:

1. clean restore, Debug build/test, Staging build/test, and Release build/test;
2. all five frozen public API baselines and net8/net9/net10 API equivalence;
3. all reusable package structural/symbol/Source Link checks;
4. all five isolated package-reference-only smoke consumers on each supported
   reusable-library target;
5. the non-interactive Runtime repository sample;
6. the deterministic Source/Compiler/Inspection toolchain sample after the
   verifier restores caller NuGet-cache state;
7. `Icod.TermInfo.Tools` structural and matching-host route smoke;
8. all six standalone archive structural checks and matching-host smoke;
9. Windows, Linux, and macOS release validation.

The Windows verifier invocation which exposed this defect is a required
regression gate.

## Publication gate

Tag `v1.6.1` SHALL identify the exact validated current `main` HEAD and match
`IcodTermInfoSuiteVersion` exactly. Publication SHALL reuse the existing
six-package trusted-publishing scope, GitHub Packages flow, six standalone
archives, symbol packages, and checksum accounting established for 1.6.0.

The published `v1.6.0` tag and `docs/1.6.0-RELEASE-AUDIT.md` remain immutable
historical records.
