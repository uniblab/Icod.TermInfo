# Icod.TermInfo 1.6.0 TC07 — Conversion Tools and Coordinated Distribution

**Tranche:** TC07
**Development version:** `1.6.0-Alpha-7`
**Status:** Implemented for validation

## Decision

TC07 exposes two standalone managed commands and routes both through the existing
single-command `Icod.TermInfo.Tools` package:

```text
captoinfo
infotocap
```

This is preferable to adding modes to `infocmp`. The historical names remain
useful in standalone archives, while the NuGet tool continues to install only
the collision-resistant `icod-terminfo` launcher.

The resulting command topology is:

```text
standalone archives
    tic
    infocmp
    toe
    captoinfo
    infotocap

NuGet tool
    icod-terminfo tic ...
    icod-terminfo infocmp ...
    icod-terminfo toe ...
    icod-terminfo captoinfo ...
    icod-terminfo infotocap ...
```

## captoinfo pipeline

`captoinfo` does not implement a second parser or mapping table. Its file-input
pipeline is:

```text
TermcapSourceParser
        |
TermcapSourceResolver
        |
TermcapConverter
        |
TerminalDescription
        |
TerminalDescriptionSourceRenderer
        |
terminfo source
```

All entries in each supplied termcap source are converted in source order.
`tc=` inheritance is resolved before output, so the emitted terminfo source is
effective resolved state rather than a textual rewrite of the original
inheritance graph.

With no file operand, `captoinfo` provides the historical command-level
environment behavior without changing Runtime discovery. `TERM` supplies the
requested name and the command explicitly constructs TC06 acquisition from
`TERMCAP`, `TERMPATH`, `HOME`, and the `Ncurses` default-path policy.

## infotocap pipeline

`infotocap` likewise composes existing engines:

```text
TermInfoSourceParser
        |
TermInfoSourceResolver
        |
TerminalDescription
        |
TermcapRenderer
        |
termcap source
```

Each `.ti` entry is resolved through `use=` before reverse rendering. The TC05
representability gate is authoritative: an entry which cannot be represented
without violating the adopted termcap contract fails with diagnostics and no
partial text for that entry.

## Command surface

Both commands target `net10.0`, consume the centralized suite version, remain
non-packable standalone executable projects, and support:

```text
-w WIDTH
-h, --help
-V, --version
--
```

`-` names standard input. `infotocap` requires at least one explicit source
operand. `captoinfo` accepts file operands or its no-file historical acquisition
mode.

TC07 intentionally does not claim complete option-for-option ncurses `tic` alias
compatibility. The compatibility target is the conversion purpose and the
already-frozen Icod engines, not a duplicate command parser.

## Semantic boundary

Both directions emit effective resolved descriptions. They do not reconstruct:

- comments or original whitespace;
- disabled/canceled source fields;
- original `tc=` or `use=` ancestry;
- source ordering beyond deterministic output of effective descriptions.

Loss, approximation, unsupported syntax, and representability failures remain
observable on standard error.

## Dependency boundary

TC07 does not change the reusable Termcap package graph:

```text
Icod.TermInfo.Termcap
        |
        v
Icod.TermInfo
```

The new command composition dependencies are intentionally outside that package:

```text
captoinfo
    -> Icod.TermInfo.Termcap
    -> Icod.TermInfo.Inspection

infotocap
    -> Icod.TermInfo.Source
    -> Icod.TermInfo.Termcap
```

Neither command project depends on another command project.

## Coordinated distribution

The six RID-specific standalone archives retain their existing artifact count,
but now contain five launchers and the Termcap managed dependency. Archive
construction, archive verification, matching-host smoke, router package
structure checks, and router package smoke are updated to require both new
commands.

The `Icod.TermInfo.Tools` NuGet package still exposes exactly one .NET tool
command, `icod-terminfo`. Its managed payload now includes both conversion
command assemblies and `Icod.TermInfo.Termcap.dll`.

## Gate

TC07 is complete when Windows, Linux, and macOS validation demonstrates that:

1. both standalone conversion commands report `1.6.0-Alpha-7`;
2. both commands execute real conversions from packaged standalone archives;
3. both commands execute through the installed `icod-terminfo` package;
4. tool-package and archive structure checks require the new assemblies;
5. the existing `tic`, `infocmp`, and `toe` tests and smoke paths remain
   unchanged in behavior.

TC08 remains responsible for differential corpus validation, fuzzing, hostile
input review, and the final 1.6 API/package/CLI freeze.
