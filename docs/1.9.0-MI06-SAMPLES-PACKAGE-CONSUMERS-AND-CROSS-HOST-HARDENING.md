# Icod.TermInfo 1.9.0 MI06 - Samples, Package Consumers, and Cross-Host Hardening

**Development version:** `1.9.0-Alpha-6`

## Purpose

MI06 proves that the MI01 through MI05 machine-readable surface works through
the artifacts consumers actually receive. It adds no public API, schema field,
command option, package, or executable. MI07 remains responsible for the final
API and release freeze.

## Reusable sample evidence

`Icod.TermInfo.Toolchain.Sample` retains its controlled parse, resolve, plan,
synthesize, compile, publish, reacquire, and compare path. After that path
succeeds, it now renders the exact `TerminalDescriptionSourcePlan` through
`TermInfoJsonRenderer` and writes the compact version-1 `sourcePlan` document
followed by one LF.

The checked-in `expected-source-plan.json` fixture freezes the exact bytes. The
sample's `--verify-fixture path` form normalizes only the repository file's line
ending and then requires exact equality with the runtime output. Release
verification runs this form in two separate processes, compares those process
outputs byte for byte, and runs the same gate on Windows, Linux, and macOS.

## Command walkthrough

The ToolSuite walkthrough now includes controlled examples for:

- `infocmp --json` effective-description documents;
- `infocmp --json -d` comparison documents;
- explicit and all-candidates `sourcePlan` documents;
- `toe --json` database-catalog documents;
- direct and `icod-terminfo` routed byte equality.

Every example uses the checked-in source and an explicit local database root.
No example depends on `TERM`, `TERMINFO`, `TERMINFO_DIRS`, or a host database.

## Package-reference-only evidence

The fresh `inspection-package-smoke` consumer is copied outside the repository
project graph, restored from the produced packages with an isolated NuGet
cache, and built for `net8.0`, `net9.0`, and `net10.0`. Its project contains a
package reference and no repository project reference.

The consumer renders all four document kinds, parses the resulting JSON, checks
schema identity and representative evidence, and exercises a large and
pathological string containing non-ASCII text, control characters, quotes, and
line breaks. It requires byte-identical rendering under `ar-SA` and `tr-TR`,
acceptance at the exact UTF-8 output bound, and deterministic rejection one byte
below that bound.

## Distributed command evidence

The installable tool package smoke and all six standalone archive smoke jobs
execute real `terminalDescription`, `comparison`, `sourcePlan`, and
`databaseCatalog` JSON commands. The workflows retain explicit roots, validate
document kinds and planning evidence, and reject partial or failed automation.
Direct command tests additionally require large escaped JSON to remain exactly
equal to reusable renderer output under multiple cultures, with one successful
document and no stderr contamination.

## Cross-host and resource evidence

The MI06 tests run across all three reusable target frameworks and the release
matrix runs on Windows, Linux, and macOS. Together they require:

1. checked-in fixture equality;
2. compact JSON with no host-dependent provenance;
3. culture-invariant rendering;
4. separate-process byte equality;
5. valid handling of large and pathological text;
6. exact UTF-8 boundary acceptance and below-bound rejection;
7. package-reference-only use of the produced Inspection package;
8. real JSON execution from the tool package and six archives.

## Preserved boundaries

MI06 preserves the frozen Runtime 1.0, Source 1.1, Compiler 1.2, Termcap 1.6,
relative-source synthesis 1.7, and planning 1.8 semantics. The MI01 public API
and MI04 version-1 JSON Schema are unchanged. Inspection retains only Runtime
and Source production dependencies, and all reusable assemblies retain version
`1.0.0.0`.

## Handoff to MI07

MI07 may now freeze the exact 1.9 Inspection API, JSON Schema, command surface,
package graph, documentation, fixtures, and release evidence. It must not add a
new feature after this hardening gate.
