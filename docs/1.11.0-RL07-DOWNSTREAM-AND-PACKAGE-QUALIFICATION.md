## Qualification objective

RL07 proves that a downstream consumer can use the public `Icod.TermInfo.Inspection` package to perform the complete protocol-neutral lifecycle decision flow without introducing an `Icod.TermInfo` dependency on `Icod.Terminal`:

```text
TerminalDescription
    -> PersistentRasterLifecycleInspector
    -> PersistentRasterLifecycleProfile
    -> PersistentRasterLifecycleRequest
    -> PersistentRasterLifecyclePlanner
    -> PersistentRasterLifecyclePlan
    -> consumer-owned live verification / execution
```

`Icod.TermInfo` remains descriptive and advisory. Terminal-side protocol I/O, resource identity, placement identity, lifecycle-generation invalidation, acknowledgements, and cleanup execution remain outside this repository.

## Ephemeral graphics do not imply persistence

The package-only consumer builds a `TerminalDescription` containing only Sixel-style static evidence. Inspection deliberately leaves persistent lifecycle dimensions such as persistent upload and placement creation as `Unknown`.

The corresponding semantic request therefore produces an `Indeterminate` plan and marks the relevant steps as requiring consumer-owned runtime verification.

This proves the 1.11 boundary that ordinary raster display support is not silently promoted to persistent-resource support.

## Consumer-owned verification strengthens knowledge

The same consumer then appends caller-owned `Verified` evidence for persistent upload and placement creation, reclassifies the evidence, and replans the same request.

The strengthened plan becomes `Success`, contains ordered `UploadResource` then `CreatePlacement` operations, carries no uncertainty issues, and no longer requires runtime verification.

TermInfo does not perform that live verification itself; it accepts the explicit verified evidence supplied by the consumer and applies the frozen RL03 precedence/classification rules.
