# Icod.TermInfo 0.8.0 T30 — API, Documentation, and Package Freeze

**Development version:** `0.8.0-rc.1`

T30 freezes the intended public surface and release-facing behavior for the
0.8 semantic-completion release. It adds no new terminal semantics and no
production arbitrary-terminfo acquisition code.

## Public API review

The T30 review keeps the existing 0.8 API shape.

### Parameter-program analysis

The structural/type analysis created for safe parameter-program evaluation
remains an implementation detail.

`TermInfoParameterProgram` publicly exposes:

- `Source`;
- `Parse`;
- reusable `Expand` overloads.

The parsed instruction representation, analyzer results, and per-description
program caches remain internal. No public analyzer/cache abstraction is added.

This keeps the public contract focused on useful operations rather than on the
current implementation of the evaluator.

### Standard capability metadata

`StandardCapabilityCatalog` and
`StandardCapabilityMetadata<TCapability>` are frozen as the public standard
metadata surface.

The catalog exposes deterministic compiled-table-order lists for Boolean,
numeric, and string capabilities plus typed metadata lookup. Each metadata
record exposes:

- `Kind`;
- `Capability`;
- `BinaryIndex`;
- `ShortName`;
- `LongName`;
- `TermcapCode`.

Metadata records are library-created and read-only. Managed enum numeric values
remain independent from `BinaryIndex`.

### Per-description enumeration and identity

The following `TerminalDescription` members are frozen:

- `Name`;
- `Aliases`;
- `Description`;
- `BooleanCapabilities`;
- `NumericCapabilities`;
- `StringCapabilities`;
- `ExtendedCapabilities`.

`Description` remains the verbose terminal description/long name. It is not an
alias and does not participate in terminal-name resolution.

Standard per-description enumeration exposes only effectively present
capabilities in deterministic compiled-table order. Internal canceled state is
not surfaced as a public value.

### Extended string expansion

The explicit name `ExpandExtendedString` is retained.

T30 deliberately does not add an ambiguous `Expand(string, ...)` overload.
Standard and extended capability namespaces remain explicit, while both use the
same parameter parser/analyzer/evaluator internally.

### Nullability and exception contracts

T30 keeps the existing nullable annotations intentional:

- `TerminalDescription.Description` is nullable because a description may be
  legitimately absent;
- `TermInfoOutputOptions.Terminal` is non-null;
- `TermInfoOutputOptions.DelayProvider` is nullable;
- `ITerminalDescriptionProvider.TryLoad` retains
  `[NotNullWhen(true)]` on its result parameter.

The exception vocabulary also remains separated by responsibility:

- `TermInfoFormatException` is malformed parameter-program syntax;
- `TermInfoEvaluationException` is parameter-program evaluation failure;
- `TermInfoPaddingFormatException` is malformed padding syntax;
- missing required capabilities continue to use their documented
  `InvalidOperationException` paths;
- a future malformed compiled-entry exception in 0.9 must use distinct
  vocabulary and must not overload `TermInfoFormatException`.

### Terminal-aware output

`TermInfoOutputOptions` remains the immutable policy/facts object for
terminal-aware output. It contains:

- the immutable `TerminalDescription`;
- optional caller-supplied baud rate;
- `PaddingMode`;
- optional caller-supplied `ITermInfoDelayProvider`.

The simple output overloads remain available for compatibility. Terminal-aware
overloads remain explicit rather than silently reading process-global terminal
state.

## Ownership and encoding boundary

T30 freezes the following ownership rules:

- the caller owns the selected `TerminalDescription`;
- the caller owns any `TermInfoExpansionContext`;
- the caller owns `TextWriter` and `Stream` lifetimes;
- the caller chooses a byte-stream `Encoding`;
- the caller supplies baud rate when a padding policy needs it;
- the caller owns any custom delay provider;
- `Icod.TermInfo` does not close caller-owned writers or streams;
- `Icod.TermInfo` does not discover tty speed or maintain `cur_term`/`ospeed`
  equivalents.

Terminfo capability strings are protocol byte data. Conventional compiled
capability bytes map one-to-one through the Latin-1 code-point range, and
`Encoding.Latin1` is the exact reverse bridge for byte-stream capability
output.

That rule does not choose the encoding for application text. Application text
encoding remains a higher-level caller/session concern.

## Windows boundary

The built-in identities are data:

- `winconsole`;
- `ms-terminal`;
- `ms-terminal-direct`.

Accessing or resolving those profiles is side-effect free.

`WindowsVirtualTerminal.TryEnableOutput()` remains a separate explicit,
reversible state-changing operation. Loading `winconsole` or a Windows Terminal
profile does not enable VT processing.

Environment hints such as `WT_SESSION`, `WT_PROFILE_ID`, and `COLORTERM` do not
silently select, upgrade, or mutate a terminal profile.

## Provider boundary

The T29 rule remains frozen:

> `ITerminalDescriptionProvider.TryLoad(...) == false` means a clean provider
> miss.

Future I/O providers must not turn permission failures, corrupt entries,
unsupported compiled formats, I/O failures, or parser failures into a clean
miss.

## 0.9 acquisition boundary

Version 0.8 ends with complete in-memory semantics but no production arbitrary
compiled-terminfo acquisition.

The following remain required 0.9 work:

- `0432` compiled parsing;
- ncurses extended-section parsing;
- `01036` / signed 32-bit numeric parsing;
- absent/canceled binary mapping;
- explicit directory providers;
- `TERMINFO`;
- `TERMINFO_DIRS`;
- `$HOME/.terminfo` and platform default roots;
- encoded `TERMINFO=hex:...` / `TERMINFO=b64:...`;
- malformed compiled-entry diagnostics;
- provider-instance loaded-description caching/refresh policy.

The checked-in T29 source/binary/manifests/malformed files are repository test
and provenance assets. They are not runtime package content.

## Package freeze

The package verifier now proves that:

- `<Version>` and `<PackageVersion>` are synchronized;
- only the managed `Icod.TermInfo.dll` runtime assembly is packed;
- no native runtime payload or runtime NuGet dependency appears;
- portable symbols and Source Link identify the repository commit;
- repository-only `tests/`, `tools/`, fixture, `.ti`, and `.bin` content does
  not enter the `.nupkg`;
- a fresh `net10.0` project can restore solely from the produced package;
- the fresh consumer can use the complete standard catalog;
- the fresh consumer can use per-description enumeration and verbose
  descriptions;
- reusable parameter programs and `ExpandExtendedString` work;
- exact Latin-1 capability-byte output works;
- terminal-aware padding works without hidden terminal state;
- `winconsole`, `ms-terminal`, and `ms-terminal-direct` are usable
  non-interactively;
- Windows Terminal indexed/direct color semantics remain distinct;
- arbitrary unsupported system identities do not silently resolve.

The repository sample's `--describe-only` path is also run against
`ms-terminal-direct` so CI exercises the new Windows Terminal public path
without requiring an interactive terminal.

## CI freeze

Both pull-request and release-branch validation run Debug and Release on:

- Windows;
- Linux;
- macOS.

The release workflow watches `main` and the active `0.8.0` release branch.
Package verification runs after the complete three-OS build/test matrix.

## T31 handoff

T31 is the final `0.8.0` completion gate. It should primarily audit and execute
the already-frozen contract, set/confirm the final `0.8.0` version, and produce
the final evidence map.

If T31 discovers that the public object model, parameter/output semantics, or
package shape still requires redesign, the T30 freeze was incomplete and the
gate must be reopened rather than papering over the discrepancy.
