## Accepted dependency architecture

- Runtime remains dependency-free and has no BerkeleyDb reference.
- Inspection remains provider-neutral, references Runtime and Source only, and
  gains no public API.
- BerkeleyDb continues to reference Runtime only.
- Only the `infocmp` and `toe` executable projects directly reference
  BerkeleyDb.
- The installed tool and standalone archives carry the managed BerkeleyDb
  assembly required by those commands.
- Production contains no P/Invoke, native Berkeley DB asset, or third-party
  Berkeley DB runtime package.

Reusable assembly identities remain `1.0.0.0`, and reusable public APIs remain
equivalent across net8/net9/net10.

## Accepted `infocmp` contract

For `-A path` and `-B path`:

1. an existing file selects `BerkeleyDbTerminalDescriptionProvider`;
2. an existing directory or unclassified path retains the conventional
   provider;
3. no extension, basename, platform, or content pre-probe selects the provider;
4. path classification is a point-in-time decision with no fallback after a
   selected provider fails.

Hashed exact-name acquisition composes with source rendering, unchanged
terminal-description JSON, semantic comparison, unchanged comparison JSON,
explicit-parent relative synthesis, and explicitly named candidate planning.

The catalog-wide `--plan-use --all-candidates` forms remain
conventional-directory-only. A BerkeleyDb `-B` file is rejected before
output.

A clean hashed miss uses `INFOCMP0002` and status 1. Construction, I/O,
container/envelope, parser, and identity failures use `INFOCMP0003` and
status 1. Usage remains status 2 and cancellation remains status 130.

## Accepted `toe` contract

Human listing accepts conventional directories and hashed files in one explicit
ordered list. Each root is inspected once:

- conventional entries retain canonical-name publication;
- hashed entries publish each HDB05 canonical or alias logical name;
- marker-0 storage keys are never emitted;
- default order preserves each provider's accepted order;
- `-s` orders publication names ordinally with existing tie-breaks;
- `-h` prints the canonical absolute root for either storage shape; and
- duplicate analysis keys the displayed publication name and continues to use
  `TerminalDescriptionComparer`.

A failed hashed catalog is all-or-nothing for that root. `TOE0005` is emitted,
later explicit roots continue, and final status is 1. Missing explicit roots
retain `TOE0002`; cancellation remains 130.

Operand-free `toe`, `toe -a`, and `toe -D` retain conventional Runtime /
Inspection discovery. Frozen JSON v1/v2 routes and schemas remain unchanged; an
explicit file remains the existing `UnsupportedStore` state.

## Distribution contract

Installed package smoke invokes routed `icod-terminfo infocmp` and
`icod-terminfo toe` against an independently constructed controlled Hash-v9
store on Windows, Linux, and macOS.

Standalone archives retain their accepted direct-launcher layout and exercise
the matching direct `infocmp` and `toe` commands for all six RIDs. Direct
and routed integration tests require exact stdout, stderr, and status
equivalence.

## Compatibility and non-goals

- Existing conventional directory behavior is unchanged.
- Runtime system discovery and the HDB04 opt-in provider are unchanged.
- No JSON schema or reusable public API is added or changed.
- `tic` remains conventional-directory-write-only.
- HDB06 does not add heterogeneous all-candidate enumeration, hashed ambient
  discovery, partial hashed catalogs, writes, transactions, recovery, native
  dependencies, or other Berkeley DB access methods/revisions/features.
