# Icod.TermInfo 1.1.0 — S03 String and Numeric Source Semantics

**Tranche:** S03
**Development version:** `1.1.0-Alpha-3`
**Runtime assembly identity:** `Icod.TermInfo, Version=1.0.0.0`
**Source assembly identity:** `Icod.TermInfo.Source, Version=1.0.0.0`
**Status:** implementation candidate; build/test/package validation required

---

## 1. Purpose

S03 interprets the value spellings retained by the S02 lexer. It deliberately
stops short of classifying capability names or constructing unresolved source
entries; those responsibilities begin in S04.

The layer boundary is:

```text
.ti source
    |
    v
TermInfoSourceLexer            S02
    |
    v
TermInfoSourceToken
    |
    v
TermInfoSourceValueParser      S03
    |
    +--> TermInfoSourceNumericValueResult
    |
    +--> TermInfoSourceStringValueResult
```

The lexer remains lossless: `TermInfoSourceToken.Text` continues to expose the
exact source spelling. S03 creates decoded values beside that lexical contract
rather than rewriting tokens.

---

## 2. Numeric value contract

`TermInfoSourceValueParser.ParseNumeric` accepts a
`TermInfoSourceTokenKind.NumericCapability` token and interprets the text after
its unescaped `#` operator.

Supported spellings follow conventional System V/ncurses source notation:

- decimal, for example `cols#80`;
- octal with a leading zero, for example `colors#0377`;
- hexadecimal with `0x` or `0X`, for example `colors#0xff`.

The semantic result is a non-negative `System.Int32`. This matches the signed
32-bit storage model used by the stable runtime while preserving the terminfo
source rule that an ordinary numeric capability is not written as a negative
number.

The parser does not clamp overflow. A spelling larger than `Int32.MaxValue`
produces an error diagnostic and no value.

Malformed or signed spellings likewise produce diagnostics rather than relying
on current-culture numeric parsing.

## 3. String value contract

`TermInfoSourceValueParser.ParseString` accepts a
`TermInfoSourceTokenKind.StringCapability` token and interprets the text after
its unescaped `=` operator.

### 3.1 Control notation

The source form:

```text
^X
```

uses the traditional control-character translation. `^?` produces DEL. A
control translation which would otherwise produce NUL is represented as byte
`0x80`, matching historical terminfo/ncurses source behavior and the compiled
format's NUL-terminated string representation.

A caret immediately following `%` is retained literally. This preserves
terminfo parameter-language text which uses `%` syntax rather than treating the
caret as an accidental control escape.

### 3.2 Backslash escapes

S03 recognizes the established terminfo spellings for:

```text
\E  \e  \a  \n  \l  \r  \t  \b  \f  \s
\^  \\  \,  \:  \|
```

Unknown backslash escapes are compatibility warnings rather than destructive
errors: the backslash is removed and the escaped character is retained, matching
the adopted ncurses behavior.

### 3.3 Octal byte escapes

A backslash followed by an octal digit consumes up to three digit characters.
The resulting value is reduced to one byte and represented by the corresponding
U+0001 through U+00FF code point.

Terminfo's historical zero rule applies:

```text
\0
\000
^@
```

all materialize as U+0080 rather than U+0000.

For ncurses compatibility, `8` or `9` encountered in the second or third digit
position is retained using the historical base-eight calculation while a
warning diagnostic records the non-octal digit.

### 3.4 Multiline values

A physical newline within a terminfo string is removed when the continuation
line begins with spaces or tabs. Leading continuation indentation is likewise
removed.

A backslash immediately before a physical newline also continues the value and
removes the following indentation.

An unindented physical continuation is an error because accepting it would make
entry boundaries ambiguous.

### 3.5 Byte preservation

Compiled terminfo strings are read by `Icod.TermInfo` with one-to-one Latin-1
byte preservation. S03 follows the same representation for byte-valued escapes:
a source byte `0xNN` becomes the .NET character U+00NN. Literal NUL is rejected
because the compiled representation uses NUL as its string terminator.

## 4. Diagnostics

S03 extends the stable `TISdddd` diagnostic namespace:

| Code | Severity | Condition |
|---|---|---|
| `TIS0010` | Error | Numeric capability has no value after `#` |
| `TIS0011` | Error | Numeric spelling is malformed for its selected base |
| `TIS0012` | Error | Numeric value exceeds `Int32.MaxValue` |
| `TIS0013` | Error | Backslash escape ends before an escaped character |
| `TIS0014` | Warning | Unknown backslash escape; escaped character retained |
| `TIS0015` | Error | Caret control escape is incomplete |
| `TIS0016` | Warning | Caret target is outside printable ASCII |
| `TIS0017` | Warning | `8` or `9` appears in an octal byte escape |
| `TIS0018` | Error | Physical string continuation is not indented |
| `TIS0019` | Error | Literal NUL occurs in a source string |

Warnings do not suppress an otherwise usable decoded value. Any S03 error makes
the corresponding result's `Value` null.

Diagnostics carry spans relative to the original S02 token and therefore retain
the caller's source identity and one-based line/column information.

## 5. Public API

S03 adds:

```text
TermInfoSourceValueParser
TermInfoSourceNumericValueResult
TermInfoSourceStringValueResult
```

The existing reviewed Source API baseline is advanced in place. The repository
package-validation scripts continue to require exact Source API parity between
`net8.0` and `net10.0` and exact agreement with
`docs/1.1.0-SOURCE-PUBLIC-API-BASELINE.txt`.

The stable `Icod.TermInfo` 1.0 public API baseline remains unchanged.

---

## 6. Compatibility corpus

S03 tests value interpretation against both focused source cases and the
checked-in T29 `.ti` fixture sources which already generated authoritative
compiled parser fixtures.

The compatibility checks include:

- decimal, octal, and hexadecimal numerics;
- the wide positive 32-bit T29 numeric fixture;
- `^G` control notation;
- `\200` high-byte preservation;
- `\E` escape translation;
- parameterized strings and padding text left intact except for source escapes.

Normal CI remains independent of an installed native `tic` or `infocmp`.

---

## 7. S03 gate

S03 is complete when:

1. both packages build and test on `net8.0` and `net10.0`;
2. both packages use development version `1.1.0-Alpha-3` while retaining
   assembly version `1.0.0.0`;
3. decimal, octal, and hexadecimal source numerics decode into non-negative
   signed 32-bit values;
4. malformed and overflowing numerics produce stable diagnostics;
5. standard control, backslash, punctuation, and octal string escapes decode
   deterministically;
6. multiline source strings obey the adopted continuation rules;
7. historical zero/high-byte behavior is preserved without embedding NUL in
   runtime strings;
8. warnings remain distinguishable from hard errors;
9. the existing T29 source corpus decodes without semantic errors;
10. the Source public API baseline and cross-target API parity gates pass; and
11. no S03 change alters the frozen `Icod.TermInfo` 1.0 runtime API contract.

After this gate, S04 may introduce the unresolved source-entry model while
reusing these lexical and value-semantics layers.
