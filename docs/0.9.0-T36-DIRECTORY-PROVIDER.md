# Icod.TermInfo 0.9.0 — T36 Explicit Directory Provider

**Tranche:** T36 — Explicit Directory Provider
**Development version:** `0.9.0-alpha.5`
**Previous tranche:** T35 — parser hardening, diagnostics, and fuzz gate
**Next tranche:** T37 — encoded `TERMINFO` and discovery inputs

---

## Purpose

T36 introduces the first filesystem-backed compiled-terminfo acquisition path.

`DirectoryTerminalDescriptionProvider` owns exactly one caller-supplied root and
feeds candidate file bytes into the hardened common
`CompiledTermInfoParser`.

T36 does not perform environment, user-home, platform-default, or multi-root
discovery. Those remain T37/T38 work.

## Public shape

The T32-frozen public ownership shape is implemented directly:

```csharp
public sealed class DirectoryTerminalDescriptionProvider
    : ITerminalDescriptionProvider
{
    public DirectoryTerminalDescriptionProvider(
        string root,
        CompiledTermInfoParserOptions? parserOptions = null);

    public string Root { get; }

    public bool TryLoad(
        string name,
        out TerminalDescription? terminal);
}
```

The `out` parameter carries the existing
`[NotNullWhen(true)]` provider contract.

The constructor validates the supplied root, converts it to an absolute
`Path.GetFullPath` form, and snapshots the selected parser maximum-entry-size
value.

The root does not need to exist at construction time. A missing root simply
produces clean exact-name misses until entries appear.

## Exact-name layouts

T36 freezes candidate order as:

```text
1. <root>/<literal-first-character>/<terminal-name>
2. <root>/<lowercase-two-digit-hex-first-byte>/<terminal-name>
```

The literal candidate always has precedence.

The hexadecimal directory uses the Latin-1/byte value of the first requested
character and lowercase invariant hexadecimal. For example:

```text
n29-legacy-minimal
    -> literal: <root>/n/n29-legacy-minimal
    -> hex:     <root>/6e/n29-legacy-minimal
```

The hex candidate is available when the first managed character fits in one
byte, which covers the byte-oriented compiled identity contract.

No uppercase-hex fallback and no recursive directory scan are performed.

## Safe requested names

Requested terminal names are validated before candidate paths are constructed.

T36 rejects:

- null, empty, or whitespace-only names;
- `.` and `..`;
- rooted paths;
- `/` and `\` directory separators on every platform;
- NUL and control characters;
- UTF-16 surrogate code units;
- characters invalid in a file name on the current platform;
- on Windows, names ending in a period or space and reserved device stems such
  as `CON`, `NUL`, `COM1`, or `LPT1`.

The provider does not normalize case or rewrite a requested terminal identity.

## Candidate reading and parser bounds

Candidate files are opened for read-only sequential access.

Before allocating the byte array, T36 checks the file's reported length against
the snapshotted `CompiledTermInfoParserOptions.MaximumEntrySize`.

An oversized candidate fails with `CompiledTermInfoFormatException` section
`entry` without allocating the complete file.

A truncation while the file is being read remains an I/O failure. If additional
bytes appear after the snapshotted length has been read, the provider also
fails rather than parsing an unstable prefix.

The completed byte array is passed to the same public
`CompiledTermInfoParser.Parse` implementation used by callers supplying bytes
directly.

## Clean miss versus failure

Only these candidate failures are clean misses:

```text
FileNotFoundException
DirectoryNotFoundException
```

The provider then tries the next frozen candidate or, after both candidates are
absent, returns `false` with a null result.

Permission failures, other I/O failures, malformed compiled entries, unsupported
compiled magic/layout, and parser failures propagate.

A present candidate whose parsed canonical name and aliases do not contain the
exact requested name throws `InvalidDataException`. An inconsistent database
entry is therefore never translated into an ordinary absence.

## Identity verification

After parsing a present candidate, T36 accepts it only when the requested name
matches, using ordinal case-sensitive comparison:

- `TerminalDescription.Name`; or
- one of `TerminalDescription.Aliases`.

This makes alias lookup independent of whether the filesystem represents an
alias as a hard link, symbolic link, copy, or separately generated equivalent
entry.

A cached canonical entry does not automatically satisfy an alias path which has
never itself been successfully looked up.

## Provider-local cache

The provider has a thread-safe, ordinal exact-name success cache.

The policy follows the T32 freeze:

- only successful immutable descriptions are cached;
- a clean miss is not negative-cached;
- parser and I/O failures are not cached as misses;
- cache publication is thread-safe;
- separately constructed directory providers do not share cached descriptions.

The normal refresh mechanism remains construction of a new provider instance.

T39 will perform the final cache/composition audit; T36 does not add timers,
watchers, asynchronous refresh, global caches, or a public `ClearCache()` API.

## Environment independence

`DirectoryTerminalDescriptionProvider` contains no lookup of:

```text
TERMINFO
TERMINFO_DIRS
HOME
platform default terminfo roots
```

Its only search root is the constructor argument.

The existing `TerminalDatabase.BuiltIn` remains unchanged and I/O-free.

## Test coverage

T36 adds temporary-root tests covering:

- the frozen public API;
- root canonicalization and parser-option snapshot behavior;
- literal first-character lookup;
- lowercase hexadecimal lookup;
- literal-before-hex candidate precedence;
- canonical-name and alias identity;
- mismatch rejection;
- clean misses;
- no negative caching;
- malformed-entry propagation;
- failure recovery without cached failure state;
- provider-local successful-entry caching;
- cache isolation between provider instances;
- concurrent cache publication;
- non-clean present-candidate failures;
- no recursive scanning;
- traversal, separator, rooted-path, NUL, and unsafe-name rejection.

The tests use only checked-in T29 binary fixtures and temporary filesystem
trees. No native `tic`, ncurses, environment discovery, or system terminfo
database is required.

## Completion evidence

T36 is complete when:

- both project version fields are `0.9.0-alpha.5`;
- `DirectoryTerminalDescriptionProvider` matches the T32-frozen public shape;
- its root is caller-owned and canonicalized at construction;
- literal first-character lookup precedes lowercase two-digit hexadecimal
  lookup;
- requested names are validated before path construction;
- candidate files are read under the snapshotted parser entry-size limit;
- all candidate bytes pass through `CompiledTermInfoParser`;
- parsed canonical/alias identity must match the exact requested name;
- only genuine missing-file/directory cases become clean misses;
- successful descriptions are cached per provider instance;
- misses and failures are not cached as misses;
- no recursive scan, environment discovery, system default, or native runtime
  dependency enters the provider;
- the T33–T35 parser and 0.8 behavioral contracts remain unchanged.

T37 may now add encoded `TERMINFO` acquisition and deterministic discovery input
ownership on top of the same pure parser.
