# Icod.TermInfo 1.2.0 C07 — Round-Trip and Differential Validation

**Tranche:** C07
**Development version:** `1.2.0-Alpha-7`
**Runtime assembly identity:** `Icod.TermInfo, Version=1.0.0.0`
**Source assembly identity:** `Icod.TermInfo.Source, Version=1.0.0.0`
**Compiler assembly identity:** `Icod.TermInfo.Compiler, Version=1.0.0.0`
**Status:** implementation candidate; build/test/package validation required

## Purpose

C07 closes the planned 1.2 implementation tranches by validating the complete
managed pipeline rather than adding another production feature surface:

```text
.ti source
    |
    v
TermInfoSourceParser / TermInfoSourceResolver
    |
    v
TerminalDescription A
    |
    v
CompiledTermInfoWriter
    |
    v
compiled bytes
    |
    v
CompiledTermInfoParser
    |
    v
TerminalDescription B

A == B semantically
```

The final package-version change from `1.2.0-Alpha-7` to `1.2.0` is intentionally
not part of C07. Release closure remains a separate reviewed patch.

## Pinned differential corpus

C07 reuses the existing T29 compiled-term corpus under:

```text
tests/Icod.TermInfo.Tests/fixtures/compiled-terminfo/
```

The checked-in reference binaries were generated with the pinned ncurses
`6.5.20250216` `tic -x` baseline recorded by the corpus. Normal C07 tests read
those committed artifacts directly and therefore require no host ncurses
installation, network access, or fixture regeneration.

The C07 differential set covers:

```text
t29-legacy-minimal
t29-legacy-alignment
t29-legacy-edge
t29-extended
t29-extended32
```

For each fixture, C07:

1. compiles the checked-in `.ti` source with `TermInfoSourceCompiler`;
2. repeats compilation and requires byte-for-byte identical Compiler output;
3. verifies the selected `0432` or `01036` magic;
4. parses the Compiler output;
5. parses the independently generated pinned `tic` binary;
6. compares both `TerminalDescription` values semantically;
7. rewrites the pinned parsed description with `CompiledTermInfoWriter`, parses
   it again, and requires semantic equivalence.

The comparison includes canonical name, description, ordered aliases, all
effective standard Boolean/numeric/string capabilities, and all extended
capability names, kinds, and values.

This deliberately compares semantics rather than requiring byte identity with
`tic`. Source cancellation tombstones do not survive
`TerminalDescription` materialization, and the Compiler contract promises
effective terminal semantics rather than reproduction of incidental source-only
or producer-specific representation choices.

## Determinism

C07 adds an explicit determinism test which constructs semantically identical
descriptions while reversing insertion order within every extended capability
kind. It writes one description under `tr-TR` culture and the other under
`fr-FR` culture and requires byte-for-byte identical output.

The fixture includes:

- standard Boolean, numeric, and string capabilities;
- a wide standard numeric requiring `01036`;
- multiple extended Booleans;
- multiple extended numerics;
- multiple extended strings;
- high Latin-1 data.

Together with the existing deterministic ordering rules and the
Windows/Linux/macOS, net8.0/net9.0/net10.0 matrix, this exercises the C07
host/culture/order independence contract without introducing environment
discovery into production code.

## Boundary and hostile-input coverage

C07 is a cumulative validation gate. The required boundary cases are already
owned by earlier Compiler tranche tests and remain part of the complete solution
test run:

- C01 covers strict identity encoding, high Latin-1, embedded NUL rejection,
  unrepresentable Unicode, names alignment, and repeated-write determinism;
- C02 covers complete and sparse standard tables, absent sentinels, legacy
  numeric boundaries, standard string offset overflow, and string-table size
  overflow;
- C03 covers extended capability ordering and all three extended kinds, high
  Latin-1 names/values, embedded NUL and Unicode rejection, signed extended
  string/name offset overflow, and extended table-size overflow;
- C04 covers automatic/explicit legacy-versus-wide selection, wide standard and
  extended numerics, sentinel-colliding negative values, and deterministic
  option behavior;
- C05 covers source parsing, inheritance, diagnostics, and materialization into
  independently loadable compiled entries;
- C06 covers safe database-layout publication, aliases, overwrite policy,
  prevalidation, and consumption through `DirectoryTerminalDescriptionProvider`.

C07 does not duplicate those tests merely to rename them. It adds the
cross-layer and independently sourced evidence which earlier tranches could not
provide.

## Database completion gate

C07 also compiles the pinned `t29-extended32` source, publishes the result into a
temporary explicit-root database with `CompiledTermInfoDatabaseWriter`, and
loads both the canonical name and alias through
`DirectoryTerminalDescriptionProvider`.

Both loads must be semantically equivalent to the Compiler-produced entry. This
proves the full Source -> Compiler -> database layout -> frozen Runtime provider
path while remaining isolated from process-global terminal installation.

## Public API and package topology

C07 adds no new production public API. The reviewed Compiler public API baseline
therefore remains unchanged.

Dependency direction remains:

```text
Compiler -> Source -> Runtime
Compiler ------------> Runtime
```

Runtime remains dependency-free, Source remains independent of Compiler, and all
three assembly versions remain `1.0.0.0`.

All three coordinated package versions advance only to:

```text
1.2.0-Alpha-7
```

The exact final `1.2.0` package-version transition belongs to the separate
release-closure patch.

## C07 gate

C07 is complete when:

- all five pinned T29 source/reference-binary pairs compare semantically;
- repeated source compilation is byte-for-byte deterministic;
- extended capability insertion order and process culture do not affect output;
- the cumulative C01-C06 boundary and hostile-input tests remain green;
- temporary database output is consumed without semantic loss through the
  existing Runtime directory provider;
- Runtime and Source approved API baselines remain frozen;
- the Compiler API baseline remains unchanged and equivalent across
  net8.0/net9.0/net10.0;
- package verification and fresh package consumers pass;
- the Windows/Linux/macOS CI matrix is green.

Passing C07 makes the implementation ready for the separate 1.2.0 release
closure/version-bump patch. It does not itself publish or finalize `1.2.0`.
