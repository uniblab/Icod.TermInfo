# Icod.TermInfo 1.4.0 T05 — tic Compilation and Database Publication

**Development version:** `1.4.0-Alpha-5`
**Baseline:** T04 managed `tic -c` validation path
**Scope:** command-layer publication policy and integration only
**Library public API change:** none

## 1. Objective

T05 adds the first filesystem-mutating behavior in the 1.4 tool-suite program.
It extends the T04 `tic` validator so a successfully validated source selection
can be published into one conventional terminfo database root.

The tranche deliberately does not redesign the lower libraries. Source parsing,
`use=` resolution, compiled representation, database path safety, alias
publication, preflight checks, staging, and overwrite mechanics remain owned by
the already-existing reusable packages.

## 2. Command contract

T05 supports:

```text
tic [options] file
tic -c [options] file
tic -D
tic -V
tic --version
tic --help
```

T05 adds these publication options:

```text
-o <directory>
-s
--force
```

The T04 options remain supported:

```text
-c
-e <name-list>
-x
-D
-V
--version
--help
```

`-c` retains its non-mutating meaning. `-o`, `-s`, and `--force` are
publication-only and are rejected when combined with `-c`; they are never
accepted and ignored.

## 3. Validation before mutation

The T04 analysis path is retained as the single semantic front end:

```text
strict UTF-8 source
    -> TermInfoSourceParser
    -> source selection
    -> TermInfoSourceResolver
    -> TerminalDescription
    -> CompiledTermInfoWriter.Write
```

T05 refactors that path so successful resolved `TerminalDescription` values are
retained after the in-memory representation check. Check-only mode renders the
same diagnostics and stops there. Publication mode consumes exactly those
validated descriptions.

No filesystem mutation occurs when parsing, resolution, selection, unknown-
extension policy, or representation validation reports an error.

## 4. Destination policy

An explicit `-o <directory>` is canonicalized to an absolute path and always
wins.

When `-o` is absent, the command asks the T02 Inspection database-location model
for the Runtime discovery snapshot, but considers only writable-policy
candidates:

```text
1. TermInfoDirectory     (directory-valued TERMINFO)
2. UserDatabase          (Runtime-defined user .terminfo root)
```

The following discovery locations are never selected implicitly for writes:

```text
EncodedTermInfo
TermInfoDirsDirectory
PlatformDefaultDirectory
```

If neither safe candidate exists, publication fails with `TIC0006` and tells the
caller to specify `-o`.

This is intentionally more conservative than native implementations which may
fall through to a system database.

## 5. Publication ownership

T05 publishes through:

```text
CompiledTermInfoDatabaseWriter.Write(
    root,
    validatedDescriptions,
    databaseOptions: ...
)
```

The command does not construct conventional entry paths itself.

The existing Compiler writer owns:

- canonical and alias destination derivation;
- platform filename/path validation;
- escape prevention;
- duplicate-destination detection;
- complete destination preflight;
- existing-destination rejection;
- publication-directory creation;
- reparse/link rejection;
- temporary-file staging;
- write-through flush;
- final move/replace;
- temporary-file cleanup after failure.

That boundary remains part of the frozen Compiler 1.2 public contract.

## 6. Overwrite policy

Default T05 behavior is conservative:

```text
existing destination -> failure
```

`--force` maps directly to:

```text
CompiledTermInfoDatabaseWriterOptions(
    overwriteExisting: true
)
```

There is no interactive prompt and no implicit overwrite based on terminal or
console state.

A preflight rejection occurs before staging, so a normal existing-entry failure
does not change the previously published entry.

## 7. Summary output

`-s` produces a concise successful-publication report on standard error:

```text
tic: output: <absolute root>
tic: compiled entries: <count>
tic: warnings: <count>
```

The entry count is the number of selected source entries published, not the
number of physical canonical-plus-alias files.

Without `-s`, successful publication produces no ordinary result text.

## 8. Diagnostics and status

T05 retains `TISdddd` Source diagnostics and T04 `TIC0001` through `TIC0005`.
It adds:

```text
TIC0006  safe output destination could not be resolved
TIC0007  database publication failed
```

Expected I/O, access, representation, path, and publication-policy failures are
reported as controlled diagnostics rather than stack traces.

Exit status remains:

```text
0    success
1    operational/data/publication failure
2    usage error
130  cancellation
```

## 9. Cancellation boundary

The frozen `CompiledTermInfoDatabaseWriter` API is synchronous and does not
accept a cancellation token. T05 does not enlarge the frozen Compiler public API
for command convenience.

Cancellation is therefore checked before the publication transaction begins.
Once the synchronous writer is entered, publication is treated as an indivisible
commit boundary and is allowed to finish. T05 intentionally does not return 130
after successful files have already been committed.

A later Compiler API revision may introduce cancellable staging if there is a
library-level requirement, but that is not a T05 prerequisite.

## 10. Test contract

T05 tests cover:

- explicit output roots;
- Runtime reload and semantic round-trip comparison;
- canonical and alias publication;
- multiple entries;
- `-e` selected publication;
- existing destination rejection without data change;
- `--force` replacement;
- `-s` destination/entry/warning summary;
- rejection of publication-only options with `-c`;
- explicit destination normalization;
- directory-valued `TERMINFO` preference;
- user-database fallback;
- refusal to fall through to encoded, `TERMINFO_DIRS`, or system/default roots;
- no-safe-default failure in the destination resolver;
- unsafe terminal path rejection through the Compiler writer;
- output-root-as-file failure without modifying that file;
- cancellation before mutation;
- continued T04 check-only non-mutation coverage.

The integration acceptance path is:

```text
.ti source
    -> tic
    -> CompiledTermInfoDatabaseWriter
    -> conventional database
    -> DirectoryTerminalDescriptionProvider
    -> TerminalDescriptionComparer
    -> semantic equality
```

## 11. Public API and dependency freeze

T05 adds no public member to:

```text
Icod.TermInfo
Icod.TermInfo.Source
Icod.TermInfo.Compiler
Icod.TermInfo.Inspection
```

The frozen Runtime 1.0, Source 1.1, Compiler 1.2, historical Inspection 1.3, and
active T03 Inspection 1.4 baselines remain unchanged.

`Icod.CommandFramework` remains confined to the net10.0 command layer.

## 12. Gate

T05 is complete when managed `tic` can validate and publish supported `.ti`
source into an explicit or safely selected conventional database, reject
unrequested overwrite, perform explicit forced replacement, and reload its
output through Runtime with semantic equality on Windows, Linux, and macOS.
