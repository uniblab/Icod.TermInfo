# Icod.TermInfo 1.4.0 T04 — `tic` Validation and Check-Only Mode

**Branch:** `1.4.0`
**Baseline commit:** `99e5f3e8e11dcc7af23c616270d1032683b9808a`
**Development version:** `1.4.0-Alpha-4`
**Status:** implementation candidate
**Gate:** managed `tic -c` validation with zero database mutation

---

## 1. Purpose

T04 introduces the first operational command behavior in the 1.4 tool-suite
line.

The tranche makes `tic` a useful standalone source validator before T05 is
allowed to add conventional database publication.

T04 composes existing package responsibilities rather than introducing a new
terminfo semantic layer:

```text
UTF-8 input
    |
    v
Icod.TermInfo.Source
    |  parse/classify/resolve use=
    v
TerminalDescription
    |
    v
Icod.TermInfo.Compiler
    |  in-memory representation validation
    v
validation result / diagnostics
```

No compiled entry is published to the filesystem.

---

## 2. Frozen package boundaries

T04 advances the coordinated development package version to:

```text
1.4.0-Alpha-4
```

for:

```text
Icod.TermInfo
Icod.TermInfo.Source
Icod.TermInfo.Compiler
Icod.TermInfo.Inspection
```

All four library assemblies retain:

```text
AssemblyVersion 1.0.0.0
```

T04 adds no public member to Runtime, Source, Compiler, or Inspection.

The active Inspection 1.4 API baseline therefore remains the T03 baseline
unchanged.

The `tic` command remains a `net10.0` application above the package family and
continues to depend on `Icod.CommandFramework 2.0.0` only at the command layer.

---

## 3. T04 command surface

Supported forms are:

```text
tic -c [options] file
tic -D
tic -V
tic --version
tic --help
```

`file` may be:

```text
-
```

which reads the complete source from standard input.

T04 requires exactly one source operand for validation.

The validation options are:

```text
-c
-e <name-list>
-x
```

Publication options remain unsupported until T05.

---

## 4. Source acquisition

T04 treats command source text as strict UTF-8.

The input reader:

- accepts UTF-8 without a BOM;
- accepts a UTF-8 BOM through normal .NET BOM detection;
- rejects malformed UTF-8 deterministically;
- does not infer source encoding from terminal capabilities;
- does not dispose caller-owned standard input;
- propagates command cancellation.

File-open, permission, malformed UTF-8, and ordinary I/O failures become
controlled `tic` operational diagnostics rather than stack traces.

The source identity used by diagnostics is:

```text
<stdin>
```

for standard input, or the caller-supplied file operand for file input.

---

## 5. Complete-document parsing

The complete supplied source document is parsed through
`TermInfoSourceParser` before T04 applies `-e` selection.

This is deliberate.

`-e` selects which entries undergo resolver and compiled-representation
validation. It does not make syntax or value errors elsewhere in the same input
document disappear.

Existing Source diagnostics retain their stable `TISdddd` codes, severity,
source identity, line, and column where available.

A parsed document containing no terminal entries is a command-level validation
error.

---

## 6. Entry selection

Without `-e`, every parsed source entry is selected in document order.

With:

```text
-e name1,name2,...
```

T04:

- accepts canonical source names;
- accepts aliases;
- matches case-sensitively;
- deduplicates repeated requested names;
- follows Source's deterministic first-match rule when duplicate lookup
  identities have already produced parser warnings;
- returns selected entries in source-document order rather than option-list
  order;
- reports every requested identity which matches no source entry.

An entry is validated at most once even if several requested aliases identify
it.

Resolver/representation errors in an unselected entry do not fail a selected
validation run unless that entry is required as a reachable `use=` parent.

---

## 7. Unknown extended capability policy

Source remains responsible for classifying capability names as:

```text
Standard
KnownExtended
UnknownExtended
Invalid
```

T04 adds command policy only.

Without `-x`:

- standard capabilities are accepted;
- known extended capabilities are accepted;
- syntactically valid `UnknownExtended` capabilities are rejected for every
  selected entry and every source entry reachable through its `use=` graph.

With `-x`, unknown extended capabilities may flow through the existing
Source/Compiler semantic model.

T04 does not modify Source classification rules or add new known extension
names.

---

## 8. Inheritance validation

Each selected entry is resolved through `TermInfoSourceResolver`.

The resolver remains authoritative for:

- canonical/alias lookup;
- `use=` inheritance;
- missing parent diagnostics;
- cycles;
- maximum inheritance depth;
- deterministic source-order behavior.

T04 does not implement a second inheritance algorithm.

---

## 9. Compiled representation validation

For each successfully resolved selected entry, T04 materializes the existing
`TerminalDescription` and calls:

```text
CompiledTermInfoWriter.Write(...)
```

only in memory.

This verifies that the effective entry can be represented exactly by the
supported conventional compiled formats, including existing Compiler checks for
identity, strings, numeric values, section limits, and size arithmetic.

The returned byte array is discarded after validation.

T04 SHALL NOT call:

```text
CompiledTermInfoDatabaseWriter
```

and SHALL NOT:

- create a terminfo database root;
- create first-character subdirectories;
- write compiled entries;
- overwrite compiled entries;
- choose a writable system destination.

Those responsibilities begin in T05.

---

## 10. Database-location reporting

Standalone:

```text
tic -D
```

uses the T02 `TermInfoDatabaseInspector.GetSystemLocations()` API.

It reports the ordered Runtime discovery model without loading or enumerating
entries and without exposing encoded `TERMINFO` payload bytes.

The output identifies each location kind and path. An encoded `TERMINFO` source
is represented by a non-secret placeholder rather than its encoded contents.

---

## 11. Diagnostics and exit status

Source diagnostics retain their existing `TISdddd` codes.

T04 command-policy diagnostics use a separate private command namespace:

```text
TIC0001  source contains no terminal entries
TIC0002  requested -e identity was not found
TIC0003  unknown extended capability requires -x
TIC0004  resolved entry is not representable by the compiled writer
TIC0005  source acquisition / UTF-8 / I/O failure
```

These codes are command presentation policy and are not added to a library
public API.

Diagnostics are written to stderr in deterministic source/offset order.
Line and column formatting is culture-independent.

Exit statuses use `Icod.CommandFramework.Diagnostics.CommandExitCodes`:

```text
0    successful validation, including warnings-only source
1    source/semantic/representation/operational failure
2    command usage error
130  cancellation
```

Successful `tic -c` writes no normal result text to stdout.

## 13. T04 non-goals

T04 does not implement:

```text
tic -o
tic -s
--force
default write destinations
database directory creation
compiled-entry publication
overwrite policy
termcap conversion
ncurses translation modes
```

These are intentionally outside the T04 gate.

---

## 14. Gate

T04 is complete when:

1. `tic -c` validates one complete UTF-8 source document from a file or stdin;
2. Source parser and resolver diagnostics remain authoritative;
3. `-e` and `-x` obey the documented command policy;
4. selected resolved entries pass the existing Compiler's in-memory
   representation checks;
5. warnings alone return success;
6. errors return failure and usage mistakes return the usage status;
7. cancellation returns the cancellation status;
8. no database publication path is reachable from T04 command execution;
9. all existing library API baselines remain unchanged;
10. Windows, Linux, and macOS CI remain green.

Only after this gate is green should T05 add filesystem publication.
