# Icod.TermInfo 0.9.0 — T34 ncurses Extended and `01036` Parser

**Tranche:** T34 — ncurses Extended Sections and `01036`
**Development version:** `0.9.0-alpha.3`
**Previous tranche:** T33 — legacy `0432` compiled parser
**Next tranche:** T35 — parser hardening, diagnostics, and fuzz gate

---

## Purpose

T34 completes the binary-format family frozen by T29.

The pure `CompiledTermInfoParser` now accepts both conventional base magics:

```text
0432   -> signed 16-bit standard and extended numerics
01036  -> signed 32-bit standard and extended numerics
```

Either base format may carry the selected ncurses extended section.

T34 does not add filesystem, environment, cache, provider, terminal-session, or
native-library behavior.

## Conventional numeric width

The six-short conventional header remains unchanged.

The numeric table width is selected only by the compiled magic:

```text
0x011a / 0432   -> 2 bytes
0x021e / 01036  -> 4 bytes
```

Standard string offsets remain signed 16-bit values in both formats.

All standard positions continue to map through
`StandardCapabilityCatalog.BinaryIndex`; the managed enum ordinal is not used
as a binary position.

## ncurses extended section

When bytes remain after the conventional string table, T34 applies the frozen
ncurses alignment rule and reads the five-short extended header:

1. extended Boolean count;
2. extended numeric count;
3. extended string count;
4. total extended string-table item count;
5. extended string-table byte size.

The extended body is interpreted as:

```text
extended Boolean bytes
alignment when required
extended numeric values
extended string-value offsets
extended capability-name offsets
extended string table
```

The string table stores extended string values first, followed by capability
names in exact Boolean, numeric, string order.

The item count is required to match:

```text
extended string values
+ Boolean names
+ numeric names
+ string names
```

Impossible count relationships fail before input-derived collections are
created.

## Extended string and name offsets

Extended string-value offsets are signed 16-bit values with the same frozen
sentinels as the conventional format:

```text
-1  absent
-2  canceled
```

Other negative offsets are malformed.

Capability-name offsets are non-negative signed 16-bit values relative to the
start of the name portion of the extended string table.

The name portion begins after the NUL-terminated extended string values. Names
are decoded one-to-one through Latin-1 and remain case-sensitive.

Duplicate extended names are rejected.

An extended name which equals a known standard terminfo short name is rejected
with `CompiledTermInfoFormatException`; it can never silently shadow the
standard capability catalog.

## Extended values

Extended Boolean values implement the frozen states:

```text
0x00  absent
0x01  present
0xfe  canceled
```

Extended numerics use the base entry's selected numeric width and recognize
`-1` / `-2` as absent / canceled.

Extended strings use the signed 16-bit offset contract and exact Latin-1 byte
decoding.

Canceled extended values pass through the existing internal builder
cancellation path before the immutable description is built.

## T29 fixture evidence

T34 promotes both previously reserved valid fixtures to production parser
evidence.

`t29-extended.bin` verifies:

- legacy `0432` standard numerics;
- ncurses extended Boolean values `XBool` and `xyz`;
- extended numeric `XNum=12345`;
- extended string `XStr="alpha\u001bbeta"`;
- exact case-sensitive extended names.

`t29-extended32.bin` verifies:

- `01036` detection;
- standard `colors=16777216`;
- standard `pairs=65536`;
- extended `XNum=2147483640`;
- extended Boolean and string values under the 32-bit numeric format.

The T29 malformed extended corpus verifies rejection of:

- a truncated extended header;
- impossible extended counts;
- an extended string offset outside its declared table;
- an extended name colliding with standard `cup`.

## Compatibility boundary

T34 changes no public acquisition API shape.

The public parser/options/exception surface frozen by T32 and introduced by T33
remains unchanged. The implementation is split as partial source files only to
keep conventional-format logic and ncurses extension logic reviewable.

All three T33 legacy fixtures remain parser inputs and must continue to pass
unchanged.

`TerminalDatabase.BuiltIn` remains I/O-free and no directory/system provider is
introduced.
