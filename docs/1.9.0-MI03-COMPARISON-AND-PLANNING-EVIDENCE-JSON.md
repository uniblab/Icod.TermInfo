# Icod.TermInfo 1.9.0 MI03 - Comparison and Planning Evidence JSON

**Development version:** `1.9.0-Alpha-3`
**Published baseline:** `1.8.0`
**Schema:** `urn:icod:terminfo:inspection:json:1`
**Schema version:** `1`
**Document kinds:** `comparison`; `sourcePlan`
**Status:** complete
**Next tranche:** MI04 - Database Catalog Manifests and JSON Schema

## 1. Outcome

MI03 makes the existing `TermInfoComparisonResult` and
`TerminalDescriptionSourcePlan` renderer overloads operational. It adds no
public API, dependency, command option, or schema file. The renderer reports the
supplied immutable result and does not recompute a comparison, rerun planning,
parse generated source, or reinterpret a planning score.

The `terminalDescription` payload remains frozen from MI02. Database-catalog
rendering remains deferred to MI04, when all four payload kinds and the complete
version-1 JSON Schema will be available.

## 2. Comparison payload

The comparison payload is:

```text
areEqual
differences[]
    kind
    capabilityName
    isExtendedCapability
    left
        text
        aliases
        capabilityValue
        sourceEntry
        sourceEntryIndex
        sourceField
        sourceFieldIndex
        sourceSpan
    right
        same stable side shape
```

Difference order is copied directly from `TermInfoComparisonResult.Differences`.
The renderer uses explicit lower-camel strings for all 15
`TermInfoDifferenceKind` values. It neither sorts nor groups the result.

`capabilityValue`, when present, contains `kind` followed by a JSON Boolean,
integer, or string `value`. `capabilityName` is the canonical standard short name
or exact extended name already carried by the difference. The extended flag and
all inapplicable side properties are explicit JSON null rather than omitted.

## 3. Source-aware evidence

A retained source entry is summarized by canonical name, ordered aliases,
nullable description, field count, and span. It does not recursively embed all
fields; only the source field which caused the difference is represented.

A retained source field includes field kind, source capability spelling,
classification, canonical capability name, standard value kind, `use=` reference
name, decoded numeric or string value, exact lexical text, and span. The
independent `sourceEntryIndex`, `sourceFieldIndex`, and most-specific
`sourceSpan` properties correspond directly to the managed difference.

Every span retains source name, zero-based UTF-16 offset, one-based line and
column, UTF-16 length, and exclusive end offset. Null source identity remains
JSON null.

## 4. Source-plan payload

The plan payload is:

```text
selectedParentCount
selectedParentUseNames[]
source
score
    localDirectiveCount
    cancellationCount
    parentCount
    renderedUtf8ByteCount
    selectedCandidateIndices[]
evaluatedPlanCount
isExhaustive
candidateCount
```

Parent names retain exact emitted order. `source` is the existing generated LF
source. All score components and selected candidate indices are copied from the
frozen planning score. `isExhaustive` is direct completeness evidence: false
means the result is explicitly bounded. `candidateCount` is the accepted
non-self candidate count already carried by the result.

## 5. Determinism, bounds, and cancellation

Both payloads reuse the MI02 explicit deterministic writer. Compact output is
canonical. Indented output uses LF and two spaces. Reusable strings contain no
trailing whitespace or line terminator. Strings use the default safe JSON
encoder and integers use invariant formatting.

The configured limit applies to the exact final UTF-8 byte count. Exact-boundary
documents succeed and one-byte-smaller limits fail without returning truncated
JSON. Cancellation is observed before traversal and at stable difference,
comparison-side, alias, selected-parent, and selected-index boundaries. Invalid
UTF-16 fails deterministically.

## 6. Evidence

MI03 checks:

- exact compact and indented fixtures for both document kinds;
- effective identity, standard, extended, and value-kind differences;
- deterministic managed difference order and explicit side nulls;
- source entry, field, index, classification, lexical text, and span evidence;
- selected parent order, generated source, all score components, evaluation
  count, `isExhaustive`, and candidate count;
- repeated-run and culture independence;
- exact UTF-8 boundaries, cancellation, and invalid UTF-16 failure;
- package-reference-only rendering of real comparison and plan results;
- preservation of the 31-type reviewed Inspection surface; and
- continued MI04 catalog boundary.

Command JSON modes remain owned by MI05. No command behavior changes in MI03.
