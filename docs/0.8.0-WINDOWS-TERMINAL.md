# Windows Terminal profiles in Icod.TermInfo 0.8

T28 adds two explicit built-in descriptions:

- `ms-terminal` — the ncurses Windows Terminal profile with 256 indexed colors.
- `ms-terminal-direct` — the ncurses Windows Terminal profile with direct RGB color.

The transcription baseline is ncurses `terminfo.src` revision 1.1267
(2026-08-14). The source entries compose `xterm+256color` or `xterm+direct`
with the shared `ms+terminal` building block. `Icod.TermInfo` mirrors that
composition using the existing generic xterm/color fragments only where the
source actually inherits them.

## Windows Terminal is not xterm

The names above are first-class terminal identities. They are not aliases for
`xterm`, `xterm-256color`, or `xterm-direct`.

The shared Windows Terminal source block carries its own behavior, including:

- DEL (`0x7f`) as the backspace-key sequence;
- Windows Terminal's `cud1`, `kbeg`, `kcbt`, `smkx`, and `rmkx` strings;
- explicit cancellation of `oc`, `smm`, and `rmm`;
- bracketed-paste metadata;
- SGR any-event mouse metadata;
- focus reporting;
- DA2 reporting with the Windows Terminal response pattern;
- VT420-style left/right margin controls;
- ECMA-48 overline, italics, and strikeout metadata;
- the BEL-terminated `xterm+tmux` cursor/clipboard metadata.

The indexed profile retains the source `xterm+256color` semantics: 256 colors,
65536 color pairs, palette initialization, and no effective `oc` because
`ms+terminal` cancels it.

The direct profile retains the source `xterm+direct` semantics: packed 24-bit
RGB, 65536 color pairs, an eight-entry indexed prefix through extended `CO`,
and extended `RGB` metadata. Direct color is interpreted by the existing
generic `TerminalColors` engine; there is no Windows-Terminal-specific color
branch.

## Selection remains explicit

`WT_SESSION`, `WT_PROFILE_ID`, and `COLORTERM` are not terminal identities and
do not cause `Icod.TermInfo` to select or mutate a profile.

`TerminalEnvironment` continues to resolve only the caller-visible `TERM`
value through the configured `TerminalDatabase`. Applications which know that
their session is Windows Terminal may select `ms-terminal` or
`ms-terminal-direct` explicitly.

Loading either profile is data-only. It does not enable Windows virtual
terminal processing and does not call Windows Console mode APIs.
`WindowsVirtualTerminal` remains the separate, explicit, reversible mechanism
for changing host console output mode.
