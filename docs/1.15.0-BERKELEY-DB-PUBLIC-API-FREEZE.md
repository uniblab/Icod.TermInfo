## Frozen public types

The nine type blocks cover:

- the explicit hashed-file terminal-description provider and its options;
- the opt-in hashed-aware system provider and its options;
- the explicit hashed-file logical catalog reader and its options;
- immutable logical catalog entries and their canonical/alias kind; and
- the package-specific malformed/unsupported database exception.

HDB09 adds no type, member, overload, default value, nullability annotation,
interface, or inheritance change to the accepted Alpha-8 contract.

## Runtime reconstruction and dependency direction

`Icod.TermInfo.BerkeleyDb` depends only on the matching coordinated
`Icod.TermInfo` Runtime package. Runtime retains its complete frozen 1.0 public
API baseline and does not reference BerkeleyDb. Source and Termcap continue to
depend only on Runtime; Compiler and Inspection continue to depend on Runtime
and Source. Inspection remains provider-neutral.

The normal release gate still reconstructs Runtime against
`docs/1.0.0-PUBLIC-API-BASELINE.txt` and retains the established Source,
Compiler, Termcap, and Inspection compatibility checks. The new BerkeleyDb
baseline is an additional exact gate, not a replacement for those authorities.

## Distribution boundary

The public freeze does not broaden the supported Berkeley DB surface. The
package remains pure managed and read only, contains no native runtime assets,
and supports only the reviewed ncurses-compatible Berkeley DB Hash-v9 subset.
Exact dependency, assembly, symbol, Source Link, and asset validation remains
owned by the managed BerkeleyDb package verifier.
