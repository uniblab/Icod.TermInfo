# Icod.TermInfo 1.3.0 I04 — Effective Semantic Comparison and Structured Differences

**Tranche:** I04
**Development version:** `1.3.0-Alpha-4`
**Assembly version:** `1.0.0.0`
**Package:** `Icod.TermInfo.Inspection`

## 1. Purpose

I04 adds the first comparison engine to the Inspection package. It compares two
immutable effective `TerminalDescription` values directly and returns a stable,
machine-readable result.

The comparison path is deliberately independent of rendering:

```text
TerminalDescription left ─┐
                          ├─> TerminalDescriptionComparer
TerminalDescription right ┘              │
                                         v
                              TermInfoComparisonResult
                                         │
                                         v
                              TermInfoDifference[]
```

No source rendering, textual diffing, or human-output parsing is required.

## 3. Difference categories

`TermInfoDifferenceKind` distinguishes:

```text
IdentityName
IdentityAliases
IdentityDescription
OnlyInLeft
OnlyInRight
DifferentValue
DifferentValueKind
```

The first three categories are identity metadata. The remaining categories are
capability differences.

`DifferentValueKind` is used by I04 when the same case-sensitive extended
capability name exists on both sides with different Runtime value kinds.
Standard capabilities have a fixed semantic value kind and therefore cannot
produce this category.

## 4. Identity comparison

Identity metadata is compared before capabilities, in this fixed order:

1. canonical name;
2. ordered aliases;
3. description.

Canonical names, aliases, and descriptions use ordinal string comparison.
Aliases are compared as an ordered sequence rather than as a set, matching the
observable `TerminalDescription.Aliases` contract.

Identity differences do not masquerade as capabilities. Their
`CapabilityName`, `IsExtendedCapability`, and capability-value properties remain
null. Name and description differences use `LeftText` / `RightText`; alias
differences carry immutable left/right alias lists.

## 5. Standard capability comparison

Standard capabilities are compared by Runtime semantic identity rather than by
display text or enum ordinal.

I04 walks:

```text
StandardCapabilityCatalog.BooleanCapabilities
StandardCapabilityCatalog.NumericCapabilities
StandardCapabilityCatalog.StringCapabilities
```

in their existing compiled-table order.

This produces a deterministic order of:

```text
standard Boolean differences
standard numeric differences
standard string differences
```

For every standard difference, `CapabilityName` is the canonical terminfo short
name and `IsExtendedCapability` is false.

Effective Boolean presence is represented as a Boolean
`TermInfoCapabilityValue(true)`. Numeric and string values retain their Runtime
types. Absence is represented by a null value on the missing side.

## 6. Extended capability comparison

Extended capabilities are matched using exact ordinal, case-sensitive names.
The union of left and right names is ordered with `StringComparer.Ordinal`.
Dictionary insertion order is never observable in the comparison result.

For each extended name:

- a left-only name produces `OnlyInLeft`;
- a right-only name produces `OnlyInRight`;
- the same name with different value kinds produces `DifferentValueKind`;
- the same name and kind with different values produces `DifferentValue`;
- equal values produce no difference.

The original `TermInfoCapabilityValue` instances are copied by value into the
structured result, so Boolean/numeric/string type information remains available
to callers without parsing presentation text.

## 7. Result immutability and input stability

`TermInfoComparisonResult.Differences` is an immutable read-only snapshot.
Alias sequences carried by `TermInfoDifference` are copied into read-only
snapshots as well.

The comparer does not alter either `TerminalDescription`. Runtime descriptions
are already immutable; I04 additionally avoids any operation which could expose
or depend on mutable enumeration state.

Self-comparison therefore obeys:

```text
Compare(x, x).AreEqual == true
Compare(x, x).Differences.Count == 0
```

## 8. Left/right reversal invariant

I04 tests the algebraic reversal rule:

```text
Compare(a, b)
Compare(b, a)
```

produce corresponding differences in the same deterministic subject order.
For the reversed result:

- `OnlyInLeft` becomes `OnlyInRight`;
- `OnlyInRight` becomes `OnlyInLeft`;
- identity, value, and value-kind categories retain their category;
- left/right metadata and capability values exchange sides.

This property makes the model suitable for tests and future presentation layers
without requiring a textual diff parser.

## 9. Effective-domain boundary

I04 operates only on `TerminalDescription` and therefore intentionally cannot
report:

- source cancellation tombstones;
- disabled source fields;
- `use=` references;
- duplicate source declarations;
- source field order;
- comments;
- source spans;
- inheritance provenance.

No cancellation/provenance category is introduced in the effective difference
model. Source-aware comparison is reserved for I05, where the unresolved Source
model is actually available.

## 10. Validation added by I04

Inspection tests cover:

- self-comparison;
- structured name/alias/description differences;
- canonical standard Boolean/numeric/string comparison ordering;
- typed standard values;
- case-sensitive extended names;
- extended left-only and right-only values;
- extended value differences;
- extended value-kind mismatches;
- deterministic extended-name ordering independent of insertion order;
- left/right reversal;
- input non-mutation;
- null-argument validation.

The package-reference-only Inspection smoke consumer also performs an I04
self-comparison, proving that the structured comparer surface is available from
the packed package rather than only through project references.
