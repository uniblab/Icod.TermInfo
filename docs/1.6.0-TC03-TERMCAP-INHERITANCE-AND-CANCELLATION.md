# Icod.TermInfo 1.6.0 TC03 — Termcap Inheritance and Cancellation

**Development version:** `1.6.0-Alpha-3`
**Tranche:** TC03
**Status:** Implementation patch

## Objective

TC03 adds bounded, deterministic `tc=` inheritance resolution to the opt-in
`Icod.TermInfo.Termcap` package. Resolution remains a termcap-source operation:
it does not convert fields into Runtime capability values and does not construct
`TerminalDescription`.

The resolver is intentionally independent of `Icod.TermInfo.Source`. It does not delegate to
`TermInfoSourceResolver`; termcap `tc=` syntax, lookup, precedence, and
cancellation remain separately testable from terminfo `use=` semantics.

## Resolver surface

The TC03 public surface is centered on:

```text
ITermcapSourceEntryProvider
TermcapSourceResolverOptions
TermcapSourceResolver
TermcapSourceResolveResult
TermcapSourceResolvedEntry
TermcapSourceResolvedField
```

`TermcapSourceResolver.Resolve` accepts either a parsed `TermcapSourceDocument`
or a caller-supplied `ITermcapSourceEntryProvider`. Provider exceptions propagate
to the caller. A clean provider miss becomes a deterministic source diagnostic.
No file-system, `TERMCAP`, `TERMPATH`, or process-global database lookup occurs in
TC03.

For document-backed resolution, every TC01 header component remains an exact,
case-sensitive lookup identity. TC03 deliberately does not decide which header
component is a canonical terminal name, alias, or prose description. If the same
component appears in multiple entries, the first entry in source order wins
deterministically.

## Precedence and cancellation

Resolution follows historical termcap lookup priority:

1. inspect the referring entry's local fields in source order;
2. the first local occurrence of an exact two-character capability code claims
   that code;
3. a local active field supplies the effective value;
4. a local `xx@` field claims the code but supplies no effective value, thereby
   suppressing inherited occurrences;
5. period-prefixed disabled fields do not claim a capability code;
6. after local fields, resolve the final `tc=` parent and inherit only capability
   codes not already claimed locally;
7. repeat recursively for the parent chain.

The result therefore contains at most one effective field for each exact
termcap capability code. Unmapped/vendor codes participate in the same precedence
and cancellation rules; TC03 does not require a TC02 Runtime mapping before
resolving a source field.

Cancellation is represented as absence from the resolved effective-field list.
The unresolved source entries remain available to callers, and every effective
`TermcapSourceResolvedField` retains its original `TermcapSourceField`, the
`TermcapSourceEntry` which supplied it, and its inheritance depth. Source spans
therefore survive resolution without being rewritten.

## Bounds and failures

`TermcapSourceResolverOptions` defaults to 64 inheritance edges and accepts a
maximum caller-selected bound of 256. A value of zero permits only a root entry
which does not require parent resolution.

TC03 adds resolver diagnostics:

```text
TCAP0017  missing source entry
TCAP0018  inheritance cycle
TCAP0019  maximum inheritance depth exceeded
```

Direct and indirect cycles are detected by active requested names and by the
identity of entries returned by the provider, so aliases which lead back to the
same parsed entry cannot evade cycle detection. Resolver diagnostics retain the
`tc=` source span which triggered the failing edge whenever one exists.

Provider contract violations are programming errors rather than source errors:
reporting success with a null entry, or a clean miss with a non-null entry,
throws `InvalidOperationException`.

## Boundary retained for TC04

TC03 deliberately does not:

- classify a field again while resolving it;
- convert an effective field into a standard Runtime capability;
- decide whether an obsolete alias is exact, approximate, or lossy;
- choose canonical terminal-name / alias / description semantics;
- construct `TerminalDescription`;
- inspect environment variables or conventional termcap database paths;
- add command or router behavior.

TC04 receives the resolved source field set and performs the first semantic
termcap-to-terminfo conversion step, including structured loss diagnostics.

## TC03 gate

TC03 is complete when local-over-inherited precedence, cancellation across
multiple levels, disabled fields, exact-code vendor inheritance, document and
provider lookup, missing references, direct and indirect cycles, source
provenance, and the configurable depth bound behave deterministically on all
three target frameworks while the package remains dependent only on Runtime.
