# Icod.TermInfo 1.14.0 RB01 — Contract and Public-API Regret Gate

## Scope

RB01 freezes the additive public vocabulary and immutable data shapes for raster-backend availability evidence and later backend selection. It intentionally adds no backend classifier, static inspector, candidate evaluator, or selection planner behavior.

## Bounds

Backend evidence reuses the proven Inspection resource limits:

- default evidence count: 256;
- maximum supported evidence count: 4096;
- source-label maximum: 256 UTF-16 code units.

The closed two-backend vocabulary bounds both selection candidates and explicit preference entries to two. Preference entries must be defined and unique.

## Lifecycle-only request correction

The initial planning sketch made `PersistentRasterPlacementRequest` mandatory. RB01 corrects that before the public API is released:

```csharp
RasterBackendSelectionRequest(
    PersistentRasterLifecycleRequest lifecycleRequest,
    PersistentRasterPlacementRequest? placementRequest = null
)
```

`PlacementRequest = null` means no advanced 1.12 placement semantics are requested. This is necessary because the frozen `PersistentRasterPlacementRequest` intentionally rejects an empty request. RB03 therefore invokes the frozen placement planner only when a non-null placement request exists.

## Ownership boundary

RB01 preserves these invariants:

- backend availability is not lifecycle or placement truth;
- 1.11 lifecycle semantics remain authoritative;
- 1.12 placement semantics remain authoritative;
- 1.13 runtime observations remain backend-neutral and unchanged;
- no public TermInfo API probes a terminal or executes Sixel/Kitty Graphics;
- no terminal-name or emulator-brand heuristics are permitted;
- no hidden backend ranking is introduced.

Derived profile/evaluation/plan constructors remain library-owned. Callers construct evidence, candidates, requests, and explicit preference options.
