# Icod.TermInfo 0.9.0 — T35 Parser Hardening, Diagnostics, and Fuzz Gate

**Tranche:** T35 — Parser Hardening, Diagnostics, and Fuzz Gate
**Development version:** `0.9.0-alpha.4`
**Previous tranche:** T34 — ncurses extended sections and `01036`
**Next tranche:** T36 — explicit directory provider

---

## Purpose

T35 hardens the pure compiled-entry parser before any filesystem or environment
provider begins feeding it arbitrary external database content.

T35 does not expand the supported binary family. The supported formats remain:

```text
0432
01036
0432 + selected ncurses extended section
01036 + selected ncurses extended section
```

No new public parser API is introduced.

## Bounds audit

The public whole-entry bound frozen by T32 remains authoritative:

```text
default maximum:     1,048,576 bytes
maximum supported:  16,777,216 bytes
```

It is checked before header walking or any input-derived parser allocation.

The conventional and ncurses section size/count fields are 16-bit values.
Consequently a declared names table, conventional string table, or ncurses
extended string table can never exceed 65,535 bytes within the selected
format. T35 deliberately does not add a second public per-string limit which
would overlap those wire-format bounds.

Standard Boolean, numeric, and string counts are now rejected against the
frozen `StandardCapabilityCatalog` before conventional section walking.

The ncurses extended header is also checked before body walking:

- the frozen string-table item relationship must be exact;
- the required number of non-empty extended capability names cannot exceed the
  declared extended string-table byte count;
- count arithmetic is kept on the `CompiledTermInfoFormatException` path.

## Extended string-table hot path

T34 resolved every extended string/name offset by searching forward for a NUL
terminator. That approach was bounded by the 16-bit table size but could repeat
the same scan for many attacker-controlled offsets.

T35 constructs one terminator index after the complete extended layout and
string-table bounds have been validated.

The index:

- contains exactly one `int` per declared extended string-table byte;
- is therefore bounded to 65,535 elements;
- is allocated only after the owning table is proven to exist;
- is filled in one reverse pass;
- makes each later NUL-termination lookup constant-time.

This removes repeated full-table scans from malformed/adversarial extended
entries without changing the decoded byte semantics.

## Diagnostic stability

Input-derived failures continue to use
`CompiledTermInfoFormatException`.

T35 locks representative section/offset vocabulary for:

```text
header
names
booleans
numerics
string-offsets
string-table
extended-header
extended-booleans
extended-numerics
extended-string-offsets
extended-name-offsets
extended-string-table
extended-names
entry
```

In particular, an out-of-range extended string-value offset is diagnosed as
`extended-string-offsets`, while an out-of-range extended capability-name
offset is diagnosed as `extended-name-offsets`. Missing NUL termination remains
a string/name data error rather than an offset-table error.

Repeated parsing of the same malformed bytes must produce the same section,
offset, and message.

## Truncation gate

T35 walks every strict byte prefix of every checked-in valid T29 parser fixture.

For legacy entries, every strict prefix must fail with
`CompiledTermInfoFormatException`.

For entries carrying an ncurses extension, the complete conventional prefix is
itself a valid conventional entry; every other strict prefix must fail through
the compiled-format exception contract.

This exercises truncation through:

- conventional header;
- names;
- Boolean table;
- alignment;
- 16-bit and 32-bit numeric tables;
- conventional string-offset table;
- conventional string table;
- extended alignment;
- extended header;
- extended Boolean table;
- extended numeric table;
- extended string-value offsets;
- extended capability-name offsets;
- extended string table.

## Adversarial count and offset gate

T35 adds deterministic tests for:

- maximum standard table counts;
- maximum declared names size with missing bytes;
- maximum declared conventional string-table size with missing bytes;
- impossible extended name/table population;
- maximum extended count combinations;
- conventional string offsets beyond their table;
- extended string offsets beyond their table;
- extended name offsets beyond their table;
- invalid negative 32-bit standard numerics;
- invalid negative 32-bit extended numerics.

These cases must never leak `OverflowException`,
`ArgumentOutOfRangeException`, or span-slicing exceptions.

## Deterministic mutation/fuzz gate

Normal tests now include two deterministic fuzz-style families.

First, 512 pseudo-random byte arrays are generated from a fixed seed. Half are
forced to begin with one of the two supported magic values so parsing proceeds
past magic validation more often.

Second, every valid T29 parser fixture is subjected to 128 deterministic
bit-mutation cases.

A mutation may still describe a valid terminal. If parsing fails, however, the
failure must remain `CompiledTermInfoFormatException`; malformed external bytes
must not expose parser implementation exceptions.

The fixed seeds make failures reproducible in CI.

## Failure atomicity

The parser still owns its builder privately and returns a
`TerminalDescription` only after the complete conventional and optional
extended entry has been consumed successfully.

T35 additionally verifies that:

- a failed parse does not mutate the caller's byte array;
- a failed parse does not contaminate a subsequent valid parse;
- no partially populated terminal description is observable.

## Native and acquisition purity

T35 adds a reflection gate proving that no method declared by
`CompiledTermInfoParser` is a P/Invoke/native entry point.

The earlier 0.9 architecture guards remain in force as well:

- `TerminalDatabase.BuiltIn` remains I/O-free;
- no T36 directory provider exists yet;
- no T37/T38 environment/system provider exists yet;
- the parser accepts bytes and explicit parser options only;
- the parser does not invoke ncurses/libtinfo at runtime.

## Optional maintainer ncurses differential check

Normal build/test remains native-tool-free.

Maintainers who have the pinned T29 ncurses baseline installed may perform the
existing fixture provenance check:

```text
dotnet run --project tools/compiled-terminfo-fixtures/Icod.TermInfo.FixtureGenerator.csproj
git diff --exit-code -- tests/Icod.TermInfo.Tests/fixtures/compiled-terminfo
dotnet test tests/Icod.TermInfo.Tests/Icod.TermInfo.Tests.csproj
```

The fixture generator requires the frozen `tic -V` identity and refuses to
silently regenerate from another ncurses version. A clean fixture diff followed
by the parser test suite therefore provides an optional differential check
against the ncurses compiler without making ncurses a build, test, package, or
runtime dependency.

## Completion evidence

T35 is complete when:

- both project version fields are `0.9.0-alpha.4`;
- impossible conventional counts fail before section walking;
- impossible ncurses count/table relationships fail before body walking;
- extended string termination lookups are bounded and indexed;
- byte-prefix truncation gates cover every valid parser fixture;
- count/offset adversaries remain inside the compiled-format exception contract;
- diagnostic section/offset behavior is deterministic;
- deterministic random/mutation fuzz tests expose no parser implementation
  exception;
- failed parses expose no partial result and contaminate no later parse;
- the parser declares no native entry points;
- T33/T34 valid fixtures continue to parse unchanged;
- no filesystem/environment/provider behavior enters the parser.

T36 may now introduce an explicit one-root directory provider on top of this
hardened pure-byte parser.
