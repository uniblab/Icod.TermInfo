# Icod.TermInfo 1.11.0 Inspection Public API Freeze

## Exact surface identity

The complete `Icod.TermInfo.Inspection` 1.11 public reflection manifest is frozen by normalized-LF SHA-256:

```text
69c7350d5d44d502ecf1698c8fe1c1336f03d38eb1a36e36219f50ac33585a86
```

The manifest uses `Icod.TermInfo.PublicApiSnapshot/v1`, retains assembly version `1.0.0.0`, and contains exactly 67 exported public types. The release verifier generates the complete manifest from each candidate assembly and rejects any hash other than the value above.

## Compatibility decomposition

The 1.11 freeze is intentionally expressed as a composite rather than duplicating the entire historical manifest in another large checked-in text file:

1. the complete 1.10 Inspection manifest remains frozen in `docs/1.10.0-INSPECTION-PUBLIC-API-BASELINE.txt`;
2. the exact 16 new 1.11 persistent-raster lifecycle type blocks are listed in `docs/1.11.0-INSPECTION-PUBLIC-API-ADDITIONS.txt`;
3. the exact six additive `TermInfoJsonRenderer` member lines are listed in `docs/1.11.0-INSPECTION-PUBLIC-API-ADDITIVE-MEMBERS.txt`; and
4. the complete resulting 1.11 manifest is independently locked by the SHA-256 above.

This gives two simultaneous release guarantees:

- removing the reviewed 1.11 delta must reproduce the frozen 1.10 manifest exactly; and
- the complete 1.11 manifest must match the frozen whole-surface hash exactly.

An accidental change to either a historical member or a reviewed 1.11 addition therefore fails release verification.

## Lower-layer contracts

## Machine-readable contracts

Public API freeze is independent from JSON schema freeze. The v1, v2, and v3 schema fingerprints are recorded in `docs/1.11.0-RL08-FREEZE-FINGERPRINTS.txt` and verified independently.
