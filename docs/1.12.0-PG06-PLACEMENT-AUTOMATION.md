# Icod.TermInfo 1.12.0 PG06 — Placement Automation

PG06 introduces the additive machine-readable contract for the advanced persistent-raster placement semantics established in PG01 through PG05.

## Version identity

PG06 owns JSON Schema version 4 only:

- schema identifier: `urn:icod:terminfo:inspection:json:4`
- schema version: `4`
- schema file: `docs/Icod.TermInfo.Inspection.schema.v4.json`

Versions 1, 2, and 3 remain frozen historical contracts. PG06 does not alter their schema files, identifiers, document kinds, renderer behavior, or fingerprints.

## Document kinds

Version 4 defines exactly two document kinds:

- `persistentRasterPlacementProfile`
- `persistentRasterPlacementPlan`

The profile document serializes the two PG01 subjects (`sourceRectangle` and `signedZOrder`), their classified support states, and the canonical PG02 evidence sequence.

The plan document serializes the PG04 planning result, prerequisite lifecycle-plan status, requested placement requirements, and structured placement issues.

## Determinism and bounds

Rendering uses the existing `BoundedJsonOutput` and `DeterministicJsonWriter` infrastructure. Property order, subject order, evidence order, requirement order, issue order, enum spellings, and numeric formatting are invariant across cultures and repeated process-local renders.

The existing `TermInfoJsonRendererOptions.MaximumOutputByteCount` limit applies to version-4 documents. Exact-size output succeeds; one-byte-too-small output fails closed. Cancellation is observed at entry and deterministic collection boundaries.

## Public API additions

PG06 adds no new public type. It adds six reviewed public members to the already-existing `TermInfoJsonRenderer` type:

- `PersistentRasterPlacementSchemaIdentifier`
- `PersistentRasterPlacementSchemaVersion`
- `Render(PersistentRasterPlacementProfile)`
- `Render(PersistentRasterPlacementProfile, TermInfoJsonRendererOptions, CancellationToken)`
- `Render(PersistentRasterPlacementPlan)`
- `Render(PersistentRasterPlacementPlan, TermInfoJsonRendererOptions, CancellationToken)`

Their exact reflection-manifest lines are recorded in `docs/1.12.0-PG06-INSPECTION-PUBLIC-API-ADDITIVE-MEMBERS.txt`.

The compatibility verifier reconstructs the frozen 1.11 Inspection surface by removing both the cumulative reviewed `PersistentRasterPlacement*` types and these six PG06 renderer members before checking the frozen 1.11 SHA-256. It then reconstructs the frozen 1.10 surface using the established 1.11 lifecycle ledgers.

## Packaging

`Icod.TermInfo.Inspection` packages `Icod.TermInfo.Inspection.schema.v4.json` alongside the frozen version-1, version-2, and version-3 schemas. PG06 tests freeze the v4 schema fingerprint and package-project wiring while reasserting the historical schema fingerprints.

## Explicit non-goals

PG06 does not add protocol/backend selection, terminal-brand guessing, raw Kitty protocol fields, raster pixel payloads, placement coordinates, z-order values, relative-placement graphs, Unicode placeholders, animation, absolute screen coordinates, scene graphs, or live probing owned by the execution layer.

Those exclusions preserve the 1.12 architecture: TermInfo describes and plans placement semantics; execution remains outside this package.
