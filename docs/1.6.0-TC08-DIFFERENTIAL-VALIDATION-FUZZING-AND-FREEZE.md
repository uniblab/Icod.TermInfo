# Icod.TermInfo 1.6.0 TC08 — Differential Validation, Fuzzing, and Freeze

**Tranche:** TC08
**Development version:** `1.6.0-Alpha-8`
**Status:** Implemented for validation

## Purpose

TC08 closes the 1.6 termcap feature line. It does not add another semantic layer.
It validates the TC01-TC07 implementation as one pipeline, freezes the active
Termcap package surface, and converts the release-time assumptions introduced by
TC07 into explicit package gates.

## Corpus and hostile-input closure

The checked-in TC08 corpus contains BSD-style and GNU/ncurses-style descriptions
covering comments, blank lines, physical-line continuation, empty fields,
`tc=` inheritance, cancellation, disabled fields, decimal/octal/hex numeric
spelling, historical string escapes, classic `%` parameter programs, padding,
and a representable two-character extended capability.

Closure tests run the corpus through:

```text
termcap source
    -> TermcapSourceParser
    -> TermcapSourceResolver
    -> TermcapConverter
    -> TerminalDescription
    -> TermcapRenderer
    -> parse / resolve / convert again
```

The reverse text must be deterministic and the selected Runtime semantics must
survive the round trip. Separate cases retain observable exact, extended,
historical-alias, approximation, unsupported, and unrepresentable decisions
from the earlier tranches.

The parser boundary tests freeze every adopted control/backslash escape and the
one-byte octal range. Literal NUL, escaped NUL, octal values above `0xff`, signed
32-bit numeric overflow, incomplete escapes, malformed records, cycles, and
configured inheritance-depth exhaustion remain deterministic failures.

A seeded 256-case mutation corpus perturbs delimiters, escapes, numeric markers,
inheritance punctuation, line endings, and NUL. Every mutation is parsed twice
under an explicit 4096-character source bound; parse diagnostics must be stable,
and any syntactically valid result is passed through the resolver with an
explicit depth bound of eight. This is intentionally bounded mutation testing,
not an unbounded random fuzzer.

Host `captoinfo` / `infotocap` comparison remains optional. Normal CI is fully
self-contained and does not require ncurses or a host termcap database.

## Public API regret review and freeze

TC08 reviewed the accumulated TC01-TC06 reusable surface and retained it without
new public members. The active package API is frozen in:

`docs/1.6.0-TERMCAP-PUBLIC-API-BASELINE.txt`

The green Alpha-7 PR validation ran the repository's existing
`Icod.TermInfo.PublicApiSnapshot/v1` reflection manifest over the Termcap
assemblies and reported SHA-256
`1e24b8a555b506594c58cf58d03bf87b2b60192f6316537cb4200498c6a92ab0` for net8.0, net9.0, and net10.0. TC08 freezes that exact rich-manifest
fingerprint, which covers the same exported-type/member/enum/default/nullability
contract used by the older package baselines. The checked-in baseline also
contains the 241 sorted XML documentation member IDs from the validated package
as a human-reviewable inventory. Release verification enforces the rich-manifest
fingerprint, cross-TFM equivalence, and packaged XML-ID inventory independently.

## Structural package verification

`tools/termcap-package-verifier` now verifies the packed artifact itself:

- `lib/net8.0`, `lib/net9.0`, and `lib/net10.0` each contain only the Termcap DLL
  and matching XML documentation payload for this package;
- assembly identity remains `Icod.TermInfo.Termcap, Version=1.0.0.0`, unsigned;
- each target-framework dependency group contains exactly one dependency,
  matching-version `Icod.TermInfo`;
- the package contains no `runtimes/` payload and does not acquire Source,
  Compiler, Inspection, or command dependencies;
- README/icon/license/repository metadata remain present;
- portable symbols and Source Link retain the package commit;
- each packaged XML documentation surface matches the frozen TC08 baseline.

`tools/termcap-package-smoke` is copied to a temporary directory before restore,
so it cannot see project references or stale repository binaries. It installs
only the packed `Icod.TermInfo.Termcap` package from the local artifact source and
executes parsing, inheritance, Runtime conversion, reverse rendering, and inline
acquisition on `net8.0`, `net9.0`, and `net10.0`.

Both Windows and POSIX release-verification wrappers run these gates.

## Coordinated release accounting

TC08 re-verifies the TC07 release model rather than changing it:

- six `.nupkg` packages are published: Runtime, Source, Termcap, Compiler,
  Inspection, and Tools;
- the five reusable libraries contribute `.snupkg` symbol packages;
- six RID-specific standalone tool archives remain attached;
- there are therefore **17** package/archive files before checksumming and **18**
  GitHub Release assets after `SHA256SUMS.txt` is added.

The release workflow must continue to publish
`Icod.TermInfo.Termcap.<version>.nupkg` to NuGet.org and GitHub Packages and attach
its symbol package to the GitHub Release.

## Trusted publishing prerequisite

NuGet.org trusted-publishing authorization for the new
`Icod.TermInfo.Termcap` package ID is an external account/repository operation;
it cannot be truthfully created or proven by repository source. Before a stable
`v1.6.0` tag is pushed, the maintainer must confirm that the package ID is
created/authorized for this repository's release workflow. TC08 freezes this as
a release prerequisite rather than pretending that a source test can grant the
NuGet.org permission.

## Completion gate

TC08 is complete for code review when the Alpha-8 branch demonstrates that:

1. the checked-in corpus and hostile-input/mutation tests pass on all supported
   Termcap target frameworks;
2. the frozen API baseline matches all packaged target frameworks;
3. package-reference-only Termcap consumers execute on net8/net9/net10;
4. the Runtime-only dependency and symbol/Source Link structure pass package
   verification;
5. the TC07 command/router/archive smoke remains green on Windows, Linux, and
   macOS;
6. release accounting remains 17 pre-checksum files and 18 final assets; and
7. trusted-publishing authorization is confirmed before the stable tag.

No Runtime, Source, Compiler, Inspection, `tic`, `infocmp`, `toe`, `captoinfo`,
`infotocap`, or router semantic change is introduced by TC08.
