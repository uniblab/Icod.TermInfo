## Classification contract

`RasterBackendClassifier.Classify(...)` classifies one requested backend at a time. Evidence belonging to any different backend is rejected rather than silently ignored.

Evidence provenance precedence is exactly:

```text
Verified > Declared > CapabilityDerived
```

Only the highest precedence present determines support state:

- positive only => `Supported`;
- negative only => `Unsupported`;
- both polarities => `Contradicted`;
- no evidence => `Unknown`.

Lower-precedence evidence never changes a higher-precedence result, but the complete canonical bounded evidence snapshot remains attached to the returned profile for auditability.

## Static inspection contract

`RasterBackendInspector` recognizes exactly one static raster-backend advertisement in RB02:

```text
extended Boolean capability: Sixel
```

For `RasterBackendKind.Sixel`, exact Boolean presence yields one positive `CapabilityDerived` evidence item with source label `Sixel` and source ordinal `0`. Absence remains `Unknown` and does not manufacture negative evidence. A capability named `Sixel` with a non-Boolean value is rejected as invalid authoritative metadata.

RB02 intentionally derives no Kitty Graphics evidence from `TerminalDescription`. Names such as `kitty`, `xterm-kitty`, `WindowsTerminal`, or `xterm-256color`, built-in profile identity, unrelated extensions, and Sixel metadata do not imply Kitty Graphics availability. Kitty therefore remains `Unknown` until stronger caller/runtime evidence exists.
