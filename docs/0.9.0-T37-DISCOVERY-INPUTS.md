# Icod.TermInfo 0.9.0 — T37 Encoded `TERMINFO` and Discovery Inputs

**Tranche:** T37 — Encoded `TERMINFO` and Discovery Inputs
**Development version:** `0.9.0-beta.1`
**Previous tranche:** T36 — explicit directory provider
**Next tranche:** T38 — system discovery and precedence

---

## Purpose

T37 freezes and implements every non-filesystem acquisition input needed by the
future system provider without yet introducing that provider.

The tranche adds:

- bounded ncurses-style `TERMINFO=hex:` decoding;
- bounded ncurses-style `TERMINFO=b64:` decoding;
- exact canonical-name/alias verification after encoded parsing;
- immutable system-discovery options;
- an internal, injectable environment/discovery snapshot;
- platform-safe `TERMINFO_DIRS` splitting;
- empty-component expansion against a caller-supplied default-root set;
- deterministic canonical root deduplication.

T38 remains responsible for the public `SystemTerminalDescriptionProvider`,
actual `TERMINFO` directory-location precedence, user-local discovery, and the
frozen Linux/macOS/Windows default-root sets.

## Public system-discovery options

T37 introduces the T32-frozen public options shape:

```csharp
public sealed class SystemTerminalDescriptionProviderOptions
{
    public SystemTerminalDescriptionProviderOptions(
        bool useEnvironment = true,
        bool useUserDatabase = true,
        bool useSystemDatabases = true,
        CompiledTermInfoParserOptions? parserOptions = null);

    public bool UseEnvironment { get; }
    public bool UseUserDatabase { get; }
    public bool UseSystemDatabases { get; }
    public CompiledTermInfoParserOptions ParserOptions { get; }
}
```

The parser options are snapshotted by value into a new immutable
`CompiledTermInfoParserOptions` instance.

The three Boolean properties remain independent trust/search controls. T37 does
not infer one from another.

## Encoded `TERMINFO`

The encoded prefixes are case-sensitive and exact:

```text
hex:
b64:
```

A value without either prefix is not interpreted by the T37 encoded-input
helper. In T38, such a `TERMINFO` value may instead identify an explicit
database location.

### Hexadecimal

The `hex:` form accepts ASCII hexadecimal pairs, case-insensitively.

Rules:

- the payload length must be even;
- every payload character must be hexadecimal;
- the decoded byte count is calculated and checked before allocating the output
  byte array;
- the decoded length cannot exceed
  `CompiledTermInfoParserOptions.MaximumEntrySize`.

Malformed hexadecimal transport syntax throws `FormatException`.

### Base64

The `b64:` form accepts:

- ordinary RFC-style Base64 using `+` and `/`;
- the URL/filename-safe `-` and `_` alphabet;
- padded input;
- valid unpadded input whose omitted `=` padding can be derived exactly.

Whitespace is not accepted inside the encoded environment value.

Padding position/count and decoded length are validated before allocating the
decoded output. The decoded length cannot exceed the configured parser maximum.

Malformed Base64 transport syntax throws `FormatException`.

## Common parser and exception boundary

After successful transport decoding, bytes are passed directly to:

```text
CompiledTermInfoParser.Parse
```

No second compiled-entry parser exists.

Consequently:

```text
bad hex/base64 wrapper syntax
    -> FormatException

valid wrapper, malformed/unsupported compiled bytes
    -> CompiledTermInfoFormatException
```

This preserves the T32/T35 distinction between acquisition encoding failures
and malformed compiled-entry failures.

## Encoded identity

A decoded terminal is accepted only when the exact requested name matches,
using ordinal case-sensitive comparison:

- the parsed canonical terminal name; or
- one parsed alias.

A valid encoded entry for another terminal produces an encoded-source miss
rather than being silently accepted. T38 may then continue its documented
search precedence.

This mirrors ncurses' rule that an encoded `TERMINFO` description is usable
when it matches the terminal name sought.

## Environment/discovery snapshot

T37 introduces an internal immutable discovery snapshot containing, as
applicable:

- `TERMINFO`;
- `TERMINFO_DIRS`;
- user-home information;
- current directory for deterministic resolution of relative search-list
  components;
- host platform identity.

Production capture reads `TERMINFO` and `TERMINFO_DIRS` only when
`UseEnvironment` is enabled, and reads user-home information only when
`UseUserDatabase` is enabled.

Tests use an injected capture overload rather than mutating process-global
environment state. Once captured, later changes to the supplied readers cannot
alter the snapshot.

T38 will construct one snapshot per system-provider instance.

## `TERMINFO_DIRS` splitting

T37 freezes the list separator as:

```text
Windows        ;
all other OS   :
```

The Windows rule deliberately preserves drive-letter colons.

Splitting preserves empty components.

## Empty components

An empty `TERMINFO_DIRS` component expands to the default-root sequence supplied
by the T38 discovery layer.

T37 deliberately does not freeze the actual default roots.

This means:

```text
explicit::other:
```

conceptually expands as:

```text
explicit
<T38 defaults>
other
<T38 defaults>
```

before deduplication.

An unset `TERMINFO_DIRS` value is different from a set-but-empty value:

```text
unset
    -> no TERMINFO_DIRS roots

set to ""
    -> one empty component
    -> T38 default-root expansion
```

No empty component means the current working directory.

## Canonicalization and deduplication

Resolved search roots are converted to absolute paths against the current
directory captured in the immutable discovery snapshot.

Duplicate roots are removed while preserving first occurrence order.

Comparison is:

```text
Windows        OrdinalIgnoreCase
other hosts    Ordinal
```

Default-root duplicates and duplicates introduced by repeated empty components
are removed by the same rule.

T37 does not resolve symbolic-link physical identity or require candidate roots
to exist. Filesystem existence checks belong to actual T38 lookup.

## T37/T38 boundary

T37 intentionally does not add:

- `SystemTerminalDescriptionProvider`;
- Linux default roots;
- macOS default roots;
- invented Windows Unix-style defaults;
- `$HOME/.terminfo` path construction;
- `TERMINFO` ordinary directory-location lookup;
- complete source precedence;
- system-provider caching/composition.

Those remain T38/T39 work.

`DirectoryTerminalDescriptionProvider` and `TerminalDatabase.BuiltIn` are
unchanged by T37.

## Completion evidence

T37 is complete when:

- both project version fields are `0.9.0-beta.1`;
- `SystemTerminalDescriptionProviderOptions` matches the T32 public freeze;
- parser options are snapshotted;
- `hex:` and `b64:` payloads are bounded before decoded allocation;
- standard and URL-safe Base64 forms are accepted;
- invalid encoded syntax remains a transport `FormatException`;
- decoded bytes use the existing compiled parser and retain its exception
  vocabulary;
- encoded identity is exact and alias-aware;
- environment inputs can be snapshotted through an injected deterministic test
  seam;
- disabled environment/user inputs are not read;
- Windows `TERMINFO_DIRS` splitting cannot split drive-letter colons;
- non-Windows splitting uses colon;
- empty components expand only to a supplied default-root sequence, never the
  current working directory;
- canonical roots are deduplicated deterministically;
- no platform default-root set or public system provider appears before T38.

T38 may now compose these frozen inputs into the public system provider and
freeze the complete host search precedence.
