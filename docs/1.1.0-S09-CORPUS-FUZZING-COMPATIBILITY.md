# Icod.TermInfo 1.1.0 S09 — Corpus, Fuzzing, and Compatibility

**Development version:** `1.1.0-Alpha-9`
**Assembly version:** `1.0.0.0`
**Status:** implementation complete — validation pending
**Next tranche:** 1.1.0 release closure

## Purpose

S09 closes the planned 1.1 source-language implementation program by widening
validation around the parser, capability classifier, cancellation state,
inheritance resolver, and `TerminalDescription` materialization path established
by S01-S08.

No new source semantic model is introduced. S09 concentrates on compatibility,
hostile-input behavior, duplicate source identities, deterministic fuzzing, and
checked-in corpus coverage while preserving the frozen 1.0 runtime contract.

## Authoritative source corpus

S09 adds a checked-in synthetic corpus under:

```text
tests/Icod.TermInfo.Source.Tests/fixtures/source-terminfo
```

The valid corpus covers:

- a simple System V-style entry;
- control and escape notation;
- ncurses-style extended Boolean, numeric, and string capabilities;
- high-byte string preservation;
- multiple source entries;
- `use=` inheritance;
- local overrides;
- cancellation through inherited state.

The malformed corpus covers:

- duplicate canonical names;
- duplicate aliases;
- alias/canonical collisions;
- orphaned fields;
- malformed numeric values;
- incomplete control escapes;
- empty `use=` references;
- empty fields;
- missing capability names;
- cyclic inheritance;
- missing inheritance parents.

The existing T29 source/compiled pairs remain the authoritative offline
source-versus-compiled compatibility corpus. Those binaries were generated by
`tic` as recorded in their checked-in manifest, but normal tests consume only
repository fixtures and do not require an installed ncurses toolchain.

## Duplicate source identity policy

Canonical names and aliases participate in one ordinal, case-sensitive source
lookup namespace.

When parsing a document:

1. the first occurrence of a lookup identity remains authoritative;
2. a repeated canonical name produces warning `TIS0025`;
3. a repeated alias produces warning `TIS0026`;
4. canonical-versus-alias collisions are diagnosed according to the form of the
   later occurrence;
5. duplicate diagnostics do not discard or reorder source entries.

Warnings are used deliberately. Historical `tic` implementations diagnose
duplicate terminal names during normal compilation, while the S07 document
adapter already defines deterministic first-source-order lookup behavior.
Callers which require unique source identities can therefore reject these
warnings without making duplicate-bearing documents nondeterministic.

## Deterministic fuzzing

S09 adds a bounded mutation test driven by a fixed linear-congruential sequence.
It performs insert, replace, and delete mutations over representative source
text using a fixed ASCII source alphabet.

The test requires repeated processing of every generated input to produce the
same:

- lexical/parser diagnostic sequence;
- token and unresolved-entry shape;
- resolver diagnostics;
- materialized runtime description when resolution succeeds.

No wall-clock seed, process-global random state, environment state, filesystem
database, or native utility participates in the fuzz loop.

The mutation count and source sizes are intentionally modest so the test remains
suitable for the ordinary `net8.0` and `net10.0` CI matrix.

## Resource-limit and graph boundaries

S09 revalidates the public hostile-input bounds through the complete source
surface rather than only their original tranche tests.

The corpus gate verifies that:

- both `string` and `TextReader` parser paths reject input beyond a configured
  source-length limit without exposing partial entries;
- an inheritance chain exactly at the configured depth limit resolves;
- the next `use=` edge fails with `TIS0024`;
- repeated failure produces the same diagnostic result.

These tests remain small and generated in memory; no large allocations are
required to exercise the boundary contracts.

## Compatibility closure

S09 is cumulative with the S08 semantic-equivalence gate. The five checked-in
T29 source/compiled fixture pairs continue to cover:

- legacy compiled layout;
- alignment padding;
- cancellation and high-byte strings;
- ncurses extended capabilities;
- wide 32-bit numerics.

The S09 compatibility test also verifies the fixture manifest records `tic` as
the generator while marking native generation as unnecessary for normal tests.

Normal CI therefore remains fully deterministic and offline with respect to
ncurses.

## Public API boundary

S09 adds no public type and no new parsing or resolution method.

The only public API additions are the two stable diagnostic-code constants:

```text
TIS0025  DuplicateSourceEntryName
TIS0026  DuplicateSourceAlias
```

Both packages advance together to `1.1.0-Alpha-9` while retaining assembly
version `1.0.0.0`.

The Source API snapshot is advanced for those constants. The frozen
`docs/1.0.0-PUBLIC-API-BASELINE.txt` runtime contract remains unchanged.

## S09 gate

S09 is ready for completion when:

- the checked-in valid corpus parses, resolves, and materializes successfully;
- duplicate canonical names and aliases produce stable warning diagnostics;
- duplicate lookup remains ordinal, case-sensitive, and source-order
  deterministic;
- malformed corpus diagnostics are reproducible;
- deterministic mutation fuzzing completes without unexpected exceptions or
  result drift;
- source-length limits behave identically for `string` and `TextReader`;
- an inheritance chain at the configured maximum depth succeeds and the next
  edge fails deterministically;
- the checked-in `tic`-generated compatibility corpus remains available without
  requiring host ncurses tools;
- the Source API baseline and `net8.0`/`net10.0` API parity gates pass;
- the frozen runtime 1.0 public API baseline remains exact;
- fresh package consumer smoke tests pass for both target frameworks.

After this gate, the planned 1.1 implementation tranches are complete. Release
closure should consist of API-regret review, final documentation/package
inspection, CI validation, and publication rather than another source-language
feature tranche.
