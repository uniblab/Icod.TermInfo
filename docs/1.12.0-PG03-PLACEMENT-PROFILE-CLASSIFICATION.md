**Development version:** `1.12.0-Alpha-3`

**Previous tranche:** PG02 — immutable placement evidence

## Purpose

PG03 classifies the immutable PG02 evidence ledger into a protocol-neutral placement profile for the two PG01 subjects:

```text
SourceRectangle
SignedZOrder
```

The profile reuses the frozen 1.11 `PersistentRasterLifecycleSupportStatus` vocabulary:

```text
Unknown
Supported
Unsupported
Contradicted
```

No new support-state enum is introduced.

```text

```

The profile retains the complete canonical PG02 evidence snapshot, including lower-precedence and contradictory assertions.

## Classification semantics

Classification is performed independently for each placement subject.

Evidence provenance precedence is:

```text
Verified
    >
Declared
    >
CapabilityDerived
```

Only evidence at the highest provenance level present for a subject determines that subject's support state:

```text
no evidence                         -> Unknown
positive only at highest level      -> Supported
negative only at highest level      -> Unsupported
positive + negative at highest      -> Contradicted
```

Lower-precedence contradictions remain visible in `Evidence` but do not override a higher-precedence conclusion.

## Determinism

The classifier first calls the bounded PG02 snapshot operation. Classification therefore inherits its immutable copy, single-enumeration bound enforcement, ordinal source-label ordering, and culture independence.

Classification itself depends only on explicit enum numerics and Boolean evidence polarity. It does not depend on culture, hash ordering, filesystem ordering, thread scheduling, terminal brand, or ambient host state.

## Compatibility boundary

PG03 does not modify:

- the 1.11 lifecycle evidence, profile, request, operation, or planner types;
- the frozen 1.11 support-status enum;
- JSON schema versions 1, 2, or 3;
- Runtime, Source, Compiler, or Termcap public APIs;
- database-set precedence semantics; or
- the production dependency graph.

The cumulative 1.12 Inspection API additions ledger is extended only with the two PG03 public types so the release verifier continues to reconstruct and hash the exact frozen 1.11 Inspection surface.
