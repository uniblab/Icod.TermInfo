# Icod.TermInfo 1.2.0 C04 — Format Selection

**Tranche:** C04
**Development version:** `1.2.0-Alpha-4`
**Runtime assembly identity:** `Icod.TermInfo, Version=1.0.0.0`
**Source assembly identity:** `Icod.TermInfo.Source, Version=1.0.0.0`
**Compiler assembly identity:** `Icod.TermInfo.Compiler, Version=1.0.0.0`
**Status:** implementation candidate; build/test/package validation required

## Purpose

C04 completes the low-level compiled-entry representation policy required before
source compilation begins. The writer now supports both conventional numeric
representations already accepted by `CompiledTermInfoParser`:

```text
0432   signed 16-bit standard and extended numerics
01036  signed 32-bit standard and extended numerics
```

C04 also freezes the small public format-policy surface used by later compiler
tranches. Filesystem/database placement remains C06 work.

## Public writer policy

The existing convenience operation remains:

```csharp
CompiledTermInfoWriter.Write(TerminalDescription description)
```

It uses automatic policy. C04 adds:

```csharp
CompiledTermInfoWriter.Write(
    TerminalDescription description,
    CompiledTermInfoWriterOptions options)
```

with:

```text
CompiledTermInfoFormat.Automatic
CompiledTermInfoFormat.Legacy
CompiledTermInfoFormat.Wide
```

and an `IncludeExtendedCapabilities` representation constraint.

The options object is immutable. An undefined enum value is an invalid caller
argument and throws `ArgumentOutOfRangeException`. Null inputs throw
`ArgumentNullException`.

## Automatic format selection

Automatic format selection is deterministic and examines every effectively
present standard and extended numeric capability.

If every present numeric value fits the legacy non-negative signed 16-bit
range, the writer emits legacy `0432`.

If at least one present numeric value is greater than `32767`, the writer emits
wide `01036` and stores all standard and extended numeric values as signed
32-bit little-endian integers.

The automatic path never chooses the wide representation merely because an
extended section is present. Extended sections are valid with either base
magic.

## Explicit format selection

An explicit `Legacy` request emits `0432` exactly or fails. It never silently
upgrades to `01036`.

An explicit `Wide` request emits `01036` exactly even when every numeric value
would fit `0432`. It never silently downgrades to the legacy representation.

This makes explicit policy suitable for callers which need reproducible format
identity in addition to semantic equivalence.

## Numeric representation

The conventional header remains six unsigned 16-bit fields in both formats.
Only numeric table width changes:

```text
Legacy  -> 2 bytes per standard/extended numeric
Wide    -> 4 bytes per standard/extended numeric
```

String offsets remain signed 16-bit fields in both formats. The ncurses
extended-section shape and ordering frozen by C03 are unchanged.

`TerminalDescription` uses signed 32-bit numeric semantics. Present negative
values are not representable by the adopted compiled family because negative
values intersect compiled sentinel space. C04 therefore rejects them in both
legacy and wide modes rather than coercing them.

## Extended-section policy

`IncludeExtendedCapabilities = true` permits the C03 extended section and is the
default.

`IncludeExtendedCapabilities = false` is a representation constraint, not a
request to discard data. If the input contains any effective extended
capability, the writer fails deterministically. A standard-only description is
written normally and contains no extended section.

The writer never silently drops extended capability data.

## Representation validation

C04 preserves and consolidates the C01-C03 representation rules:

- identity, aliases, descriptions, capability names, and strings use strict
  reversible Latin-1;
- embedded NUL is rejected in NUL-terminated fields;
- identity fields reject the compiled `|` separator;
- absent/canceled numeric sentinel collisions are rejected;
- legacy numerics must fit their signed 16-bit representation;
- wide numerics use exact signed 32-bit values;
- standard and extended string/name offsets must fit signed 16-bit fields;
- conventional and extended string-table sizes must fit unsigned 16-bit fields;
- extended counts and item counts must fit unsigned 16-bit fields;
- total-entry arithmetic is checked before allocation/narrowing.

Large extended strings and names are rejected before an oversized encoded byte
array is allocated whenever their individual table growth already exceeds the
binary field limits.

A structurally valid `TerminalDescription` which cannot be represented under
the selected policy fails with `InvalidOperationException`. Invalid API
arguments continue to use the normal argument exceptions. No successful path
truncates, wraps, replaces, upgrades, downgrades, or discards data contrary to
the selected policy.

## Determinism

For the same `TerminalDescription` and writer options, C04 emits identical bytes
across supported operating systems and target frameworks.

Automatic format selection depends only on semantic numeric values. Standard
capabilities remain ordered by `StandardCapabilityCatalog.BinaryIndex` and
extended capabilities remain ordered by C03's ordinal, case-sensitive
Boolean/numeric/string grouping.

## Validation

C04 tests cover:

- automatic preference for legacy `0432` at the `32767` boundary;
- automatic promotion to `01036` for standard and extended values above that
  boundary;
- exact `int.MaxValue` standard and extended round-trip;
- explicit Legacy exact-or-fail behavior;
- explicit Wide exact behavior for otherwise-legacy values;
- direct four-byte standard and extended numeric layout assertions;
- negative/sentinel-colliding numeric rejection in wide mode;
- extended-section exclusion as a fail-not-drop constraint;
- invalid options and null-options argument behavior;
- repeated-write byte determinism;
- fresh Compiler package consumption which forces automatic `01036` selection.

The Compiler public API baseline is intentionally advanced in C04 to freeze the
format enum, writer-options type, and explicit-options overload.

## Scope boundary

C04 does not add:

- terminfo source parsing or inheritance resolution to Compiler;
- a Compiler dependency on `Icod.TermInfo.Source`;
- filesystem/database-layout output;
- native `tic`, `infocmp`, or ncurses dependencies.

Those remain later tranches.

## C04 gate

C04 is complete when boundary numeric/string/count cases select or reject
formats predictably; explicit requests never silently change format; standard
and extended wide numerics round-trip through the existing parser; the reviewed
Compiler API baseline matches on net8.0/net9.0/net10.0; package consumers pass;
and the Windows/Linux/macOS CI matrix is green.

C05 may then compose the already-complete Source parser/resolver with this
frozen low-level writer policy.
