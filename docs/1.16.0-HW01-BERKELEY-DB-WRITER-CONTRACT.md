# Icod.TermInfo 1.16.0 HW01 Berkeley DB Writer Contract

## Candidate contract freeze

HW01 freezes the terminfo-specific public boundary for deterministic managed
Berkeley DB Hash-v9 publication. The coordinated development version is
`1.16.0-Alpha-1`; reusable assembly identity remains `1.0.0.0` on `net8.0`,
`net9.0`, and `net10.0`.

The complete candidate reflection manifest is checked in as
`docs/1.16.0-BERKELEYDB-PUBLIC-API-BASELINE.txt`. Its normalized-LF SHA-256 is:

```text
01a84c409fb222324009272de0213d1b1a8dc3df1ccac46ce66341f17d4baa81
```

The manifest contains exactly **12 exported public types**. Relative to the
accepted 1.15 nine-type freeze, the only additions are:

- `BerkeleyDbTerminalDatabaseEntry`;
- `BerkeleyDbTerminalDatabaseWriterOptions`; and
- `BerkeleyDbTerminalDatabaseWriter`.

No writer result type, writer-specific exception, raw key/value operation,
native dependency, or additional production dependency is introduced.

## Frozen behavior boundary

The entry and options values snapshot caller-owned mutable input. `Write`
performs one bounded enumeration, cancellation checks, portable terminal-name
validation, exact ordinal ownership checks, physical record-count enforcement,
compiled-entry parsing, and canonical/ordered-alias agreement before any
destination interaction.

HW01 does not construct a database image or touch the destination. A valid
preflight reaches the deliberate `NotSupportedException` boundary whose message
assigns Hash-v9 image construction to HW02. Deterministic pages, buckets,
inline records, overflow records, and final byte emission begin in HW02.
