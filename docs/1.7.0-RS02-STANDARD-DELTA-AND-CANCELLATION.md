# Icod.TermInfo 1.7.0 RS02 — Standard Capability Delta and Cancellation Engine

**Development version:** `1.7.0-Alpha-2`
**Tranche:** RS02
**Status:** implementation contract
**Previous tranche:** RS01 — Synthesis Contract and Internal Model
**Next tranche:** RS03 — Extended Capability Synthesis

## Objective

RS02 turns the RS01 relative-source synthesis contract into an operational engine
for the complete standard terminfo capability catalog.

Given one effective target `TerminalDescription` and an explicitly ordered set of
effective parent descriptions, Inspection now computes the inherited standard
baseline and emits only the local Boolean, numeric, and string declarations or
cancellations required to make Source resolution reproduce the target.

RS02 does not change the public synthesis surface introduced by RS01.

## Parent precedence

The existing `Icod.TermInfo.Source` resolver remains authoritative.

For source such as:

```text
child,
    use=left,
    use=right,
```

Source processes parent references from right to left. The leftmost parent
therefore has the highest parent-to-parent priority.

RS02 computes the equivalent effective baseline directly from the supplied parent
descriptions. For each standard capability it scans parents in caller order and
uses the first parent in which that capability is present.

An absent capability in a higher-priority parent does not mask a value supplied
by a lower-priority parent. Parent inputs are effective `TerminalDescription`
values, so RS02 does not invent or reconstruct source-level cancellation
provenance for a parent merely because an effective capability is absent.

The synthesizer never reorders, removes, or deduplicates caller-supplied parents.
Every accepted parent produces one `use=` field in the original order.

## Standard Boolean delta

For every standard Boolean capability:

| Inherited | Target | Local source |
|---|---|---|
| absent | absent | nothing |
| absent | present | `cap,` |
| present | present | nothing |
| present | absent | `cap@,` |

## Standard numeric delta

For every standard numeric capability:

| Inherited | Target | Local source |
|---|---|---|
| absent | absent | nothing |
| absent | value | `cap#value,` |
| same value | same value | nothing |
| value A | value B | `cap#valueB,` |
| present | absent | `cap@,` |

Numeric comparison is exact.

## Standard string delta

For every standard string capability:

| Inherited | Target | Local source |
|---|---|---|
| absent | absent | nothing |
| absent | value | `cap=value,` |
| same value | same value | nothing |
| value A | value B | `cap=valueB,` |
| present | absent | `cap@,` |

String comparison is ordinal and exact. RS02 does not normalize padding,
parameter expressions, escape sequences, or other string semantics merely to
reduce source text.

## Rendering and deterministic order

Relative rendering reuses the frozen Inspection renderer policy:

1. target identity header;
2. standard Boolean declarations or cancellations;
3. standard numeric declarations or cancellations;
4. standard string declarations or cancellations;
5. ordered `use=` references.

Within each standard capability kind, the caller-selected
`TerminalDescriptionSourceCapabilityOrder` is authoritative.

The existing `Canonical`, `SingleLine`, and `OneCapabilityPerLine` layout policies
remain available through `TerminalDescriptionSourceSynthesisOptions`.

A cancellation is sorted in the same position as the capability it cancels. It
is not moved into a separate cancellation block.

The same target, ordered parents, and options produce byte-identical source.

## Target identity

The target owns the synthesized entry header.

RS02 preserves:

- canonical name;
- aliases in target order;
- descriptive text.

Parent identity metadata does not alter the target header.

## Extended capability boundary

Extended capability synthesis remains RS03 work.

For a request containing one or more parents, RS02 rejects the request with
`NotSupportedException` if the target or any supplied parent contains an
extended capability. This is deliberate: ignoring inherited extended state could
produce source which appears valid while resolving to semantics different from
the target.

The zero-parent synthesis form remains the RS01 behavior and continues to use the
existing complete effective renderer, including extended capabilities.

## Public API and package boundary

RS02 adds no public types, methods, properties, constructors, enums, or constants.

The RS01 public surface remains:

```text
TerminalDescriptionSourceSynthesisParent
TerminalDescriptionSourceSynthesisOptions
TerminalDescriptionSourceSynthesizer
```

Production dependency direction remains:

```text
Icod.TermInfo.Inspection
    -> Icod.TermInfo.Source
    -> Icod.TermInfo

Icod.TermInfo.Inspection
    -> Icod.TermInfo
```

Inspection gains no production Compiler or Termcap dependency.

Runtime, Source, Compiler, and Termcap public API baselines remain frozen.
All five reusable assemblies retain `AssemblyVersion` `1.0.0.0`.

## Semantic round-trip gate

RS02 correctness is judged through the actual Source parser and resolver rather
than through a duplicate test-only inheritance implementation.

For every standard-capability fixture:

```text
target
+ ordered effective parents
    -> TerminalDescriptionSourceSynthesizer
    -> relative child source
    + full source representations of the parents
    -> TermInfoSourceParser
    -> TermInfoSourceResolver
    -> TerminalDescription
    -> TerminalDescriptionComparer
    -> AreEqual == true
```

The deterministic fixture set covers:

- an empty parent;
- a target identical to its parent;
- target-only Boolean, numeric, and string additions;
- numeric and string overrides;
- inherited removals requiring cancellation;
- mixed declarations and cancellations;
- two-parent collisions;
- three-parent collisions;
- leftmost-parent priority;
- target-local priority above every parent;
- target identity preservation;
- configured layout behavior;
- repeated byte-for-byte deterministic synthesis;
- rejection of parented extended-capability requests until RS03.

```text
1.7.0-Alpha-2
```

The published stable release remains `1.6.1`.

Historical RS01 documentation retains its `1.7.0-Alpha-1` development record.

## RS02 gate

RS02 is complete when:

- the coordinated development version is `1.7.0-Alpha-2`;
- parented standard-capability synthesis is operational;
- parent aggregate precedence agrees with Source;
- unnecessary local fields are omitted;
- inherited removals produce cancellations;
- target standard additions and overrides are emitted correctly;
- parent order is preserved in emitted `use=` fields;
- target identity is preserved;
- deterministic renderer options remain honored;
- all standard-capability round-trip fixtures resolve semantically equal to the
  target;
- extended relative synthesis remains explicitly deferred to RS03;
- Runtime, Source, Compiler, and Termcap public APIs remain unchanged;
- Inspection retains Runtime-and-Source-only production dependencies.

RS03 may then extend the same engine to case-sensitive extended Boolean, numeric,
and string capabilities without changing the standard-capability semantics
frozen here.
