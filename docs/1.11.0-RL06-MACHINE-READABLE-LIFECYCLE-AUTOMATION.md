```text

```

```text

```

## Profile document

`TermInfoJsonRenderer.Render(PersistentRasterLifecycleProfile, ...)` emits:

- all eight lifecycle support states in fixed semantic order;
- the canonical evidence count;
- the complete canonical evidence snapshot;
- evidence subject, polarity, provenance kind, source label, and source ordinal.

The renderer preserves the RL02/RL03 distinction between raw evidence and classified support state. Contradictions and lower-precedence evidence remain observable rather than being discarded from machine output.

## Plan document

`TermInfoJsonRenderer.Render(PersistentRasterLifecyclePlan, ...)` emits:

- `Success`, `Indeterminate`, or `Impossible` status;
- the aggregate runtime-verification requirement;
- deterministic step and issue counts;
- ordered semantic operation steps;
- per-step runtime-verification requirements;
- structured issue operation, subject, support status, and verification requirement.

The document remains protocol-neutral. It contains no Kitty identifiers, terminal image identifiers, placement identifiers, wire payloads, coordinates, or execution state.

## Determinism and bounds

Lifecycle rendering reuses `TermInfoJsonRendererOptions` and the existing bounded deterministic JSON writer. RL06 tests freeze compact vectors, exact UTF-8 output-bound behavior, cancellation, repeated rendering, and culture independence.

Schema v3 bounds match the public lifecycle contracts, including the maximum evidence count and maximum bounded plan sizes.
