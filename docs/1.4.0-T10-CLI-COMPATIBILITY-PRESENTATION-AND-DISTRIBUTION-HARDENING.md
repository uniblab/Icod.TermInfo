# Icod.TermInfo 1.4.0 T10 — CLI Compatibility, Presentation, and Distribution Hardening

**Development version:** `1.4.0-Alpha-10`

## Objective

T10 makes `tic`, `infocmp`, and `toe` behave as one coherent command suite
without adding a new semantic engine. Runtime, Source, Compiler, and Inspection
public contracts remain unchanged.

## Command-line hardening

The three command entry points now normalize only unambiguous short-option
forms before handing control to their established semantic parsers.

Supported T10 syntax rules include:

- unambiguous clustered Boolean short options;
- attached values for short options which already take values;
- separated values for the same options;
- `--` end-of-options;
- hyphen-leading operands after `--`;
- idempotent repetition of flag-like options;
- explicit conflict diagnostics for mutually exclusive modes;
- exact operand-count validation;
- explicit usage errors for unsupported ncurses compatibility switches.

`tic` accepts clustered `-c`, `-x`, and `-s`; `-e` and `-o` accept attached
values. `infocmp` accepts clustered presentation/comparison flags and attached
`-A`, `-B`, `-w`, and `-s` values. `toe` accepts clustered `-a`, `-h`, and `-s`;
`-u` and `-U` accept attached source paths while remaining standalone modes.

Unsupported options are never silently ignored.

## Presentation hardening

Operational diagnostics use the suite shape:

```text
command: subject-or-source[:line:column]: CODE severity: message
```

Source line and column numbers are formatted with invariant culture. Usage
diagnostics remain command-prefixed and point users to `--help`.

No command emits ANSI styling merely because output is connected to a terminal.
The same semantic output is therefore suitable for redirected streams.

Existing deterministic ordering contracts remain authoritative:

- Source/Compiler diagnostics remain source-aware and deterministic;
- Inspection rendering/comparison ordering remains deterministic;
- `toe` database and dependency ordering remains deterministic.

Repeated enumeration of the exact same `toe` root does not compare that root
against itself for semantic duplicate markers.

## Documentation

The root README now contains a Tool Suite section. Each command README contains
explicit sections for:

- synopsis;
- options;
- operands;
- environment;
- exit statuses;
- examples;
- compatibility;
- non-goals.

The command READMEs also document T10 clustered/attached-value syntax and the
`--` end marker.

## Distribution

T10 establishes the canonical command distribution as six framework-dependent
.NET 10 suite archives:

```text
Icod.TermInfo.Tools.<version>.win-x64.zip
Icod.TermInfo.Tools.<version>.win-arm64.zip
Icod.TermInfo.Tools.<version>.linux-x64.tar.gz
Icod.TermInfo.Tools.<version>.linux-arm64.tar.gz
Icod.TermInfo.Tools.<version>.osx-x64.tar.gz
Icod.TermInfo.Tools.<version>.osx-arm64.tar.gz
```

`.github/scripts/build-tool-archives.sh`:

1. verifies the coordinated version across all four libraries and all three
   commands;
2. publishes `tic`, `infocmp`, and `toe` for each RID as framework-dependent
   `net10.0` applications;
3. places all three commands and required managed dependencies in one payload;
4. adds README/license documentation and a deterministic suite manifest;
5. normalizes file timestamps and archive member ordering;
6. emits ZIP for Windows and deterministic `tar | gzip -n` archives for Linux
   and macOS;
7. requires exactly six archives.

PR and main Ubuntu validation build the archives as non-public Actions artifacts.
The release workflow builds the canonical six archives and attaches them to the
GitHub Release alongside the eight existing NuGet/symbol package artifacts and a
single SHA-256 manifest.

The user supplies the .NET 10 runtime. The archives are not self-contained.

## Deliberately deferred

T10 does not add:

- NuGet global-tool packaging;
- `tic -Q1/-Q2/-Q3`;
- `tic -v[n]`;
- `toe -v[n]`;
- termcap conversion;
- hashed/Berkeley DB support;
- any new Runtime, Source, Compiler, or Inspection public API.

## Validation

T10 tests cover clustered and repeated options, attached values,
`--`, hyphen-leading operands, conflicting modes, unsupported switches,
coordinated Alpha-10 versions, README documentation coverage, archive names, and
release-workflow integration.

The archive builder itself is exercised by PR/main/release CI on Ubuntu.

**Gate result:** T10 is complete when the solution tests pass on Windows, Linux,
and macOS and the Ubuntu archive-validation step produces all six canonical
framework-dependent suite archives.
