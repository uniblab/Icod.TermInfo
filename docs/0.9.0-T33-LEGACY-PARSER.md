# Icod.TermInfo 0.9.0 — T33 Legacy `0432` Compiled Parser

**Tranche:** T33 — Legacy `0432` Compiled Parser
**Development version:** `0.9.0-alpha.2`
**Previous tranche:** T32 — foundation and acquisition API freeze
**Next tranche:** T34 — ncurses extended sections and `01036`

---

## Purpose

T33 introduces the first production arbitrary compiled-terminfo acquisition
component: the pure byte-oriented parser frozen by T32.

The implementation accepts the conventional legacy magic `0432` (`0x011a`)
base format and constructs the same immutable `TerminalDescription` model
completed in 0.8. It performs no filesystem, environment, terminal-session,
cache, or native-library work.

The public surface introduced by T33 is exactly:

```text
CompiledTermInfoParserOptions
CompiledTermInfoParser
CompiledTermInfoFormatException
```

Directory and system providers remain reserved for later tranches.

## Supported legacy layout

T33 accepts the frozen conventional little-endian body:

1. six 16-bit header fields;
2. NUL-terminated canonical name / aliases / verbose description;
3. standard Boolean bytes;
4. the required zero alignment byte when the numeric table would begin at an
   odd offset;
5. signed 16-bit standard numeric values;
6. signed 16-bit standard string offsets;
7. the declared string table.

Only legacy magic `0432` is accepted in this tranche.

Magic `01036` and appended ncurses extended sections are deliberately rejected
until T34. In particular, T33 does not silently return a partial description
when valid conventional data is followed by an extended section.

## Standard capability mapping

Compiled table positions are mapped through `StandardCapabilityCatalog`.

The parser uses the catalog's frozen `BinaryIndex` ordering and does not use
managed enum ordinals as compiled positions. A declared standard table longer
than the frozen catalog is an unsupported compiled layout and fails with
`CompiledTermInfoFormatException`.

## Sentinel semantics

The T29 frozen sentinels are implemented exactly:

| Kind | Absent | Canceled |
| --- | ---: | ---: |
| Boolean | `0x00` | `0xfe` |
| Numeric | `-1` | `-2` |
| String offset | `-1` | `-2` |

Boolean `0x01` is the present value. Other Boolean byte values are malformed.

Numeric values below `-2` and string offsets below `-2` are malformed.

Canceled values are applied through the existing internal
`TerminalDescriptionBuilder` cancellation hooks before the immutable
description is built. The completed public model therefore continues to expose
both absent and canceled effective values as not present.

## Capability byte fidelity

Names and capability strings are decoded with the .NET Latin-1 mapping.

For capability strings this is the exact reversible 8-bit bridge frozen by
T25: every input byte `0x00` through `0xff` maps one-to-one to the corresponding
Unicode code point without locale-dependent decoding.

The T29 legacy-edge fixture therefore preserves its `0x80` key-backspace byte
as `"\u0080"` while retaining parameter programs and padding annotations
verbatim.

## Resource policy

`CompiledTermInfoParserOptions` implements the T32 bounds:

```text
default maximum: 1,048,576 bytes
absolute maximum configurable value: 16,777,216 bytes
```

Entry size is checked before header parsing or input-derived allocation.

Section extents are validated with checked arithmetic before names or
capability strings are decoded. String offsets must point inside the declared
string table and each referenced string must terminate inside that table.

Malformed input produces no returned partial description.

## Diagnostics

Malformed or unsupported compiled input throws
`CompiledTermInfoFormatException`, distinct from parameter-language
`TermInfoFormatException`.

T33 uses these stable `Section` values where applicable:

```text
entry
header
names
booleans
alignment
numerics
string-offsets
string-table
extended
```

`Offset` is a zero-based byte offset when a concrete location exists and `-1`
when the failure applies to the entry as a whole, such as a configured size
limit.

Exact diagnostic prose may be hardened in T35 without changing this exception
ownership model.

## Fixture evidence

Normal tests parse the checked-in T29 corpus directly and do not invoke `tic`.

T33 validates:

- `t29-legacy-minimal.bin`;
- `t29-legacy-alignment.bin`;
- `t29-legacy-edge.bin`;
- truncated legacy header rejection;
- impossible conventional count rejection;
- missing names terminator rejection;
- illegal standard string offset rejection;
- unsupported magic rejection;
- explicit rejection of T34 extended/32-bit fixtures.

The semantic assertions cover canonical name, aliases, verbose description,
Boolean/numeric/string values, ordinary absence, cancellation, numeric
alignment, parameter expansion, padding annotations, and high-byte capability
data.

## Historical guard updates

Earlier 0.8 tests intentionally prohibited production acquisition types because
0.8 had not yet begun arbitrary compiled loading. T33 removes only the obsolete
forward-looking parser prohibition.

The tests continue to require:

- the frozen 0.7/0.8 semantic and enum compatibility baselines;
- `TerminalDatabase.BuiltIn` to remain in-memory and I/O-free;
- no directory or system provider implementation before its owning tranche;
- no fixture corpus embedded in the runtime assembly;
- no `TERMINFO`, `TERMINFO_DIRS`, or default-system-root discovery literals in
  the production assembly.
