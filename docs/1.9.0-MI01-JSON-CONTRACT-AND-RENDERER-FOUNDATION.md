## Objective

MI01 establishes the reusable machine-readable output boundary without emitting
a partial production schema. It freezes:

- schema identity and version;
- the four supported document kinds;
- top-level envelope property names and order;
- compact and indented presentation policy;
- UTF-8 output bounds;
- cancellation and exception boundaries;
- the minimal public renderer API;
- package and dependency ownership.

Operational payload rendering begins only after the kind-specific schema is
implemented and independently testable:

```text
MI02    TerminalDescription
MI03    TermInfoComparisonResult and TerminalDescriptionSourcePlan
MI04    TermInfoDatabaseCatalog and complete JSON Schema
```

## Public API

MI01 adds exactly two exported Inspection types:

```text
TermInfoJsonRendererOptions
TermInfoJsonRenderer
```

No public JSON DOM type, writer abstraction, converter, naming policy, schema
object, or generic serializer is introduced.

### `TermInfoJsonRendererOptions`

The immutable options type exposes:

```text
DefaultMaximumOutputByteCount = 4,194,304
MaximumSupportedOutputByteCount = 67,108,864
MaximumOutputByteCount
WriteIndented
```

The parameterless constructor selects compact output and the default byte bound.
The explicit constructor validates a byte bound between one and the supported
maximum and accepts only the indentation flag as presentation policy.

The options type deliberately does not retain `CancellationToken`. Cancellation
belongs to one operation, not to reusable immutable policy.

### `TermInfoJsonRenderer`

The static renderer exposes:

```text
SchemaIdentifier = urn:icod:terminfo:inspection:json:1
SchemaVersion = 1
```

It provides a default and an explicit-policy overload for each supported value:

```csharp
Render( TerminalDescription value );
Render( TerminalDescription value, options, cancellationToken );

Render( TermInfoComparisonResult value );
Render( TermInfoComparisonResult value, options, cancellationToken );

Render( TerminalDescriptionSourcePlan value );
Render( TerminalDescriptionSourcePlan value, options, cancellationToken );

Render( TermInfoDatabaseCatalog value );
Render( TermInfoDatabaseCatalog value, options, cancellationToken );
```

The overloads are strongly typed. A generic `object` entry point would permit
unreviewed CLR shapes to become schema and is prohibited.

## Envelope contract

Every operational document will use:

```json
{
  "schema": "urn:icod:terminfo:inspection:json:1",
  "schemaVersion": 1,
  "documentKind": "terminalDescription",
  "data": {}
}
```

The property order is exact:

1. `schema`
2. `schemaVersion`
3. `documentKind`
4. `data`

Document kinds are exact ordinal strings:

```text
terminalDescription
comparison
sourcePlan
databaseCatalog
```

MI01 does not publish a JSON Schema file containing empty placeholder payloads.
MI04 publishes the complete version-1 schema after every payload union is
operational.

## Text and byte policy

The reusable renderer will return a string with:

- deterministic property and item order;
- invariant JSON primitive formatting;
- default safe `System.Text.Json` escaping;
- compact output by default;
- two-space indentation and LF internal line endings when requested;
- no trailing whitespace;
- no trailing line terminator.

UTF-8 encoding of the returned string without a byte-order mark is the canonical
byte representation. `MaximumOutputByteCount` is measured against that encoding,
not UTF-16 string length.

Commands will append one LF after the reusable result.

## Validation and temporary operation boundary

Every explicit-policy overload validates in this order:

1. required value;
2. required options;
3. pre-cancellation;
4. operational tranche availability.

MI01 then throws `NotSupportedException` with the owning future tranche:

```text
TerminalDescription                 MI02
TermInfoComparisonResult            MI03
TerminalDescriptionSourcePlan       MI03
TermInfoDatabaseCatalog             MI04
```

This temporary failure is intentional. Returning only an envelope, an empty
payload, or a subset of one kind would create apparently valid machine output
whose meaning must later change.

## Dependency and distribution contract

```text
Icod.TermInfo.Inspection
    -> Icod.TermInfo.Source
    -> Icod.TermInfo
```

No Compiler, Termcap, command, third-party JSON, or new package dependency is
introduced. The six-package registry family, five-command router, and six
standalone archive RIDs remain unchanged in MI01.

Runtime, Source, Compiler, and Termcap receive coordinated prerelease metadata
only. No command behavior changes before MI05.
