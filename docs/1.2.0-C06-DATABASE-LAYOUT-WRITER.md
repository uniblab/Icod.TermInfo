# Icod.TermInfo 1.2.0 C06 — Database-Layout Writer

**Tranche:** C06
**Development version:** `1.2.0-Alpha-6`
**Runtime assembly identity:** `Icod.TermInfo, Version=1.0.0.0`
**Source assembly identity:** `Icod.TermInfo.Source, Version=1.0.0.0`
**Compiler assembly identity:** `Icod.TermInfo.Compiler, Version=1.0.0.0`
**Status:** implementation candidate; build/test/package validation required

## Purpose

C06 adds the first controlled filesystem output to the Compiler package while
preserving the C01 low-level writer contract.

`CompiledTermInfoWriter` remains pure and returns bytes. Filesystem publication
is owned separately by:

```text
CompiledTermInfoDatabaseWriter
```

The database writer never reads `TERMINFO`, `TERMINFO_DIRS`, a home directory,
or platform defaults. The caller must supply the output root explicitly. It can
publish an already-successful C05 compilation result or compile one or more
resolved `TerminalDescription` values before filesystem publication.

## Layout

Each canonical terminal name and alias is published beneath a lowercase
two-digit hexadecimal directory derived from the first Latin-1 byte:

```text
root/
    78/
        xterm
        xterm-256color
```

The existing `DirectoryTerminalDescriptionProvider` already checks this
conventional hexadecimal layout after the literal first-character layout, so
C06 output is directly consumable without runtime changes.

Aliases receive their own compiled entry file containing the same complete
compiled payload. No hard-link requirement is introduced.

## Path safety

C06 validates every canonical name and alias before touching the filesystem.

Names which are rooted, dot entries, contain directory separators, contain NUL
or control characters, contain surrogate/non-Latin-1 characters, violate the
host filename rules, or conflict with Windows device names are rejected.

Destination paths are canonicalized and checked relative to the explicit root.
Existing child directory reparse points/symbolic links are refused so normal
publication does not intentionally traverse outside the selected tree.

## Overwrite policy

`CompiledTermInfoDatabaseWriterOptions` freezes the initial overwrite contract:

```text
OverwriteExisting = false   default; existing files fail
OverwriteExisting = true    replace existing files
```

All destinations are validated before publication begins. A destination which
is a directory is always rejected.

## Failure and atomicity

The overload accepting `TermInfoSourceCompilationResult` refuses a result with
any error diagnostic before creating the output root. This prevents a failed
source compilation from producing a partial database.

The `TerminalDescription` overloads likewise compile the complete description
batch before creating directories. If any description is not representable by
the requested `CompiledTermInfoWriterOptions`, no output root is created.

For a valid batch, all compiled bytes and destination identities are
materialized before filesystem output. Each file is written completely to a
same-directory temporary file, flushed, and then published with `File.Move`.
Replacement uses the overwrite form of that same-directory move.

This provides atomic per-file publication where the host filesystem supports
atomic rename semantics. A host I/O failure after publication has begun may
leave already-published complete entries, but the writer does not expose a
partially written destination file.

## Package and compatibility contract

C06 adds no Runtime or Source public API. Dependency direction remains:

```text
Compiler -> Source -> Runtime
Compiler ------------> Runtime
```

All three coordinated package versions advance to `1.2.0-Alpha-6`; all three
assembly versions remain `1.0.0.0`.

The Compiler package smoke consumer now publishes a temporary database and
reloads the source-compiled child through
`DirectoryTerminalDescriptionProvider`.

## C06 gate

C06 is complete when a temporary database produced by
`CompiledTermInfoDatabaseWriter` can be consumed by the existing
`DirectoryTerminalDescriptionProvider`, canonical and alias lookups work,
unsafe paths are rejected before filesystem mutation, overwrite behavior is
explicit and tested, failed source compilation produces no output root, the
reviewed Compiler public API baseline matches on net8.0/net9.0/net10.0, and the
Windows/Linux/macOS CI matrix is green.
