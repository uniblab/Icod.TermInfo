# Icod.TermInfo 0.9.0 — T38 System Discovery and Precedence

**Tranche:** T38 — System Discovery and Precedence
**Development version:** `0.9.0-beta.2`
**Previous tranche:** T37 — encoded `TERMINFO` and discovery inputs
**Next tranche:** T39 — provider cache, refresh, and composition

---

## Purpose

T38 introduces the public system provider frozen by T32 and composes the T37
discovery inputs into one deterministic host-database search.

The public provider remains explicit and opt-in:

```csharp
public sealed class SystemTerminalDescriptionProvider
    : ITerminalDescriptionProvider
{
    public SystemTerminalDescriptionProvider(
        SystemTerminalDescriptionProviderOptions? options = null);

    public bool TryLoad(
        string name,
        out TerminalDescription? terminal);
}
```

Constructing this provider does not modify `TerminalDatabase.BuiltIn`.

## Snapshot ownership

The public constructor first snapshots the immutable options and then captures
the environment, user-home information, current directory, and host platform
through the T37 discovery snapshot.

The provider therefore has stable discovery inputs for its lifetime:

```text
new provider
    -> new discovery snapshot

existing provider
    -> unchanged discovery snapshot
```

The internal constructor used by tests accepts an already-created snapshot and
an explicit default-root set. This keeps discovery tests deterministic and
avoids process-global environment mutation.

## Frozen source precedence

For one requested terminal name, T38 searches in this order:

```text
1. TERMINFO encoded entry, when TERMINFO begins with hex: or b64:
2. TERMINFO explicit directory-tree location
3. user-local <home>/.terminfo, on non-Windows hosts
4. TERMINFO_DIRS roots in declared order
5. platform default roots
```

A successful higher-precedence source stops the search.

A valid encoded `TERMINFO` entry whose canonical name and aliases do not match
the requested name is not used; directory discovery then continues.

Malformed encoded syntax or malformed decoded compiled bytes remains an error
and does not fall through.

## `TERMINFO` directory location

A non-empty, non-encoded `TERMINFO` value is interpreted as a directory-tree
root.

Relative values are resolved against the current directory captured at provider
construction.

If the root is absent, that source is a normal miss and lower-precedence
sources may be searched.

If a candidate in that root is malformed, unreadable, or otherwise fails with
an I/O/parser error, the error propagates.

If the `TERMINFO` location exists but is a file rather than a directory, T38
throws `NotSupportedException` when that source is reached. This explicitly
marks hashed-database storage as outside the 0.9 contract rather than silently
treating it as an absent directory.

The same present-file rule is applied to every directory source reached by the
system provider.

## User database

When `UseUserDatabase` is true, non-Windows hosts search:

```text
<captured-home>/.terminfo
```

after `TERMINFO` and before `TERMINFO_DIRS`.

Missing home information omits this source.

Windows deliberately does not invent a `%USERPROFILE%\.terminfo` default.
Windows callers can still use `TERMINFO`, `TERMINFO_DIRS`, or an explicit
`DirectoryTerminalDescriptionProvider`.

## `TERMINFO_DIRS`

When `UseEnvironment` is true and `TERMINFO_DIRS` is set, T38 uses the T37
platform-safe splitter:

```text
Windows        ;
other hosts    :
```

Roots retain their declared order.

Relative roots are resolved against the snapshotted current directory.

An empty component expands the T38 platform defaults at that point in the list
only when `UseSystemDatabases` is true.

When `UseSystemDatabases` is false, empty components contribute no roots, while
non-empty environment roots remain usable. The environment and system-default
options therefore remain independent controls.

## Frozen platform defaults

T38 freezes this deterministic directory-tree default set:

### Linux

```text
/etc/terminfo
/lib/terminfo
/usr/share/terminfo
```

The order intentionally covers the conventional Debian/Ubuntu layout and the
common Red Hat-family subset without probing package-manager-specific or
application-specific paths.

### macOS

```text
/usr/share/terminfo
```

The macOS system ncurses database uses this conventional location.

T38 does not guess Homebrew Cellar/keg paths. A Homebrew or application-specific
database can be selected through `TERMINFO`, `TERMINFO_DIRS`, or an explicit
directory provider.

### Windows

```text
<none>
```

Windows gets no invented Unix-like system directory and no invented user
`.terminfo` directory.

Explicit/environment-configured conventional directory trees remain supported.

### Other platforms

No implicit default root is frozen in 0.9. Explicit/environment roots remain
available.

## Root canonicalization and deduplication

All directory roots are canonicalized with `Path.GetFullPath`.

The provider removes duplicate roots across all directory source categories
while retaining the first occurrence.

Comparison is:

```text
Windows        ordinal, case-insensitive
other hosts    ordinal, case-sensitive
```

This includes defaults expanded inside `TERMINFO_DIRS` and defaults appended at
the end. A default root reached through an empty list component is therefore not
searched again later.

T38 does not attempt physical/symbolic-link identity resolution.

## Restricted discovery options

The T37 options are enforced independently:

```text
UseEnvironment == false
    ignore TERMINFO
    ignore TERMINFO_DIRS

UseUserDatabase == false
    omit <home>/.terminfo

UseSystemDatabases == false
    omit final platform defaults
    empty TERMINFO_DIRS components expand to nothing
```

A non-empty `TERMINFO_DIRS` component still works when
`UseSystemDatabases == false` because it is an environment-controlled source,
not an implicit platform default.

## Clean misses and failures

The system provider preserves the existing provider result contract.

Clean misses include:

- missing requested entry under an otherwise valid directory root;
- an absent configured root;
- an encoded entry which is valid but belongs to another terminal;
- exhaustion of all enabled sources.

Errors include:

- invalid encoded transport syntax;
- malformed compiled bytes;
- unsupported compiled format;
- access/permission failures;
- ordinary propagated I/O failures;
- a reached configured source which is a file/hashed database rather than a
  conventional directory tree;
- unsafe requested terminal names.

The system provider never catches these categories and turns them into `false`.

## Cache boundary

T38 constructs one ordered set of `DirectoryTerminalDescriptionProvider`
instances for the provider lifetime.

Those directory providers retain the successful-entry cache already implemented
and frozen by T36.

T38 does not add an independent system-level encoded-entry cache, cache-clear
API, timer, watcher, or global cache.

T39 remains responsible for the final cache/concurrency/refresh/composition
audit.

## Built-in isolation

`TerminalDatabase.BuiltIn` is unchanged.

A system provider is created only when an application explicitly constructs
one. Built-in lookup never consults environment variables, user databases, or
host roots.

Applications may compose system and built-in providers through the existing
`TerminalDatabase` API; the documentation/sample freeze for that composition
remains T39/T40 work.

T38 adds deterministic temporary-root coverage for:

- the T32-frozen public provider surface;
- development version `0.9.0-beta.2`;
- exact Linux/macOS/Windows/other default-root sets;
- encoded `TERMINFO` precedence;
- encoded identity mismatch fall-through;
- explicit `TERMINFO` directory precedence;
- missing explicit-root fall-through;
- user database precedence;
- ordered `TERMINFO_DIRS`;
- empty-component default expansion in place;
- final default-root precedence;

- present file/hashed-source rejection;

Tests use checked-in T29 fixtures and temporary directory trees only.

No native ncurses/libtinfo installation is required.

## Completion evidence

T38 is complete when:

- both version fields are `0.9.0-beta.2`;
- `SystemTerminalDescriptionProvider` matches the T32 public freeze;
- provider construction snapshots permitted discovery inputs;
- encoded `TERMINFO` is evaluated before every directory source;
- ordinary `TERMINFO` is treated as the first directory-tree source;
- user `.terminfo` is searched on non-Windows hosts when enabled;
- `TERMINFO_DIRS` order and empty-component semantics are preserved;
- Linux defaults are `/etc/terminfo`, `/lib/terminfo`,
  `/usr/share/terminfo`;
- macOS default is `/usr/share/terminfo`;
- Windows and other platforms have no invented platform defaults;
- directory roots are canonicalized and deduplicated deterministically;
- disabled environment/user/system categories are excluded exactly;
- malformed or unsupported explicit sources are not hidden as misses;
- `TerminalDatabase.BuiltIn` remains unchanged and I/O-free;
- no hashed-database, native ncurses, source-parser, terminal-session, or
  process-global provider state is introduced.

T39 may now perform the final provider-local cache, concurrent-first-load,
refresh, and explicit composition audit.
