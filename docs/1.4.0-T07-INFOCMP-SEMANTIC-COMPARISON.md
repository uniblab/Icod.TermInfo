# Icod.TermInfo 1.4.0 — T07 `infocmp` Semantic Comparison

**Development version:** `1.4.0-Alpha-7`
**Tranche:** T07
**Command:** `infocmp`
**Status:** implementation candidate

---

## 1. Objective

T07 extends the T06 one-terminal `infocmp` command with deterministic semantic
comparison while preserving the existing Runtime, Source, Compiler, and Inspection
public contracts.

The tranche intentionally composes the released Inspection comparison engine rather
than adding another comparison model. In particular, difference mode delegates to:

```text
TerminalDescriptionComparer.Compare(left, right)
```

No comparison is performed by rendering terminal descriptions and parsing or
diffing the resulting text.

---

## 2. Operand contract

The complete operand behavior through T07 is:

```text
0 terminal operands
    -> use TERM
    -> render one effective terminal description

1 terminal operand
    -> render that effective terminal description

2 or more terminal operands
    -> compare the first terminal with each subsequent terminal
```

For two or more operands, semantic-difference mode is the default when no explicit
`-d`, `-c`, or `-n` selector is supplied.

The first terminal is the stable left-hand side for every pair. For:

```text
infocmp first second third
```

T07 compares:

```text
first <-> second
first <-> third
```

and does not implicitly compare `second` with `third`.

---

## 3. Database selection

T07 adds:

```text
-B <directory>
```

The database roles are:

```text
-A <directory>    first terminal
-B <directory>    every subsequent terminal
```

Each option constructs an explicit `DirectoryTerminalDescriptionProvider` for its
side. If the matching option is absent, that side uses a normal
`SystemTerminalDescriptionProvider`.

Neither option mutates `TERMINFO`, `TERMINFO_DIRS`, `HOME`, or any other process
environment variable.

All requested terminals are acquired before comparison output is written. A failure
to acquire a later operand therefore cannot leave a misleading partial comparison
report on standard output.

---

## 4. Comparison modes

T07 adds four comparison switches:

```text
-d    semantic differences
-c    common effective capabilities
-n    standard capabilities absent from all operands
-q    short presentation
```

`-d`, `-c`, and `-n` are mutually exclusive. `-q` changes presentation only.

### 4.1 Difference mode (`-d`)

`-d` uses `TerminalDescriptionComparer` as the authoritative semantic engine. Its
structured difference order remains:

```text
canonical identity
alias identity
description identity
standard Boolean capabilities
standard numeric capabilities
standard string capabilities
extended capabilities in ordinal name order
```

T07 formats those structured records for the command line but does not redefine
what constitutes a semantic difference.

By default, effective extended-capability differences are filtered from command
output. `-x` includes them. Identity differences are never filtered by `-x`.

A comparison which finds differences is successful command output and returns exit
status `0`.

### 4.2 Common mode (`-c`)

`-c` reports capabilities which are present on both sides of each first-versus-next
pair with equal effective values.

Standard capabilities are traversed through `StandardCapabilityCatalog`; no local
copy of the capability vocabulary or compiled-table ordering is introduced.

With `-x`, extended capabilities present on both sides with exactly equal name,
value kind, and value are also reported. Extended names are compared and ordered
ordinally.

### 4.3 Absent mode (`-n`)

`-n` reports standard capabilities absent from **all** compared terminal
descriptions. It therefore evaluates the complete operand set rather than emitting
a separate pairwise absent report.

The absence universe is deliberately limited to `StandardCapabilityCatalog`. An
arbitrary extended capability vocabulary is open-ended, so T07 does not invent
extended names merely to report their absence. Supplying `-x` does not enlarge the
`-n` universe.

### 4.4 Short presentation (`-q`)

`-q` removes descriptive headings/indentation where practical while preserving the
same semantic comparison and deterministic ordering. It never changes equality,
capability filtering, acquisition, or exit status.

---

## 5. T06 option interaction

The following options remain one-terminal source-listing controls:

```text
-0
-1
-w <width>
-s <key>
```

T07 rejects those options when two or more terminal operands select comparison
mode. They are not silently ignored.

`-x` is meaningful in both layers:

- one-terminal rendering includes extended capabilities;
- `-d` and `-c` comparison reports include extended capabilities;
- `-n` remains standard-only by definition.

`-B`, `-d`, `-c`, `-n`, and `-q` require two or more terminal operands.

---

## 6. Presentation and escaping

Comparison presentation is command-owned. It is intentionally not added to the
Inspection public API.

Identity text and string capability values are emitted in single quotes with
deterministic escaping for backslash, quote, newline, carriage return, tab,
backspace, form feed, and other control characters. Numeric formatting is invariant
culture. Boolean presence uses `T`/`F`, and a missing non-Boolean value is shown as
`NULL`.

For an extended capability whose effective value kind differs between the two
terminals, T07 includes the value kinds explicitly so the report does not collapse
that semantic distinction.

---

## 7. Exit and diagnostic contract

T07 retains the command-suite statuses:

```text
0      success, including comparisons which find differences
1      operational/acquisition/data failure
2      usage error
130    cancellation
```

Existing T06 diagnostics remain the acquisition contract:

```text
INFOCMP0001    TERM required but missing/empty
INFOCMP0002    terminal not found
INFOCMP0003    provider/database acquisition failure
INFOCMP0004    effective description cannot be rendered losslessly
INFOCMP0005    database discovery/reporting failure
```

T07 does not introduce a new diagnostic code merely to report semantic
differences; differences are normal stdout data.

---

## 8. API and dependency audit

T07 adds no Runtime, Source, Compiler, or Inspection public API.

The active file:

```text
docs/1.4.0-INSPECTION-PUBLIC-API-BASELINE.txt
```

therefore remains unchanged from T06. Historical 1.0/1.1/1.2/1.3 API baselines
remain unchanged as well.

Production dependency direction remains:

```text
infocmp
    -> Icod.CommandFramework
    -> Icod.TermInfo.Inspection
        -> Icod.TermInfo.Source
        -> Icod.TermInfo
```

`infocmp` does not gain a production Compiler dependency. The InfoCmp test project
may continue to use Compiler to construct deterministic conventional database
fixtures.

All four reusable library assemblies retain:

```text
AssemblyVersion 1.0.0.0
```

## 9. Validation coverage

T07 command tests cover:

- equal descriptions and default `-d`;
- canonical-name differences;
- alias and description metadata differences;
- Boolean differences;
- numeric differences;
- string differences;
- extended-only differences;
- extended value-kind mismatch;
- common standard and extended capabilities;
- standard capabilities absent from all operands;
- first-versus-many behavior;
- the same terminal name loaded from two explicit roots;
- differences returning success;
- later-operand acquisition failure without partial stdout;
- invalid comparison option/operand shapes returning usage status;
- short `-q` presentation;
- deterministic standard and ordinal extended difference ordering.

The existing T06 tests continue to protect one-terminal rendering, database
reporting, stream ownership, culture independence, insertion-order independence,
and cancellation.

---

## 10. T07 gate

T07 is complete when:

1. two or more terminal operands reliably select first-versus-each-subsequent
   comparison;
2. `-d` delegates to `TerminalDescriptionComparer`;
3. `-c`, `-n`, and `-q` obey the command contract above;
4. `-A`/`-B` database roles are deterministic and environment-independent;
5. semantic differences return success;
6. acquisition and usage failures retain their conventional statuses;
7. comparison output order is deterministic and culture-independent;
8. no reusable library public API has changed; and
9. Windows, Linux, and macOS staging build/test validation is green.

**Gate T07:** common managed `infocmp` semantic comparison workflows are stable
and deterministic.
