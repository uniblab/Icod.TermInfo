# Icod.TermInfo 1.2.0 C01 — Compiler Package Foundation and Binary Writer Contract

**Tranche:** C01
**Development version:** `1.2.0-Alpha-1`
**Runtime assembly identity:** `Icod.TermInfo, Version=1.0.0.0`
**Source assembly identity:** `Icod.TermInfo.Source, Version=1.0.0.0`
**Compiler assembly identity:** `Icod.TermInfo.Compiler, Version=1.0.0.0`
**Status:** implementation candidate; build/test/package validation required

## Purpose

C01 establishes `Icod.TermInfo.Compiler` as the optional managed inverse of the
existing compiled-entry reader without changing the frozen Runtime or Source
public contracts.

The C01 dependency graph is:

```text
Icod.TermInfo.Compiler
        |
        v
  Icod.TermInfo

Icod.TermInfo.Source
        |
        v
  Icod.TermInfo
```

Compiler does not depend on Source until source compilation is deliberately
introduced by C05. Runtime remains dependency-free, and Source never depends on
Compiler.

## Package foundation

Runtime, Source, and Compiler advance together to `1.2.0-Alpha-1` while all
three assemblies retain version `1.0.0.0` and remain unsigned.

Compiler targets:

```text
net8.0;net9.0;net10.0
```

C01 adds the Compiler package and tests to the solution, introduces an
independent Compiler public-API baseline, extends three-target API equivalence,
adds structural Compiler package validation and a fresh package-reference-only
consumer, and packs Compiler in both Staging and Release workflows.

## Writer contract

The initial public surface is intentionally small:

```text
CompiledTermInfoWriter
    TerminalDescription -> byte[]
```

`Write` emits deterministic minimal legacy `0432` bytes containing the compiled
names section and the required little-endian six-short header. It writes the
alignment byte required before the numeric section when the names section ends
on an odd offset.

C01 deliberately emits zero Boolean, numeric, and string counts. A description
which already contains standard or extended capabilities is rejected with
`NotSupportedException`; C02 and C03 own those tables.

## Exact representation rules

C01 does not synthesize or silently alter identity data. The writer requires a
verbose description and rejects embedded NUL, the names-section `|` separator,
and characters outside Latin-1. The terminating NUL is supplied by the writer.
If the names section exceeds the legacy 16-bit section-size field, writing
fails deterministically.

These are representation failures of an otherwise valid `TerminalDescription`,
not parser diagnostics. C04 remains responsible for reviewing any broader
public options or explicit representation-failure surface.

## Purity and determinism

The writer does not inspect environment variables, read or write filesystem
state, invoke `tic`/`infocmp`/ncurses, or own process-global caches. For the same
representable description it returns byte-for-byte identical output across
repeated calls and supported platforms/frameworks.

Alias order is preserved because aliases are already ordered identity metadata.

## Validation

C01 tests cover:

- exact legacy magic and zero table counts;
- required alignment;
- parser round-trip of name, description, and aliases;
- high Latin-1 identity bytes;
- deterministic repeated output;
- missing-description and unrepresentable-identity failures;
- deliberate rejection of capability-bearing descriptions;
- coordinated three-package version and assembly identity;
- Compiler -> Runtime-only project dependency;
- solution/workflow/release-verifier participation;
- independent Compiler API baseline and three-target equivalence;
- structural NuGet/symbol validation and fresh package consumption.

## C01 gate

C01 is complete only after the complete solution, tests, package packing,
`verify-release-package`, three-OS CI matrix, and fresh Runtime/Source/Compiler
consumers pass. This document records the implementation candidate and does not
claim those external validation results in advance.

C02 may then implement complete standard capability emission using only the
canonical `StandardCapabilityCatalog.BinaryIndex` ordering contract.
