# Icod.TermInfo 1.0.0 T43 — Robustness and Compatibility Gate

T43 advances the development package to `1.0.0-beta.1`.

The tranche adds confidence and enforceable compatibility gates. It does not add
a terminal family, parser format, discovery source, or other production runtime
feature.

## T42 baseline prerequisite

The T42 implementation is present and has already built/tested successfully on
both `net8.0` and `net10.0`.

One T42 acceptance artifact remains deliberately human-owned:

```text
docs/1.0.0-PUBLIC-API-BASELINE.txt
```

Generate it with:

```text
dotnet run --project tools/public-api-snapshot/Icod.TermInfo.PublicApiSnapshot.csproj -c Release -- --write
```

Review the entire file before committing it. T43 release validation now runs:

```text
public-api-snapshot --check
```

so package/release validation will fail until that reviewed baseline exists.

Because T42 changed no production public API relative to the completed 0.9
implementation, the reviewed T42 manifest also serves as the source/API
compatibility baseline inherited from 0.9.0.

## Expanded deterministic parser corpus

T43 adds a generated conventional-entry corpus in the normal test suite.

The generated entries vary:

- canonical names;
- aliases and descriptions;
- Boolean table lengths;
- legacy `0432` signed-16-bit numerics;
- `01036` signed-32-bit numerics;
- odd/even section alignment;
- values above the signed-16-bit range for `01036`.

The same corpus is parsed under:

```text
InvariantCulture
tr-TR
ar-SA
```

and the resulting semantic snapshots must be identical.

This deliberately targets culture-sensitive failure modes such as casing,
numeric formatting/parsing, and locale-dependent comparison.

## Expanded fuzz and mutation campaign

T35 already established deterministic parser-boundary fuzzing.

T43 adds a larger normal-test campaign:

```text
4,096 deterministic random byte arrays
512 deterministic mutations per valid checked fixture
up to 8 bit edits per mutation
```

As before, arbitrary malformed bytes may either parse successfully or fail, but
a parser failure must remain inside `CompiledTermInfoFormatException`.

No unrelated runtime exception is accepted as a malformed-input outcome.

## Pinned ncurses differential campaign

The existing fixture generator already freezes:

```text
tic -V
ncurses 6.5.20250216
```

T43 adds:

```text
--check
```

to the fixture generator.

The check:

1. snapshots the checked-in compiled/malformed `.bin` corpus;
2. verifies the exact pinned `tic` provenance;
3. recompiles every checked `.ti` source with `tic -x`;
4. re-derives the adversarial seeds;
5. byte-compares every generated file and the exact file-name set;
6. reports any drift as an error;
7. restores the original checked-in bytes before exit.

This is a maintainer differential campaign, not a normal CI dependency. Normal
build/test/package validation remains free from ncurses and network
requirements.

Run it on a host with the pinned toolchain:

```text
dotnet run --project tools/compiled-terminfo-fixtures/Icod.TermInfo.FixtureGenerator.csproj -- --check
```

## Concurrency/cache stress

T39 established single-flight provider semantics.

T43 increases the stress level to 256 simultaneous first-load tasks against one
`DirectoryTerminalDescriptionProvider`.

Every task must receive the same immutable `TerminalDescription` instance.

This does not change cache policy:

- successful entries remain provider-local and cached;
- misses are retryable;
- failures are retryable;
- new provider instances remain the explicit refresh mechanism.

## Resource/bounds audit

T43 verifies the parser's configured maximum entry size at the exact boundary:

```text
maximum == entry length
    -> parse succeeds

maximum == entry length - 1
    -> CompiledTermInfoFormatException
```

The existing parser hardening/overflow/truncation suites remain authoritative for
the broader resource contract.

## net8.0 / net10.0 API equivalence

`Icod.TermInfo.PublicApiSnapshot` gains:

```text
--compare <assembly-a> <assembly-b>
```

The comparison loads each assembly into an isolated collectible load context,
emits the same exhaustive API manifest used by the T42 baseline, and requires
byte-for-byte manifest equality.

Release validation compares:

```text
bin/Release/net8.0/Icod.TermInfo.dll
bin/Release/net10.0/Icod.TermInfo.dll
```

This turns "same source project" into an explicit cross-TFM public-contract gate.

## 0.9 compatibility baseline

T42 deliberately made no production runtime API change when it introduced the
1.0 version/assembly policy and maintenance tooling.

Therefore the reviewed T42 API manifest is the 1.0 public API inherited from
0.9.0.

T43 does not generate or bless a replacement baseline. It only checks the
reviewed file.

The complete historical 0.6-0.9 behavioral test corpus also continues to execute
under both supported frameworks.

## Package icon and metadata

The project already packed `icon.png`; T43 now declares it through:

```xml
<PackageIcon>icon.png</PackageIcon>
```

The package verifier now requires both the file and matching nuspec metadata.

The verifier also audits:

- package id/version;
- authors;
- project URL;
- readme metadata;
- icon metadata;
- LGPL-3.0-or-later license expression;
- license-acceptance flag;
- non-empty description;
- non-empty tags;
- git repository URL and exact commit;
- absence of runtime NuGet dependencies;
- exact net8/net10 managed payloads;
- stable `1.0.0.0` assembly identity;
- unsigned identity;
- both portable Source Link PDBs.

## Release-validation order

The release verifier now performs:

```text
generated metadata check
    -> approved API baseline check
    -> net8/net10 API equivalence
    -> package structure/metadata/symbol verification
    -> fresh package consumer on net8
    -> fresh package consumer on net10
    -> non-interactive sample
```

The publishing boundary is unchanged:

```text
PR workflow
    -> never publishes

push-main workflow
    -> main only
    -> may publish after validation
```

## Production scope

T43 changes no file under `src/`.

The only production-project changes are prerelease/package metadata.

No T43 change expands the frozen terminfo semantics, parser format family,
discovery precedence, cache policy, terminal profiles, or output behavior.
