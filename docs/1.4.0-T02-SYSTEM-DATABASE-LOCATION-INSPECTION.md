## 1. Purpose

T02 exposes the ordered system terminfo discovery plan as reusable read-only
Inspection API without enlarging the frozen Runtime 1.0 public contract.

This tranche provides the reusable mechanism required later by:

```text
tic -D
infocmp -D
toe discovery
```

T02 deliberately does **not** enumerate database contents. Conventional database
catalog enumeration remains T03.

## 2. Architectural boundary

Runtime remains authoritative for discovery policy.

The effective layering is:

```text
SystemTerminalDescriptionProvider
        |
        | internal discovery plan
        v
Icod.TermInfo.Inspection
        |
        v
TermInfoDatabaseInspector
```

Inspection does not copy or reinterpret `TERMINFO`, user-database,
`TERMINFO_DIRS`, platform-default, path-normalization, or duplicate-root rules.
It consumes the same internal directory-source construction used by
`SystemTerminalDescriptionProvider`.

Runtime therefore gains only a narrow internal coordination seam:

- an internal immutable database-location descriptor;
- an internal location-kind enum;
- an internal method which projects the existing discovery plan;
- friend access for `Icod.TermInfo.Inspection` and its deterministic tests.

`docs/1.0.0-PUBLIC-API-BASELINE.txt` remains unchanged.

## 3. Public Inspection API

T02 adds three public Inspection types:

```text
TermInfoDatabaseLocationKind
TermInfoDatabaseLocation
TermInfoDatabaseInspector
```

The public entry point is:

```csharp
TermInfoDatabaseInspector.GetSystemLocations(
    SystemTerminalDescriptionProviderOptions? options = null
)
```

The result is an immutable read-only snapshot captured for that call.

## 4. Location kinds

The T02 public model distinguishes:

```text
EncodedTermInfo
TermInfoDirectory
UserDatabase
TermInfoDirsDirectory
PlatformDefaultDirectory
```

These values describe where a location entered the Runtime search plan.

A platform default inserted in-place by an empty `TERMINFO_DIRS` component is
reported as `TermInfoDirsDirectory`, because it participates in the search plan
at that environment-list position. A later final platform-default occurrence is
then removed by Runtime's existing duplicate-root logic.

## 5. Encoded TERMINFO privacy

Encoded `TERMINFO` is represented as a location kind, but its encoded payload is
not returned through Inspection.

For:

```text
TermInfoDatabaseLocationKind.EncodedTermInfo
```

`TermInfoDatabaseLocation.Path` is always `null`.

The API therefore reports that encoded discovery would precede directory
searches without exposing the hex/base64 entry bytes or pretending that the
encoded value is a filesystem database.

T02 does not decode or parse the payload merely to inspect the discovery plan.
Normal Runtime loading retains responsibility for validating encoded content.

## 6. Directory location semantics

Every non-encoded location exposes a normalized fully-qualified directory path.

The exact order follows Runtime:

```text
1. encoded TERMINFO, when present
2. directory-valued TERMINFO
3. non-Windows user .terminfo
4. TERMINFO_DIRS entries, including defaults inserted by empty components
5. remaining enabled platform defaults
```

Directory duplicate elimination also remains Runtime behavior:

```text
Windows    ordinal, case-insensitive
other      ordinal, case-sensitive
```

The first occurrence wins.

## 7. Snapshot semantics

The public Inspector follows the same capture model as a newly created
`SystemTerminalDescriptionProvider`:

- system-provider options are snapshotted;
- permitted environment variables are captured once;
- user-home input is captured once;
- current directory is captured once;
- host platform is captured once;
- directory paths are resolved against that captured current directory.

The returned list does not observe later process-environment changes.

The deterministic test seam accepts an explicit internal discovery snapshot and
explicit default-root set. This test-only path is not public API.

## 8. No filesystem enumeration

T02 may construct the same directory providers Runtime would use to canonicalize
the discovery plan, but it does not:

- enumerate a terminfo root;
- open a compiled entry;
- validate whether a directory currently exists;
- traverse subdirectories;
- read a hashed database;
- mutate provider caches;
- create or modify filesystem state.

Those concerns are intentionally outside this tranche.

## 10. Package boundary

Production dependencies remain:

```text
Inspection -> Source -> Runtime
Inspection ----------> Runtime
```

Inspection still has no production dependency on Compiler.

Runtime, Source, and Compiler acquire no Inspection dependency.

The package-reference-only Inspection smoke consumer exercises the new public
Inspector API on `net8.0`, `net9.0`, and `net10.0` with all discovery sources
disabled so the smoke test is independent of host environment and databases.

## 11. Validation cases

T02 deterministic tests cover:

- encoded `TERMINFO` precedence;
- non-disclosure of encoded payloads;
- directory-valued `TERMINFO`;
- user `.terminfo` placement;
- `TERMINFO_DIRS` order;
- empty `TERMINFO_DIRS` components;
- duplicate final platform defaults;
- relative-path normalization;
- Windows case-insensitive duplicate elimination;
- Linux platform defaults;
- macOS platform defaults;
- Windows having no implicit Unix default roots;
- disabled environment discovery;
- disabled user discovery;
- disabled system discovery;
- a completely restricted provider policy;
- immutability of the returned public snapshot.

Normal CI remains independent of host ncurses tools and host terminfo contents.

## 13. T02 completion gate

T02 is complete when:

- Runtime's frozen 1.0 public API baseline remains exact;
- Source's frozen 1.1 public API baseline remains exact;
- Compiler's frozen 1.2 public API baseline remains exact;
- Inspection's historical 1.3 baseline remains unchanged;
- the active 1.4 Inspection baseline contains exactly the reviewed T02 addition;
- Inspection reports the same ordered location plan used by Runtime;
- encoded `TERMINFO` payloads are not exposed;
- normalized path and platform duplicate semantics are deterministic;
- database contents are not enumerated;
- the package-only Inspection smoke consumer passes on all three library TFMs;
- the complete Windows/Linux/macOS Staging matrix passes.

After this gate is green, T03 may build conventional database catalog enumeration
on top of these location semantics without reopening Runtime discovery policy.
