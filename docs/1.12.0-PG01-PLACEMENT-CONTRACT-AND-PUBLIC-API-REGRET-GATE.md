# Icod.TermInfo 1.12.0 — PG01 Placement Contract and Public API Regret Gate

**Tranche:** PG01 — architecture, vocabulary, and public API regret gate  
**Development version:** `1.12.0-Alpha-1`  
**Baseline:** stable `1.11.0`  
**Primary package:** `Icod.TermInfo.Inspection`

## Purpose

PG01 freezes the smallest durable public vocabulary required for the 1.12 advanced persistent-raster placement line before evidence, classification, planning, database composition, or automation are implemented.

The release remains deliberately bounded to two protocol-neutral semantic subjects:

```text
SourceRectangle = 0
SignedZOrder    = 1
```

`SourceRectangle` means that a persistent raster placement can select a pixel-space sub-rectangle from an uploaded raster resource.

`SignedZOrder` means that a persistent raster placement can carry an explicit signed stacking-order value.

These subjects describe whether the semantics are available. They do not carry concrete rectangle coordinates or z-order values.

## Frozen 1.11 boundary

Version 1.12 builds beside the 1.11 persistent-raster lifecycle contract rather than widening it.

The following 1.11 evidence-subject membership and numerics remain unchanged:

```text
RasterDisplay       = 0
PersistentUpload    = 1
AcknowledgedUpload  = 2
PlacementCreation   = 3
MultiplePlacements  = 4
PlacementUpdate     = 5
PlacementDeletion   = 6
ResourceDeletion    = 7
```

No 1.12 placement subject is added to `PersistentRasterLifecycleEvidenceSubject`.

The four-state support vocabulary is reused unchanged:

```text
Unknown       = 0
Supported     = 1
Unsupported   = 2
Contradicted  = 3
```

Unknown continues to mean that available evidence does not establish a conclusion. It does not mean unsupported.

## Public surface introduced by PG01

PG01 adds exactly one public type:

```csharp
public enum PersistentRasterPlacementSubject {
	SourceRectangle = 0,
	SignedZOrder = 1,
}
```

No evidence type, profile, request, planner, JSON document, protocol identifier, concrete placement value, or runtime execution API is added by PG01.

## Package and dependency ownership

The new vocabulary belongs to `Icod.TermInfo.Inspection`.

The dependency boundary remains:

```text
Icod.TermInfo.Inspection
    -> Icod.TermInfo.Source
    -> Icod.TermInfo
```

No production dependency on `Icod.Terminal` or `Icod.DCurses` is introduced.

`Icod.Terminal` remains responsible for concrete rectangle values, concrete signed z-order values, terminal-side resource/placement identity, live verification, wire encoding, execution, invalidation, and cleanup.

## JSON compatibility

JSON versions 1, 2, and 3 remain immutable.

PG01 adds no JSON surface. Version 4 is reserved for PG06 and will contain exactly the additive placement profile and placement plan document kinds described by the 1.12 roadmap.

## Explicit exclusions

PG01 and the 1.12 release do not introduce:

- relative-placement graphs;
- Unicode placeholders;
- animation or frame lifecycle;
- absolute screen-coordinate placement;
- scene-graph policy;
- protocol/backend selection;
- Kitty image/placement identifiers;
- raw APC fields;
- image decoding or pixel buffers;
- terminal-session ownership;
- live probing owned by TermInfo.
