# Icod.TermInfo 1.4.0 Release Audit

**Release version:** `1.4.0`
**Runtime assembly version:** `1.0.0.0`
**Source assembly version:** `1.0.0.0`
**Compiler assembly version:** `1.0.0.0`
**Inspection assembly version:** `1.0.0.0`
**Status:** Final release candidate — main Release validation and tag publication remain

## Purpose

This document is the final release gate for the coordinated `Icod.TermInfo`
1.4.0 package family and managed command suite. T01-T11 are complete. Release
closure is not another feature tranche: it freezes versioning, package/API
contracts, command artifacts, documentation, and the publication gate.

The publication boundary remains immutable tag `v1.4.0`. Ordinary pull requests
and pushes to `main` validate candidates but do not publish packages.

## Frozen library contract

The stable release SHALL preserve:

- `docs/1.0.0-PUBLIC-API-BASELINE.txt` as the exact Runtime API;
- `docs/1.1.0-SOURCE-PUBLIC-API-BASELINE.txt` as the exact Source API;
- `docs/1.2.0-COMPILER-PUBLIC-API-BASELINE.txt` as the exact Compiler API;
- `docs/1.3.0-INSPECTION-PUBLIC-API-BASELINE.txt` as the historical Inspection
  1.3 baseline;
- `docs/1.4.0-INSPECTION-PUBLIC-API-BASELINE.txt` as the frozen Inspection 1.4
  API;
- exact net8/net9/net10 API equivalence for all four libraries;
- assembly version `1.0.0.0` for all four reusable assemblies;
- Runtime dependency-free;
- Source depending only on Runtime;
- Compiler depending on Runtime and Source;
- Inspection depending on Runtime and Source and not on Compiler.

All four library projects SHALL declare both `Version` and `PackageVersion`
exactly `1.4.0`.

## Frozen command contract

`tic`, `infocmp`, and `toe` SHALL each:

- target `net10.0`;
- report version `1.4.0`;
- remain non-packable solution executables;
- use `Icod.CommandFramework` only in the command layer;
- retain the T10 CLI/presentation contract and T11 corpus/hostile-input gates;
- introduce no command-to-command project dependency.

The command projects SHALL declare `Version` exactly `1.4.0`.

## Artifact contract

The stable release contains fourteen checksummed package/archive artifacts:

```text
4 .nupkg
4 .snupkg
6 framework-dependent tool-suite archives
```

The tool archives are:

```text
Icod.TermInfo.Tools.1.4.0.win-x64.zip
Icod.TermInfo.Tools.1.4.0.win-arm64.zip
Icod.TermInfo.Tools.1.4.0.linux-x64.tar.gz
Icod.TermInfo.Tools.1.4.0.linux-arm64.tar.gz
Icod.TermInfo.Tools.1.4.0.osx-x64.tar.gz
Icod.TermInfo.Tools.1.4.0.osx-arm64.tar.gz
```

`SHA256SUMS.txt` covers all fourteen artifacts, producing fifteen final GitHub
Release assets.

The user supplies the .NET 10 runtime. The archives are not NuGet global tools,
self-contained bundles, NativeAOT images, installers, or signed/notarized
platform packages.

## Archive execution gate

Structural archive validation alone is insufficient for final release closure.

After the six archives are built and structurally verified, CI downloads them
onto Windows, Linux, and macOS runners. Each runner selects the archive matching
its operating system and architecture, unpacks it, and executes the actual
release payload.

The smoke gate SHALL:

1. run `tic --version`, `infocmp --version`, and `toe --version` and require
   `1.4.0`;
2. use the unpacked `tic` to publish a controlled source entry into a temporary
   conventional database;
3. use the unpacked `infocmp` to acquire/render that entry;
4. use the unpacked `toe` to enumerate that entry.

The release workflow SHALL not begin package publication until this smoke gate
and the complete Windows/Linux/macOS Release validation matrix have succeeded.

## Required final validation

Before tag creation, the stable release-finalization commit SHALL pass the
complete `main` workflow, including:

- Release restore/build/test on Windows, Linux, and macOS;
- all four package verifiers;
- all four package-reference-only consumers across net8/net9/net10;
- frozen API and cross-target API-equivalence checks;
- checked-in differential corpus and hostile-input tests;
- construction and structural verification of all six tool archives;
- unpacked release-archive smoke on matching Windows/Linux/macOS runners.

Equivalent local package validation remains documented in `docs/RELEASING.md`.

## Tag publication

Tag `v1.4.0` SHALL:

1. identify the exact stable release-finalization commit already validated on
   `main`;
2. identify a commit contained in `main`;
3. match all four library `Version`/`PackageVersion` values and all three command
   `Version` values exactly;
4. repeat the complete Release matrix;
5. rebuild and structurally verify all six tool archives;
6. repeat the unpacked archive smoke gate on Windows/Linux/macOS;
7. publish the four validated `.nupkg` files to NuGet.org;
8. publish the same four `.nupkg` files to GitHub Packages;
9. create the GitHub Release with four `.nupkg`, four `.snupkg`, six tool
   archives, and `SHA256SUMS.txt`.

NuGet trusted publishing must authorize all four package IDs for
`release.yaml` and the `Release` environment before the tag is pushed.

## Final sign-off

The 1.4.0 release is complete only when:

- the `v1.4.0` tag workflow succeeds;
- all four version 1.4.0 packages are visible on NuGet.org;
- all four version 1.4.0 packages are visible in GitHub Packages;
- the GitHub Release contains exactly fifteen expected assets;
- fresh consumers can restore all four final packages;
- the six command archives remain downloadable and their checksums match;
- `v1.4.0` still identifies the exact validated release commit.

Do not move or recreate a published release tag. Any package, archive, source,
documentation, or API-baseline change after release requires a new version and a
new validated immutable tag.
