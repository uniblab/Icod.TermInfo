# Icod.TermInfo 1.2.0 C02 — Standard Capability Emission

**Tranche:** C02
**Development version:** `1.2.0-Alpha-2`
**Runtime assembly identity:** `Icod.TermInfo, Version=1.0.0.0`
**Source assembly identity:** `Icod.TermInfo.Source, Version=1.0.0.0`
**Compiler assembly identity:** `Icod.TermInfo.Compiler, Version=1.0.0.0`
**Status:** complete — validated and integrated on the 1.2.0 working branch

## Purpose

C02 extends the C01 legacy `0432` writer from identity-only entries to complete
standard Boolean, numeric, and string capability emission without changing the
reviewed Compiler public API.

The public operation remains:

```text
CompiledTermInfoWriter
    TerminalDescription -> byte[]
```

The package dependency graph is unchanged:

```text
Compiler -> Runtime
Source   -> Runtime
```

Compiler does not depend on Source before C05.

## Standard table ownership

C02 derives compiled positions exclusively from:

```text
StandardCapabilityCatalog.BinaryIndex
```

Managed enum ordinal values are not compiled positions. The writer does not
maintain a private duplicate capability table.

For each standard kind, the declared table count is the highest effectively
present binary index plus one. Therefore trailing absent positions are omitted
deterministically while absent positions before a present capability remain
represented in the table.

## Boolean table

Standard Boolean values use the frozen conventional encoding:

```text
0x00  absent
0x01  present
```

`TerminalDescription` exposes only effectively present Booleans, so C02 does not
invent cancellation values.

## Numeric table

Legacy `0432` stores standard numerics as signed 16-bit little-endian values.

C02 writes:

```text
-1       absent
0..32767 present
```

A present negative value, including `-1` or `-2`, is not representable from the
effective runtime model and fails deterministically. Values greater than
`32767` also fail in C02 rather than being truncated; C04 owns `01036`
wide-numeric selection.

## String offset and value tables

Each standard string position contains a signed 16-bit little-endian relative
offset into the string table or `-1` for absence.

Present string values:

- use the runtime's exact Latin-1 byte bridge;
- reject characters outside Latin-1;
- reject embedded NUL;
- receive one terminating NUL in the compiled string table.

Every present string start offset must fit the non-negative signed 16-bit offset
range. The complete string table must fit the unsigned 16-bit header size field.
Those constraints are checked before narrowing values to binary fields.

C02 emits strings in canonical standard binary order, so output is deterministic
and independent of dictionary enumeration order.

## Layout and alignment

The standard legacy layout is:

```text
six-short header
names
Boolean table
optional zero alignment byte
numeric table
string offset table
string table
```

The numeric table begins on an even offset after the names and Boolean sections.
All multi-byte fields are emitted little-endian.

## Scope boundary

C02 supports standard capabilities only. Any effective extended capability still
causes `NotSupportedException`; C03 owns ncurses extended sections.

C02 does not introduce filesystem access, environment discovery, native
ncurses/`tic`, database-layout policy, or source parsing.

## Validation

C02 tests cover:

- complete standard-catalog semantic round-trip;
- sparse standard tables and deterministic trailing omission;
- direct absent-sentinel and binary-index layout assertions;
- Boolean, numeric, and string table ordering;
- numeric `32767` success and out-of-range rejection;
- high Latin-1 string round-trip;
- embedded-NUL and non-Latin-1 rejection;
- signed string-offset overflow rejection;
- unsigned string-table-size overflow rejection;
- continued C01 identity-only behavior;
- continued rejection of extended capabilities;
- fresh Compiler package consumption using standard capabilities.

The Compiler public API baseline remains unchanged from C01.

## C02 gate

C02 is complete when standard-only descriptions round-trip exactly at the
semantic level through:

```text
TerminalDescription
    -> CompiledTermInfoWriter
    -> legacy 0432 bytes
    -> CompiledTermInfoParser
    -> TerminalDescription
```

and the complete solution, package verifier, fresh package consumers, and
Windows/Linux/macOS CI matrix pass.

C03 may then add deterministic ncurses extended-capability emission without
changing the C02 standard-table contract.
