# Icod.TermInfo 0.8.0 — T29 0.9 Binary and Provider Readiness Gate

T29 freezes the input and error-semantics target for the first arbitrary compiled-terminfo implementation planned for 0.9.0. It deliberately does **not** add a production compiled-entry parser, a directory provider, system-database discovery, `TERMINFO`, `TERMINFO_DIRS`, `$HOME/.terminfo`, encoded `TERMINFO=hex:` / `TERMINFO=b64:` loading, or filesystem caching.

The binary-format authority for this gate is the conventional ncurses/System V-compatible layout documented by ncurses `term(5)`, with the portability boundary stated there: X/Open does not standardize a universal compiled representation, and the initial target follows the default ncurses/Solaris-like ordering rather than claiming compatibility with divergent HP-UX, AIX, OSF/1, or other historical vendor layouts.

## Frozen 0.9 binary contract

The first 0.9 parser is expected to accept these two conventional base formats:

- legacy magic `0432` (octal), encoded as little-endian `0x011a`, with signed 16-bit standard numeric values;
- extended-number magic `01036` (octal), encoded as little-endian `0x021e`, with signed 32-bit standard numeric values.

For either magic, the conventional section is:

1. six little-endian 16-bit header values: magic, names size, Boolean count, numeric count, string-offset count, and string-table size;
2. NUL-terminated names field containing canonical name, aliases, and final verbose description separated by `|`;
3. one byte per standard Boolean capability;
4. zero or one alignment byte so the numeric table begins on an even offset;
5. standard numeric values, 16-bit for `0432` and 32-bit for `01036`;
6. signed 16-bit offsets for standard string capabilities;
7. the NUL-terminated string table.

The frozen sentinel meanings are:

| Kind | Absent | Canceled |
| --- | ---: | ---: |
| Boolean | `0x00` | `0xfe` (`0376`) |
| Numeric | `-1` | `-2` |
| String offset | `-1` | `-2` |

No other negative numeric or string-offset sentinel is valid in the selected contract.

Capability bytes are decoded one-to-one through the reversible 8-bit string contract established by T25. A future parser must not feed capability bytes through locale-dependent text decoding.

## Frozen ncurses extended section

When bytes remain after the conventional section, the first 0.9 parser must support the ncurses extension appended to either base magic. After the conventional section, alignment is applied as required before the extension header.

The extension header contains five little-endian 16-bit counts/sizes:

1. extended Boolean count;
2. extended numeric count;
3. extended string count;
4. total number of items represented by the extended string table;
5. extended string-table byte size.

The following data is ordered as extended Booleans, extended numerics, extended string offsets, extended string values, then extended capability names. A zero alignment byte is inserted after the extended Boolean bytes when needed to align the extended numeric table. Extended numerics use the base entry's numeric width: signed 16-bit values under `0432` and signed 32-bit values under `01036`. Extended string offsets remain signed 16-bit values. Names are ordered Boolean, numeric, then string. Extended names remain case-sensitive.

The selected 0.9 semantic target must reject or otherwise explicitly handle an extended name which collides with a known standard short name. It must never silently shadow the standard capability catalog.

## Frozen absence/cancellation mapping

A parser must distinguish absent from canceled while interpreting compiled bytes. Canceled data must never become a real `false`, negative numeric value, or string payload, and must never leak an inherited value during construction. The effective immutable `TerminalDescription` API may continue to expose both absent and canceled capabilities as not present after composition has completed.

This is consistent with the internal cancellation model established by T26 and with the public 0.8 model: the parser is responsible for preserving cancellation long enough to build the correct effective description, not for exposing a new public canceled-state API.

## Provider clean-miss contract

`ITerminalDescriptionProvider.TryLoad(...) == false` is frozen to mean **clean miss**: the provider did not resolve the requested terminal and another configured provider may be consulted.

Future I/O-backed providers must not translate permission failures, I/O failures, corrupt compiled entries, unsupported compiled formats, or parser defects into `false`. Such failures must remain distinguishable from an ordinary absent terminal. `TerminalDatabase` therefore retains useful first-match-wins composition without needing a new provider result type merely to distinguish miss from failure.

The existing `TermInfoFormatException` remains reserved for malformed parameter-program syntax. The future compiled-entry parser must use distinct exception vocabulary; `CompiledTermInfoFormatException` is the reserved conceptual name for malformed compiled-entry data. T29 does not add that type because no production compiled parser exists yet.

## Checked-in fixture corpus

Fixtures live under `tests/Icod.TermInfo.Tests/fixtures/compiled-terminfo/`. Normal tests consume the checked-in bytes and never invoke `tic`.

The valid corpus covers:

- `t29-legacy-minimal.bin`: `0432`, canonical name, alias, verbose description, Boolean/numeric/string values, and explicit absent slots;
- `t29-legacy-alignment.bin`: a conventional entry whose Boolean section requires the numeric-alignment byte;
- `t29-legacy-edge.bin`: `0432`, canceled Boolean/numeric/string sentinels, parameterized strings, padding annotations, and a `0x80` capability byte;
- `t29-extended.bin`: ncurses extended Booleans, numeric and string values, multiple extended names, while retaining legacy `0432` standard numerics;
- `t29-extended32.bin`: `01036`, standard numeric values above the signed 16-bit range including `16777216`, plus ncurses extended data.

Adversarial seeds cover truncated header, impossible conventional and extended counts, missing names terminator, illegal conventional and extended string offsets, unsupported magic, malformed extended header, and a structurally derived extended-name collision with the standard short name `cup`.

`manifests/manifest.json` records exact SHA-256 hashes, header expectations, effective semantic expectations, and generator provenance. Tests verify the hashes so fixture drift is intentional and reviewable.

## Fixture provenance and regeneration

The checked-in valid binaries were generated with:

```text
ncurses 6.5.20250216
```

using the equivalent of:

```text
tic -x -o <temporary-output> <source-file>
```

The source descriptions are preserved under `source/`. `generate-fixtures.py` reproduces the valid binaries, performs the one documented Boolean-cancellation sentinel edit which standalone `tic` normalizes away, derives the collision seed, and creates the malformed seeds. The script intentionally refuses to regenerate with another `tic -V` string; changing the generator baseline must therefore be a deliberate source change accompanied by refreshed provenance and hashes.

Regeneration is a maintainer operation only. `tic` and Python are **not** build, test, package, or runtime dependencies.

## Architecture guard

T29 tests assert that the production assembly contains no type whose identity suggests the reserved compiled parser/directory-provider implementation and that the fixture corpus is not embedded as a production assembly resource. This is intentionally a guardrail rather than a parser implementation.

At the end of T29, 0.9 can begin from deterministic bytes, explicit expected semantics, a frozen provider miss/failure boundary, and a fixed vendor/format scope without redesigning the completed 0.8 in-memory model.
