# Icod.TermInfo 1.4.0 — T08 `toe` Conventional Database Listing

**Development version:** `1.4.0-Alpha-8`
**Tranche:** T08
**Command:** `toe`
**Status:** implementation candidate
**Reusable public API change:** none

---

## 1. Objective

T08 turns the T01 `toe` command shell into a deterministic conventional
terminfo database-listing utility.

The command composes the reusable mechanisms established earlier in 1.4:

```text
T02 Runtime discovery snapshot
        |
        v
TermInfoDatabaseInspector.GetSystemLocations()
        |
        v
T03 conventional database catalog
        |
        v
parsed TerminalDescription identities
        |
        v
toe presentation and exit policy
```

T08 does not reproduce Runtime search-path policy, compiled-entry parsing, or
filesystem traversal in the command layer.

Source dependency analysis remains T09 work.

## 2. Command contract

T08 supports:

```text
toe [options] [directory ...]
toe -D
toe -V
toe --version
toe --help
```

Listing options are:

```text
-a
-h
-s
```

The T09 source dependency switches:

```text
-u
-U
```

are deliberately rejected as usage errors in T08.

## 3. Explicit directory operands

When one or more directory operands are supplied, `toe` inspects exactly those
roots in operand order.

Every explicit root is processed. `-a` does not alter this rule.

An explicit missing root is an operational error because the caller requested
that exact database. An explicit non-directory store is also an operational
error.

## 4. Default discovery

When no directory operand is supplied, `toe` obtains the ordered Runtime
discovery snapshot through:

```csharp
TermInfoDatabaseInspector.GetSystemLocations()
```

Encoded `TERMINFO` has no directory path and is skipped for catalog enumeration.

Without `-a`, missing discovery roots are clean misses and the command continues
until it finds the first applicable conventional directory. That conventional
database is listed and the search stops.

With `-a`, every applicable conventional directory is inspected in Runtime
search order.

Malformed, unsupported, or unavailable database locations produce diagnostics
without preventing later safe locations from being considered.

## 5. Catalog and identity boundary

Every root is inspected through:

```csharp
TermInfoDatabaseInspector.InspectDirectory(
    root,
    parserOptions: null,
    cancellationToken: cancellationToken
)
```

The command therefore consumes T03's bounded conventional traversal, link/reparse
policy, parser resource limits, physical placement validation, deterministic
ordering, and issue model.

A filename is never treated as terminal identity.

Each successful physical catalog entry is presented using its parsed canonical
name and parsed description:

```text
canonical-name<TAB>description
```

Alias publications therefore continue to display the canonical identity carried
by their compiled entry. Duplicate canonical names are not globally collapsed.

## 6. Presentation controls

### `-h`

`-h` writes one heading before each conventional database:

```text
# <absolute-database-root>
```

The heading is command presentation only and is not added to Inspection.

### `-s`

`-s` explicitly orders entries by:

```text
canonical name, ordinal
physical path, ordinal
```

The physical-path tie break keeps duplicate canonical identities deterministic.

Without `-s`, T08 preserves the deterministic order supplied by the T03 catalog.

### `-D`

`-D` reports the T02 discovery snapshot as:

```text
location-kind<TAB>path
```

Encoded `TERMINFO` is represented by `<encoded>` rather than exposing its
payload.

## 7. Diagnostics and exit status

T08 uses command-private diagnostic codes:

```text
TOE0001  Runtime database discovery failed
TOE0002  explicitly requested database root is missing
TOE0003  database root is not a supported conventional directory
TOE0004  T03 catalog issue or unavailable root
TOE0005  explicit/root inspection operation failed
```

For a conventional catalog with individual issues, T08:

1. emits every safely parsed entry;
2. emits the deterministic T03 issues on standard error;
3. continues to later roots when the command contract calls for it;
4. remembers that an operational error occurred;
5. returns failure only after all safely obtainable results have been emitted.

Exit status remains:

```text
0      success
1      operational/database failure
2      usage error
130    cancellation
```

Cancellation propagates through T03 inspection and returns 130.

## 8. Dependency and API audit

Production remains:

```text
toe
    -> Icod.CommandFramework
    -> Icod.TermInfo.Inspection
        -> Icod.TermInfo.Source
        -> Icod.TermInfo
```

`toe` does not gain a production Compiler dependency.

The `Icod.TermInfo.Toe.Tests` project references Compiler only to publish
deterministic private conventional database fixtures.

T08 adds no public member to Runtime, Source, Compiler, or Inspection. The
active 1.4 Inspection public API baseline therefore remains unchanged from T06.

All four reusable library assemblies retain:

```text
AssemblyVersion 1.0.0.0
```

## 9. Validation coverage

T08 command tests cover:

- empty conventional roots;
- one explicit root;
- multiple explicit roots and operand ordering;
- default directory-valued `TERMINFO` discovery;
- acceptance of `-a` with explicit operands without changing their semantics;
- root headings;
- canonical ordinal sorting;
- duplicate canonical names across roots;
- alias publications retaining parsed canonical identity;
- malformed-entry continuation;
- oversized-entry rejection through Runtime parser limits;
- explicit missing roots;
- unsupported non-directory stores;
- unavailable roots when host permissions can be restricted;
- linked conventional child directories when the host permits link creation;
- cancellation;
- deterministic output independent of entry publication order;
- `-D`;
- `-V` / `--version`;
- explicit rejection of T09 `-u` / `-U`.

The tests use private temporary roots and do not depend on a host terminfo
database for ordinary listing behavior.

## 11. T08 gate

T08 is complete when:

1. explicit conventional roots are enumerated in operand order;
2. default listing composes T02 discovery rather than copying search policy;
3. T03 remains authoritative for filesystem traversal and compiled-entry
   validity;
4. `-a`, `-h`, `-s`, and `-D` obey the documented T08 contract;
5. canonical identity and description come from parsed entries;
6. duplicate canonical names remain visible;
7. catalog issues do not hide safely obtainable entries;
8. any operational catalog issue produces final failure after safe output;
9. T09 source dependency modes remain unimplemented;
10. all seven coordinated projects report `1.4.0-Alpha-8`;
11. all reusable library public API baselines remain exact; and
12. Windows, Linux, and macOS staging validation is green.

**Gate T08:** managed `toe` can reliably enumerate supported conventional
terminfo databases without native ncurses or duplicated discovery logic.
