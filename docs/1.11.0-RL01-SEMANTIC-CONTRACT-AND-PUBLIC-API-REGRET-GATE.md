# Icod.TermInfo 1.11.0 RL01 — Semantic Contract and Public API Regret Gate

**Development version:** `1.11.0-Alpha-1`  
**Tranche:** RL01  
**Published baseline:** `1.10.0`  
**Primary package:** `Icod.TermInfo.Inspection`  
**Status:** implementation committed; CI validation pending

## Objective

RL01 freezes the minimum public semantic vocabulary required by later persistent-raster lifecycle evidence, classification, planning, and automation work.

No terminal protocol execution, live probing, resource ownership, placement ownership, or lower-layer parser behavior is introduced by this tranche.

## Public additions

RL01 adds exactly two public types to `Icod.TermInfo.Inspection`:

```text
PersistentRasterLifecycleSupportStatus
PersistentRasterLifecycleOperation
```

### Support status

The exact membership and numerics are:

```text
Unknown      = 0
Supported    = 1
Unsupported  = 2
Contradicted = 3
```

Semantics:

- `Unknown` means the available evidence establishes neither support nor lack of support.
- `Supported` means the available evidence establishes the semantic capability.
- `Unsupported` means the available evidence establishes that the semantic capability is unavailable.
- `Contradicted` means conclusive positive and negative evidence coexist and the contradiction is retained.

Absence of a static terminfo capability is not, by itself, `Unsupported`.

### Lifecycle operations

The exact membership and numerics are:

```text
DisplayEphemeral = 0
UploadResource   = 1
CreatePlacement  = 2
UpdatePlacement  = 3
DeletePlacement  = 4
DeleteResource   = 5
```

These values describe protocol-neutral semantic intent. They do not expose or imply Kitty image IDs, Kitty placement IDs, APC field dictionaries, Sixel protocol frames, or any other wire-level ownership identity.

## Package boundary

Both types live in `Icod.TermInfo.Inspection`.

RL01 makes no public additions to:

- `Icod.TermInfo`;
- `Icod.TermInfo.Source`;
- `Icod.TermInfo.Compiler`;
- `Icod.TermInfo.Termcap`.

`Icod.TermInfo` has no dependency on `Icod.Terminal`.

## Downstream interpretation

The intended downstream mapping is semantic only:

```text
Icod.TermInfo operation/support vocabulary
        |
        v
consumer policy / optional live verification
        |
        v
Icod.Terminal runtime resource/placement APIs
```

TermInfo does not allocate or retain live terminal identity.

## Compatibility

RL01 preserves:

- all 1.10 database-set APIs and precedence semantics;
- all 1.9 version-1 JSON documents;
- all 1.10 version-2 database automation documents;
- all existing enum numeric values in pre-1.11 public contracts;
- all lower-layer runtime/source/compiler/termcap behavior.

The coordinated suite version advances to `1.11.0-Alpha-1` only after the RL01 vocabulary is present.

## Tests

`RL01PersistentRasterLifecycleContractTests` freezes exact enum membership and integer values so later tranches cannot accidentally reorder, renumber, or broaden the foundational vocabulary without an explicit compatibility decision.

## Deferred to RL02+

RL01 intentionally does not yet add:

- evidence records;
- evidence precedence;
- caller-declared or caller-verified evidence;
- lifecycle profiles;
- classification;
- lifecycle requests;
- plans or planner results;
- database-set lifecycle composition;
- machine-readable lifecycle documents.

Those build on this frozen vocabulary in RL02-RL08.
